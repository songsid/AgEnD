# 加入 Hub 與信任試行 Hub

> Alpha 線上的試行行為。公司帳號登入是正規入口；下面的配對表單與試行
> 信任開關是給需要的 Hub 用的。Hub 換上受信任的憑證後請關閉試行信任。

## 單一入口

在自己的儀表板開**設定 → Hub**，只有一個輸入框**Hub 位址**。輸入管理員
給你的位址即可（`hub.example.com` 就夠，不用加 `https://`）；有加入碼就
空一格接在後面（`hub.example.com ABCD-EFGH`）。

框裡的 Hub 一回答說它接受公司帳號登入，登入就是唯一的入口：舊的
**其他方式**配對碼表單會收起來。**其他方式**只留給沒有公司帳號登入的
Hub——以及連不上 Hub、或憑證不受信任的時候，因為頁面還無法判斷。

## 配對碼表單

**其他方式**是給沒有公司帳號登入的 Hub 用的配對碼方式，表單有自己的
**Hub 位址**框：填配對碼一起提供的位址（結尾有連接埠）。那是成員位址，
不是 Hub 網頁的位址。

配對碼是 12 個字元，只有 0–9 與 a–f（例如 `1a2b3c4d5e6f`）；連字號與
空白會忽略。頁面在要求確認之前先檢查格式，格式不對就不能送出。在這裡
打入加入碼（`XXXX-XXXX`）是跑錯地方了：「這是加入碼。請在這張卡片最上方
的「Hub 位址」輸入位址、空一格，再輸入這組碼。」

確認後如果沒有套用成功，頁面會寫處理方的自己的原因，而不是籠統的重試：

- 「已確認，但沒有套用：這不是有效的配對碼。配對碼是 12 個字元，只有
  0–9 與 a–f。」
- 「已確認，但沒有套用：這不是 Hub 的成員位址。」
- 「已確認，但沒有套用：連不到這個位址上的 Hub。」
- 「已確認，但沒有套用：Hub 拒絕了這組配對碼（已使用、已過期，或不是
  這個 Hub 發的）。」
- 「已確認，但沒有套用：Hub 目前忙碌，請稍後再試。」

## 信任試行 Hub 的自簽憑證

團隊試行中的 Hub 可能用自簽的測試憑證，這台電腦無法自動確認它的身分。
在**Hub 位址**框裡會顯示「這個 Hub 用的是測試用的自簽憑證」、**憑證指紋**
和**顯示完整指紋**。跟 Hub 管理員核對指紋後，按**信任這個 Hub 並繼續**——
或是**取消**。信任會把那一張憑證存下來（只認這個 Hub 位址），接著走公司
帳號登入；已經打好的加入碼會保留。

之後找到的那一行會寫「已信任這個 Hub 的自簽憑證（測試用）。」憑證若有
更動，存好的釘選會拒絕連線；管理員確認換過後，按**重新信任並繼續**，
只換掉顯示中的那一個舊釘選。過期、名稱錯誤、發行鏈不受信任，維持原來
的憑證錯誤——信任不會蓋掉這些。

Fleet 的**允許信任自簽憑證的 Hub（測試用）**開關一直在**設定 → Hub** 裡，
連上之後也在。試行結束、或 Hub 換上受信任的憑證後請關掉；alpha 版預設
開，穩定版預設關。關掉之後連線就要普通的憑證信任；用來登入而開啟的瀏覽
器，維持它自己的憑證政策。
