# 辦公室畫面

[English](office.md)

**Fleet → 組織圖 → 辦公室** 把你的 fleet 畫成一間小小的像素辦公室：每個 instance 是一個小人，姿勢就是它的狀態；instance 之間的訊息、委派與回報會在房間裡飛來飛去。這份指南說明怎麼使用它、設定辦公室、製作外觀包、安排配置，以及讓 agent 參與。

> **版本。** 辦公室畫面在 **2.3.0** 推出，含辦公桌與工作室兩種風格，以及存在主機上的辦公室。這裡其他幾乎所有功能都是在 **2.3.2 beta** 加入的，另有兩個家具欄位還沒發布；[版本](#版本)列出每個功能從哪一版開始。標示 **尚未發布** 的功能已在 `main` 上，但還沒有任何已發布的版本包含它，正式推出前請先別依賴它。

## 快速導覽

打開 dashboard（在 General 傳 `/web`），進 **Fleet → 組織圖**，在畫布與清單旁選 **辦公室**。這個選擇會記在那台裝置上。訪客看不到組織圖，也看不到辦公室。

**姿勢代表什麼。**

| 狀態 | 姿勢 | 說明 |
|---|---|---|
| working | 在桌前打字 | 埋頭打字中 |
| idle | 喝茶休息（區域風格裡會走到休息區） | 喝茶休息 |
| paused、stopped | 睡著 | 睡著了 |
| 需要你、crashed、看起來卡住 | 舉手 | 在呼叫你 |

小人偶爾會在對話泡泡裡說一句符合狀態的短句。泡泡絕不會顯示訊息內容。

**移動畫面。** 拖曳平移，用滾輪或雙指縮放。**+**／**−** 以整數像素倍率縮放，**Fit** 顯示整個場景；**填滿**（每個辦公室各自記住）改成填滿整個面板，超出的部分會被裁切，拖曳即可看到。辦公室有焦點時，`+`、`-`、`0`（顯示全部）鍵可用，`f` 切換 **全螢幕**（Esc 離開）。右下角的總覽可以跳到某處；手機上不顯示。縮放、中心點與 Fit／填滿會依裝置、依辦公室和風格分別記住。畫面一律是不平滑的像素畫，縮放與平移都不會有動畫。

**全螢幕** 只顯示辦公室，縮放按鈕、總覽、精簡的辦公室切換器與「結束全螢幕」浮在上面。頁面無法進入全螢幕時（iPhone），或瀏覽器拒絕時，辦公室會改成蓋滿整個視窗。打開聊天會離開全螢幕，全螢幕狀態不會被記住。

**手機上**，場景會用上方各列下面剩下的高度，所以放大後可以拖到場景底部。不在全螢幕時，縮放按鈕排成一列放在上方。只有很矮的螢幕會保留 200 px 的場景並讓面板捲動；在上方各列上滑動即可捲動。

**滑過與點擊。** 滑過（或點一下）某個人，會顯示它的名稱、狀態與 backend；點擊（或再點一下）打開它的聊天。**尋找** 會淡化不符合的人。

**辦公室工具列。**

| 控制項 | 作用 | 記在哪裡 |
|---|---|---|
| **辦公室** | 要顯示哪間：**整個 fleet**、某間已存的辦公室，或 **所有辦公室** | 每台裝置 |
| **顯示** | 只顯示某個 team 或大廳 | 每個瀏覽器 |
| **成員** | 釘選特定 instance；**顯示全部** 會清除 | 每個瀏覽器 |
| **風格** | **辦公桌**、**工作室**、**溫馨** 或上傳的外觀包（用於整個 fleet；已存的辦公室有自己的風格） | 每個瀏覽器 |
| **隱藏暫停與停止的成員** | 不顯示睡著的人 | 每個瀏覽器 |
| **0–6 點就寢：閒著的人去睡** | 見[辦公室裡的日常](#辦公室裡的日常)（區域風格與所有辦公室） | 每台裝置，預設關閉 |
| **大廳格** | 在所有辦公室裡，為不在任何辦公室的 instance 加一格 | 每個瀏覽器，預設開啟 |

**風格。**

- **辦公桌**：每個 team 一間房間，每個 instance 一張桌子；General 和未加入 team 的 instance 在大廳。進行中的委派是工作者桌上的一個資料夾。比面板小的辦公桌辦公室會置中。
- **工作室**：一個場景，分成四個區域（工作區、休息區、求救區、午睡角）。每個 instance 會沿著走道走到它狀態對應的區域。
- **溫馨**：同樣的場景，畫在 AgEnD 內附的一張溫暖像素畫裡：辦公桌、沙發與咖啡、懶骨頭、白板。它的公告欄寫著外觀包可以改造這個房間。溫馨是還沒選過風格的瀏覽器與新辦公室的預設；已存的辦公室保留自己的風格。
- **上傳的外觀包**：可以是像工作室那樣的區域場景，也可以是用自己圖片的辦公桌式配置。

下文把工作室、溫馨與區域外觀包統稱為 **區域風格**。只有它們有走動、座位、編輯配置、就寢、散步與信件。

**人多的時候。** 某個區域的人比座位多時，多出來的人會排成更密的格子，再多就在角落顯示「+N」。那裡只有呼叫與工作會有泡泡（最多幾個），名牌在滑過或取得焦點時才顯示。

**所有辦公室**（存了兩間以上辦公室後出現在切換器裡）把每間已存的辦公室各畫成一格，每格和它單獨顯示時完全一樣，並標上名稱與人數。**大廳格** 為不在任何辦公室的 instance 加一格；每個人都在某間辦公室時它會停用並說明。點一格的標題，或雙擊那一格，會打開那間辦公室。不同辦公室的人之間的流量會直接飛過去。縮放低於 75% 時，名牌只在滑過時顯示。編輯辦公室與編輯配置要等到只顯示一間辦公室時才能用。

**減少動態效果**（系統設定）時，姿勢靜止、空中沒有東西在飛，泡泡一次整句出現。

## 設定辦公室

fleet 管理者在直接連線的 dashboard 上（不是透過公開連結）使用辦公室工具列的 **編輯辦公室**。螢幕寬度 1200 px 以上時，它會在右側以面板開啟，取代 AI 用量欄的位置，旁邊的辦公室仍然可以操作；較窄時是置中的對話框。× 或 Esc 關閉。

1. **新增辦公室**，取個名稱。
2. **成員**：整個 team 或個別 instance。沒選任何人的辦公室會顯示全部。
3. **風格**：辦公桌、工作室、溫馨或已上傳的外觀包。
4. **儲存**。

辦公室屬於整個 fleet：每個人看到的是同一批。主機把它們存在 AgEnD home 的 `web-offices.json`（`GET`／`PUT /ui/offices`），從不寫進 fleet.yaml，所以修改不會重啟任何東西。最多 20 間辦公室，每個人每分鐘最多儲存 20 次。

如果你編輯時別人已經存過，你的儲存會被拒絕，什麼都不會被覆蓋。選 **保留我的編輯**（下一次儲存會取代對方的修改），或 **載入對方的版本**。有未儲存的修改時離開頁面，會先詢問你。

**整個 fleet** 是頁面自己的辦公室，每次都依你的 team 組出來；它從不被儲存，風格是每個瀏覽器自己的選擇。

## 使用外觀包

外觀包是畫師為辦公室畫的圖：一個 `manifest.json` 加上 PNG 檔。製作方式見[製作外觀包](#製作外觀包)。

**上傳。** 在 **編輯辦公室 → 外觀包** 用 **上傳外觀包**，把外觀包的 `manifest.json` 和所有 PNG 一起選取，或用 **上傳資料夾**。主機會檢查每一項（見[上限](#上限)），遇到第一個問題就拒絕，並指出在哪裡，例如 `furniture[3].sprite.w: a whole number from 1 to 512`。外觀包會完整存在 AgEnD home 的 `web-office-skins/<id>/`，從不被修改。

**使用。** 已存的外觀包會出現在每個 **風格** 選單裡。在編輯辦公室為某間辦公室選它，或在辦公室工具列為整個 fleet 選它。頁面無法載入的外觀包會以辦公桌顯示，並附上說明。

**更新。** 在網頁上，先刪除外觀包再上傳新版；主機已經有的 id 會被拒絕。有[外觀包權限](#讓-agent-管理外觀包)的 agent 則可以直接取代，並保留上一版供還原。

**刪除。** 按外觀包的刪除按鈕。用它的辦公室會改以辦公桌顯示，並附上說明。

## 製作外觀包

外觀包描述一個 **1280×720 邏輯畫布**（16:9）上的場景；manifest 裡所有座標都是這個邏輯單位。圖片是像素畫，以每個圖片像素 `scale` 個邏輯單位（預設 2）不平滑地畫出。

一個最小的區域外觀包：

```json
{
  "format": 1,
  "id": "harbour",
  "background": "room.png",
  "areas": {
    "desks":  { "rect": [40, 120, 620, 440], "seats": [[120, 220], [260, 220], [400, 220]] },
    "lounge": { "rect": [700, 120, 540, 260], "seats": [[760, 260], [880, 260]] },
    "nap":    { "rect": [700, 420, 540, 260], "seats": [[780, 560]] }
  },
  "stateZones": { "working": "desks", "paused": "nap", "stopped": "nap", "default": "lounge" },
  "characters": {
    "default": {
      "idle":    { "src": "people/idle.png", "frames": 4, "w": 32, "h": 48, "fps": 4 },
      "working": { "src": "people/work.png", "frames": 4, "w": 32, "h": 48, "fps": 6 },
      "walk":    { "src": "people/walk.png", "frames": 2, "w": 32, "h": 48, "fps": 6 }
    }
  }
}
```

`room.png` 必須是 16:9，每個影格條的圖片必須剛好是 `frames·w × h` 像素：上例的 `idle` 是 128×48。

**區域、座位與狀態。** 區域是一個矩形 `[x, y, w, h]` 加上它的座位，依填滿的順序排列。座位是 `[x, y]`，也就是人的腳站的位置，必須在區域的矩形內。`stateZones` 把每個狀態（`needs`、`crashed`、`stuck`、`working`、`idle`、`paused`、`stopped`、`missing`）送到某個區域；沒列出的狀態去 `"default"`，沒有就去第一個區域。就寢時，閒著的人會去 `paused` 用的那個區域。

**角色。** 必須有 `characters.default`，且至少有 `idle`。一組角色的姿勢是 `working`、`idle`、`paused`、`needs`；缺少的姿勢以 `idle` 顯示。可以有更多組（最多 64 組），用 `byInstance: { "atlas": "fox" }` 依名稱指定給 instance。

**走動。** 外觀包有路徑圖（`waypoints` 與 `edges`）時，人會沿著它走，沒有就直接走到座位。新來的人從 `door` 走進來（預設在底部中間）。走路的影格條依每一步的方向挑選：`walkDown`（朝向觀看者）、`walkUp`，或 `walkSide`——畫成面向右邊，往左時左右翻轉。缺少的用 `walk`，再沒有就用 idle。設定 `"straight": true` 時，每段斜走都會變成 L 形，先橫走再上下走，三種走路影格條就永遠和移動方向一致；路徑圖用水平與垂直的邊來畫，轉角就會落在走道上。

**飛的東西。** 訊息、委派、回報與廣播會以外觀包的 `props`（`task`、`send`、`report`、`broadcast`）在人之間飛，沒有就用內建的圖。一組角色可以有自己的 `prop`：它的人送出的所有東西都會畫成那個。

**家具。** 每件家具是放在 `(x, y)` 的一個影格條，有自己的 `depth`：小於 1000 畫在人下面，1000 以上畫在人上面，`"depth": "y"` 則依底部和人一起排序，站得比較下面的人在前面。家具可以：

- 在有人處於某個狀態時播放：`activeWhen`（一個狀態或清單），可以搭配自己的 `activeSprite`，以及 `activeFor`（一個 instance 或最多 8 個的清單）只看那些人；否則停在第一格，或設 `"loop": true` 一直播放；
- 用 `label`（1–40 字）掛一個名牌，像人一樣（畫成家具的 NPC）；
- 用 `walk`（它自己的走路影格條，`walk` 必填）像閒著的人一樣在原地附近散步；
- 用 `night` 在就寢時睡覺：`{ "sprite": STRIP, "x": …, "y": … }`（省略 x／y 就在原地）；
- **尚未發布：** 等它的人坐下，並把人藏起來。`"activeOn": "seated"` 讓家具只在 `activeFor` 裡的某人、處於該狀態、走到自己的座位後才啟動，對方一走開就恢復（預設 `"state"` 跟著狀態變）。`"hides": true`（需要 `activeFor`）讓家具啟動時不畫出那些人；走動中的人一律會畫出來。他們的名牌（在家具的名牌位置排成一列，排在家具自己的名牌之後）與泡泡改畫在家具上，滑過或點擊某人的名牌或家具的圖，就會選到那個人。適合床、轎子或帳篷這類和人合成一張圖的家具。

**前景與外框。** `foreground` 是蓋在整個場景上的 16:9 PNG，畫在人與家具之上、名牌、泡泡與「+N」之下：用來畫門框、柱子、桌子前緣，把走到後面的人遮住。`matte`（`#rrggbb`）是面板不是 16:9 時場景周圍的顏色；沒有設定時，頁面會取背景邊緣的顏色。

**泡泡。** `bubbles: { "en": { "working": ["On it."] }, "zh-TW": { … } }` 取代頁面內建的某個狀態的句子：最多 12 句，每句 1–40 字。

**辦公桌式外觀包。** 沒有 `stateZones` 的外觀包沿用辦公桌配置，可以提供自己的 `room`（`floor`、`wall`）與 `desk`（`back`、`front`、`lit`）圖片。

**尺寸與錨點。** 影格條顯示的大小是 `w·scale × h·scale`，除非它用邏輯單位指定 `dw` 或 `dh`；只給其中一個時，另一個依比例算出。`(ax, ay)` 是圖片上要放在位置點的那一點（預設底部中央，所以人站在座位上）。scale 2 時的建議尺寸：角色 32×48，道具 12×12。

**檢查外觀包。** 檢查很嚴格：未知的欄位、超出範圍的值，或指向不存在的名稱，都會讓整個外觀包被拒絕，並指出在哪裡。有外觀包權限的 agent 可以對資料夾跑 `office_pack_check`，什麼都不會存（見[下方](#讓-agent-管理外觀包)）。頁面與主機用的是同一套規則。

## 安排配置

在區域風格的已存辦公室上，fleet 管理者可以用 **編輯配置** 移動東西。修改會存成那間辦公室自己的 *overrides*；外觀包保持上傳時的樣子，用同一個外觀包的其他辦公室不受影響。

- 疊加層顯示 1280×720 座標格（**顯示座標**），每個座位、家具、門與路徑點都有一個控制點。每個空座位會顯示一個淡淡的人形，擺出那個區域的姿勢。
- 拖曳控制點，或用 Tab 選到它再用方向鍵移動（Shift：一次 10）。
- **新增路徑點**／**移除路徑點**；選了路徑點後，可以 **連到** 另一個，或 **取消連接** 某條走道。
- 會在就寢時睡覺的家具還有一個夜間控制點「家具 {id}（夜間）」：淡淡的夜間圖、一個月亮，以及一條連到白天位置的細線。拖曳它，就能給家具自己的夜間位置；**回到 pack 的夜間位置** 可以復原。
- 選取的座位有 **保留給** 與 **不在時借給別人**；見[保留座位](#保留座位)。
- **儲存配置** 存起來；**還原成 pack 的配置** 回到外觀包自己的配置；**取消**（或 Esc）關閉。

螢幕寬度 1200 px 以上時，它的控制項在右側面板裡，整個畫布都留給控制點；較窄或全螢幕時，控制項是畫布下方的一列。開著時，辦公室切換器與編輯辦公室會等它關閉。若別人在這期間存過辦公室，儲存會告訴你並保留你的配置；再按一次儲存，就會套用到目前的清單。

主機每次儲存都會檢查 overrides：座位必須留在自己的區域內，每個區域的座位數要和外觀包一樣。overrides 是針對某一個外觀包做的：換成其他風格時會被忽略（「它儲存的配置不適用這個風格」）。之後外觀包被換掉、配置不再適用時，那間辦公室會先用外觀包自己的配置，直到有人修正；agent 要換掉外觀包時會先被詢問（見[下方](#讓-agent-管理外觀包)的 `drop_invalid_overrides`）。

## 保留座位

有些姿勢是為某個座位畫的，例如兩個人在沙發上互相靠著，或某人坐在自己的桌前。保留座位能讓它們正確顯示。

- 在編輯配置裡選一個座位，再選它要 **保留給** 哪些辦公室成員（可以多選）。它的控制點會加上一圈。
- 座位保留給的人來到它的區域時會先坐那裡：優先坐上次坐的那個，否則坐區域順序中第一個保留給他的座位。
- 其他人不會坐那裡，除非開了 **不在時借給別人**，而且保留的人都在別處。保留的人回來時，借坐的人會讓開。一般座位會比可以借的座位先分配出去。
- 沒有開放借用、保留的人又都在別處的座位，不算進那個區域可容納的人數。
- 外觀包也可以保留座位：座位可以寫成 `{ "x": 760, "y": 260, "for": ["atlas"], "lend": false }`，取代 `[x, y]`。辦公室自己的保留會取代外觀包對那個座位的保留；保留給「沒有人」就是取消外觀包的保留。

## 辦公室裡的日常

這些需要區域風格。

- **就寢**（**0–6 點就寢：閒著的人去睡** 勾選框，每台裝置，預設關閉）：觀看者時間 00:00 到 06:00，閒著的人只要睡覺區（`paused` 用的那個區域）還有空位，就會走過去睡，頭上冒 Zzz；其他人原地打瞌睡。工作中的人繼續工作。有 `night` 的家具會在夜間位置睡覺。
- **散步：** 閒著的人偶爾會走到附近一個沒有座位的路徑點，停幾秒再走回來。有 `walk` 的家具也會這樣散步。散步只在單一辦公室（不是所有辦公室）、沒有減少動態效果、也沒開編輯配置時發生。
- **信件：** 辦公室外的人寄給辦公室裡某人的訊息，會變成一封信從門口飛進來，落在房間裡（減少動態效果時不會）。收件人會走過去撿起來，睡著時除外。一封信最多等一分鐘。
- **流量：** 同一間辦公室裡的人之間，東西會從寄件人飛到收件人。委派會一直顯示為進行中，直到工作者的回報回來。

## 分享畫面

fleet 管理者可以讓 fleet 以外的人在一段時間內觀看即時辦公室，不需要登入。在辦公室工具列按 **分享…**：可以在直接連線的 dashboard 上，也可以透過臨時公開連結登入後使用；唯讀 session 與訪客不能分享。沒有對應的聊天指令。

1. 選一間辦公室或 **所有辦公室**，以及時間：15 分鐘到 24 小時（預設 1 小時；`web.office_share.max_hours` 設定上限）。
2. 勾選 **包含 agent 自己的狀態文字**，就連 agent 的 `office_set` 文字也一起顯示。
3. 按 **建立連結**，再按 **複製連結**。連結只會顯示給你，而且只顯示一次。

觀看者看到的那間辦公室（或所有辦公室）和 dashboard 畫的一樣：場景、名稱、身分色與狀態，每 5 秒更新，可以縮放、Fit 與全螢幕。其他什麼都沒有：沒有聊天、不能點進任何東西、沒有設定，也沒有模型、費用或說明。只顯示辦公室的成員，`cross_instance_visibility: hidden` 的 instance 一律不顯示。

每個連結有自己在臨時通道上的網址（`https://<random>.trycloudflare.com/o/<token>`），和 dashboard 的不同；第一個連結建立時啟動，最後一個結束時停止。同時最多 10 個連結。每個連結每分鐘最多 120 個請求，外觀包的圖片另外計算，所以即使所有辦公室都用滿檔的外觀包，每個房間也都載得出來。連結在以下情況結束：時間到、按 **撤銷**（在 **設定 → 存取與安全 → 辦公室分享連結**，或分享表單下方）、`web.office_share.enabled` 設為 `false`、建立者不再是 fleet 管理者、它的辦公室被刪除，或 fleet 重啟。每個連結的建立與撤銷都會在 General 公告（絕不包含連結本身）。Cloudflare 拒絕建立新的臨時通道時，建立連結會請你過幾分鐘再試。

更多關於 dashboard 的連線方式：[web-dashboard.zh-TW.md](web-dashboard.zh-TW.md)。

## 辦公室裡的 agent

有人替某個 agent 打開 **辦公室** dashboard 功能（`office_access: true`）後，它可以看到自己所在的辦公室，並短暫指揮自己的角色。這個功能沒設定就是關閉，在 **設定 → Agent 預設值** 或該 agent 的 **進階 → Dashboard 權限** 設定；打開要先確認，關掉會立刻移除工具。

- `office_view { office? }`：它所在的已存辦公室，含成員與狀態。用上傳的區域外觀包的辦公室，還會列出座位（`"區域:序號"`）、路徑點、家具（NPC）與門，並已套用該辦公室的配置 overrides。其他辦公室（辦公桌、工作室、溫馨，或沒有區域的外觀包）會回傳 `walks: false`，沒有這些點。
- `office_set { office?, go?, say?, pose?, seconds?, clear? }`：走到某個座位、路徑點或另一位成員身邊（`go`）；說一句 1–40 字的話（`say`）；擺一個姿勢：idle、working、needs 或 paused（`pose`）；持續 5–120 秒（預設 30）。`clear: true` 結束。`walks` 為 false 的地方，那句話與姿勢會顯示，`go` 會被拒絕。
- 每個動作會取代上一個。時間到、或 agent 開始新的工作時就結束；agent 在呼叫人、暫停或停止、或就寢時間睡覺時不會顯示。動作只存在記憶體裡。
- 每個 agent 每分鐘最多 6 次、每小時最多 60 次；被拒絕時會附上 `cooldown_ms`。
- 命令列也可以：`agend-agent office view [office]` 與 `agend-agent office set '<json>'`。

## 讓 agent 管理外觀包

agent 可以自己檢查、上傳、取代、刪除與還原外觀包，例如發布畫師的修正，不必每次都由人手動上傳。外觀包全 fleet 都看得到，所以這是另一個開關：在 **設定 → Agent 預設值** 或該 agent 的 **進階 → Dashboard 權限** 打開 **辦公室外觀包**（`office_pack_access: true`）。沒設定就是關閉，打開要先確認。

**工具。**

| 工具 | 作用 |
|---|---|
| `office_pack_list` | 每個外觀包（id、名稱、檔案數、位元組、版本、可還原的上一版、哪些辦公室在用）、已存的辦公室、核准模式、這個 agent 等待中的變更，以及這一小時還剩多少額度 |
| `office_pack_check` | 跑主機自己的檢查，什麼都不存：`PACK OK` 或第一個拒絕原因 |
| `office_pack_upload` | 檢查與上限和網頁上傳相同；fleet 已經有的 id 會立刻被 **取代** |
| `office_pack_restore` | 還原保留的上一版（被換下的那版變成上一版，所以還原也能用同樣方式復原） |
| `office_pack_delete` | 刪除外觀包，連上一版一起刪，除非 `keep_previous: true` |
| `office_set_style` | 把已存的辦公室指向某個外觀包或內建風格（`pixel` = 辦公桌、`studio`、`cozy`） |

**送出外觀包。** 外觀包可以是一個資料夾（`dir`），裡面有 `manifest.json` 與 manifest 指到的 PNG；也可以是一個 `manifest` 物件加上 `files`（`{ "<它用的名稱>": "<路徑>" }`）。`packs: [...]` 一次送出好幾個，算一批。agent 那一側只讀那些檔案，而且只在它的工作目錄或 fleet 的共用資料夾（`~/.agend/shared`）裡；符號連結會被跟隨，但必須留在裡面。fleet 收到的是檔案內容，從不是路徑。

**安全地取代。** 被取代的外觀包會先檢查、先寫好，再一次換上。任何一步失敗都保留舊版，中途辦公室也不會掉回辦公桌。每個外觀包保留一份上一版，不算進 16 個的上限。

**配置不再適用時。** 每間在這個外觀包上有配置 overrides 的已存辦公室，都會用新版再檢查一次：座位、家具、夜間位置與保留座位。若有項目不再適用（座位數變了、座位離開了區域、家具或保留的座位不見了），檢查、上傳與還原都會拒絕，並說出辦公室與規則。加上 `drop_invalid_overrides: true` 時，只會丟掉剛好那些項目並列出來——保留座位是一個座位一個座位地丟，絕不會丟掉辦公室的整份配置。

**核准。** fleet 管理者在 **編輯辦公室 → 會改外觀包的 agent** 選擇模式：

- **要我核准**（預設）：每個變更都會先等待，直到 fleet 管理者在那裡核准，或在 General 的通知上按 **核准**／**拒絕**。核准時會再判斷一次。等待中的變更只存在記憶體裡，保留 24 小時，同時最多 8 個，fleet 重啟會清掉。
- **直接套用**：變更立刻套用，並通知管理者。

同一個面板也列出哪些 agent 可以改外觀包、等你核准的變更，以及最近的變更。

**紀錄與上限。** 每次上傳、取代、刪除與還原都會記錄在 `~/.agend/web-office-skins/.agent-changes.log`（誰、何時、哪個外觀包、檔案數、位元組，以及 manifest 與每張圖的 sha256，方便把還原對應到某個版本），並在 General 用一則短訊息通知 fleet 管理者。每個 agent 每小時最多 20 批、200 MiB。一次呼叫是一批，最多 16 個外觀包、100 MiB 的圖片；被拒絕的與檢查不算。磁碟上所有外觀包最多佔 640 MiB：16 個滿檔的外觀包，加上各自的上一版。

命令列也可以：`agend-agent office packs`、`pack-check <dir>`、`pack-upload <dir>… [--drop-invalid-overrides]`、`pack-delete <id> [--keep-previous]`、`pack-restore <id>`、`style <office> <pack>`。

## 參考

### manifest

| 欄位 | 必填 | 說明 |
|---|---|---|
| `format` | ✅ | `1` |
| `id` | ✅ | 1–40 個英文字母、數字、`_` 或 `-`。不能是 `pixel`、`studio` 或 `cozy`；只差大小寫的 id 會衝突 |
| `scale` | ❌ | 每個圖片像素幾個邏輯單位，1–8（預設 2） |
| `background` | 有 `stateZones` 時 | 場景的圖，16:9 |
| `foreground` | ❌ | 蓋在場景上的 16:9 圖（只能搭配 `stateZones`） |
| `matte` | ❌ | `#rrggbb`，場景周圍的顏色 |
| `areas` | 有 `stateZones` 時 | `{ 名稱: { rect: [x, y, w, h], seats: [座位, …] } }`，最多 32 個區域，每個最多 64 個座位 |
| `stateZones` | ❌ | 狀態 → 區域；`"default"` 給其餘狀態。沒有它就沿用辦公桌配置 |
| `door` | ❌ | 新來的人走進來的 `[x, y]`（預設底部中間） |
| `waypoints` | ❌ | `[{ id, x, y }, …]`，最多 512 個 |
| `edges` | ❌ | `[[id, id], …]`，最多 2048 條 |
| `straight` | ❌ | `true`：每次走動都先橫走再上下走 |
| `furniture` | ❌ | 家具，最多 128 件（見[家具](#家具)） |
| `characters` | ✅ | `{ 角色組: { 姿勢: STRIP, … } }`，最多 64 組；必須有含 `idle` 的 `default`。欄位：`working`、`idle`、`paused`、`needs`、`walk`、`walkDown`、`walkUp`、`walkSide`、`prop` |
| `byInstance` | ❌ | instance 名稱 → 角色組，最多 500 個 |
| `props` | ❌ | `task`、`send`、`report`、`broadcast`：飛行物的 STRIP |
| `bubbles` | ❌ | `{ "en" \| "zh-TW": { 狀態: [句子, …] } }`，最多 12 句，每句 1–40 字 |
| `room`、`desk` | ❌ | 辦公桌配置的圖：`room.floor`、`room.wall`、`desk.back`、`desk.front`、`desk.lit` |

座位是 `[x, y]` 或 `{ "x", "y", "for": [instance, …]（最多 16 個）, "lend": false }`，必須在它的區域內。座標橫向 0–1280、縱向 0–720。外觀包宣告的名稱不能是每個物件都有的名稱（`constructor`、`toString`、`__proto__` 等）。

### 影格條

STRIP 是 `{ "src", "frames", "w", "h", "fps", "ax", "ay", "dw", "dh" }`：

| 欄位 | 範圍 | 預設 |
|---|---|---|
| `src` | 外觀包裡的檔案：英文字母、數字、`. _ - /`，不能有 `..`，不能以 `/` 開頭 | — |
| `frames` | 1–32，由左到右並排，中間沒有空隙 | — |
| `w`、`h` | 每格 1–512 圖片像素 | — |
| `fps` | 0–30；0 只顯示第一格 | 4 |
| `ax`、`ay` | 錨點，單位是圖片像素 | 底部中央 |
| `dw`、`dh` | 顯示大小，單位是邏輯單位（1–1280、1–720） | `w·scale`、`h·scale` |

### 家具

| 欄位 | 說明 |
|---|---|
| `id` | 新的名稱：英文字母、數字、`_`、`-` |
| `sprite` | 它的 STRIP |
| `x`、`y` | 錨點放的位置 |
| `depth` | −10000–10000（小於 1000：畫在人下面），或 `"y"`（和人一起排序） |
| `activeWhen` | 一個狀態或最多 8 個的清單：有人處於該狀態時播放（或顯示 `activeSprite`） |
| `activeSprite` | 啟動時的圖（需要 `activeWhen`） |
| `activeFor` | 一個 instance 或最多 8 個的清單：只看他們的狀態（需要 `activeWhen`） |
| `loop` | `true`：沒有啟動時也一直播放 |
| `label` | 家具下方的名牌，1–40 字 |
| `night` | `{ sprite, x?, y? }`：就寢時怎麼睡、睡在哪裡 |
| `walk` | `{ walk, walkDown?, walkUp?, walkSide? }`：在原地附近散步 |
| `activeOn` | **尚未發布。** `"state"`（預設）或 `"seated"`：等它的人坐下才啟動（需要 `activeWhen`） |
| `hides` | **尚未發布。** `true`：啟動時不畫出它的人，他們的名牌與泡泡改畫在家具上（需要 `activeFor`） |

### 配置 overrides

辦公室的 `overrides`（由編輯配置寫入；每次 `PUT /ui/offices` 都會檢查）：

| 欄位 | 說明 |
|---|---|
| `pack` | 它是針對哪個外觀包做的；換成其他風格時會被忽略 |
| `seats` | `{ 區域: [[x, y], …] }`：座位數和外觀包一樣，每個都在區域內 |
| `furniture` | `{ 家具: [x, y] }` |
| `furnitureNight` | `{ 家具: [x, y] }`：夜間位置，只用於外觀包有 `night` 的家具 |
| `seatFor` | `{ 區域: { "序號": { "for": [instance, …], "lend": false } } }`；`"for": []` 取消外觀包的保留 |
| `door` | `[x, y]` |
| `waypoints`、`edges` | 路徑圖，整份取代 |

## 升級與降版

- **升級** 會保留你的辦公室、外觀包與配置，不需要手動搬移。
- **在 2.3.2 之內降版。** 夜間位置與保留座位存在辦公室清單旁邊，所以降回較早的 2.3.2 beta 時，每間辦公室都還讀得到，只是少了這兩項。agent 以 `keep_previous` 刪除的外觀包，上一版存在它自己的 `.kept-<id>` 資料夾，所以降回 2.3.2-beta.10 時仍然可以上傳與刪除那個 id。
- **降回 2.3.1 或 2.2.6。** `office_access` 與 `office_pack_access` 存在 fleet.yaml 的 `dashboard` 之外，所以舊版會接受這個檔案並忽略它們。2.3.1 沒有外觀包：用外觀包或溫馨的辦公室會以辦公桌顯示並附上說明。**2.3.1 不會顯示存過配置（編輯配置）的辦公室；若有人在 2.3.1 上儲存辦公室，那間辦公室就會永久消失。** 降回 2.3.1 之前，請別在上面儲存辦公室，或先把你的配置記下來。
