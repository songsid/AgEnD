# 辦公室畫面

[English](office.md)

**Fleet → 組織圖 → 辦公室** 把你的 fleet 畫成一間小小的像素辦公室：每個 instance 是一個小人，姿勢就是它的狀態；instance 之間的訊息、委派與回報會在房間裡飛來飛去。這份指南說明怎麼使用它、設定辦公室、製作外觀包、安排配置，以及讓 agent 參與。

> **版本。** 辦公室畫面在 **2.3.0** 推出，含辦公桌與工作室兩種風格，以及存在主機上的辦公室。這裡其他幾乎所有功能都是在 **2.3.2** 加入的；[版本](#版本)列出每個功能，以及它最早出現在哪個 2.3.2 beta。

## 快速導覽

打開 dashboard（在 General 傳 `/web`），進 **Fleet → 組織圖**，在畫布與清單旁選 **辦公室**。這個選擇會記在那台裝置上。訪客看不到組織圖，也看不到辦公室。

**姿勢代表什麼。**

| 狀態 | 姿勢 | 說明 |
|---|---|---|
| working | 在桌前打字 | 埋頭打字中 |
| idle | 喝茶休息（區域風格裡會走到休息區） | 喝茶休息 |
| paused、stopped | 睡著 | 睡著了 |
| 需要你、crashed、看起來卡住 | 舉手 | 在呼叫你 |

小人偶爾會在對話泡泡裡說一句符合狀態的短句。泡泡絕不會顯示訊息內容。

**移動畫面。** 拖曳平移，用滾輪或雙指縮放。**+**／**−** 以整數像素倍率縮放，**Fit** 顯示整個場景；**填滿**（每個辦公室各自記住）改成填滿整個面板，超出的部分會被裁切，拖曳即可看到。辦公室有焦點時，`+`、`-`、`0`（顯示全部）鍵可用，`f` 切換 **全螢幕**（Esc 離開）。右下角的總覽可以跳到某處。單一辦公室整個都在畫面裡時，總覽會隱藏（它只會重複面板的內容），放大、平移或切到填滿後就會回來；「所有辦公室」一律顯示總覽。手機上不顯示。縮放、中心點與 Fit／填滿會依裝置、依辦公室和風格分別記住。畫面一律是不平滑的像素畫，縮放與平移都不會有動畫。

**全螢幕** 只顯示辦公室，縮放按鈕、總覽、精簡的辦公室切換器與「結束全螢幕」浮在上面。輪播時，暫停、下一間與目前辦公室名稱會放在切換器旁邊。頁面無法進入全螢幕時（iPhone），或瀏覽器拒絕時，辦公室會改成蓋滿整個視窗。打開聊天會離開全螢幕，全螢幕狀態不會被記住。

**手機上**，場景會用上方各列下面剩下的高度，所以放大後可以拖到場景底部。不在全螢幕時，縮放按鈕排成一列放在上方。只有很矮的螢幕會保留 200 px 的場景並讓面板捲動；在上方各列上滑動即可捲動。

**滑過與點擊。** 滑過某個人，會顯示它的名稱、狀態與 backend。點擊（或點一下）它，或在桌子清單的項目上按 Enter，會打開它的[名片](#名片)。雙擊某個人會直接打開它的聊天。**尋找** 會淡化不符合的人。

**辦公室工具列**只有一列：左邊是你在看的範圍，右邊是動作（**編輯辦公室**、**分享…**）與 **⚙ 顯示選項**。手機上，**⋯** 會用一張表單依同樣的順序列出全部，並以 **顯示選項** 標題分段。Hub 房間的辦公室則從縮放按鈕下方的齒輪打開同一份顯示選項。

| 控制項 | 作用 | 記在哪裡 |
|---|---|---|
| **辦公室** | 要顯示哪間：**整個 fleet**、某間已存的辦公室、**所有辦公室**，或 **輪播…** | 每台裝置 |
| **輪播…** | 勾選的辦公室輪流全螢幕（看板）。**輪播 n/m 間 ▾** 勾選；**暫停**／**下一間**，或空白鍵／←／→ | 辦公室與間隔記在這個瀏覽器；進入時開始播放 |
| **顯示** | 只顯示某個 team 或大廳 | 每個瀏覽器 |
| **成員** | 釘選特定 instance；**顯示全部** 會清除 | 每個瀏覽器 |

**⚙ 顯示選項** 是下拉選單，不會蓋住整個辦公室：勾選後立即生效，選單保持開啟；點其他地方或按 Esc 就會關閉。

| 選項 | 作用 | 記在哪裡 |
|---|---|---|
| **風格** | **辦公桌**、**工作室**、**溫馨**、**冒險者公會**、**學校** 或上傳的外觀包（用於整個 fleet；已存的辦公室有自己的風格） | fleet 管理員選的會套用到整個 fleet；其他人選的只留在自己的瀏覽器 |
| **隱藏暫停與停止的成員** | 不顯示睡著的人 | 每個瀏覽器 |
| **隱藏名字和等級** | 人的頭上不畫名牌和等級徽章；滑過或用尋找框找到的人仍會顯示；正在呼叫你的人仍顯示名字（不顯示等級） | 每個瀏覽器 |
| **隱藏小地圖** | 角落不顯示小地圖 | 每個瀏覽器 |
| **0–6 點就寢：閒著的人去睡** | 見[辦公室裡的日常](#辦公室裡的日常)（區域風格與所有辦公室） | 每台裝置，預設關閉 |
| **大廳格** | 在所有辦公室裡，為不在任何辦公室的 instance 加一格 | 每個瀏覽器，預設開啟 |
| **拖曳與摸頭** | 把人拿起來、摸頭或餵點心：見[辦公室裡的日常](#辦公室裡的日常)（區域風格） | 每台裝置，預設開啟 |
| **對話框** | [對話框](#對話框)：有人對這裡的 agent 說了什麼，以及回覆 | 每個瀏覽器，預設關閉 |
| **對話方式** | 在這裡按 **對話** 會怎樣：彈出視窗、側邊面板、對話框或頭頂氣泡；見[在辦公室裡對話](#在辦公室裡對話)（只在儀表板） | 每個瀏覽器，預設彈出視窗 |
| **圖例** | 桌子之間傳遞的物品代表什麼，顯示在場景上方（**即時** 開啟時） | 每個瀏覽器 |

**風格。**

- **辦公桌**：每個 team 一間房間，每個 instance 一張桌子；General 和未加入 team 的 instance 在大廳。進行中的委派是工作者桌上的一個資料夾。比面板小的辦公桌辦公室會置中。
- **工作室**：一個場景，分成四個區域（工作區、休息區、求救區、午睡角）。每個 instance 會沿著走道走到它狀態對應的區域。
- **溫馨**：同樣的場景，畫在 AgEnD 內附的一張溫暖像素畫裡：辦公桌、沙發與咖啡、懶骨頭、白板。它的公告欄寫著外觀包可以改造這個房間。溫馨是還沒選過風格的瀏覽器與新辦公室的預設；已存的辦公室保留自己的風格。
- **冒險者公會** 與 **學校**（#2947）是沿用溫馨格局的另外兩張圖：冒險者公會大廳（地圖桌、酒館角落、旅店床鋪、任務佈告欄），以及教室（學生課桌、配販賣機的沙發角落、保健室病床、黑板）。
- **上傳的外觀包**：可以是像工作室那樣的區域場景，也可以是用自己圖片的辦公桌式配置。

下文把工作室、溫馨、冒險者公會、學校與區域外觀包統稱為 **區域風格**。只有它們有走動、座位、編輯配置、就寢、散步與信件。

**人多的時候。** 某個區域的人比座位多時，多出來的人會排成更密的格子，再多就在角落顯示「+N」。那裡只有呼叫與工作會有泡泡（最多幾個），名牌在滑過或取得焦點時才顯示。

**所有辦公室**（存了兩間以上辦公室後出現在切換器裡）把每間已存的辦公室各畫成一格，每格和它單獨顯示時完全一樣，並標上名稱與人數。**大廳格** 為不在任何辦公室的 instance 加一格；每個人都在某間辦公室時它會停用並說明。沒在切換器選過別的之前，辦公室一打開就是這個全域圖。點一格的標題，或點那一格（不是點在人身上），會進入那間辦公室（只限這次瀏覽）；工具列的 **← 返回全域** 回到全域圖。從切換器選的辦公室和以前一樣會在每台裝置記住。不同辦公室的人之間的流量會直接飛過去。縮放低於 75% 時，名牌只在滑過時顯示。編輯辦公室與編輯配置要等到只顯示一間辦公室時才能用。

**輪播…**（同一個切換器，存了兩間以上辦公室，且在已登入的 dashboard）是給電視看的看板：勾選的辦公室輪流佔滿畫面，間隔你自己選（15 秒到 10 分鐘）。工具列的 **輪播 n/m 間 ▾** 打開可捲動的清單（全選／全不選；Esc 或點外面關閉），二十間也不會把工具列折成好幾列；順序就是清單裡的順序。**暫停** 與 **下一間** 在工具列和全螢幕裡；空白鍵暫停，←／→（或 N／P，或遙控器的播放／下一首／上一首）切換。辦公室與間隔記在這個瀏覽器；每次進入輪播都會開始播放。編輯辦公室與編輯配置要等離開輪播。分享連結不提供輪播。

**減少動態效果**（系統設定）時，姿勢靜止、空中沒有東西在飛，泡泡一次整句出現。

## 設定辦公室

fleet 管理員以管理員 session，使用辦公室工具列的 **編輯辦公室**。螢幕寬度 1200 px 以上時，它會在右側以面板開啟，取代 AI 用量欄的位置，旁邊的辦公室仍然可以操作；較窄時是置中的對話框。× 或 Esc 關閉。

1. **新增辦公室**，取個名稱。
2. **成員**：**全部**；**指定**，再選整個 team 或個別 instance（還沒勾任何人時仍顯示全部）；或 **沒有人（只有 NPC）**：那裡不坐任何 agent，只有風格裡的 NPC（#2752）。在 `web-offices.json` 裡，全部是 `"members": []`，沒有人是 `"members": ["team:"]`，也就是一個沒有名稱的 team，不會有 team 叫這個名字。
3. **風格**：辦公桌、工作室、溫馨、冒險者公會、學校或已上傳的外觀包。
4. **待命只在自己的區域走動**（預設關閉，#4104）：在分區風格裡，閒著的人只在自己座位所在的區域裡散步，也不會去串門子。
5. **儲存**。

辦公室屬於整個 fleet：每個人看到的是同一批。主機把它們存在 AgEnD home 的 `web-offices.json`（`GET`／`PUT /ui/offices`），從不寫進 fleet.yaml，所以修改不會重啟任何東西。最多 20 間辦公室，每個人每分鐘最多儲存 20 次。

如果你編輯時別人已經存過，你的儲存會被拒絕，什麼都不會被覆蓋。選 **保留我的編輯**（下一次儲存會取代對方的修改），或 **載入對方的版本**。有未儲存的修改時離開頁面，會先詢問你。

**整個 fleet** 是頁面自己的辦公室，每次都依你的 team 組出來。它不會被存成一間辦公室，但它的風格存在主機上：fleet 管理員在辦公室工具列選的風格，就是每台裝置和每個分享連結看到的。不能編輯辦公室的人也可以選風格，但只留在自己的瀏覽器，並在那裡優先使用。主機還沒有存風格時，管理員之前在自己瀏覽器選的風格，會在第一次打開辦公室時送上主機。

## 使用外觀包

外觀包是畫師為辦公室畫的圖：一個 `manifest.json` 加上 PNG（或 WebP）檔。製作方式見[製作外觀包](#製作外觀包)。

**上傳。** 在 **編輯辦公室 → 外觀包** 用 **上傳外觀包**，把外觀包的 `manifest.json` 和所有 PNG、WebP 一起選取，或用 **上傳資料夾**。主機會檢查每一項（見[上限](#上限)），遇到第一個問題就拒絕，並指出在哪裡，例如 `furniture[3].sprite.w: a whole number from 1 to 512`。外觀包會完整存在 AgEnD home 的 `web-office-skins/<id>/`，從不被修改。

**使用。** 已存的外觀包會出現在每個 **風格** 選單裡。在編輯辦公室為某間辦公室選它，或在辦公室工具列為整個 fleet 選它。頁面無法載入的外觀包會以辦公桌顯示，並附上說明。

**更新。** 在網頁上，先刪除外觀包再上傳新版；主機已經有的 id 會被拒絕。有[外觀包權限](#讓-agent-管理外觀包)的 agent 則可以直接取代，並保留上一版供還原。

**刪除。** 按外觀包的刪除按鈕。用它的辦公室會改以辦公桌顯示，並附上說明。

## 製作外觀包

外觀包描述一個 **1280×720 邏輯畫布**（16:9）上的場景；也可以用 `"canvas": [w, h]` 自訂大小（640×360 到 5120×2880，任何比例：更大的辦公室，或更寬的）。manifest 裡所有座標都是這個邏輯單位，而且要在畫布內；背景與前景圖的比例要和畫布一樣（單張圖每邊最多 5120 px、16 Mpx，所以 5120×2880 的背景可以原尺寸放進來；大圖存成 WebP，才放得進單檔 4 MiB 的上限）。畫面會縮放顯示整個畫布（手機上也是），需要多小就能縮多小；「所有辦公室」裡大辦公室會縮小放進自己的格子。圖片是像素畫，以每個圖片像素 `scale` 個邏輯單位（預設 2）不平滑地畫出。

一個最小的區域外觀包：

```json
{
  "format": 1,
  "id": "harbour",
  "background": "room.png",
  "areas": {
    "desks":  { "rect": [40, 120, 620, 440], "seats": [[120, 220], [260, 220], [400, 220]] },
    "lounge": { "rect": [700, 120, 540, 260], "seats": [[760, 260], [880, 260]] },
    "nap":    { "rect": [700, 420, 540, 260], "seats": [[780, 560]] }
  },
  "stateZones": { "working": "desks", "paused": "nap", "stopped": "nap", "default": "lounge" },
  "characters": {
    "default": {
      "idle":    { "src": "people/idle.png", "frames": 4, "w": 32, "h": 48, "fps": 4 },
      "working": { "src": "people/work.png", "frames": 4, "w": 32, "h": 48, "fps": 6 },
      "walk":    { "src": "people/walk.png", "frames": 2, "w": 32, "h": 48, "fps": 6 }
    }
  }
}
```

`room.png` 必須是 16:9，每個影格條的圖片必須剛好是 `frames·w × h` 像素：上例的 `idle` 是 128×48。

**更長的多圖動畫（#4231）。** 單張水平影格條最多 32 格。如果要做 5–10 秒以上的連續動畫（例如 30 FPS × 10 秒 = 300 格），或想幫每一格設定不同停留時間，任何影格條都可以改用以下兩種寫法，而且同一個外觀包裡可以和原本的單張影格條混用：

- **多張影格條依序串接：** 把 `src` 寫成水平 PNG 影格條的陣列（最多 32 張圖、總格數最多 600 格），系統會預先解碼並依序銜接播放。`frames` 可寫單一數字（每張圖格數相同時）或與 `src` 等長的陣列：

```json
"working": {
  "src": ["people/work_01.png", "people/work_02.png", "people/work_03.png"],
  "frames": [32, 32, 16],
  "w": 64, "h": 96, "fps": 12,
  "loopFrom": 16
}
```

- **逐格清單與個別停留時間：** 省略 `src`，改在 `frames` 列出 `{ "src", "ms"? }`（最多 600 步，每張圖為 `w × h` 像素，`ms` 為 33–60000 毫秒）；同一張圖可在多步重複使用，只會上傳與解碼一次。單張或多張影格條也可以用 `durations` 陣列（每格的毫秒數）取代 `fps`。
- **播放方式：** 預設從第 0 格播完後循環。加上 `"once": true` 會只播一次並停在最後一格；加上 `"loopFrom": <格數索引>` 則先播一次進入段（`0 .. loopFrom - 1`），接著持續循環剩餘影格。若裝置開啟「減少動態效果」（`prefers-reduced-motion: reduce`），所有影格條一律停在第 0 格。
- **切圖建議：** 單張圖維持在 32 格與寬度 5120 px 以內（例如 64×96 的角色拆成 10 張、每張 30 格 = 300 格，30 FPS 可播 10 秒）。整包維持在 220 個檔案、42 MiB 與總解碼像素 64 Mpx 以內，手機播放就能保持流暢。想省檔案數，可以把好幾個姿勢放在同一張圖，再用 `row`／`col` 切出各影格條（見[影格條](#strips)）。

**區域、座位與狀態。** 區域是一個矩形 `[x, y, w, h]` 加上它的座位，依填滿的順序排列。座位是 `[x, y]`，也就是人的腳站的位置，必須在區域的矩形內。`stateZones` 把每個狀態（`needs`、`crashed`、`stuck`、`working`、`idle`、`paused`、`stopped`、`missing`）送到某個區域；沒列出的狀態去 `"default"`，沒有就去第一個區域。就寢時，閒著的人會去 `paused` 用的那個區域。

**角色。** 必須有 `characters.default`，且至少有 `idle`。一組角色的姿勢是 `working`、`idle`、`paused`、`needs`；缺少的姿勢以 `idle` 顯示。可以有更多組（最多 64 組），用 `byInstance: { "atlas": "fox" }` 依名稱指定給 instance。

**走動。** 外觀包有路徑圖（`waypoints` 與 `edges`）時，人會沿著它走，沒有就直接走到座位。新來的人從 `door` 走進來（預設在底部中間）。走路的影格條依每一步的方向挑選：`walkDown`（朝向觀看者）、`walkUp`，或 `walkSide`——畫成面向右邊，往左時左右翻轉。缺少的用 `walk`，再沒有就用 idle。設定 `"straight": true` 時，每段斜走都會變成 L 形，先橫走再上下走，三種走路影格條就永遠和移動方向一致；路徑圖用水平與垂直的邊來畫，轉角就會落在走道上。

**飛的東西。** 訊息、委派、回報與廣播會以外觀包的 `props`（`task`、`send`、`report`、`broadcast`）在人之間飛，沒有就用內建的圖。一組角色可以有自己的 `prop`：它的人送出的所有東西都會畫成那個。

**家具。** 每件家具是放在 `(x, y)` 的一個影格條，有自己的 `depth`：小於 1000 畫在人下面，1000 以上畫在人上面，`"depth": "y"` 則依底部和人一起排序，站得比較下面的人在前面。家具可以：

- 在有人處於某個狀態時播放：`activeWhen`（一個狀態或清單），可以搭配自己的 `activeSprite`，以及 `activeFor`（一個 instance 或最多 8 個的清單）只看那些人；否則停在第一格，或設 `"loop": true` 一直播放；
- 用 `label`（1–40 字）掛一個名牌，像人一樣（畫成家具的 NPC）；
- 用 `walk`（它自己的走路影格條，`walk` 必填）像閒著的人一樣在原地附近散步；
- 用 `night` 在就寢時睡覺：`{ "sprite": STRIP, "x": …, "y": … }`（省略 x／y 就在原地）；
- 等它的人坐下，並把人藏起來。`"activeOn": "seated"` 讓家具只在 `activeFor` 裡的某人、處於該狀態、走到自己的座位後才啟動，對方一走開就恢復（預設 `"state"` 跟著狀態變）。`"hides": true`（需要 `activeFor`）讓家具啟動時不畫出那些人；走動中的人一律會畫出來。他們的名牌（在家具的名牌位置排成一列，排在家具自己的名牌之後）與泡泡改畫在家具上，滑過或點擊某人的名牌或家具的圖，就會選到那個人。適合床、轎子或帳篷這類和人合成一張圖的家具。

**前景與外框。** `foreground` 是蓋在整個場景上的 16:9 PNG，畫在人與家具之上、名牌、泡泡與「+N」之下：用來畫門框、柱子、桌子前緣，把走到後面的人遮住。`matte`（`#rrggbb`）是面板不是 16:9 時場景周圍的顏色；沒有設定時，頁面會取背景邊緣的顏色。

**泡泡。** `bubbles: { "en": { "working": ["On it."] }, "zh-TW": { … } }` 取代頁面內建的某個狀態的句子：最多 12 句，每句 1–40 字。

每個人也可以有自己的聲音。一組角色可以在姿勢旁邊帶自己的 `bubbles`（格式與上限相同）；`bubblesByInstance` 則讓某個 instance 不必有自己的角色組也能有自己的句子：

```text
"characters": {
  "default": { "idle": STRIP },
  "fox": { "idle": STRIP, "bubbles": { "zh-TW": { "working": ["正在嗅線索。"] } } }
},
"byInstance": { "atlas": "fox" },
"bubblesByInstance": { "quill": { "zh-TW": { "idle": ["墨水乾了。"] } } }
```

某人在某個狀態說的句子，取下面第一個在頁面語言下有該狀態句子的：他自己的（`bubblesByInstance`）、他的角色組的（`byInstance` 指定的組，否則 `default`）、外觀包的 `bubbles`、最後是頁面內建的。所以只寫了 `working` 句子的角色組，閒著時仍說外觀包的句子。agent 用 `office_set` 說的話仍然蓋過這些。

**辦公桌式外觀包。** 沒有 `stateZones` 的外觀包沿用辦公桌配置，可以提供自己的 `room`（`floor`、`wall`）與 `desk`（`back`、`front`、`lit`）圖片。

**尺寸與錨點。** 影格條顯示的大小是 `w·scale × h·scale`，除非它用邏輯單位指定 `dw` 或 `dh`；只給其中一個時，另一個依比例算出。`(ax, ay)` 是圖片上要放在位置點的那一點（預設底部中央，所以人站在座位上）。scale 2 時的建議尺寸：角色 32×48，道具 12×12。

**立繪與對話框。** 外觀包可以為[對話框](#對話框)提供臉孔與樣式：

```json
"portraits": {
  "default": "portraits/agent.png",
  "byInstance": { "atlas": { "idle": "portraits/atlas.png", "working": "portraits/atlas-busy.png" } },
  "byUser": { "discord:123456789": "portraits/owner.png" },
  "npc": { "npc-elder": "portraits/elder.png" }
},
"dialogBox": { "frame": "ui/box.png", "slice": 12, "background": "#2b1d14", "border": "#c8a165", "text": "#f6ead7", "name": "#ffd27a" }
```

- 立繪可以是一個檔案，或依狀態分的表情（`idle`、`working`、`needs`，至少一個）。缺少的狀態用 `idle`，再沒有就用它有的任一張。透明 PNG，最大 1024×1536 px，站在對話框後方（底部對齊）。
- `default` 給 agent 用。`byInstance`（最多 500）以 instance 名稱對應；`byUser`（最多 200）以聊天記錄的帳號 `adapter:id` 對應；`npc`（最多 128）對應外觀包定義的家具項目。
- `dialogBox.frame` 是最大 512×512 px 的九宮格圖，每邊 `slice` 個圖片像素（1–128，預設 8）；顏色是 `#rrggbb`，沒給的用儀表板的顏色。
- `dialogBox.bubble` 是 **對話方式** 選「頭頂氣泡」（見下方）時，畫在頭上的回覆的樣式：同樣的鍵（`frame` 最大 512×512、`slice` 預設 6、`background`、`border`、`text`、`name`），再加上 `enter` 出現方式：`pop`（預設）、`fade` 或 `none`。沒給的話是淺色底，和狀態氣泡一樣。
- 只有對話框第一次需要時才會載入。

**自訂點心與吃東西動畫（#4255）。** 外觀包可以附上可選的點心與 `eat` 動作（`characters.<組別>.eat`，支援單張、多張與逐格影格條）：

```json
"snacks": [
  {
    "id": "cookie",
    "label": { "en": "Cookie", "zh-TW": "餅乾" },
    "sprite": { "src": "snacks/cookie.png", "frames": 1, "w": 24, "h": 24, "dw": 28, "dh": 28 },
    "eat": { "src": "snacks/cookie_eat.png", "frames": 4, "w": 24, "h": 24, "fps": 6, "once": true },
    "radius": 260
  }
]
```

- `snacks` 可放 1–12 個項目，每項有唯一 `id`、可選的 `label`（1–24 字或 `{ "en"?, "zh-TW"? }`）、必填的 `sprite`、可選的進食覆蓋影格條 `eat`，以及可選的吸引半徑 `radius`（60–1280 邏輯單位，預設 260）。所有點心圖片都計入外觀包的檔案數、容量與 64 Mpx 像素上限。
- 沒有 `snacks` 的外觀包不顯示點心盤，名片上的內建 **餵點心** 按鈕行為完全不變。

**被拖曳動畫（#4267）。** 角色組可以選填 `dragged` 影格條（`characters.<組別>.dragged`，找不到時退回 `characters.default.dragged`；支援單張、多張與逐格影格條）。未設定時，被拖曳的小人會以內建的懸空晃動效果搭配地面陰影顯示，放開後自動回到原本姿勢。

**摸頭動畫。** 角色組可以選填 `pat` 影格條（找不到時退回 `characters.default.pat`）。被摸頭時會完整播一輪（至少和愛心一樣久，1.8 秒），播完回到原本姿勢；沒有的話，跟以前一樣只顯示愛心和台詞。角色組也可以選填 `walkLeft`（往左走時用它，不再翻轉 `walkSide`）和 `stand`（一張靜止站姿，當作卡片頭像，取代待機影格條的第一格）。

**Agent 個人名片（`card`）。** 外觀包可以選填 `card` 來客製化 Agent 個人名片（桌機旁浮卡或手機底部抽屜）的預設版型、配色、底圖／九宮格邊框與欄位排列：

```json
"card": {
  "preset": "rpg",
  "style": {
    "background": "#1f1916",
    "backgroundImage": "ui/card_bg.png",
    "frame": "ui/card_frame.png",
    "slice": 12,
    "border": "#c8a165",
    "text": "#f6ead7",
    "muted": "#c9b69a",
    "accent": "#e5b84b",
    "barTrack": "#382d25",
    "barFill": "#e5b84b",
    "buttonBg": "#3a2c22",
    "buttonText": "#f6ead7",
    "buttonPrimaryBg": "#c88d2e",
    "buttonPrimaryText": "#1a120b",
    "radius": "sm"
  },
  "layout": {
    "avatarSize": "lg",
    "avatarSource": "portrait",
    "headerAlign": "center",
    "width": 340,
    "sections": ["header", "level", "rows", "now", "tell", "actions"],
    "rows": ["office", "model", "backend", "today", "firstSeen"],
    "rowColumns": 2,
    "hide": ["instance"]
  }
}
```

- `preset` 選擇內建版型：`default`、`rpg`、`compact` 或 `dossier`；明確填寫的 `style` 與 `layout` 欄位會覆寫預設值。不含 `card` 的外觀包維持原本的名片樣式不變。
- `style` 顏色嚴格限定 `#rrggbb`（不接受任意 CSS）。上傳時會檢查成對色彩的 WCAG 對比度：`text`/`background`、`muted`/`background`、`accent`/`background`、`buttonText`/`buttonBg` 與 `buttonPrimaryText`/`buttonPrimaryBg` 至少 4.5:1；`border`/`background` 與 `barFill`/`barTrack` 至少 3.0:1。`backgroundImage` 為最大 1024×1024 px 的 PNG（會疊加可讀性遮罩）；`frame` 為最大 512×512 px 的九宮格 PNG，`slice` 1–128（預設 8，須符合 `slice * 2 < min(w, h)`）。兩者都在首次打開名片時才延遲載入。`radius` 為 `none`、`sm`、`md` 或 `lg`。
- `layout` 可調整 `avatarSize`（`sm` 44 px、`md` 56 px、`lg` 84 px）、`avatarSource`（`sprite` 或使用 `portraits` 的 `portrait`，缺少時回退待機小人）、`headerAlign`（`left` 或 `center`）、桌機寬度 `width`（280–400 px；手機底部抽屜會忽略）、`sections`（從 `header`、`level`、`rows`、`now`、`tell`、`actions` 挑選不重複順序，若有指定則必須保留 `header` 與 `actions`）、`rows`（`office`、`model`、`backend`、`today`、`firstSeen` 的不重複順序）、`rowColumns`（`1` 或 `2`）、`hide`（`instance`、`title`、`badge`、`level`、`xpBar`、`office`、`model`、`backend`、`today`、`firstSeen`、`now`）與 `gap`（卡片和人物之間的距離 0–240 px，另加人物半寬；預設 12）。
- `motion` 設定卡片彈出的動畫：`enter` 可選 `none`、`fade`、`pop`、`rise`、`slide`、`bounce`，`ms` 為 80–1200（預設 220）。浮動卡片和手機底部抽屜都會播放；開啟減少動態效果時不播。
- 分享連結仍會先濾除 `model`、`backend`、`today`、`firstSeen`、`tell` 與互動按鈕，才套用 `card.layout`——外觀包無法在分享連結上露出被隱藏的欄位。

**檢查外觀包。** 檢查很嚴格：未知的欄位、超出範圍的值，或指向不存在的名稱，都會讓整個外觀包被拒絕，並指出在哪裡。有外觀包權限的 agent 可以對資料夾跑 `office_pack_check`，什麼都不會存（見[下方](#讓-agent-管理外觀包)）。頁面與主機用的是同一套規則。

## 安排配置

在區域風格的已存辦公室上，fleet 管理員可以用 **編輯配置** 移動東西。修改會存成那間辦公室自己的 *overrides*；外觀包保持上傳時的樣子，用同一個外觀包的其他辦公室不受影響。

- 疊加層顯示外觀包的座標格（沒設 `canvas` 時是 1280×720；**顯示座標**），每個座位、家具、門、信件落點與路徑點都有一個控制點。信件落點是一個信封，標出其他辦公室寄來的信落在哪裡；外觀包沒有指定時它以虛線顯示目前信件落下的位置，拖曳它就會給這個辦公室自己的落點。每個空座位會顯示一個淡淡的人形，擺出那個區域的姿勢。
- 拖曳控制點，或用 Tab 選到它再用方向鍵移動（Shift：一次 10）。
- **新增路徑點**／**移除路徑點**；選了路徑點後，可以 **連到** 另一個，或 **取消連接** 某條走道。
- 會在就寢時睡覺的家具還有一個夜間控制點「家具 {id}（夜間）」：淡淡的夜間圖、一個月亮，以及一條連到白天位置的細線。拖曳它，就能給家具自己的夜間位置；**回到 pack 的夜間位置** 可以復原。
- 選取的座位有 **保留給** 與 **不在時借給別人**；見[保留座位](#保留座位)。
- **儲存配置** 存起來；**還原成 pack 的配置** 回到外觀包自己的配置；**取消**（或 Esc）關閉。

螢幕寬度 1200 px 以上時，它的控制項在右側面板裡，整個畫布都留給控制點；較窄或全螢幕時，控制項是畫布下方的一列。開著時，辦公室切換器與編輯辦公室會等它關閉。若別人在這期間存過辦公室，儲存會告訴你並保留你的配置；再按一次儲存，就會套用到目前的清單。

主機每次儲存都會檢查 overrides：座位必須留在自己的區域內，每個區域的座位數要和外觀包一樣。overrides 是針對某一個外觀包做的：換成其他風格時會被忽略（「它儲存的配置不適用這個風格」）。之後外觀包被換掉、配置不再適用時，那間辦公室會先用外觀包自己的配置，直到有人修正；agent 要換掉外觀包時會先被詢問（見[下方](#讓-agent-管理外觀包)的 `drop_invalid_overrides`）。

## 保留座位

有些姿勢是為某個座位畫的，例如兩個人在沙發上互相靠著，或某人坐在自己的桌前。保留座位能讓它們正確顯示。

- 在編輯配置裡選一個座位，再選它要 **保留給** 哪些辦公室成員（可以多選）。它的控制點會加上一圈。
- 座位保留給的人來到它的區域時會先坐那裡：優先坐上次坐的那個，否則坐區域順序中第一個保留給他的座位。
- 其他人不會坐那裡，除非開了 **不在時借給別人**，而且保留的人都在別處。保留的人回來時，借坐的人會讓開。一般座位會比可以借的座位先分配出去。
- 沒有開放借用、保留的人又都在別處的座位，不算進那個區域可容納的人數。
- 外觀包也可以保留座位：座位可以寫成 `{ "x": 760, "y": 260, "for": ["atlas"], "lend": false }`，取代 `[x, y]`。辦公室自己的保留會取代外觀包對那個座位的保留；保留給「沒有人」就是取消外觀包的保留。

## 辦公室裡的日常

這些需要區域風格。

- **就寢**（**0–6 點就寢：閒著的人去睡** 勾選框，每台裝置，預設關閉）：觀看者時間 00:00 到 06:00，閒著的人只要睡覺區（`paused` 用的那個區域）還有空位，就會走過去睡，頭上冒 Zzz；其他人原地打瞌睡。工作中的人繼續工作。有 `night` 的家具會在夜間位置睡覺。
- **散步：** 閒著的人偶爾會走到附近一個沒有座位的路徑點，停幾秒再走回來。有 `walk` 的家具也會這樣散步。散步只在單一辦公室（不是所有辦公室）、沒有減少動態效果、也沒開編輯配置時發生。辦公室開了 **待命只在自己的區域走動**（#4104）時，散步只會走到那個人（或家具原位）所在區域裡的路徑點；來回的路線在路徑圖允許時都留在區域裡，否則只經過走廊（不屬於任何區域的地方）。只能穿過其他區域才到得了的點不會用，那個人就留在座位上；也沒有人會去串門子。會走動的家具若原位不在任何區域裡，就照以前一樣散步。
- **拖曳與摸頭**（**⚙ 顯示選項** 裡的 **拖曳與摸頭** 勾選框，每台裝置，預設開啟；#4119、#4266、#4267）：把人拿起來拖曳時，他會懸空進入「被拖曳」狀態（有設定就播放外觀包的 `characters.<組別>.dragged`／`default.dragged` 動畫，否則以內建懸空晃動表現），同一區域內可換過去的座位地面會顯示圓圈提示。放到同區域的另一個合法座位上，他就會直接坐到新座位並繼續工作（若目標座位已被其他非保留成員佔用會自動互換，同時遵守保留座位與 **待命只在自己的區域走動**；這台裝置針對該辦公室與風格會記住你的座位安排）；放到空地上則會走回原座位（開啟 **待命只在自己的區域走動** 時不會跨越其他區域）。按 Esc 可取消拖曳。用滑鼠時按住他再移動；手機上長按到他被拿起來（手指先移動的話仍是拖曳畫面）。他的名片上有 **摸頭** 和 **餵點心**：頭上會冒出幾顆愛心，並在對話泡泡裡說一句話。只在你自己 dashboard 上的單一辦公室有：所有辦公室、輪播、編輯配置與分享連結都沒有；開啟減少動態效果時也沒有：勾選框會關閉並鎖住，**⚙ 顯示選項** 裡它下方有一行「已關閉：系統開了「減少動態效果」」。沒有強制開啟的開關；要玩就在裝置上關閉減少動態效果。這只屬於你：不會存到主機，也不會給其他人看到，Agent 也不會知道，除非你在他的名片上勾選 **讓 <agent> 知道（隨下一則訊息）**（每個 Agent 個別設定，預設關閉）。勾選後，每次摸頭或餵食會先排隊，等下一則本來就會送給它的訊息時，在 `[Recent reactions: …]` 附上一行，例如 `[Office] <你的名字> patted your head ×3`。不會叫醒 Agent，也不會自己另外送訊息。每人每種最多累積 20 次，這一行最長 200 字。外觀包可以自訂摸頭與餵食時說的話（`bubbles.<lang>.pat` 與 `.feed`，見下方）。
- **自訂點心**（套用有 `snacks` 的外觀包且開啟 **拖曳與摸頭** 時；#4255）：場景左下角會出現浮動點心盤（手機上位於區域膠囊上方）。把點心拖到清醒的成員身上——或點一下選取後再點成員——就會直接餵食（若有 `eat` 或 `default.eat` 動作便會播放，並顯示愛心、`feed` 句子與可選的 **讓它知道**）。把點心放到空地上（場上最多同時放 6 個，無人認領 30 秒後消失），半徑 `radius` 內最多 4 位最近的閒置成員會沿著走廊跑來搶（並遵守 **待命只在自己的區域走動**）；第一個到的會吃掉它，其餘跑過來的成員會短暫說「被搶先了！」並走回座位。睡著的成員不會被叫醒。整個互動只在瀏覽器端進行，分享連結、所有辦公室、輪播、編輯配置與開啟減少動態效果時均不顯示。
- **串門子**（外觀包的 `idleVisits`，#3685）：閒著的人偶爾會改去別的區域，例如花園或溫泉，在那裡找個空位坐一陣子，再走回自己的座位。空位是指沒人坐、沒有其他串門的人正要過去，而且沒有保留給別人（除非它開放借用）的座位。沒有空位時就照常散步。每次輪到可以散步時，每一項的 `weight` 會和散步的 100 一起抽，所以一項 weight 20 的設定，每 120 次中有 20 次會出門。到了之後停留 `minSeconds`–`maxSeconds` 秒。不會去自己所在的區域，不是閒著的人不會動，其餘規則和散步相同（單一辦公室、沒有減少動態效果、沒開編輯配置）。要不要出門、什麼時候、去哪個區域，只由名字和時間決定，所以每個畫面都一樣。到了那裡坐哪個空位則可能因畫面而異：每個開著的頁面會保留串門的人已經坐下的位子，之後才變成閒著的人不會把他們擠走；較晚打開的頁面則重新分配座位。
- **信件：** 辦公室外的人寄給辦公室裡某人的訊息，會變成一封信從門口飛進來，落在外觀包的 `mailDrop`（或這個辦公室在編輯配置中自己指定的位置）。沒有指定時，落在最靠近房間中央、不在任何座位上的路徑點。更多信件會每隔 16 px 往右排，不會落在座位上。減少動態效果時不顯示信件。收件人會走過去撿起來，睡著時除外。一封信最多等一分鐘。
- **流量：** 同一間辦公室裡的人之間，東西會從寄件人飛到收件人。委派會一直顯示為進行中，直到工作者的回報回來。

## 對話框

**⚙ 顯示選項** 裡的 **對話框** 會在場景下方開啟視覺小說風格的對話框（#2861，由 hxhsandy 設計）。每個瀏覽器各自設定，預設關閉；沒勾選前，辦公室和以前完全一樣。

- **有人傳訊息給這裡顯示的 agent**（從網頁、Discord 或 Telegram，或點了按鈕）：對話框從下方滑出，左邊是對方的立繪，顯示名字與訊息的前約 120 個字，逐字打出。
- **agent 工作時**，它的立繪出現在右邊，附一行簡短狀態：它自己用 `office_set` 設定的那一行，沒有的話是「處理中…」。
- **它的回覆**換到 agent 那一側（前約 120 個字），幾秒後對話框淡出。
- **同時有好幾段對話**時依序排隊，最新的在前；對話框顯示「+N」，這段結束後換下一段。
- **點一下對話框**開啟該 agent 的資料卡（畫面移到他身上）；**點兩下**開啟他的聊天。
- agent 之間的往來維持原樣：空中飛的資料夾、信封與信件。

會顯示什麼：

- **在儀表板上**，只顯示你本來就能在聊天裡讀到的文字：對話框聽的是聊天收到的同一批即時訊息。頁面重新連線時補送的舊訊息不算新消息，不會開啟對話框。狀態列永遠不顯示。
- **分享連結永遠不顯示任何文字。** 對話框只說「傳了一則訊息給 Atlas。」和「已回覆。」，傳訊的人顯示為沒有臉的「有人」；分享的狀態只帶時間，不帶內容也不帶是誰。
- **隱藏暫停與停止的成員**照樣適用：只有畫在目前這間辦公室裡的人會說話。畫成睡著的人（暫停、停止，或就寢時間在床上）的對話會等他醒來開始工作，或 3 分鐘後消失。
- **減少動態效果：** 不滑動、不打字、不淡出；對話框整個出現、直接消失。
- 螢幕閱讀器會把每一句念一次（polite live region）。

**臉孔。** 優先使用外觀包的 `portraits`（見下方）。沒有的話，agent 以它的頭像（身分卡圖片、bot 頭像或 persona emoji）加框顯示，再沒有就是首字；人則顯示首字。分享連結沒有頭像：有立繪用立繪，否則用首字。

### 在辦公室裡對話

**⚙ 顯示選項** 裡的 **對話方式** 決定成員的 **對話**（資料卡、座位、對話框）要做什麼。每個瀏覽器各自設定，只在儀表板上有（分享連結和訪客頁面沒有）：

| 對話方式 | 按「對話」會 |
|---|---|
| **彈出視窗**（預設） | 和以前一樣，在另一個視窗開啟他的聊天。 |
| **側邊面板** | 辦公室旁邊的面板：最近的訊息、和聊天一樣排版的回覆、輸入框。手機上是從下方拉起的面板。 |
| **對話框** | 像視覺小說的對話框，疊在場景下緣（辦公室大小不變），旁邊是他的大立繪，框內有一行可以直接打字給他。 |
| **頭頂氣泡** | 回覆一頁一頁畫在地圖上他的頭上，場景下方有一行可以打字給他。 |

- **Enter** 送出；**Shift+Enter** 換行（用輸入法選字時按 Enter 不會送出）。
- 每種方式顯示的都是和聊天同一段對話：在這裡傳的會出現在聊天裡，他的回覆也即時出現。
- **開啟完整聊天** 開啟聊天本身，要傳檔案、引用、表情回應等等請用它。
- 一次只有一種對話：選 **側邊面板** 或 **頭頂氣泡** 時，下方不會再出現[對話框](#對話框)；選 **對話框** 時，由這個對話框取代它。不論 **對話框** 顯示選項有沒有勾選，**對話框** 對話方式都能用，也不會改動那個勾選。

**「對話框」方式。** 框裡只顯示他那一方：整段回覆逐字打出，每頁兩行（手機三行），一頁打完會出現 ▼。點一下對話框（或按 Enter、空白鍵）：先把這頁一次顯示完，再到下一頁，最後一頁之後關閉這則回覆。文字不會壓到立繪。顏色用外觀包的 `dialogBox`，沒有的話是深藍底配金色。**歷史紀錄** 在框上打開這段對話的紀錄：雙方的話、和聊天一樣排版的回覆，以及 **開啟完整聊天**。**×** 關閉對話框。

**頭頂氣泡。** 回覆分頁畫在他的頭上，樣式用外觀包的 `dialogBox.bubble`（見下方），沒有的話是淺色底。場景下方的 **完整回覆** 顯示他最後一則回覆的全文。

**播放**（對話框自己的按鈕；頭頂氣泡則在場景下方那一列；每個瀏覽器各自記住）：

| 播放 | 作用 |
|---|---|
| **點擊**（預設） | 每頁等你點一下。 |
| **自動** | 一頁打完後停一下就自己往下播，停的時間隨長度增加（1.4–5 秒）。 |
| **快速** | 很快打完，短暫停一下就往下播。 |
| **跳過** | 現在就關掉所有正在顯示的回覆。 |

## 交通工具

區域外觀包可以用 `vehicles`（最多 4 個）讓列車（或任何交通工具）沿一圈軌道繞行：

```json
"vehicles": [{
  "id": "loop-line", "label": "環線列車",
  "sprite": { "src": "train.png", "frames": 2, "w": 192, "h": 96, "fps": 4 },
  "path": [[80, 80], [5040, 80], [5040, 2800], [80, 2800]],
  "speed": 120,
  "stops": [{ "at": 1, "seconds": 10, "platform": [4980, 1650] }],
  "seats": [{ "dx": -48 }, { "dx": 0 }, { "dx": 48 }]
}]
```

- `path`：3–64 個點，最後一點接回第一點，一圈跑完接著下一圈。`speed` 是每秒幾個邏輯單位（5–600，預設 80）。
- `stops`：停靠的路徑點（`at`，點的索引）、停多久 `seconds`（1–600，預設 8），以及月台 `platform`：乘客在這裡等車、上車、下車。有座位的交通工具至少要有一站。
- `seats`（最多 16）：乘客坐的位置，以交通工具錨點為準、沿行進方向的位移（`dx` 往前、`dy` 往右），轉彎時跟著轉。
- `sprite`：朝右的圖（往左時左右翻轉）；或用 `sprites` 依方向給（`right`、`left`、`up`、`down`），都是影格條。行駛時播放，停靠時停在第一格。
- 交通工具在哪裡只由時間決定，所以每個畫面看到的位置都一樣。
- **誰上車由 agent 自己決定**（`office_set { ride }`，見[辦公室裡的 agent](#辦公室裡的-agent)），不是外觀包指定：乘客走到離自己座位最近的月台，等列車停靠再上車，坐進空位跟著繞行、在車上工作（名牌、對話泡泡、名片都跟著走）。搭乘結束時，會留在車上直到下一站，在月台下車再走回去。客滿就等下一班。就寢、暫停或停止時，也一樣在下一站下車。呼叫人時（needs、crashed、stuck）不一樣：乘客會立刻在原地下車、走回自己的位置，不讓任何東西擋住呼叫的人走到服務台；呼叫結束後，只要搭乘還沒到期，就會再去搭。

## 分享畫面

fleet 管理員可以讓 fleet 以外的人在一段時間內觀看即時辦公室，不需要登入。在辦公室工具列按 **分享…**：可以在直接連線的 dashboard 上，也可以透過臨時公開連結登入後使用；唯讀 session 與訪客不能分享。沒有對應的聊天指令。

1. 選 **整個 fleet**、一間辦公室或 **所有辦公室**，以及時間：15 分鐘到 24 小時（預設 1 小時；`web.office_share.max_hours` 設定上限）。目前顯示的是整個 fleet 時，預設就是它。
2. 選 **外觀**：**淺色**、**深色**，或 **依觀看者的裝置**。預設是你的 dashboard 現在顯示的淺色或深色；dashboard 跟隨裝置時，就用裝置目前的淺色或深色。
3. 勾選 **包含 agent 自己的狀態文字**，就連 agent 的 `office_set` 文字也一起顯示。
4. 按 **建立連結**，再按 **複製連結**。連結只會顯示給你，而且只顯示一次。

觀看者看到的那間辦公室（或所有辦公室）和 dashboard 畫的一樣，套用連結的外觀，整個 fleet 則用 fleet 的風格：場景、名稱、身分色與狀態，每 5 秒更新，可以縮放、Fit 與全螢幕。其他什麼都沒有：沒有聊天、沒有設定，也沒有模型、費用或說明。點擊某個人會打開它的名片，只有名稱、頭銜、狀態、辦公室與等級。只顯示辦公室的成員，`cross_instance_visibility: hidden` 的 instance 一律不顯示。

每個連結有自己在臨時通道上的網址（`https://<random>.trycloudflare.com/o/<token>`），和 dashboard 的不同；第一個連結建立時啟動，最後一個結束時停止。同時最多 10 個連結。每個連結每分鐘最多 120 個請求，外觀包的圖片另外計算，所以即使所有辦公室都用滿檔的外觀包，每個房間也都載得出來。連結在以下情況結束：時間到、按 **撤銷**（在 **設定 → 存取與安全 → 辦公室分享連結**，或分享表單下方）、`web.office_share.enabled` 設為 `false`、建立者不再是 fleet 管理員、它的辦公室被刪除，或 fleet 重啟。每個連結的建立與撤銷都會在 General 公告（絕不包含連結本身）。Cloudflare 拒絕建立新的臨時通道時，建立連結會請你過幾分鐘再試。

更多關於 dashboard 的連線方式：[web-dashboard.zh-TW.md](web-dashboard.zh-TW.md)。

## 辦公室裡的 agent

有人替某個 agent 打開 **辦公室** dashboard 功能（`office_access: true`）後，它可以看到自己所在的辦公室，並短暫指揮自己的角色。這個功能沒設定就是關閉，在 **設定 → Agent 共用設定** 或該 agent 的 **進階 → Dashboard 權限** 設定；打開要先確認，關掉會立刻移除工具。

- `office_view { office? }`：它所在的已存辦公室，含成員與狀態。用上傳的區域外觀包的辦公室，還會列出座位（`"區域:序號"`）、路徑點、家具（NPC）與門，並已套用該辦公室的配置 overrides。其他辦公室（辦公桌、工作室、溫馨，或沒有區域的外觀包）會回傳 `walks: false`，沒有這些點。
- `office_set { office?, go?, say?, pose?, seconds?, clear? }`：走到某個座位、路徑點或另一位成員身邊（`go`）；說一句 1–40 字的話（`say`）；擺一個姿勢：idle、working、needs 或 paused（`pose`）；持續 5–120 秒（預設 30）。`clear: true` 結束。`walks` 為 false 的地方，那句話與姿勢會顯示，`go` 會被拒絕。
- `office_set { ride, seconds? }`：到辦公室的交通工具上工作（見[交通工具](#交通工具)）：agent 走到月台，等列車停靠再上車，坐進空位跟著繞行。搭乘持續 60–28800 秒（預設 3600）；開始新工作不會結束搭乘，`clear: true` 或新的 `office_set` 才會，agent 會在下一站下車。呼叫人時會立刻下車，直到呼叫結束。`office_view` 會列出交通工具（`spots.vehicles`：id、名稱、座位數、月台）。
- 每個動作會取代上一個。時間到、或 agent 開始新的工作時就結束；agent 在呼叫人、暫停或停止、或就寢時間睡覺時不會顯示。動作只存在記憶體裡。
- 每個 agent 每分鐘最多 6 次、每小時最多 60 次；被拒絕時會附上 `cooldown_ms`。
- 命令列也可以：`agend-agent office view [office]` 與 `agend-agent office set '<json>'`。

## 讓 agent 管理外觀包

agent 可以自己檢查、上傳、取代、刪除與還原外觀包，例如發布畫師的修正，不必每次都由人手動上傳。外觀包全 fleet 都看得到，所以這是另一個開關：在 **設定 → Agent 共用設定** 或該 agent 的 **進階 → Dashboard 權限** 打開 **辦公室外觀包**（`office_pack_access: true`）。沒設定就是關閉，打開要先確認。

**工具。**

| 工具 | 作用 |
|---|---|
| `office_pack_list` | 每個外觀包（id、名稱、檔案數、位元組、版本、可還原的上一版、哪些辦公室在用）、已存的辦公室、核准模式、這個 agent 等待中的變更，以及這一小時還剩多少額度 |
| `office_pack_check` | 跑主機自己的檢查，什麼都不存：`PACK OK` 或第一個拒絕原因 |
| `office_pack_upload` | 檢查與上限和網頁上傳相同；fleet 已經有的 id 會立刻被 **取代** |
| `office_pack_restore` | 還原保留的上一版（被換下的那版變成上一版，所以還原也能用同樣方式復原） |
| `office_pack_delete` | 刪除外觀包，連上一版一起刪，除非 `keep_previous: true` |
| `office_set_style` | 把已存的辦公室指向某個外觀包或內建風格（`pixel` = 辦公桌、`studio`、`cozy`、`guild`、`school`） |

**送出外觀包。** 外觀包可以是一個資料夾（`dir`），裡面有 `manifest.json` 與 manifest 指到的 PNG；也可以是一個 `manifest` 物件加上 `files`（`{ "<它用的名稱>": "<路徑>" }`）。`packs: [...]` 一次送出好幾個，算一批。agent 那一側只讀那些檔案，而且只在它的工作目錄或 fleet 的共用資料夾（`~/.agend/shared`）裡；符號連結會被跟隨，但必須留在裡面。fleet 收到的是檔案內容，從不是路徑。

**安全地取代。** 被取代的外觀包會先檢查、先寫好，再一次換上。任何一步失敗都保留舊版，中途辦公室也不會掉回辦公桌。每個外觀包保留一份上一版，不算進 16 個的上限。

**配置不再適用時。** 每間在這個外觀包上有配置 overrides 的已存辦公室，都會用新版再檢查一次：座位、家具、夜間位置與保留座位。若有項目不再適用（座位數變了、座位離開了區域、家具或保留的座位不見了），檢查、上傳與還原都會拒絕，並說出辦公室與規則。加上 `drop_invalid_overrides: true` 時，只會丟掉剛好那些項目並列出來——保留座位是一個座位一個座位地丟，絕不會丟掉辦公室的整份配置。

**核准。** fleet 管理員在 **編輯辦公室 → 會改外觀包的 agent** 選擇模式：

- **要我核准**（預設）：每個變更都會先等待，直到 fleet 管理員在那裡核准，或在 General 的通知上按 **核准**／**拒絕**。核准時會再判斷一次。會刪掉版面設定的變更，只有在仍然刪掉通知上列出的那些項目時才會套用；如果之後有人改過辦公室，核准會被拒絕，agent 必須重新送出。等待中的變更只存在記憶體裡，保留 24 小時，同時最多 8 個，fleet 重啟會清掉。
- **直接套用**：變更立刻套用，並通知管理員。

同一個面板也列出哪些 agent 可以改外觀包、等你核准的變更，以及最近的變更。

**紀錄與上限。** 每次上傳、取代、刪除與還原都會記錄在 `~/.agend/web-office-skins/.agent-changes.log`（誰、何時、哪個外觀包、檔案數、位元組，以及 manifest 與每張圖的 sha256，方便把還原對應到某個版本），並在 General 用一則短訊息通知 fleet 管理員。每個 agent 每小時最多 20 批、200 MiB。一次呼叫是一批，最多 16 個外觀包、100 MiB 的圖片；被拒絕的與檢查不算。檢查另有自己的額度：每個 agent 每小時 60 批、1 GiB（以送出的大小計）。每次檢查都算，不論是否通過。磁碟上所有外觀包最多佔 640 MiB：16 個滿檔的外觀包，加上各自的上一版。

命令列也可以：`agend-agent office packs`、`pack-check <dir>`、`pack-upload <dir>… [--drop-invalid-overrides]`、`pack-delete <id> [--keep-previous]`、`pack-restore <id>`、`style <office> <pack>`。

## 等級

每個 instance 都有等級，依它整個有紀錄期間做過的工作計算（#2661）。

- **工作 token**＝未快取的輸入＋快取寫入＋輸出。快取讀取不算。Kiro 例外：它沒有回報快取命中，因此估算的重送上下文會算進 Office 等級的輸入工作量。用量報告的輸入／快取拆分與費用計算不變。
- **等級**＝floor(√(工作 token ÷ 100,000))，沒有上限。100 萬工作 token 約 Lv 3，2.6 億約 Lv 50，10 億是 Lv 100。
- 數字來自用量報告讀的用量資料（[機群 → 用量](web-dashboard.zh-TW.md)）；顯示等級時不會讀取對話紀錄。Kiro 的用量是依文字長度估算的，包含 Kiro 工作的等級會標示為估算。
- **首次出現**是最早有工作紀錄的那天。如果 fleet 比用量收集更早開始，就是開始收集的那天。
- 用量紀錄保留 400 天。更早的日子在清除前會先加進 `usage-lifetime.json`，所以等級不會下降。
- 更新後第一次掃描 Kiro 時，AgEnD 會在背景分批自動補入更早的 classic／TUI 歷史。只補最早已記錄日期之前的完整日子（也會檢查已累計的終身紀錄），跳過已有紀錄的日期，並標示為估算。這可能讓「首次出現」提前。進度可在重新啟動後接續，每個 instance 的完成標記會防止重複補入，不需要指令或確認。同一工作目錄由兩個 instance 共用時，仍不歸入任何一方。來源讀不到、格式不完整或檔案過大時，會保留待補狀態，在日誌記錄警告，之後掃描再試。
- fleet 每分鐘最多計算一次等級，不論有多少頁面與分享連結在讀。

誰看得到什麼：

- **dashboard：**每個等級，加上工作 token、今天的工作量與請求數、首次出現。這些數字依用量報告的規則：`web.usage_panel` 為 `false` 時不提供；透過公開連結時，只有 `web.usage_report_on_public_link` 不是 `false` 時提供（M-3278 起預設開啟）。其他情況只顯示等級。
- **分享連結的觀看者：**只有該分享顯示的人的等級，其他都沒有。
- **訪客：**看不到辦公室，所以也沒有等級。
- **agent：**`office_view` 會列出每位成員的 `level`。它不會改變 agent 能做的任何事。

`web.office_levels: false` 會關閉等級：fleet 不提供任何等級，也不顯示徽章或等級列。這個開關也在 **設定 → 網頁儀表板 → 辦公室等級**，變更立即生效。

### 徽章

等級顯示在每個名牌左上角的小徽章上。它疊在名牌邊緣，不占名牌的寬度。超過 999 的等級寫成 1.1k。徽章的顏色依階級，使用 dashboard 的狀態色：

| 等級 | 顏色 | 預設頭銜 |
|---|---|---|
| 0–9 | 灰 | 新手 |
| 10–19 | 綠（`--ok`） | 學徒 |
| 20–34 | 藍（`--accent`，淡底） | 熟手 |
| 35–49 | 藍（`--accent`，實心） | 專家 |
| 50–99 | 金（`--warn`） | 大師 |
| 100+ | 紅（`--danger`） | 傳奇 |

有人升級時，他頭上會短暫出現一個光圈，同一區（辦公桌配置裡是同一間房）的人轉頭看過來，頭上顯示「!」。減少動態效果時不顯示。

### 名片

點擊某個人會在他旁邊打開名片。它是浮出的卡片，不是對話框：辦公室照常運作、不會變暗，名片開著時他會停在原地，關掉後才繼續走；但如果他開始呼叫你，仍會走到求救區。再點同一個人、按 Esc，或點其他地方就會關閉；點另一個人會換成他的名片。在手機上，名片是畫面底部的面板，往下滑即可關閉。

名片寬 320 px，顯示：

- 他在這間辦公室風格裡的閒置圖，加上徽章；顯示名稱；instance 名稱（一行，過長會截斷，滑過顯示全名）；狀態與頭銜，例如「工作中 · 大師」。
- XP 條上方兩行：「Lv 50 · 250M 工作 token」，再來是「再 10.1M 到 Lv 51」。部分工作來自 Kiro 時，token 後面會加上「（估算）」。
- 辦公室與區域、模型、backend、今天的工作 token 與請求數，以及首次出現至今的天數。
- **現在：**和滑過時的提示同一行動態。
- **在辦公室找他** 會平移並放大到他身上；**聊天** 打開他的聊天。
- 名字旁的 **✎** 可以幫他改名，只有你看得到：輸入的名字（最多 24 字）會出現在他的名牌、名片和對話框，只限這個瀏覽器；名片上仍顯示 instance 名稱。留空就恢復原名。分享連結上沒有這個按鈕。

觀看者不該看到的列會省略：沒有提供數字的地方（見上方）不顯示 token 列；分享連結只顯示名稱、頭銜、狀態、辦公室與等級。

### 外觀包的頭銜

外觀包可以自訂頭銜，也可以把頭銜固定給某人：

```json
"levels": {
  "titles": [{ "from": 1, "name": "實習生" }, { "from": 20, "name": "工程師" }, { "from": 50, "name": "首席" }],
  "fixed": { "atlas": { "title": "創辦人", "hideLevel": true }, "barista": { "title": "咖啡大師" } }
}
```

- `titles`：最多 32 筆。每個 `from` 是 0–100000，且比前一筆大；每個 `name` 1–24 字。低於第一筆的等級沿用預設頭銜。
- `fixed`：最多 500 筆。鍵是 instance 名稱，或以家具 `id` 指定的 NPC；不論等級都顯示該頭銜。設定 `hideLevel: true` 時，徽章變成小菱形記號，名片只顯示頭銜，沒有「Lv n」與 XP 條。NPC 的名牌會顯示它的標籤與頭銜，加上記號；NPC 沒有名片。
- 分享連結只會拿到它顯示的人與 NPC 的固定頭銜。

### 所有辦公室的頭銜

想讓每間辦公室都用同一套頭銜、又不想逐一修改外觀包，可以在 **設定 → 網頁儀表板 → 所有辦公室的等級頭銜** 為整個 fleet 設定一次（#3679）。它接受和外觀包 `levels` 相同的 `{ "titles": […], "fixed": {…} }` JSON，並以相同規則檢查。留空則使用預設頭銜。

- 每間辦公室都使用 fleet 的頭銜，不論它是什麼風格。
- 用自帶 `levels` 的外觀包畫的辦公室，若外觀包有 `titles`，就改用外觀包的。固定頭銜會合併：fleet 的 `fixed` 與外觀包的都會套用，同一個名字兩邊都有時以外觀包的為準。
- 只有管理員 session 可以變更（`PUT /ui/office-level-titles`，與辦公室的儲存一起計次）。它存在 `web-offices.json` 的辦公室旁邊，並隨辦公室一起提供（`GET /ui/offices` 的 `levels`），所以每個頁面與分享連結都會立即套用變更。
- 分享連結會拿到所有頭銜，但固定頭銜只給它顯示的人，以及不是 instance 的名字（NPC）。

### manifest

| 欄位 | 必填 | 說明 |
|---|---|---|
| `format` | ✅ | `1` |
| `id` | ✅ | 1–40 個英文字母、數字、`_` 或 `-`。不能是 `pixel`、`studio`、`cozy`、`guild` 或 `school`；只差大小寫的 id 會衝突 |
| `scale` | ❌ | 每個圖片像素幾個邏輯單位，1–8（預設 2） |
| `canvas` | ❌ | `[w, h]`：場景大小（邏輯單位），640–5120 × 360–2880（預設 1280×720）。舊版 AgEnD 會拒絕有這個鍵的外觀包 |
| `background` | 有 `stateZones` 時 | 場景的圖，16:9（有 `canvas` 時：和畫布同比例） |
| `foreground` | ❌ | 蓋在場景上的 16:9 圖（只能搭配 `stateZones`） |
| `matte` | ❌ | `#rrggbb`，場景周圍的顏色 |
| `areas` | 有 `stateZones` 時 | `{ 名稱: { rect: [x, y, w, h], seats: [座位, …] } }`，最多 32 個區域，每個最多 64 個座位 |
| `stateZones` | ❌ | 狀態 → 區域；`"default"` 給其餘狀態。沒有它就沿用辦公桌配置 |
| `door` | ❌ | 新來的人走進來的 `[x, y]`（預設底部中間） |
| `mailDrop` | ❌ | 其他辦公室寄來的信落下的 `[x, y]`，例如信箱或櫃檯。之後的信每隔 16 px 往右排，遇到座位會跳過。預設：最靠近中央、沒有座位的路徑點 |
| `waypoints` | ❌ | `[{ id, x, y }, …]`，最多 512 個 |
| `edges` | ❌ | `[[id, id], …]`，最多 2048 條 |
| `straight` | ❌ | `true`：每次走動都先橫走再上下走 |
| `idleVisits` | ❌ | 需搭配 `stateZones`：`[{ "area", "weight", "minSeconds", "maxSeconds" }, …]`，最多 8 項，同一區域只能出現一次：閒著的人偶爾會去坐一陣子的區域（見[辦公室裡的日常](#辦公室裡的日常)）。`weight` 1–100，與散步的 100 一起抽；`minSeconds` 5–600；`maxSeconds` `minSeconds`–600 |
| `furniture` | ❌ | 家具，最多 128 件（見[家具](#家具)） |
| `characters` | ✅ | `{ 角色組: { 姿勢: STRIP, … } }`，最多 64 組；必須有含 `idle` 的 `default`。欄位：`working`、`idle`、`paused`、`needs`、`walk`、`walkDown`、`walkUp`、`walkSide`、`walkLeft`、`eat`、`dragged`、`pat`、`stand`、`prop`，以及 `bubbles`（這組自己的句子，格式同外觀包的 `bubbles`） |
| `byInstance` | ❌ | instance 名稱 → 角色組，最多 500 個 |
| `props` | ❌ | `task`、`send`、`report`、`broadcast`：飛行物的 STRIP |
| `bubbles` | ❌ | `{ "en" \| "zh-TW": { 狀態: [句子, …] } }`，最多 12 句，每句 1–40 字。除了狀態之外，也可以用 `pat` 與 `feed`（#4119）：在辦公室被摸頭或餵食時說的話（沒設定就用頁面自己的話）。角色組與個別 instance 的 `bubbles` 也可以用 |
| `bubblesByInstance` | ❌ | instance 名稱 → 他自己的句子，格式同 `bubbles`，最多 500 個（見[製作外觀包](#製作外觀包)的「泡泡」） |
| `room`、`desk` | ❌ | 辦公桌配置的圖：`room.floor`、`room.wall`、`desk.back`、`desk.front`、`desk.lit` |
| `levels` | ❌ | `{ titles, fixed }`：等級的頭銜與固定頭銜（見[外觀包的頭銜](#外觀包的頭銜)） |
| `portraits`、`dialogBox` | ❌ | 對話框的臉孔與樣式（見[製作外觀包](#製作外觀包)） |
| `card` | ❌ | `{ preset?, style?, layout? }`：選填的 Agent 個人名片預設版型（`default`、`rpg`、`compact`、`dossier`）、經 WCAG 對比檢查的 `#rrggbb` 配色、`backgroundImage`（≤ 1024×1024 px）、九宮格 `frame`（≤ 512×512 px）與版面設定（#4256） |

座位是 `[x, y]` 或 `{ "x", "y", "for": [instance, …]（最多 16 個）, "lend": false }`，必須在它的區域內。座標橫向 0–1280、縱向 0–720；設了 `canvas` 就是它的寬與高。外觀包宣告的名稱不能是每個物件都有的名稱（`constructor`、`toString`、`__proto__` 等）。

### 影格條

STRIP 是 `{ "src", "frames", "durations", "w", "h", "fps", "ax", "ay", "dw", "dh", "once", "loopFrom", "row", "col" }`：

| 欄位 | 範圍 | 預設 |
|---|---|---|
| `src` | 外觀包裡的檔案，或 1–32 張水平影格條的陣列（當 `frames` 是 `{ src, ms? }` 物件清單時省略）；檔名限英文字母、數字、`. _ - /`，不能有 `..`，不能以 `/` 開頭 | — |
| `frames` | 單張 `src`：1–32；陣列 `src`：每張 1–32 格的單一數字或與 `src` 等長的陣列（總計 1–600 格）；無 `src` 時：1–600 筆 `{ "src", "ms"? }`（每張 `w × h`） | — |
| `durations` | 選填，每格停留毫秒數陣列（33–60000，長度須等於總格數；不可與 `fps` 或物件清單式 `frames` 並用） | — |
| `w`、`h` | 每格 1–512 圖片像素 | — |
| `fps` | 0–30；0 只顯示第一格 | 4 |
| `ax`、`ay` | 錨點，單位是圖片像素 | 底部中央 |
| `dw`、`dh` | 顯示大小，單位是邏輯單位（1 到畫布寬、1 到畫布高：預設 1280 與 720） | `w·scale`、`h·scale` |
| `once` | `true`：從第 0 格播一次後停在最後一格 | `false` |
| `loopFrom` | `0` 到 `總格數 − 1`：先播一次進入段 `0 .. loopFrom − 1`，之後從 `loopFrom` 起循環（不可與 `once: true` 並用） | `0` |
| `row`、`col` | 0–4095：從一張大圖切出影格——第 *i* 格是第 `row` 列、第 `col + i` 欄的 `w × h` 格子，一張圖可以放好幾個姿勢、給好幾條影格條共用。圖片至少要 `(col + frames)·w × (row + 1)·h`（沒寫這兩個的影格條仍須剛好 `frames·w × h`）。不可用在逐格清單 | — |

## 升級與降版

- **升級** 會保留你的辦公室、外觀包與配置，不需要手動搬移。
- **有 `card` 的外觀包與降版**（#4256）。較舊的版本會拒絕含 `card` 鍵的外觀包並以辦公桌顯示、附註；外觀包檔案仍完整留在磁碟上，升級回來就會恢復。若需在舊版使用，降版前請移除 `card`。
- **有 `portraits` 或 `dialogBox` 的外觀包與降版**（#2861）。和 `levels` 一樣，較舊的版本會拒絕這種外觀包並以辦公桌顯示、附註。降版前請移除這兩個鍵，或重新上傳不含它們的外觀包。對話框的其他設定都不存在主機上。
- **有 `levels` 的外觀包與降版。** 等級之前的版本會拒絕含 `levels` 鍵的外觀包，所以在那裡會以辦公桌顯示並附註。需要降版時，請移除這個鍵，或重新上傳不含它的外觀包。
- **所有辦公室的等級頭銜與降版。** 舊版會忽略 fleet 的頭銜（`web-offices.json` 的 `levels`），它下一次儲存辦公室時會把它丟掉。升級後請重新設定。
- **等級與降版。** 等級之前的版本不會開啟 `usage-lifetime.json`，所以降版會保留它。不過舊版執行期間，會把超過 400 天的日子直接清除、不累計，重新升級後等級就少了那幾天。其他都不會遺失。
- **在 2.3.2 之內降版。** agent 以 `keep_previous` 刪除的外觀包，上一版存在它自己的 `.kept-<id>` 資料夾，所以降回 2.3.2-beta.10 時仍然可以上傳與刪除那個 id。#2706 的修正（2.3.2-beta.12）之後，辦公室的配置存在辦公室清單旁邊；降回這個修正之前的 2.3.2 beta 時，每間辦公室都還在，但沒有配置，在那裡儲存會丟掉配置。
- **降回 2.3.1 或 2.2.6。** `office_access` 與 `office_pack_access` 存在 fleet.yaml 的 `dashboard` 之外，所以舊版會接受這個檔案並忽略它們。2.2.6 沒有辦公室畫面。2.3.1 沒有外觀包：用外觀包或溫馨的辦公室會以辦公桌顯示並附上說明。每間辦公室的配置（編輯配置、夜間位置、保留座位）都存在辦公室清單旁邊，2.3.1 不會讀那裡：所以每間辦公室都會顯示，只是沒有配置；在 2.3.1 上儲存會永久丟掉配置。這需要 #2706 的修正：2.3.2-beta.11 以前，配置存在辦公室的項目裡，2.3.1 會完全不顯示那間辦公室，在那裡儲存會把它刪掉。不論哪種情況，若配置很重要，降版前請先備份 `web-offices.json`。
- **在舊版上的「沒有人」辦公室**（#2752）。舊版把 `["team:"]` 當成找不到的 team，所以那間辦公室仍然沒有人。它的編輯辦公室會顯示 **已選 1 個**，但沒有勾任何項目；在那裡勾選某人會把那個人加進去，之後辦公室就有那個人。
