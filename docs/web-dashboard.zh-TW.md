# Web dashboard

English: [web-dashboard.md](web-dashboard.md)

Dashboard 的瀏覽器分頁在聊天、View、設定與登入頁使用銀色 **Ag** 圖示，臨時公開連結也相同。將頁面加入手機主畫面時，可使用同款 apple-touch 圖示。圖示隨套件附上，由 dashboard 本身提供，載入時不需要登入。

AgEnD 的 web dashboard 是 fleet 自己跑的一個小型 web server，上面有三個面板：

| 面板 | 用途 |
|---|---|
| **`/ui`**：網頁 app | 跟 agent 對話（聊天、檔案、中止回覆）、看誰正在工作，管理 instance、task、排程與 team。每個聊天都有自己的網址 `/ui/chat/<name>`；Fleet 在 `/ui/fleet`（`/ui/fleet/schedules`、`…/teams`、`…/org`、`…/cache`、`…/config`）；**等你處理** 在 `/ui/needs` |
| **`/view`** | 以讀取為主的總覽：每個 agent 的即時終端、名單、用量，也可以編輯 agent 的個人檔案與頭像 |
| **`/settings`** | fleet 設定——你的偏好設定、網頁外觀、agent、連線、ClassicBot、預設值、`fleet.yaml`——可以套用並重啟。每個分頁都有自己的網址：`/settings/device`（偏好設定）、`…/appearance`、`…/bots`、`…/classic`、`…/general`、`…/web`、`…/advanced`（`/settings` 是 Agent） |

`/ui`、`/view` 和 `/settings` 是同一個有側欄的 app：**Fleet 概覽**、**等你處理**、**搜尋**、instance 清單、**設定**和 **Session** 選單都在側欄。Agent 的 **View**、**紀錄**與**詳細資訊**是它標頭下方的分頁。在裡面切換不會重新載入頁面，上一頁／下一頁也可以用。打開 `/` 會進入 `/ui`，並回到你上次開著的聊天。舊的 `/ui#instance=<name>` 連結仍然有效，登入後也會帶到正確的聊天。

server 只聽 **`127.0.0.1`**，port 是 `health_port`（預設 **19280**）。除非你另外開通，否則只有本機連得到，請見[從別的裝置連線](#從別的裝置連線)。

## 登入

dashboard 用**一次性登入碼**登入，絕不使用帶有憑證的連結。

1. 取得登入碼，兩種方式擇一：
   - 在 General 使用 **`/web`**（限 fleet admin；Discord 原生 slash），按 **💻 AgEnD 電腦登入（取碼）**，或選 **🌐 其他裝置登入（臨時公開）**（須允許公開連結）。取碼指示放在最前面，不再列出重複的頁面網址或已關閉連結的倒數。選單不含碼，bot 會私送連結與一次性登入碼，接著再把登入碼單獨傳一則，手機上就能只複製登入碼（點一下即可複製：Telegram 以程式碼格式顯示，Discord 以行內程式碼顯示）。公開連結的期限以 fleet 的時區顯示，並附上 UTC 偏移。
   - Telegram 上，你要先開啟和 bot 的私訊，它才能傳訊息給你。`/web` 私送不到時，點 **開啟私訊**（或對 bot 傳送 `/start web`）並按「開始」，同一個選單會在私訊裡出現：在那裡選擇，登入碼就送到選單下方。私送失敗後 10 分鐘內，bot 本身的「開始」按鈕（單獨的 `/start`）也有同樣效果，限一次。
   - 在主機上執行 **`agend web`**，會印出登入碼並開啟登入頁；`agend web --code` 則只印出來、不開瀏覽器。
2. 打開登入頁，輸入 8 個字元的登入碼（`ABCD-EFGH`，有沒有連字號、大小寫都可以）。

本機私訊包只有三行：登入網址、五分鐘內單次使用的登入碼，以及勿轉傳／撤銷提醒。公開私訊包另加實際的連結到期時間，以 fleet 時區顯示。本機網址不會顯示另一個「連結期限」欄位；登入碼與瀏覽器 session 的期限不同。仍會另外傳送一則只有登入碼的訊息。

關於登入碼：
- 只能用**一次**，**5 分鐘**後到期；只有最新的那一組有效，重新取得會取代前一組。
- 同一組輸錯 5 次就作廢；跨多組累計輸錯太多次，會暫停登入幾分鐘。還沒發出任何登入碼時，根本沒有東西可以猜。
- 本機登入預設通知 General，可用 `web.notify_login: false` 關閉；公開登入一律需要已確認的公開通知。

**傳一組新的登入碼給我。** 曾用 `/web` 的登入碼登入過的瀏覽器，登入頁會出現這個按鈕，不必回聊天室再要。新的碼只會私訊給收到上一組碼的那個人，絕不會發到群組，而且對方必須仍是 fleet 管理員。私訊會寫出是哪個瀏覽器、經由公開連結還是本機網路要求的。和任何新的碼一樣，它會取代前一組，包括 `/web` 剛送出的那組。每個瀏覽器一分鐘一次、一小時五次（整個 fleet 另有每 20 秒一次、每小時 20 次的上限）；輸錯碼導致登入暫停期間不能要。`agend web` 給的碼不會讓瀏覽器取得這個按鈕。公開連結上，只有同一條連結仍開著時才有效，登入照常在 General 公告。`/web revoke` 與 `agend web-token rotate` 會讓所有瀏覽器失去這個按鈕。

舊的 `?token=` 連結或書籤（例如舊版印出的 `/ui?token=…`）**不能**用來登入：它會開到登入頁，網址列裡的 token 也會被清掉。

## Session

- 每個 fleet 都使用自己的瀏覽器 cookie 名稱，因此同一主機、不同連接埠的儀表板可以同時保持登入。升級後會自動遷移屬於該 fleet 的有效工作階段；變更連接埠不會改變 cookie 識別。登出只影響該 fleet，輪替 token 仍會撤銷原有憑證。
- session 是伺服器上的一筆紀錄，不是存在瀏覽器裡的值。預設在登入後最多 **48 小時**、或閒置 **48 小時**就會結束（以先到者為準；直接連到 dashboard 時，這兩個值可用 `web.session.local.absolute_hours`／`idle_hours` 設定，最多 720 小時，見[設定](configuration.zh-TW.md)）；本機 session 在 fleet 重啟後仍有效。公開 session 綁定單次入口，四小時／閒置 30 分鐘及入口關閉都會使其失效；不能用於本機或下一個入口，本機 cookie 與 header token 也不能用於公開入口。
- 只有你的操作才算使用：打開頁面或聊天、送出訊息、變更任何東西。頁面自己定時做的事一律不算：即時串流（重新連線也一樣）、備援輪詢，以及 `/view` 的終端、名單與用量更新。所以開著不管的分頁——包括 `web.view_access: session` 時的 `/view`——仍會在閒置期限後結束（本機預設 48 小時、公開 session 30 分鐘）。
- session 結束時，頁面會提示一次（「登入已結束。重新登入」），而且保留你畫面上正在做的事。
- **Session 選單**（在側欄最下方）會顯示：
  - 你目前用哪個瀏覽器登入、這個 session 什麼時候到期（只顯示時刻：「最晚 … 到期，或閒置 … 後到期」）；
  - 有不只一個瀏覽器登入時：所有已登入的裝置（目前這台標示 **This device**，其他每台都可以按 **Sign out**），以及 **全部登出（Sign out everywhere）**。
- 最多保留 8 個 session；第九個登入時，最久沒用的那個會被登出。

### 讓所有瀏覽器登出（revoke）

看到不是你做的登入，或有一台不再信任的裝置時，以下任一種方式都可以：

| 在哪裡 | 怎麼做 |
|---|---|
| Telegram | `/web revoke` |
| Discord | `/web` slash 指令，選 **`action: revoke`** |
| 主機上 | `agend web-token rotate`（同時也會輪替 CLI 用的 token；執行中的 fleet 會直接套用，不用重啟） |
| 瀏覽器裡 | Session 選單 →**全部登出** |

如果伺服器存不了這個變更（磁碟有問題），回覆會明確告訴你：大家**目前**都登出了，但重啟後 session 可能會回來，請先修好磁碟再 revoke 一次。

## 聊天（`/ui`）

**暫停的代理。** 傳送訊息會喚醒暫停的實例，包括 ClassicBot 房間；傳送期間輸入區顯示「正在喚醒」。若喚醒遭拒（例如沒有可用空位），訊息會以「沒有送出」留在對話裡，附上原因與「重試傳送」，不會自動重送。已停止的實例仍須先啟動；讀取歷史或加入附件不會喚醒它。訪客與公開連結的傳送權限不變。

在左側選一個 instance 就能跟它對話。web 聊天跟它的 Telegram／Discord topic 是**同一個對話**：
- 你在 web 發的訊息，會以 `🌐 web · <你的名字>: …` 同步到 topic（見下方「agent 看到的是誰」）。
- agent 的回覆照常送到 Telegram／Discord，web 也會同時顯示。
- 你可以對話到一半在 web 和手機之間切換。
- **切換聊天：** 你最近開過的 12 個聊天（手機上 6 個）會立刻回來，停在你離開時的位置；它們合計超過 2,400 則訊息時，保留的會少一些。最久沒開的先被釋放，收藏的聊天則排在所有非收藏聊天之後。只是路過的聊天（開不到一秒就換到別的，例如沿著清單一路點下去）不會被保留，所以不會擠掉你正在用的聊天；最後一次點擊永遠算數：路過的聊天還在載入的內容會被放棄。一陣子沒開的聊天會重新繪製，畫面在補齊內容時不會移動：照片從一開始就保留它的大小。
- **完全沒有聊天平台？** `fleet.yaml` 裡沒有設定 `channel` 或 `channels` 時，只靠 dashboard 就能用：agent 的回覆會送到 web 聊天。
- **需要時再看導覽。** **設定 → 偏好設定 → 聊天導覽**會打開一個 Agent 的聊天（你上次開的那個），介紹 Agent 清單、檔案、Stop 和「等你回應」標記。它不會自己出現；沒有可開的 Agent 時會直接告訴你。

### agent 看到的是誰（#1827）

- **用 `/web` 的驗證碼登入：** 驗證碼是私訊給你的 Discord 或 Telegram 帳號，所以對 agent 來說，這個瀏覽器就是那個帳號。你的網頁訊息會以 `[user:<名字> via web, id:<你在那個平台的使用者 id>]` 送達。在 Discord 或 Telegram 上認得你的 agent，在網頁上也認得你；`via web` 標示你是從網頁發的。
  - **名字：** 預設是你登入時帳號的顯示名稱，也可以在 **設定 → 偏好設定 → 你的名字** 另取一個。名字會跟著你到每一台登入的裝置，包括公開連結；改名不會改變 id。
  - **名字規則：** 1–32 個字，只能用字母、數字、空格、單一表情符號和 `. - _ ' ·`。不能含有「via」這個字，也不能用 AgEnD 保留的名字，或這裡某個 agent、bot 的名字。
- **用其他方式登入**（`agend web` 的驗證碼，或 2.2 以前的工作階段）：和以前一樣是 `web-user`。你仍可以為這些訊息設定名字；用 `/web` 的驗證碼登入一次，這個瀏覽器就會成為你的帳號。
- **一般的請求，agent 會當作是你本人提出的**（#1939）：問問題、查資料、分析，以及它自己範圍內的工作。**需要你點頭的動作**——發布或推出版本、超出 agent 自己工作範圍的刪除等破壞性或無法復原的操作、超出平常工作的花費、憑證或密鑰，或把你的授權交給另一個 agent——則要你的帳號背書，因為一個開著的瀏覽器無法證明是誰在用：授權這個瀏覽器，或在 Discord、Telegram 上確認。在那之前，#1756 的人類授權收據不會把網頁訊息記成你的帳號。
  - 按 **授權這個瀏覽器**（在輸入框下方左側的那一列：**未驗證 · 授權**；或在 session 選單中），再到 Discord 或 Telegram 私訊確認卡片。之後你的訊息會以 `[user:<名字> via web (verified), id:<你的使用者 id>]` 送達，送達收據也帶有你帳號的授權（`authority.kind: web-verified`）：agent 會像對待你在 Discord 或 Telegram 上送出的訊息一樣檢查並轉交它。
  - 效力持續到授權到期（`web.verified_authority.max_session_hours`，預設 48 小時）、你登出，或網頁授權被撤銷為止。訪客與臨時（quick tunnel）公開連結永遠不適用。
  - **透過你自己的固定網域（#2453），需自行開啟。** 設定了固定網域（`web.public_link.hostname`，named tunnel）時，設定 → 網頁 → 網頁授權 會出現 **也允許透過我的固定網域（<網域>）**，預設關閉（`web.verified_authority.named_link`）。
    - **開啟時** 需在 General 或這台電腦上確認，提出要求的瀏覽器不能自己確認。
    - **開啟後，** 透過該網域登入的瀏覽器也能用同樣方式授權。確認卡會寫「透過你的固定網域 <網域>（網際網路）」，裝置清單也會標示。
    - **授權隨連結結束：** 按「關閉」、`/web revoke`、連結到期、fleet 重新啟動，或關閉這個選項都會結束授權。關閉選項後，透過連結給出的回執會立即視為無。
    - **關閉選項** 會立即結束透過連結的所有 session 的授權，但不會結束 session 本身：它們仍可像一般公開連結 session 一樣聊天。
    - **「只有這台電腦可以授權」** 仍然優先。
    - **開啟代表你接受：** 這個網域在網際網路上，Cloudflare 也看得到流量。已授權 session 的 cookie 若被盜，在上述任一情況發生前都能從任何地方重播。
- **同一個名字也用在：** topic 同步、ClassicBot 房間的紀錄、回覆按鈕的選擇、投票結果、你建立或認領的任務，以及網頁的 `/steer` 和 `/btw`。
- **投票：** 你在網頁投的票，和你在 Discord 或 Telegram 投的是同一張選票。

### 版面
- 對話是置中的一欄。你的訊息是靠右的泡泡；agent 的回覆佔滿整欄，每則都有 **複製**。
- **程式碼區塊**會標出語言，並有 **複製** 與 **換行**（長行改為換行而不是橫向捲動，這個瀏覽器會記住）。超過 30 行的區塊會先收合，按 **展開全部 N 行** 打開。
- **Discord 伺服器表情**以 `<:名稱:id>`（或 `<a:名稱:id>`）寫出時，若屬於 fleet 的 Discord bot 所在的伺服器，會顯示為表情圖片；AgEnD 只取得一次並由 dashboard 提供，頁面不會從 Discord 載入。其他的，或圖片無法載入的，會顯示為 `:名稱:`（不會出現原始標記或空白方框）。
- 任何訊息裡的 **emoji** 都會用你系統的彩色 emoji 字型繪製（Windows 是 Segoe UI Emoji、macOS 是 Apple Color Emoji、Linux 是 Noto Color Emoji），不論 agent 的主題字型為何，不會顯示成方框。若在 Linux 上到處都是方框，請安裝彩色 emoji 字型（例如 `fonts-noto-color-emoji`）。
- **提及（mention）**的呈現方式和 Discord 一樣：`<@id>`（或 `<@!id>`）顯示為 **@名稱**，角色 `<@&id>` 顯示為 **@角色名稱**，頻道 `<#id>` 顯示為 **#頻道**，滑鼠停留時顯示 id。名稱來自 AgEnD 已經知道的資訊（fleet 的 bot、傳訊息給它的人、它的 bot 所在的 Discord 伺服器）；不知道名稱時顯示 **@user**（或 @role、#channel）。Telegram 的 **@使用者名稱** 也有相同外觀。程式碼裡的內容不會改動。
- 只有在你停在最底部時，畫面才會跟著新訊息捲動。往上捲去看舊訊息時，畫面會留在原處，按 **↓ N 則新訊息** 回到最下面。
- 側欄頂端的側欄按鈕可以隱藏側欄（按 ☰ 叫回來），這個選擇會被記住。在手機上側欄是抽屜：按 ☰ 打開——或在對話上往右滑——選了東西、點旁邊、往左滑或按 Esc 就會關上。（從螢幕最左邊開始的滑動仍是瀏覽器的「上一頁」；在程式碼、表格、終端畫面或輸入框上的滑動也交給它們自己。）手機下方另有分頁列（聊天、待處理、Fleet、設定），螢幕鍵盤打開時會讓出空間。在 agent 的任何一頁（聊天、View、紀錄或詳細資訊）上，目前的分頁都是**聊天**，點它會回到那個 agent 的聊天。
- 標題列顯示 instance 的名稱與狀態、**聊天 / View / 紀錄 / 詳細資訊** 切換、**字級** 和 **用量**（聊天、View、紀錄、詳細資訊和 Fleet 上都是這兩個，順序相同）。**字級** 依序是 小 → 中 → 大，這台瀏覽器只有一個設定：在任何頁面選了，每個頁面、重新載入後都是這個字級。**用量** 是 AI 訂閱用量：寬螢幕（1200 px 以上）上是與頁面並列的右側面板，預設不開，按 **用量**（或面板的 ✕）可顯示或隱藏，這台裝置會記住；較窄的螢幕上，**用量** 會以對話框開啟。**⋯** 選單裡有 **Instance 詳細資料** 和這個 instance 的操作，而且只列出適用的：已停止的有 **啟動**；執行中的有 **重新啟動** 和 **停止 instance**；**刪除** 放在最後，要輸入名稱確認。
  - **讀取失敗時保留上次的數字**（#2236 後續）。某個 provider 讀取失敗時（token 過期、請求受限、網路不穩或其他錯誤），那一列會保留上次成功讀到的數字，最多一週前的。
    - 數字會變灰，並有一行說明原因與時間：**已過期 · 快取於 14:05**、**暫時無法更新 · 快取於 …** 或 **讀取失敗 · 快取於 …**。
    - 過期或其他錯誤時，第二行說明該怎麼做。
    - 之後已經重置的時段顯示 **已於 … 重置**，不顯示數字。
    - 從未成功讀取的 provider 仍顯示錯誤；一旦讀取成功，標示就會消失。
- **主題**與**語言**（**設定 → 偏好設定**；未登入看 `/view` 時，在**登入**旁的 ☀ 按鈕，只套用在那個瀏覽器）：*跟隨系統* 依各裝置的淺色／深色設定；*淺色* 或 *深色* 則固定使用。語言會套用到每個面板。
- **誰回覆了（#2179）。** 每一列會顯示那個 agent 最後一次回覆某個人的時間（透過它的 reply 工具，在頻道或網頁聊天；instance 之間的訊息不算）：第一行是名字和 context %，第二行最後是時間（「剛剛」「2 分鐘前」「3 小時前」「昨天」）。10 分鐘內的回覆會有高亮，高亮會自己慢慢淡掉，不需要標為已讀。時間每 30 秒更新一次，新的回覆約 10 秒內會出現（下一次狀態更新）。
  - **排序：** **編輯** 旁邊的按鈕會寫出目前怎麼排序。**自訂**（預設）是你自己的順序，有回覆也不會讓列跳動。**最近回覆** 會把其他列不分組、依最後回覆排在一起；你的最愛照你的順序固定在最上面，若選了 **也依最近回覆排序**，最愛也會一起排序。開啟時暫停拖曳排序。這個選擇會跟著你到每台裝置。
  - 訪客看不到回覆時間，也沒有排序。匿名的檢視頁面也沒有回覆時間，所以它的列表一律照你的自訂順序。
- **側欄怎麼分組（#2172）。** 屬於某個團隊（fleet.yaml 的 `teams.<名稱>.members`）的 instance 會列在它的團隊底下，不看它的標籤；同時屬於好幾個團隊時列在第一個。不屬於任何團隊的，列在它的第一個標籤底下；ClassicBot 房間列在 **Classic**，其他列在 **其他**。團隊排在前面，再來是標籤。每個分組標題會標出它是什麼：團隊有團隊圖示，標籤前面有 **#**（名稱和團隊一樣的標籤，是另一個分組）。**設定 → Agents** 也這樣分組。
- **側欄的每個 instance** 以顯示名稱呈現，滑鼠停留時顯示 instance 名稱（兩個 instance 顯示名稱相同時，名稱也會寫在下方）。圖片依序為：在 View 上傳的圖片（**編輯個人資料**）、它自己的 bot 頭像（擁有專屬 bot 時；General bot 只有 General 在用時也算），否則是它說話用的 bot 頭像（通常是 General bot）、persona emoji，或名稱的第一個字。每個 instance 都有一個[識別色](#識別色)，預設顯示在名稱、列左側的色條與圖片外框。圖片上的圓點是它的狀態：閒置、工作中、似乎卡住、已暫停（空心）、已停止、已當掉或等你處理，也會讀給螢幕閱讀器。圖片與伺服器表情由這台電腦上的 AgEnD 取得，由 dashboard 自己提供；頁面不會從 Discord 或 Telegram 載入。篩選可用任一名稱找到 instance。篩選時，你目前開著的 instance 會固定在最上方的 **目前** 底下，不論是否符合篩選，所以不會找不到正在對話的對象；計數仍只算符合的項目，清除篩選後它會回到原本的位置。
  - 在 View（**編輯個人資料**）設定的顯示名稱優先於 agent 自己設定的（`set_display_name`）。在 View 清除它後，會再次顯示 agent 自己的名稱（或 instance 名稱）。
- 側欄底部只有一列：**設定**與**登入狀態**。**設定 → 偏好設定**放的是你的名字、主題、語言、暱稱或本名優先、HTML 預覽和導覽。
- **最愛（#1664）。** 為 instance 加上星號，就會釘選在側欄最上方的**最愛**，依加入的順序排列。在電腦上，滑鼠移到某一列或聚焦時會出現 ☆，已加入最愛的列會一直顯示。在手機上，請點清單上方的**編輯**。**編輯**也會顯示 ↑ ↓ 讓你調整最愛的順序。已刪除的 instance 會從清單移除；暫停或停止的仍會保留。最多 50 個。
- **偏好設定在你的所有裝置同步（#1665）。** 主題、語言、名稱順序、側欄的排序、收合的群組、篩選與最愛、HTML 預覽，以及網頁外觀的選擇（是否顯示 agent 的主題、卡片大小、你的側欄小工具、識別色），都存在 AgEnD 主機上，手機和電腦會保持一致。變更會立刻出現在你的其他裝置，或在它們下次載入時出現。每個瀏覽器都留有一份副本，頁面送達時就已套用你的主題，不會閃爍。更新後裝置第一次載入時，會把主機還沒有的設定上傳；之後以主機上的值為準。導覽、文字大小、視圖寬度、側欄顯示或隱藏、面板寬度、程式碼換行與桌面通知，留在各裝置。公開連結可以讀取你的偏好設定，但無法變更。
- **在手機上**，螢幕鍵盤出現時頁面會跟著縮小，輸入框會留在鍵盤上方；版面也會避開瀏海與底部的 home bar。

### 鍵盤與螢幕閱讀器
- agent 工作時按 **Esc** 會中止它的回覆，就像在它的終端機按 Esc 一樣。agent 閒置時沒有作用；有表單或選單開著時，Esc 會先關掉它們。
- 側欄的每一列都是連結：用 **Tab** 移到、按 **Enter** 打開（中鍵或 Ctrl+點擊會在新分頁打開）。在手機上，抽屜打開時頁面其他部分無法操作。
- 訊息不會在到達時被逐則朗讀。螢幕閱讀器只會聽到粗略的事件，每個一次：agent 開始工作、完成、已回覆，或正在等你回應。對話本身是可以瀏覽的紀錄。

### 輸入
- **Enter** 送出，**Shift+Enter** 換行。
- **傳送，和 Discord 一樣。**
  - 訊息會立刻出現，呈淡色並顯示「傳送中…」，輸入框也馬上可以打下一則。AgEnD 收到後，它會變成一般的訊息：只有一個泡泡，不會重複。連續送出的訊息依序送出。
  - 沒送到的訊息會留著，不再是淡色，附上原因（「沒有送出：…」）和三個按鈕：
    - **重試傳送**：再送一次同一則訊息。已上傳的檔案不會重傳。如果第一次其實已送到 agent、只是回應遺失，重試會認出它：agent 不會收到兩次。AgEnD 只在記憶體裡記住 10 分鐘：fleet 重新啟動後，重試啟動前送出的訊息會再送一次。
    - **放回輸入框**：把它的文字、檔案和回覆放回輸入框，讓你修改。Ctrl/⌘+Z 可以復原。
    - **刪除**：捨棄它。
  - 不會自動重試。等待送出的訊息只存在這個分頁：重新整理頁面就會消失。
- **回覆某則訊息（#2272）。**
  - **開始回覆：**
    - **桌面：** 滑鼠移到訊息上，按右上角的 **↩**；或對訊息按右鍵，選 **回覆／複製文字／複製連結**。按住 Shift 再按右鍵，或在選取的文字上按右鍵，仍會出現瀏覽器自己的選單。
    - **手機：** 在訊息上往左滑（和 Telegram 一樣），或長按訊息開同一個選單。往右滑仍會打開側欄，在訊息上也一樣。
    - **鍵盤：** 在聚焦的訊息上按 **R**。
  - **回覆中：** 輸入框上方會有一列「回覆 *寄件人*」與開頭幾個字（或 [圖片]／[檔案]）。按 **✕** 或 **Esc** 取消。
  - **送出的訊息** 上方會顯示引用。點引用會跳到原訊息並閃一下；如果聊天已不再保存那則訊息，頁面會說明。
  - **agent 收到的：** 和 Discord、Telegram 回覆一樣的 `(reply_to: "…")`。這段文字由伺服器從被引用的訊息讀出：只有一行，最多 500 字。
  - **誰可以回覆：** 只能回覆這個聊天還保存著的訊息。訪客只能回覆自己看得到的訊息；如果訪客看到的回覆所引用的訊息自己看不到，引用處會顯示「之前的一則訊息」。
  - **網頁回顯** 到 Discord 或 Telegram 時，若被引用的訊息就在同一個主題或房間裡，回顯會是那個平台上的**原生回覆**（#2281）。被引用的可以是有人在那裡發的訊息、agent 落在那裡的回覆，或是之前網頁訊息的回顯。若原訊息已被刪除，回顯會以一般訊息送出。
    - **其他情況：** 若被引用的訊息原本就在那個頻道，開頭會是「↩ *寄件人*：*開頭幾個字*」，例如這個版本之前的訊息，或另一個主題裡的訊息。
    - **只在網頁上的原訊息** 只會被提到（「↩ 之前一則 web chat 訊息」），內容不會被複製出去。
    - **保存的資料：** 每則訊息在平台上的位置（連線、聊天、主題與訊息 id）會保存在對話記錄旁，重新啟動後也還在。它永遠不會出現在網頁、訪客或公開連結上。
- **輸入框下方是一列**，靠左：先是這個瀏覽器的網頁授權，接著是按鍵提示（`✓ 已驗證 · Enter 送出 · Shift+Enter 換行`）。授權到何時（「以你的身分發言到 …」）在 **✓ 已驗證** 的提示框裡；觸控螢幕上點一下即可看到。訪客會在這裡看到給訪客的說明，臨時公開連結則說明為何無法授權。手機上不顯示按鍵提示。
- 訊息支援 **Markdown**：標題、**粗體**、*斜體*、~~刪除線~~、`code`、程式碼區塊、清單、引用、分隔線、連結。另外還有：
  - **表格**：`| a | b |`，標題列下面接一列 `|---|---|`，用 `:--` / `--:` / `:-:` 指定對齊。儲存格裡要放直線請寫 `\|`。
  - **巢狀清單**：依縮排決定層級，最多六層。
  - **程式碼上色**：標記為 `js`、`ts`、`json`、`python` 或 `sh` 的程式碼區塊會上色，其他語言照原樣顯示。
  - 連結會在新分頁開啟，而且只有 `http(s)` 和 `mailto` 會變成連結。
  - 不論是你的還是 agent 的訊息，內容都無法產生任何 HTML。
- 重新整理頁面不會清空對話：fleet 會保留每個 instance 最近的訊息。

### 檔案與圖片
- 用 **📎**、貼上或拖曳到聊天區都可以附加檔案（拖曳時會顯示放置位置）。每個檔案會以標籤顯示在輸入框上方，附上檔名與大小，按 **✕** 移除。
- 貼上超過 **4,000 個字元**的文字時，會改成文字檔附加，而不是塞進輸入框；按標籤上的 **改為文字** 可以放回輸入框。
- **檔案上傳時**，每個檔案都會在訊息泡泡裡顯示自己的進度條和百分比，圖片顯示為縮圖。檔案一個接一個上傳，還沒輪到的顯示「等待中」。上傳中斷的檔案會標示**失敗**，按**重試傳送**只會上傳還缺的檔案。
- 限制：預設每則訊息最多 **5 個檔案**，每個 **50 MB**，合計 **100 MB**。
  - 在 `fleet.yaml` 用 `web.upload_max_file_mb` 和 `web.upload_max_total_mb` 改這兩個大小：整數 MB，1–500。單一檔案不會大於整則訊息的上限。`agend reload` 後，下一次上傳就套用；已開著的頁面重新載入後才會用新的數字。值無法使用時，`agend doctor` 和 fleet 啟動時會警告。
  - **透過公開連結**時，不論設定為何，單一檔案最多 **95 MB**：Cloudflare 臨時通道每個請求大約只能傳 100 MB，而每個檔案是一次上傳。拒絕時會說明原因。
  - 聊天送出前會先用這些限制檢查檔案，伺服器也會依實際收到的位元組再檢查每一次上傳。
  - 檔案邊收邊寫到磁碟，大檔案也不會佔用很多記憶體。上傳一分鐘都沒有資料，或超過 30 分鐘，就會中止並刪掉已收到的部分。透過公開連結時，通道會在連線 15 秒沒有動靜時中斷。
  - agent 拿到的是路徑，所以檔案大小對 AgEnD 沒有影響；不過有些 agent CLI 可能拒絕讀取非常大的文字檔。
- 類型：**任何檔案**，跟 Discord、Telegram 一樣。類型由檔案內容判斷，不看檔名。PNG、JPEG、GIF、WebP 視為圖片；PDF 與 UTF-8 文字檔照原樣保留。其他檔案（壓縮檔、Office 檔、程式、HTML、SVG……）以原本的副檔名存放（只取小寫英數字，否則用 `.bin`），在聊天裡一律只能下載，絕不會在頁面上開啟。
- agent 收到檔案的方式跟從 Telegram 收到完全一樣：檔案會放在 instance 工作區的 inbox（`<AGEND_HOME>/workspaces/<instance>/inbox`），並附上一行 `[📷 Image: …]` 或 `[📎 File: …]`。
- agent 在回覆裡附的檔案也會顯示在聊天裡：圖片直接顯示，影片與音訊直接播放；Markdown、CSV/TSV、JSON、程式碼與文字檔有 **Show** 卡片（顯示 200 行，再按 **Show all … lines**；超過 1 MiB 請下載閱讀）。其他檔案則是下載，絕不會在頁面上開啟。透過臨時公開連結時只有圖片會直接顯示。
- **點聊天裡的圖片**會在聊天上方以原尺寸開啟（按著修飾鍵點則照瀏覽器的方式開啟檔案），一開始會縮放到符合視窗。要看大圖的細節：
  - **電腦**：滾輪以游標為中心縮放；圖片大於視窗後，一般滾輪改為捲動，縮放則用 Ctrl/⌘+滾輪（或觸控板雙指縮放）。點圖片會在那個位置切到 **100%**，再點一次回到符合視窗；拖曳可移動。**符合寬度**（或 `W`）讓長圖橫向撐滿視窗，往下捲動就能閱讀。工具列在 **−** 與 **+** 之間顯示目前的縮放比例（點它切換符合視窗／100%）。按鍵：`+`、`-`、`0`（符合視窗）、`1`（100%）、`W`；方向鍵切換同一則訊息的圖片，Esc 關閉。
  - **手機**：雙指縮放，單指拖曳移動，點兩下在那個位置切到 100%（再點兩下回到符合視窗）；點深色區域關閉。
  - 每張圖片都從符合視窗開始，切到下一張也會重新符合視窗。回覆裡的圖片與臨時公開連結上的圖片用的是同一個檢視器。
- 聊天會為每個回覆檔案另存一份副本（`<AGEND_HOME>/workspaces/<instance>/web-files`），所以 agent 改寫或刪掉原檔、或 fleet 重新啟動後，檔案仍能開啟。符號連結、超過 50 MB 的檔案，以及 AgEnD 狀態資料夾內（inbox/ 以外）的檔案不會顯示。訊息離開聊天紀錄時副本會一併刪除；每個 instance 最多保留 1 GiB 的副本，超過時先刪最舊的。
- 附加了但**30 分鐘內沒送出**的檔案會被刪除。fleet 重啟後，留下的這類檔案也會在啟動時、放滿 30 分鐘後刪除。
- 已送出的檔案會在 inbox 保留 **7 天**，跟從 Telegram 收到的檔案一樣。

### HTML 預覽
agent 的回覆裡有 ` ```html ` 區塊，或附上 `.html`／`.htm` 檔案時，下方會出現一張卡片，可以幫你執行那段 HTML。
- **檔案和區塊用法相同。** 檔案的卡片在回覆的附件下方。只有在你按 **預覽** 或 **在面板中開啟** 時，才會向 fleet 讀取它的 HTML，並在和區塊相同的沙箱框架裡執行；檔案絕不會在 dashboard 自己的位址上開啟。**下載** 就是卡片上方那個檔案本身的連結。fleet 已經沒有的檔案（副本因超過上限被刪除，或是在 AgEnD 開始保留副本之前送出的）會直接說明，請 agent 再傳一次。
- **上限 1 MiB。** 超過 1 MiB（以 UTF-8 計）的區塊或檔案不提供預覽。檔案會先檢查列出的大小才讀取，讀到的位元組數也會再檢查一次。檔案一律以 UTF-8 讀取。
- **預設是關閉的，要你自己打開。** 用 **設定 → 偏好設定** 的 **允許預覽 HTML**，或卡片的 **⋯** 選單。它只會問一次，並說明這代表什麼。這個選擇存在 AgEnD 主機上，所以會套用到每一台登入這台主機的裝置（公開連結永遠不會）；關掉時，所有正在執行的預覽都會停止。
- **每次都要你按下才會執行。** **預覽** 會在卡片下方的框架裡執行，並顯示這段說明：*「Previews run the agent's HTML in an isolated frame. It cannot use your login, but it may be able to send data out. Only preview content you trust. A preview can slow or freeze this tab.」* 按說明上的 **我知道了** 可以隱藏它，直到你下次登入；預覽外圍的黃色框線一律保留。按 **停止** 關閉。一次只會執行一個預覽。
- **下載** 會把區塊的 HTML 存成 `reply.html`（檔案保留原本的檔名），絕不會在 dashboard 裡開啟。
- **在面板中開啟** 會把區塊放到對話旁邊，空間比較大。在手機上它是全螢幕的頁面，按 **←** 回到對話。
  - 從閒置的卡片開啟時，面板有自己的 **預覽** 要你按。從正在執行的預覽開啟時，同一個按鈕會把那個預覽移到面板裡。
  - 面板的工具列：**頁面**／**程式碼**（原始碼）、**重新載入**、**停止**、**下載**。頂端的 **來自 …** 會顯示這個區塊所在的訊息。
  - 拖曳分隔線可調整寬度，或把焦點移到分隔線上用 ← →、Home、End。這台裝置會記住寬度。
  - 之後的回覆帶來同一個區塊的較新版本時（`<title>` 相同；沒有 title 時則是任何較新的區塊），或同一個檔案的較新版本時（檔名相同），面板會用 **顯示** 提示你。它絕不會自己換掉，新版本也要等你按 **預覽**。
  - 關閉面板（**×**、**←** 或 Esc）或打開別的對話時，面板的預覽會停止。在卡片裡啟動預覽會停止面板的預覽：一次只會執行一個預覽。
  - 沒有「在新分頁開啟」：HTML 只會在沙箱框架裡執行。要拿到別處，請用 **下載**。
- **它能做什麼、不能做什麼。** 預覽在另一個位址的沙箱裡執行，所以無法使用你的登入、讀取你的 session，也無法操作 dashboard。但它**可能**可以把資料傳出去（沒有瀏覽器能擋住所有管道），所以只預覽你信任的 HTML。
- **只有 agent 的回覆**（由 fleet 標記）才會有卡片。來自人的 HTML（web、Telegram 或 Discord）一律只顯示成程式碼，人上傳的 `.html` 檔也只是一般下載連結。被長度上限截斷的區塊不會有預覽：請 agent 改用 `.html` 檔案傳送。agent 也被告知完整頁面優先用檔案，因為長區塊在 Discord 與 Telegram 上會被切開。
- **在哪裡能用。** 預覽來自第二個本機 port：`health_port + 1`（19281）。透過 SSH 使用時也要轉送它：`ssh -L 19280:127.0.0.1:19280 -L 19281:127.0.0.1:19281 <host>`。透過 tunnel 或 proxy 時需要設定 `web.preview_origin`（對應到那個 port 的另一個主機名稱），而且 proxy 必須原樣傳遞外部的 `Host`。不符合時，卡片會說明預覽為什麼關閉，只提供程式碼與 **下載**。
- **在臨時公開連結上（#1723）** 也能預覽，用手機也可以。
  - 公開連結會在背景為預覽另開一條自己的 quick tunnel，時機是連結自己的通道拿到網址之後（連結一定先向 Cloudflare 要，#1767）。連結不等它：自己的通道一好就可以用。
  - 預覽通道還沒好時，卡片會顯示「預覽啟動中…」，好了就照常執行。開不起來時連結照常可用，卡片會說明原因。
  - 預覽通道若連不上（邊緣節點還沒認得它的名稱），會換一個新網址再開一次，期間卡片仍顯示「啟動中」（#1732）。
  - 它隨連結一起關閉。
  - 它的網址是另一個 `trycloudflare.com` 名稱。`trycloudflare.com` 在 Public Suffix List 上，所以框架和儀表板是不同的站點，隔離得比本機預設（同一名稱的另一個 port）更好。
  - 你這台裝置的選擇（**允許 HTML 預覽**）照樣適用，而且無法透過公開連結更改。
  - `web.preview_on_public_link: false` 會關閉這個功能。若已設定 `web.preview_origin`，就改用它，不另開通道。
- **⋯ → 這台裝置永不預覽 HTML** 會在這個瀏覽器工作階段裡，隱藏所有卡片的 **預覽**。
- **卡住的預覽** 可以按 **停止** 關掉；但它可能繼續佔用該分頁的預覽程序，之後在同一個分頁裡的新預覽可能無法啟動，請在新分頁打開 dashboard。

### Ticks：訊息送到哪一步了
你送出的每則訊息都會顯示目前進度，跟 Telegram 用 reaction 表示的步驟相同：

| Tick | 意思 |
|---|---|
| ◷ | 排在別的訊息後面等待 |
| ✓ | 已交給 agent |
| ✓✓ | agent 已經收到 |
| ! | 沒送達 |
| ⊘ | 在 agent 收到前被 **Stop** 取消 |

**回應（reaction）。** 只需要確認的訊息（「OK」、「謝謝」），agent 可能用一個 emoji（👍、👌、🙏…）放在你的泡泡下方作為回應，而不是回覆，跟 Discord、Telegram 一樣。它會立刻出現，重新整理或換一台裝置也看得到。如果你的訊息有複製到 agent 的 Discord/Telegram topic 或房間，那則副本也會有同樣的回應。回應本身就是完整的答覆：聊天不會說 agent 結束這一輪卻沒有回覆。

### 「*name* is working…」與 Stop
目前打開的聊天裡的 agent 正在工作時，輸入框上方會出現這一列，輸入框裡的 **送出** 也會換成 **中止回覆**。開始打字後 **送出** 會回到旁邊：agent 工作時送出的訊息會排隊等下一輪。
- Stop 的效果跟 Telegram 的取消鍵、`/cancel` 一樣：中斷 agent 目前的回覆（送 Esc），並丟掉還在排隊的訊息，它們的 ticks 會變成 ⊘。
- 中止回覆**不會**停掉 instance 程序；要停掉程序，請用標題列 **⋯** 選單裡的 **停止 instance**。
- 這一列會顯示 agent 已經工作多久（從這個頁面看到它開始工作起算）。按下 Stop 後會顯示「正在中止 *name*…」，直到 agent 停下來。
- agent 停在終端機上等待（權限詢問、登入、對話框）時，這一列會顯示「*name* 正在等你回應」，側欄上的 instance 也會出現 **等你回應** 標記。這是從終端畫面判讀的，請當作參考。可以用下方的提示按鈕回應，或到主機上處理。

### 回應 fleet 的提示
instance 看起來卡住、自己結束，或停在互動式提示時，Telegram／Discord 上的按鈕也會出現在該 instance 的聊天裡：*Force restart* / *Keep waiting*、*Restart* / *Ignore*、*請 General 協助* / *我自己處理*。
- 它們是**同一個提示**：不論在哪邊，先回答的算數。另一邊的按鈕隨後會顯示結果，提示也會在所有地方同時到期。
- 只有這幾種跟 instance 健康有關的提示會出現在 web 上；`/clear` 的確認、登入、ClassicBot 的核准、tips，以及 `/model`、`/effort` 選單，都會留在原本發出的地方。web chat 有自己的 `/clear`、`/model`、`/backend` 與 `/effort`（見下方）。
- 頁面沒連線時發出的提示，重新連上後會立刻出現；如果期間已經在別處回答了，會顯示為已回答。
- **沒有聊天平台？** 只用 dashboard 的 fleet，這些提示會直接出現在該 instance 的聊天裡。互動式提示的 *請 General 協助* 是請 General instance 去看它的終端機，所以只有 fleet 有 General 時才會出現。

### 指令與快速動作
在輸入框開頭打 `/`，會列出這個 instance 自己的聊天指令，和它的 Telegram/Discord topic 接受的指令相同，由相同的處理程式依相同的規則執行。
- **指令清單**：輸入時會即時篩選。↑/↓ 移動，**Tab** 補完，**Enter** 執行，**Esc** 關閉。
- **可用指令**：
  - `/ctx`：context 用量、模型與推理強度。
  - `/compact [指示]`
  - `/clear`：會先確認。
  - `/model [名稱]` 和 `/effort [等級]`：不加參數時會列出可選項目。
  - `/backend [backend] [模型] [推理強度]`：換到另一個 CLI backend，一次選一項（backend、它的模型、它的推理強度），再先確認。只重新啟動一次，並開全新的 session。模型清單和 `/model` 一樣只用快取。
  - `/cancel`
  - `/btw <問題>`
  - `/steer <文字>`
  - `/pause` 和 `/wake`
  - `/save <檔名>`
- **結果顯示的位置**：輸入框上方。
  - `/clear` 和 `/cancel` 會說明已送出，這個結果幾秒後會自己消失。需要閱讀的結果、要選擇的清單和拒絕的原因（即使只是一段文字）會一直留著，直到你關掉。
  - `/compact` 從指令送到代理的那一刻起顯示「壓縮中…」，等代理的對話紀錄寫下壓縮完成，再顯示「對話已壓縮」，然後消失。這適用於 Claude Code 和 Codex，因為 AgEnD 讀得到它們的對話紀錄。
  - kiro（classic 和 TUI 的 V2 引擎）會在自己的窗格上顯示壓縮的結果，卡片就跟著那個窗格：顯示**對話已壓縮**，或說明 kiro 沒有壓縮對話，原因是對話太短或壓縮被中止。在 TUI 上按 Esc 或 Ctrl-C 都中止不了壓縮；「已壓縮」的意思是 kiro 的「Compacting conversation...」那一行出現後又消失了。除了「太短」之外，從沒看過其他失敗的樣子，所以分辨不出來。
  - 其他後端（包括 kiro 的 V3 引擎）會說明無法偵測壓縮何時完成，然後消失。
  - 10 分鐘內都沒有紀錄時，會說明這件事並留著。如果指令沒有送到代理，或代理在這期間停止、重新啟動或換了後端，會說明已無法追蹤這次壓縮。
- **不是指令的情況**：其他以 `/` 開頭的內容照舊當成一般訊息送出；輸入框旁有待送檔案時打的指令也一樣。
- **fleet 層級的指令**（`/status`、`/restart`、`/update`、`/login` 等）仍在 General 使用。
- **`/raw`** 不在清單中。透過臨時公開連結時，以 `/raw ` 開頭的訊息會被拒絕，`/save` 也是。
- **快速動作**：
  - 聊天標題列上的模型與推理強度，點了會開啟可選清單。
  - instance 的 context 用到 70% 時，輸入框上方會出現 **壓縮** 和 **清空…**。

## Fleet（`/ui/fleet`）
fleet 共用的工作與總覽，每項一個分頁，各有自己的網址。標題列的 **文件** 會在新分頁開啟文件網站上簡短的網頁使用說明（依 dashboard 的語言）。

**單一 instance 的詳細資訊**（`/ui/fleet/agent/<name>`）是那個 instance 在 Fleet 這一側的頁面：執行環境（backend、模型、effort、花費、context、5 小時和 7 天額度）、最近活動，唯讀的設定摘要（顯示名稱、說明、目錄、綁定在哪裡、標籤），以及它在任務看板上的工作（它手上的卡，和看板上 **Instance** 列的一樣；點卡片會到看板打開它）。要修改設定請按 **到設定編輯**。它的 ⋯ 選單可以啟動、重新啟動、停止、暫停或喚醒它，呼叫和確認步驟與聊天頁的 ⋯ 選單及設定相同；刪除 instance 仍在聊天頁的 ⋯ 選單和設定裡。ClassicBot 房間的詳細資訊會顯示它的房間而不是目錄，只提供暫停和喚醒（和設定裡一樣），**到設定編輯** 會開啟它的 ClassicBot 設定。沒有指定連線的 instance 會顯示為綁定在 fleet 的第一個連線，這是它的預設。
- 在 instance 的頁面上，標題列可以在它的 **聊天**、**View**、**紀錄** 和 **詳細資訊** 之間切換（手機上是標題列下方的分頁），instance 不變。沒有登入、只讀 View 的人看不到這個切換。
- 側欄最上方的 **Fleet 概覽**（以及手機的 Fleet 分頁）會打開你在這台裝置上次用的 Fleet 分頁（第一次是組織圖）；instance 的詳細資訊是它標頭下方的**詳細資訊**分頁。在詳細資訊頁上，點側欄的 instance 會開它的詳細資訊（在 View 上開它的 View，在紀錄上開它的紀錄）；在 Fleet 分頁（概覽、Tasks 等）上則會開它的聊天。
- **Tasks**：任務看板（[功能說明](features.zh-TW.md#在網頁上fleet--tasks)）。所有專案和待你處理的事（**確認**、**退回**、**回覆**）；專案頁是主任務依狀態分欄的看板（可拖曳、依負責人篩選、展開子任務）；卡片從右側抽屜打開（手機上是從下方滑出的面板），每個欄位都能編輯，還有子任務、留言、進度紀錄和變更歷史。只有登入的人能確認做完的工作。卡片只能取消，不能刪除。在卡片標題上按 Alt+方向鍵可以不拖曳就移動卡片。主任務卡會顯示現在誰在做；等你確認但還沒補齊的卡會標**待補齊**，按確認時會先問一次。搜尋旁的 **Instance** 依團隊列出每個 instance（工作中的在前），以及它手上的卡，跟它的 `task mine` 讀到的一樣：進行中、卡住、待確認、負責的主任務、可以開始、等前置；從那裡可以直接打開卡片。公開連結上的看板只能看，設為 hidden 的 instance 也不會列出。
- **排程**：所有排程（包括靜默排程），以文字說明何時執行與下一次執行時間。**New schedule**（Repeat 以 cron 表示式重複，或 Once 指定日期與時間）、**Edit**（用 **Enabled** 勾選框暫停）與 **Delete**。沒有「立即執行」，也不能在這裡設定是否靜默。透過公開連結時，排程只能檢視。
- **Teams**：**New team**、**Edit**（成員與描述，與 `update_team` 工具相同的更新）與 **Delete**。team 無法重新命名，請建立新的再刪除舊的。透過公開連結時，team 只能檢視。
- **組織圖**（`/ui/fleet/org`；從任何頁面點側欄最上方（手機上是抽屜最上方）的 **Fleet 概覽**，第一次會打開它，之後打開你上次用的 Fleet 分頁）：最上方是 General，下面是 `fleet.yaml` 的各個 team，最後是未加入 team 的 instance。
  - **Canvas**（預設）或 **List**，這台裝置會記住。
  - 畫布：拖曳平移，滾輪或雙指縮放，**Zoom in / Zoom out / Fit to screen**，以及按鍵 `+`、`-`、`0`（符合畫面）和方向鍵。**Overview**（右下角，手機上沒有）顯示整張圖，點一下就移過去。點 team 標題可以收合（這台裝置會記住）。**Find** 會把不符合的變暗；按 Enter 展開並跳到第一個符合的。卡片顯示頭像、狀態、名稱和 backend，點一下（或按 Enter）開啟聊天。
  - 清單模式顯示每個 instance 的顯示名稱、負責的工作、backend 與模型、即時狀態（工作中、閒置、等你回應、似乎卡住、已暫停、已停止、已當掉）、它的 Discord 討論串或 Telegram topic 連結，以及 **Open chat**。
  - **Live**（預設開啟）會畫出 instance 之間正在傳送的訊息（#1918）。**Key**（在工具列；打開後說明列位在畫布上方，不會蓋住畫布）說明線條：顏色代表種類（delegate_task、send_to_instance、report_result、broadcast）——排隊中是點線、傳送中會移動、送達或被讀取後淡出 12 秒。**×N** 表示好幾則共用一條線；縮小時，線改成連接整個 team。`delegate_task` 也會畫出工作：一條從委派者到執行者、緩慢移動的線會保持**進行中**，直到執行者的 `report_result`（相同 correlation id）回來，接著一條線回傳後消失；4 小時後仍沒有回報的會以**尚未回報**淡出。重新整理或公開連結也看得到進行中的委派。每條線都終止於卡片或收合的 team 方框，同一方框內的兩張卡片會在方框內相連。絕不顯示訊息內容，`cross_instance_visibility: hidden` 的 instance 不會出現。透過公開連結時每 5 秒更新一次。
  - **線條怎麼走（#2182）：** 每條線從卡片連到卡片，繞過其他卡片，從 team 外框的缺口進出（不會沿著外框走，也不會穿過 team 的名稱），走最短的空路；共用一段路的線會分開畫（空隙很擠時會靠得比較近），箭頭也不會壓在外框上。縮小時，或瀏覽器無法執行路由器時，線條照舊沿著 team 之間的空隙走。路由器是 [libavoid](https://www.adaptagrams.org/)（透過 `libavoid-js` 0.4.5，LGPL-2.1-or-later，AgEnD 以 npm 相依套件原樣提供）；它在自己的 worker 裡執行——這是 dashboard 唯一能執行 WebAssembly 的地方，而且這個 worker 連不到任何地方。
  - 組織圖只負責顯示：操作請在 Discord 或聊天裡進行。
  - **Office**（和 Canvas、List 並列的第三種檢視）：把 fleet 畫成一間像素風的小辦公室。每個團隊一間房，每個 instance 一張桌子；General 和不屬於任何團隊的 instance 共用大廳。工作中的 instance 會打字，閒置的會喝茶，暫停或停止的會睡覺，需要你處理或看起來卡住的會舉手。每則訊息、委派或回報都會沿著走廊從寄件者的桌子飛到收件者的桌子。滑過（或點一下）桌子可以看卡片資訊，點擊則打開聊天。有 **Desks**（預設）和 **Studio** 兩種風格。
  - 你在主機上保存的 **Office** 由 fleet 管理者編輯：可以新增、改名、刪除辦公室，選擇風格和成員（整個團隊或單一 instance；不選則為全部）。如果編輯時名單已被改過，儲存會被拒絕，不會覆蓋任何東西；由你選擇保留自己的修改（下次儲存會取代較新的名單）或載入較新的名單。唯讀的 session 和公開連結只能看；訪客看不到組織圖和 Office 檢視。
- **快取**（`/ui/fleet/cache`）：在 24 小時、7 天或 30 天內，每個 Claude Code 與 Codex instance 的提示快取在兩次請求之間過期的頻率、重寫的成本，以及保溫 ping 是否划算。
  - 資料來自本機的 transcript，不呼叫任何供應商 API；每個 instance 只保存一份小摘要（`cache-ledger.json`）。
  - 成本以單一價目表的牌價計算，並顯示查證日期。
  - transcript 有記錄快取寫入時就採用它；沒有記錄時（部分 Codex session），改以未快取的輸入估算重寫量，數字會標示為估算；快取存活時間只能假定時也會標示為估算。
  - Kiro 顯示「Not available (credit-billed; no cache data)」；AgEnD 讀不到快取資料的其他 CLI 也一樣。
  - **快取寫入 5 分 / 1 時：** 每個 Claude instance 會顯示以 5 分鐘 TTL 和以 1 小時 TTL 寫入的 token 各有多少（#2001）。
  - **實際存活（#2010）：** 5 分鐘快取實際能撐多久，依過去 7 天內 5 到 60 分鐘的請求空檔實測。
    - 很少被重寫（至少 10 個空檔中最多一成）：視為 1 小時，保溫也照 1 小時模擬。
    - 大多被重寫（至少一半）：卡片會建議為該 instance 設定 `prompt_cache_ttl: "1h"`（見[設定](configuration.zh-TW.md#claude-提示快取-ttl)），而不是保溫；fleet 列會計算這類 instance 的數量。
    - 空檔太少：會說明這一點，數字也會標示為估算。
  - Agent 以 `get_cache_report` 讀取同一份報告。General、協調者與 full 權限的 instance 可以看到所有 instance，其他有這個工具的 agent 只能看到自己那一列（`minimal` 工具組沒有這個工具）。
- **用量**（`/ui/fleet/usage`，#2122）：每個 agent 的 token、請求數、已送達訊息數，以及**依牌價換算的 API 等值——不是實際花費**（訂閱方案不按 token 計費），期間可選今天、7 天、本月、全部或自訂日期，依 fleet 的時區計算。◔ 用量對話框有連到這裡的 **依 agent →**。
  - **各列**依 API 等值排序（全都沒有定價時依 token），每列有長條、輸入／輸出／快取讀取／快取寫入／token 總計、請求數與訊息數，以及它的 backend、模型與憑證 profile。可以依 agent、backend、模型、憑證 profile 或 team（依目前設定）分組。
  - **標記都寫成文字：** Codex 不記錄快取寫入，所以顯示「未回報」（是估算），絕不顯示 0；不在價目表裡的模型會顯示 token 與「未定價」；這個版本之前讀到的小時會註明當時沒有記錄 backend 與 profile。Kiro 與其他 AgEnD 讀不到的 CLI 列在下方並附上原因，絕不顯示成 $0。Claude 的 subagent（sidechain）回合目前還不計入。
  - **趨勢與熱度圖：** 前 5 名 agent 與其他的每日堆疊圖，以及每日總計的日曆；「已讀取、沒有用量」的日子（灰色）與「未收集」的日子（虛線）分得開。兩者都有文字說明，不只靠顏色。
  - **CSV：** **下載 CSV** 會存下目前這份回答的每日資料列（日期、時區、agent、backend、模型、tier、profile、各 token 欄、請求數、金額、計價基準與標記；訊息另列）。
  - **新鮮度：** 自 fleet 啟動起收集（保留 400 天），每 10 分鐘讀取一次；讀取還在追趕時，頁面會說總數可能還會增加。頁面不會定時重新讀取。
  - **不是一次全部：** 期間很長、每日資料列超過一次回答能帶的數量時，頁面會說明趨勢、熱度圖與 CSV 從哪一天開始；各列與總計仍涵蓋整段期間。只有不在價目表裡的模型用過的日子會顯示為有用量（「未定價」），絕不會顯示成沒有用量。fleet 的時區變更過時，每一天保留當初計算的時區，頁面也會說明；跨兩個時區的日子會分別列出各部分。
  - **誰看得到：** 已登入的 session；訪客一律看不到。透過臨時公開連結時，除非 **設定 → 網頁 → 透過公開連結提供用量報告** 已開啟（`web.usage_report_on_public_link: true`，見[設定](configuration.zh-TW.md)；立即生效），否則顯示「公開連結上不提供」，並附上連到直接開啟的儀表板上那個開關的連結。`web.usage_panel: false` 會把它和其他用量一起隱藏。Agent 以 `get_usage_report` 讀取同一份報告。
- **設定**：fleet 的頻道、存取權限與預設值。

## 等你處理（`/ui/needs`）

所有等你處理的事，來自每個 bot 的世界，集中在一份清單：fleet 的提示（沒有回應、已結束、在終端機上等待）、停在權限、危險指令、登入或其他對話框的 agent、因需要登入而暫停或已崩潰的 agent、fleet 無法確認或無法送達的傳送，以及等你確認或卡住在問問題的看板卡片（**打開卡片**）。這和每個 bot 在 General 的「等你處理」即時訊息是同一份清單（那裡每個 bot 只顯示自己的 agent）。在任何地方處理過的事——Discord、Telegram 或這裡——都會從每份清單消失。

- 側欄的 **等你處理**（手機上是一個分頁）會顯示待處理的數量；瀏覽器分頁的標題會以 `(N)` 開頭。
- 清單依 agent 分組，最舊的在前。提示有它自己的按鈕；傳送有 **確認**；因登入而暫停的 agent，在 dashboard 能執行它的登入時有 **登入**（#2233）；每一項都有 **開啟聊天**。
- **在這台裝置通知我**：分頁在背景時，有新的事等你處理就跳出桌面通知（在終端機上的等待要持續 5 秒才通知）。設定只對這個瀏覽器有效，開啟時會請求權限，而且需要安全的網址：`127.0.0.1`/`localhost` 或 HTTPS 公開連結，區網的一般 HTTP 網址不行。手機上不提供：手機請以 Discord 通知為主（General 裡的新訊息，以及可選的私訊）。

## 搜尋（Ctrl+K）

找回某件事當初是交給哪個 agent：一次搜尋每個 agent 的聊天（Discord、Telegram 與網頁，以 fleet 記錄的為準）、agent 之間的訊息（send_to_instance、delegate_task、report_result、broadcast），以及 Task Board。Agent 自己終端機裡的對話紀錄不在搜尋範圍內，那是它的**紀錄**分頁。
- **打開：** 側欄的 **搜尋**（在 **等你處理** 下方，標著快捷鍵）、在任何地方按 **Ctrl+K**（Mac 上是 **⌘K**），或在側欄收起時及手機上按標頭的 🔍。在某個 agent 的聊天裡按 **Ctrl+F**（**⌘F**），會打開已限定為該 agent 的搜尋；在其他地方 Ctrl+F 仍是瀏覽器的尋找。側欄的**篩選**框是另一回事：它依名稱、模型或後端篩選 agent 清單。
- **輸入：** 打字時（稍停一下）就會出現結果，依 agent 分組、最新的在前，每筆標著**聊天**、**訊息**（agent 之間的，顯示為發送者 → 接收者）或**任務**，並標出你輸入的詞。1–2 個字的短詞也可以（包含中文）；只有短詞時會搜尋最新的 5,000 筆，對話框會說明。什麼都沒輸入時，會列出你最近的搜尋（只存在這個瀏覽器）。
- **按鍵：** ↑↓ 移動、**Enter** 開啟、**Esc** 或點外面關閉。**篩選**可展開：agent、團隊、時間（24 小時、7 天、30 天）、種類，以及**只看我的**（你寫的訊息）。
- **開啟結果：** 聊天訊息會開啟該 agent 的聊天，跳到那則訊息並閃一下。聊天已不保留的訊息、agent 之間的訊息與任務，會顯示搜尋保留的副本（聊天訊息會連同前後幾則），並提供可前往的聊天或 Task Board。
- **保留什麼：** 搜尋有自己的索引（AgEnD home 中的 `search.db`）：第一次會用 fleet 已有的資料補齊，之後隨事件更新，保留 `web.search.retention_days`（預設 90 天）。存入前會先遮蔽密鑰；訊息的驗證 id、工作目錄與分支一律不保留。`cross_instance_visibility` 為 `hidden` 的 agent，其往來訊息不會被找到。
- **誰能用：** 登入 dashboard 的 fleet 管理員，不論是在這台電腦上，還是透過臨時公開連結；手機上也能用（選單裡的**搜尋**，或 🔍 按鈕）。訪客一律不能用：訪客頁面沒有搜尋列、按鈕或快捷鍵，Ctrl+F 仍是瀏覽器的尋找。`web.search.public_link: false` 只在公開連結上關閉搜尋，`web.search.enabled: false` 則全部關閉（[設定](configuration.zh-TW.md)）。

## 文字欄位的復原與重做

每個可以打字的框（輸入框、搜尋、側欄篩選、設定、Task Board、CSS 與 YAML 編輯器）都有自己的復原紀錄。
- **按鍵：** **Ctrl+Z** 復原，**Ctrl+Shift+Z** 或 **Ctrl+Y** 重做；Mac 上用 **⌘Z** 與 **⌘⇧Z**。只有游標在文字框裡時才會生效，其他地方仍照瀏覽器原本的行為。
- **一次只影響一個框：** 在一個框裡復原，不會改到另一個框（瀏覽器原生的復原是整頁共用一個堆疊）。打字以一個詞為單位復原，停頓過也算一段。輸入法（IME）組字中時，這些按鍵交給輸入法處理。
- **頁面填進框裡的內容也能復原：** Tab 補完的 `/指令`或補上的參數、送出失敗後的**放回輸入框**、長貼上用**改為文字**放回、點選的最近搜尋、用 Esc 或 × 清掉的側欄篩選、選定或重設的狀態 emoji、小工具範例，以及還原的 CSS 版本。顏色色票是選擇而不是文字：選了色票後，色碼框的紀錄會重新開始。
- **瀏覽器自己的復原**（編輯選單或右鍵選單）也走同一份紀錄。瀏覽器的重做只在它自己復原過之後才會出現，所以重做請用按鍵。
- **不能復原的：** 已送出的訊息不會回到輸入框（避免不小心重送）。按新增或送出後清空的內容，以及儲存後重新載入的值，都從新的紀錄開始。密碼欄位維持瀏覽器原本的行為。

## 紀錄（`/ui/log/<name>`）

逐步顯示 agent 做了什麼：它收到的要求、它的回覆（絕不顯示思考過程）、每次工具呼叫（Read、Edit、Search、Run、Web、MCP、Sub-agent……，可按 **Show output**）、錯誤、每回合結束、壓縮，以及 fleet 事件（例如當掉後重新啟動）。
- 用 **All / Tools / Errors** 篩選；更新中會顯示 **Live**。
- **工作狀態紀錄**顯示觀察到的執行狀態變化，以及任務與待回覆事項的筆數。這些項目列在 **All**，不列在 **Errors**。目前只記錄觀察結果，不會補送繼續工作的提示，也不改變重啟後的恢復行為。
- 一開始載入最新 200 步；**Load older steps** 每次多載入 100 步，頁面最多保留 1000 步。
- 預設關閉，要由 fleet admin 開啟：`web.log_tab`（**設定 → 網頁 → Log tab: each agent's steps**），或在分頁上按 **Turn on the Log**，需等 fleet admin 確認。
- Claude Code 全部顯示，instance 停止後也看得到；Codex 在執行中時顯示；kiro 只顯示 fleet 事件。其他 CLI 會說明沒有 AgEnD 能讀的 transcript。秘密值會被遮蔽。

## `/view`

`/view` 會列出每個 agent：即時終端畫面、包含狀態與 context 的名單，以及 AI 訂閱用量。每個 agent 都有自己的網址 `/view/<name>`；只開 `/view` 會回到這個瀏覽器上次看的那一個。

- **檢視開著時，名單就在側欄**（手機上在抽屜裡）：和側欄一樣分組（先團隊，再標籤），最下方是篩選框（按 **/** 可直接跳過去），順序可以自己拖曳調整。每列顯示已用的 context 和 backend 的顏色，滑鼠移上去可看其他資訊。
- **標題列**有 **字級**、**用量** 和 **說明**。在 View 上字級依序是 填滿 → 小 → 中 → 大：**填滿**（預設）讓終端畫面剛好放進框裡、不會更大，最小 6 px。小／中／大則是所有頁面共用的字級。在其他頁面選字級，View 仍維持填滿；只有在 View 自己的字級按鈕才會離開填滿。終端畫面在淺色和深色主題下都維持深色。
- **終端下方的識別卡**（橫幅、標語、介紹、小／中／大）在 agent 有識別卡時一律顯示。**編輯個人資料** 在它底下，可修改顯示名稱、角色、描述、頭像與識別卡。已上傳圖片時會有**移除圖片**，儲存後改回 bot 的頭像、persona emoji 或名稱第一個字。上下文用量在側欄列與詳細資料，不在這張卡上。

- **讀取 `/view` 預設不用登入**（`web.view_access: open`），連每個 agent 的即時終端也一樣，不需要帳號，也不限於部分 agent。Dashboard 只在 `127.0.0.1` 上監聽，但「任何連得到這個 port 的人」其實比你自己更多：
  - 這台機器上的其他使用者與程式；
  - 你設定的反向代理、tailnet 分享或 port 轉送所放進來的人（`web.allowed_hosts`）；
  - 在 WSL2 上，Windows 那一側。

  如果機器只有你連得到，這樣沒問題；否則請設定：
  ```yaml
  web:
    view_access: session   # 讀取 /view 也需要已登入的 session
  ```
- **未登入時，`/view` 只有檢視：** 側欄只有檢視和 **登入**，不會顯示或讀取任何需要登入的內容；**登入後才能編輯** 會帶你去登入頁，再回到原頁。
- **編輯 agent 的個人檔案或頭像一律需要登入。** 名單順序是會同步的偏好設定之一（見上方）；未登入的讀者則只保存在那個瀏覽器。
- 腳本仍然可以用 `X-Agend-Token` header 寫入。

## `/settings`

**連線 → 立即重試** 讓斷線的連線立刻再試一次，不必重新啟動 AgEnD。已有嘗試正在進行時會沿用它。啟動失敗會持續重試，間隔最多五分鐘，直到 fleet 停止；不再因長時間斷網而永久放棄。此控制需要在本機網址以管理員登入，公開連結不提供，也不會改動 token、權限或儲存的綁定。稍後重新整理連線分頁可查看恢復結果。

**偏好設定**、**網頁外觀**、**Agent**、**連線**、**ClassicBot**、**一般**、**網頁**和**開發者**（以 YAML 或 JSON 呈現整份 `fleet.yaml`；可 **Edit**、**Copy**、**Download fleet.yaml**，以及不經下方列、立即套用的 **Apply & save**）是分頁，各有自己的網址。搜尋框可篩選 agent、連線和 ClassicBot 房間；**設定精靈** 的四個步驟和 `agend quickstart` 相同；它一律新增一個連線，接到新的 agent 或你已有的 agent。

還沒有任何聊天連線（只用網頁）的 fleet，會在設定的 Agent／連線分頁上方顯示一張卡片（聊天頁不顯示，那裡只有一個指示：選一個 Agent，或建立一個）：**連接聊天應用程式** 會開啟設定精靈，**只用網頁** 會在這個瀏覽器裡隱藏它。

- **變更會先暫存，再一起套用。** 在 agent、連線或 ClassicBot 聊天室的 **設定** 對話框按 **暫存變更** 就會暫存；一般或網頁分頁的 **檢查變更** 也一樣。（連線的新綁定、**Delete this bot**、供應商 API 金鑰與 **New connection** 會直接套用；偏好設定與網頁外觀會立即儲存。）下方的列會顯示數量和套用的代價（立即生效、重新啟動該 agent，或重新啟動 AgEnD）；**套用變更** 一次套用全部，**捨棄** 則全部丟掉。在分頁之間切換時暫存的變更會保留；帶著暫存變更離開設定時，會先問 **要捨棄 N 項尚未套用的變更嗎？**
- **按下套用後，即使離開也會繼續。** 你可以去聊天或任何地方：寫入、重新載入和進度都會繼續，頂端會有一行顯示進度，回到設定時可以看到細節。前一次套用完成前，不能再套用一次。需要重新啟動 AgEnD 本身時，會提供 **重新啟動 AgEnD**（另有確認）。
- **網頁** 分頁是 dashboard 本身的設定：從這裡登入後可維持多久、閒置多久登出（`web.session.local.*`；留空 = 預設值）、`/login` 開啟的瀏覽器終端機（開或關，以及分鐘數）、web 同步、紀錄分頁（`web.log_tab`）和公開連結選單。放寬存取的變更——延長 session 或閒置時間、重新開啟瀏覽器終端機或增加分鐘數、公開連結——要等 fleet admin 在 General 確認（或用 `agend settings confirm <id>`，見下方「確認敏感變更」）；收緊存取的變更立即套用。其他網頁設定只列出、不能修改：它們決定 dashboard 監聽和公開的內容，請在 `fleet.yaml` 編輯（之後執行 `agend reload`；`web.preview_port` 與 `web.preview_origin` 需要重新啟動）。透過臨時公開連結無法變更這些設定：分頁會說明原因，伺服器也會拒絕。
- **Dashboard 權限**（agent 的 **設定** → **進階**；所有 agent 的預設在 **一般 → 預設值**）：在工具組之外，再決定這個 agent 能在 dashboard 上用哪些功能：**它的外觀**（主題、圖片、小工具、特效、mod 提案）、**任務看板**、**你的網頁外觀設定**。每個 agent 的每一項可以跟預設，或設成 **允許**／**關閉**。關閉立即生效：agent 的呼叫會被拒絕並說明原因，它的工具清單也會拿掉這些工具；打開（不論是單一 agent 或透過預設）要先確認，拿到任務看板的 agent 會收到怎麼開始的通知。新的 fleet（由 `agend init`、`agend quickstart` 或設定頁建立）一開始任務看板是關閉的：它的 fleet.yaml 會寫著 `defaults.dashboard.task_board: false`。在預設值（或單一 agent）勾選 **任務看板** 即可打開。既有的 fleet 維持原樣：未設定代表允許。`fleet.yaml` 的欄位是 `dashboard`（[設定說明](configuration.zh-TW.md#instancesname)）。
- **新增 agent** 和側欄的 **+**（新增 instance）是同一個對話框。
- **登入**（在 agent 清單下方，#2233）列出這台機器上每個 backend 的登入，以及代理使用的每個憑證設定檔和它們的狀態。**登入**（或 **重新登入**）會開啟登入對話框；dashboard 無法執行的登入會顯示要在機器上執行的指令，尚未安裝的則顯示安裝指令。見[遠端登入 CLI](features.zh-TW.md#遠端登入-clilogin)。
- **Bot token 在這裡輸入，不用編輯 `.env`。** **新增連線** 和 **設定精靈** 會用密碼欄位請你貼上 bot 的 token；**驗證** 會向 Telegram 或 Discord 確認這是哪個 bot，並在儲存前顯示（「這是 @your_bot。」）。
  - token 存在這台電腦的 `~/.agend/.env`，名稱由 AgEnD 自動產生（`AGEND_DISCORD_TOKEN`、`AGEND_DISCORD_2_TOKEN`、`AGEND_TELEGRAM_PERSONA1_TOKEN`…）。**進階** 會以唯讀方式顯示，給自行管理 `.env` 的人參考；不需要任何人手動輸入。
  - 兩者一律 **新增** 連線。同一平台的第二個 bot（即使在同一個伺服器）會成為自己的連線（`discord-2`…），絕不會取代既有的連線。要換某條連線的 token，請開它的 **設定** → **進階** → **更換**。
  - 連線會顯示 **已設定 token**（執行中時附上 bot 名稱）或 **缺少 token**，永遠不顯示 token 本身。當 AgEnD 已經在執行其他連線、且 fleet 層級沒有其他變更時，新的連線會在套用後立刻啟動，不需要重新啟動；套用卡片會顯示「正在啟動新連線」。fleet 的第一條連線，或修改既有連線，仍會出現 **重新啟動 AgEnD**。在沒有執行中的連線上更換 token 也會這樣直接啟動它；若是第一條連線，則要等那次重新啟動。
- **需要 fleet 管理員確認的變更**（見[確認敏感變更](#確認敏感變更)）會在任何面板顯示一張卡片：變更內容、剩餘時間，以及 **撤回**。套用會等它；確認後其餘部分繼續，若被拒絕或逾時，之後的變更都不會套用，並重新暫存（bot token 需要重新輸入）。

### App 圖示

瀏覽器分頁上 dashboard 的圖，以及手機「加入主畫面」捷徑的圖示。**設定 → 網頁外觀 → 外觀 → App 圖示**：

- **選擇圖片…** 選一張正方形的圖：PNG、JPG 或 WebP，512 × 512 以上。比較寬或比較高的圖會取中間的正方形；比較小的會被放大（卡片會提醒你，因為可能不夠清晰）。按 **使用這個圖示** 之前會先看到新圖示；**取消** 會保留原本的。
- **恢復預設** 換回 AgEnD 圖示。
- 只有管理者的 session 能更換。唯讀的 session 看得到；訪客和公開連結沒有這張卡片。
- **誰看得到：** 能打開 dashboard 網址的人都看得到——登入頁和公開連結顯示的是同一個圖示，就像原本的 AgEnD 圖示一樣。請不要用私人照片。
- **iPhone 或 iPad** 的主畫面會保留加入捷徑當時的圖示：要看到新圖，請刪掉捷徑再重新加入。Android 和電腦上的瀏覽器下次造訪時就會換。
- Dashboard 有 web app manifest（`/manifest.webmanifest`：名稱 AgEnD、standalone、192 和 512 px 的圖示），所以在 Android 或電腦上把它安裝成 App 也會用同一個圖示。

主機會用這一張圖做出各種尺寸（180 px 的 touch icon、32/48 px 的 favicon、manifest 的 192 和 512 px），存在它的狀態目錄（`web-app-icon/`）。每個圖示網址都帶著圖示的版本，所以一換圖瀏覽器就會拿到新的。

### 識別色

每個 agent 都有一個顏色，讓你在側欄一眼找到它。
- **顏色的來源**，依序是：
  - 有人替它挑的顏色；
  - agent 自己的顏色（主題的 `identity.color`，沒有的話用強調色；在你顯示 agent 主題時才算）；
  - 它自己的 bot 在 Discord 身分組的顏色；
  - 否則是依名稱選出的幾種柔和自動配色之一（兩個 agent 可能同色）。
- **顯示的位置：** 名稱、列左側的色條、圖片外框，可任意組合。預設三者都顯示。有人替 agent 做的選擇優先，其次是 agent 自己的，最後是這台主機的預設。
- **改某個 agent 的顏色：** 在聊天或詳細資料按 **⋯ → 顏色…**，或在 View 的 **編輯個人資料** 按 **顏色…**。
  - 可以從 12 種顏色（淺色與深色都清楚）或自訂色碼中挑選，並選擇顯示位置。
  - **重設** 會回到 agent 的、bot 的或自動的顏色。
  - 透過臨時公開連結也能修改，就和編輯個人資料一樣。
- **這台主機的設定**，在 **設定 → 網頁外觀 → 識別色：**
  - 預設的顯示位置；
  - **關閉顏色**，在這台主機隱藏所有識別色。有人挑過的顏色會保留，重新開啟後就會回來。
- **還原預設值**（設定 → 網頁外觀）：見下方「還原預設值」。

### 自訂 CSS（設定 → 網頁外觀）

**網頁外觀**放的是你自己的樣式表，只套用在你自己的畫面：你登入的每一台裝置都會套用，不會影響別人。它套用在聊天、Fleet、詳細資訊、等你處理、紀錄和 View。

- **不會套用在設定頁。** 設定頁一律以原本的樣子顯示，所以把東西藏起來的樣式表隨時都能改回來。
- **以下地方也不會套用：**
  - 登入頁；
  - 臨時公開連結（那是另一個人，而且進不了設定）；
  - 沒有登入的 `/view` 讀者。
- **儲存並試用。** 儲存後的版本先試用。每一頁都會出現一條提示問 **保留這份自訂 CSS？**，15 秒內按 **保留**，否則會自動還原。分頁被關掉，或 CSS 把提示藏起來，也會還原。
- **由 General 幫你儲存。** 你請 General 修改自訂 CSS 時，那個版本會等你打開 dashboard（最多 10 分鐘；沒打開就直接還原，從未顯示過）。它的 20 秒從顯示在你的畫面上那一刻才開始算，所以把提示藏起來的 CSS 仍會還原。在聊天裡跟 General 說「保留」：如果這句話在 20 秒之後才送到，General 會把那個版本重新套用。如果你在這之間又在自己的頁面存了另一個版本，General 不會改去保留那一個，而是先問你要哪一個。
- **可以寫什麼。** 最多 64 KiB，而且絕不從網路載入任何東西：
  - 不接受 `@import`、`@namespace`、`@charset`。
  - 不接受任何 `url()` 或 `src()`，只有引用「資源」裡檔案的 `url("asset:<id>")` 例外。
  - 不接受 `image-set()`、`cross-fade()`、`element()`、`paint()`、`expression()`、`behavior`、`-moz-binding`、`javascript:` 和 `vbscript:`。
  - 儲存時會說明拒絕的原因。實際送出的是依你寫的內容重新整理過的乾淨版本，不會是原本上傳的位元組。
- **資源。** PNG、WebP、JPEG、GIF 或 WOFF2：最多 16 個檔案，合計 1 MiB。會移除 GPS 位置等中繼資料。**複製引用** 會給你可以貼上的 `url("asset:<id>")`。
- **先前的版本。** 保留最近五版，按 **改用這版** 即可換回。**關閉（所有裝置）** 會回到原本的樣子。
- **這台裝置。** **在這台裝置關閉自訂 CSS** 只影響這個瀏覽器，所以手機版面可以在手機上修。在任何頁面網址最後加上 `?safe=1`，這一次載入就不套用自訂 CSS。

### Agent 的主題

Agent 可以替自己的網頁聊天設定外觀，包括淺色與深色的顏色、強調色、對話泡泡的圓角與外框、字型、背景圖片、自己的圖片，以及工作中顯示的文字。它用 `set_web_theme`、`set_web_theme_asset`、`reset_web_theme` 這幾個工具設定（在 shell 裡是 `agend-agent theme`）。

- **它自己的聊天，也可以是整個頁面（#2196）。** 主題會改變該 agent 的聊天面板，以及它在側欄的圖片與外框顏色。agent 也可以在**它的聊天、View、紀錄或詳細資訊開著時，把配色用在整個頁面**：側欄、頁首和用量欄（手機上是抽屜、頁首和下方分頁）。打開另一個 agent，頁面就換成它的樣子；打開沒有頁面配色的 agent 或其他頁面，頁面就回到你自己的樣子。頁首跟著頁面走：沒有頁面配色時，即使下面的聊天有主題，頁首也是你自己的樣子。
  - **只有顏色。** 不會改字型、圖片、CSS 或版面，所以切換時什麼都不會移動。AgEnD 的狀態顏色（等你處理的數字、狀態圓點、錯誤、焦點框）永遠不會被改；文字、強調色和這些狀態顏色在它的側欄與背景上讀不清楚的頁面配色會被拒絕。
  - **你的選擇優先。** 聊天或詳細資訊的 **⋯ → 頁面配色**：*依 agent 的設定*（預設）、*整個頁面*或*只在它的聊天*——跟你替 agent 選的顏色一樣，存在這台主機上。
  - 設定頁和其他 agent 的聊天都不受影響。
- **給你自己的自訂 CSS（#2199）。** agent 的聊天、View、紀錄或詳細資訊開著時，`<body>` 會帶有 `data-agent="<它的 instance 名稱>"`，其他頁面則沒有。它跟頁面同一刻切換，不論是否顯示 agent 的主題，所以你的樣式表可以跟著你正在看的 agent 變化——例如 `body[data-agent="atlas"] { --bg-sidebar: #e2f0ed; }`。
- **檢查兩次。** 主機只儲存通過檢查的值（固定的顏色、字型與外框選項，以及在兩種模式下都看得清楚的文字）。頁面繪製前會再檢查一次，其餘的一律捨棄。
- **圖片留在主機上。** 圖片由儀表板本身提供，已移除中繼資料，不會從網路載入。
- **由人決定。** 在聊天或「詳細資料」的 **⋯** 選單裡：
  - **鎖定主題** 讓 agent 不能再改；**解除主題鎖定** 則恢復。
  - **重設主題…** 會移除主題，並保留鎖定。
  - 兩者都需要已登入的管理者，臨時公開連結上也不會出現。
- **你的開關。** **設定 → 網頁外觀 → 顯示 agent 的主題、效果與小工具** 可在你所有的裝置上關閉主題。關閉後每個聊天看起來都一樣，圖片與外框顏色也會換回各自 bot 的。網址加上 `?safe=1` 載入時也不顯示主題。
- **減少動態效果。** 即使系統要求減少動態效果，環境效果仍會播放。若要在某台裝置上讓環境效果保持靜止，請勾選該開關下方的 **效果：跟隨系統的「減少動態效果」設定**（只套用於這台裝置；預設關閉）。同一個裝置偏好也控制 Canvas Worker 效果；只有系統要求不會讓它們暫停。
- **限制。** Agent 每次變更至少相隔 30 秒，每小時最多 10 次。上傳（圖片、效果、mod）不計次數；每張圖片的大小限制與 agent 的圖片配額仍然適用。你在個人資料替 agent 上傳的圖片優先於主題的圖片。在 `fleet.yaml` 設定 `web.themes.agent_edit: false` 會拒絕所有 agent 的變更。

### 身分卡

每個 agent 都可以有一張身分卡：肖像、橫幅、一行標語與一段簡介。

- **誰來設定。** Agent 用 `set_web_theme` 設定自己的（`card.tagline`、`card.bio`，以及 `card.portrait`／`card.banner`，指向用 `set_web_theme_asset` 為這兩個欄位上傳的圖片）。人在 View 的 **編輯個人資料** 設定自己的。**人設定的欄位優先於 agent 的，逐欄比較**：欄位留空就顯示 agent 的。
- **顯示位置。** Agent **詳細資料** 的最上方；**View** 的終端下方；以及 agent 聊天的標題正下方。聊天中的卡片預設隱藏，用聊天標題列上的 **卡片按鈕** 顯示（在 ⋯ 旁邊，訪客與公開連結也有；卡片顯示時按鈕會反白）。按下會開一個小選單，有兩個勾選項：**顯示卡片**，以及 **顯示小圖和介紹**。取消勾選第二項只留下橫幅（以及下方 agent 的小工具列），節省高度；卡片隱藏時、或卡片沒有橫幅時，第二項會變灰。卡片本身不放任何按鈕；顯示時橫幅緊貼在標題下方。兩個選擇都只保存在這台裝置上。
- **大小。** 每張卡片都有 **小／中／大**。**設定 → 網頁外觀 → 身分卡** 設定你所有裝置上每張卡片的大小，卡片上自己的控制可以單獨設定那張卡片。透過臨時公開連結時，大小只保存在那台裝置上。
- **文字只是文字。** 標語與簡介絕不會成為標記或連結。圖片由儀表板本身提供，並已移除 GPS 等中繼資料。
- **橫幅的裁切與焦點。** 橫幅會配合每張卡片裁切。畫出來絕不會寬於 **5 : 1**（螢幕更寬時置中，兩側是它自己的模糊延伸），也不會窄於 **9 : 4**（會裁掉左右兩側）。因此在任何螢幕與版面，每張卡片都看得到 **安全範圍**：1600×600 橫幅（預設上限）中間 **84% 的寬度** 與 **53% 的高度**，也就是 **1350×320 的範圍**。在編輯個人資料的 **橫幅焦點** 可以把它往上或往下移：拖動滑桿，預覽會顯示安全範圍（虛線）與手機上的中卡片範圍（黃色）。Agent 用 `card.bannerFocus`（0 頂端 … 100 底部）設定，General 用 `set_web_settings { what: "banner_focus" }`；人的設定優先。請把臉與文字放在安全範圍內。
- **太大的圖片。** 編輯個人資料會提議把超過限制的肖像或橫幅縮小（「這張圖片是 3000×4000，會縮小為 1024×1365。」）。伺服器會像檢查任何上傳一樣檢查結果。
- **清除卡片** 會移除你的標語、簡介、肖像與橫幅，改顯示 agent 自己的卡片。人按下 **重設主題…** 會移除 agent 的卡片並保留你的。**鎖定主題** 讓 agent 無法變更自己的卡片。
- **透過臨時公開連結** 可以編輯卡片，和個人資料、頭像一樣。主題的重設與鎖定，以及下面的上傳限制，都不能在那裡變更。
- **Agent 怎麼看自己。** `get_web_appearance` 告訴 agent 它現在的樣子：頭像與來源（個人資料、主題、bot、emoji 或首字）、外框顏色、識別色與它的來源（有人挑選的、主題的強調色、自己 bot 的 Discord 身分組顏色，或自動配色）、身分卡的每個欄位（以及是誰設定的）、各模式的主題、是否被鎖定，以及它的限制。`preview_web_appearance` 會把這些畫成每個模式一張 SVG，放在它自己的工作目錄（`.agend/appearance/light.svg`、`dark.svg`），SVG 用到的圖片會另存在旁邊（`avatar.png`、`portrait.png`…），只有它自己的圖片。在 shell 裡用 `agend-agent appearance` 與 `agend-agent appearance preview [light|dark]`。
- **上傳限制：** 見下方「身分卡上傳限制」。

### 身分卡上傳限制

**設定 → 網頁外觀 → 身分卡上傳限制**（或 `fleet.yaml` 的 `web.appearance`）設定任何人可上傳的肖像與橫幅上限，以及每個 agent 可保留的圖片數量。
- 欄位：肖像寬、高（px）與大小（KiB）；橫幅寬、高與大小；每個 agent 的圖片數；每個 agent 的圖片空間（MiB）。每欄都會顯示目前生效的值與允許範圍；留空＝預設值（以灰字顯示）。
- 預設：肖像 1024×1536、1.5 MiB；橫幅 1600×600、768 KiB；每個 agent 8 張、4 MiB。
- 調低立即生效；調高需 fleet admin 確認。限制只影響之後的上傳，已存的圖片不受影響。
- 只有已登入的管理員能在這裡看到並修改；否則請編輯 `fleet.yaml` 的 `web.appearance`。

### 小工具

小工具是由 dashboard 自己繪製的一小塊資訊面板：數字、進度條、一行文字、短清單、彩色標籤、走勢線。放置的人只寫**要顯示什麼**（一段簡短的 JSON 規格）和**數值**——絕不是 HTML、腳本、連結或 CSS。dashboard 用自己的元件、以頁面的顏色繪製，外加一圈細框與 **✦ 標題** 標籤，所以小工具不會被誤認為 AgEnD 的介面，裡面也沒有可以點的東西。

- **位置。** agent 可以在**自己的聊天**放一個（標頭下方的一條，最多 4 項），在**自己的詳細資料頁**放一個（最多 8 項）。你自己的小工具放在**側邊欄**的實例清單下方；agent 不能放在那裡。
- **即時數值。** 除了自己設定的數值，agent 的小工具還可以顯示它自己的狀態、context 使用量與花費，和頁面本來顯示的一樣。你的側邊欄小工具可以顯示 fleet 的計數：工作中、需要你、閒置、已停止。不會為它讀取其他任何資料。
- **agent 怎麼設定。** 用 `set_web_widget` 加上 `slot`（`chat_header` 或 `details`）與 `spec` 放置或替換；只給 `data` 則更新已放置小工具的數值——最多每 10 秒一次、每小時 180 次，和主題變更分開計算。`remove_web_widget` 移除它。在 shell 裡用 `agend-agent widget set|data|remove`。
- **由人決定。** **鎖定主題** 也會讓 agent 無法變更自己的小工具。聊天或詳細資料的 **⋯** 選單有 **移除聊天標頭的小工具** 與 **移除詳細資料頁的小工具**。由人放置的小工具（來自 mod）會接受 agent 給的數值，但 agent 無法替換或移除它。**重設主題…** 會移除 agent 的小工具。
- **你的側邊欄小工具。** **設定 → 網頁外觀 → 你的側邊欄小工具** 接受 JSON 格式的規格與數值，儲存前會顯示預覽並指出問題；**從範例開始** 會填入 fleet 的計數。它和你的偏好一起保存在你所有的裝置上，透過臨時公開連結或加上 `?safe=1` 時都不會顯示。
- **你的開關** 會連同主題一起隱藏 agent 的小工具。臨時公開連結會顯示 agent 的小工具，和身分卡一樣。

### 環境效果

環境效果是 agent 放在自己聊天中的輕量裝飾：飄落的花瓣、雪花、上升的燈籠、閃爍的星星，或在你點擊處散開的符號。agent 只送出資料（一個預設樣式、最多 4 個符號或小圖片、顏色與幾個數值），由儀表板繪製。不會執行任何 agent 程式碼，因此不需要同意，預設就會播放。

- **位置。** 在該 agent 聊天的訊息後方，絕不蓋住輸入區或標頭。它不會攔截點擊、觸控或焦點：點擊星星只會在訊息上方短暫出現，你的點擊仍會落在下方的元素上。
- **各一個。** 每個聊天最多一個循環效果（飄落、上升或閃爍）與一個點擊效果。
- **agent 怎麼設定。** 用 `set_web_ambient` 指定 `preset`（`fall`、`rise`、`twinkle`、`burst-on-click`）與 `glyphs`；`clear_web_ambient` 移除。它算一次主題變更：同樣的頻率限制，**鎖定主題** 也會擋下它。
- **由人決定。** 聊天的 **⋯** 選單有 **清除環境效果** 與 **清除點擊效果**；**重設主題…** 會兩者都清除。可請 General 為某個 agent 設定（設定後屬於你，agent 不能再改）。
- **沒有顯示時，** 聊天的 **⋯** 選單會說明原因，選擇該行即在原地修正（臨時公開連結上也可以）：**顯示 agent 的主題、效果與小工具** 已關閉（會將它開啟）；**效果：跟隨系統的「減少動態效果」設定** 已開啟且系統要求減少動態效果（這台裝置不再跟隨）；或頁面以 `?safe=1` 開啟（會離開安全模式）。
- **減少動態效果。** 系統要求減少動態效果、但環境效果仍在播放時，聊天會在那台裝置上提示一次（「你的系統要求減少動態效果；效果目前開著。」），並附 **在這裡關閉**，按下即為那台裝置勾選 **效果：跟隨系統的「減少動態效果」設定**。
- **成本。** 最多 24 個循環符號，同時最多 3 次各 16 個的點擊爆發，只用 transform 與 opacity 動畫。分頁隱藏時會暫停。
- **臨時公開連結** 也會顯示，依檢視者自己的開關，和 agent 的主題與小工具一樣。
- **Mod** 會攜帶它（匯入或匯出時的 **環境效果**）。

### Mod

Mod 是一個檔案 `<name>-<version>.agendmod.json`，帶著一套外觀：agent 的主題與圖片、身分卡文字（標語與簡介，絕不含卡片圖片）、小工具、效果，以及自訂 CSS。它是最多 8 MiB 的純 JSON，沒有 zip，也不需要解開。在 **設定 → 網頁外觀 → Mod** 匯入、列出、下載、解除安裝與匯出。

- **匯入分兩步。**
  - **匯入 mod 檔案…** 會檢查整個檔案，在任何變更之前列出全部內容：主題的顏色與圖片、身分卡文字、每個小工具的樣子、每個效果繪製的位置與接收的事件，以及**完整的自訂 CSS**。作者標示為未經驗證。
  - 勾選你要的部分、選擇要套用到哪個 agent，再按 **安裝**。只有勾選的部分會一次套用；任何一部分失敗就什麼都不變。
- **自訂 CSS 永遠不會預先勾選。** 它會標示「這是檔案裡的自訂 CSS——開啟前請先讀過」。勾選後它會成為你自己的 CSS 並進入試用：按 **保留**，否則 15 秒後還原。
- **套用到哪裡。** 主題、身分卡文字與 agent 的小工具會套用到你選的 agent，視為人的選擇（**鎖定主題** 與 **重設主題…** 照常可用）。側邊欄小工具會成為你的。自訂 CSS 一如既往只屬於你。
- **檢查很嚴格。** 每個檔案都要列出 SHA-256，並且剛好被一個部分使用。路徑一律小寫、不含 `..`。每個部分都依它自己的功能檢查：主題對比、圖片類型與大小、小工具規格、自訂 CSS 規則，以及效果。
- **版本。** Mod 的身分就是它的內容。匯入已安裝名稱的另一個版本時，會詢問是否 **取代**。最多可安裝 20 個 mod、共 64 MiB。
- **下載** 會取回已安裝 mod 的檔案。檔案是完整的 bundle，連匯入時沒選的效果也在裡面。所以帶有效果的檔案，只有能分享其中每個效果的人能下載：自己擁有內容相同的效果，或是有人共用的效果。沒有效果的檔案，任何管理員都能下載。
- **解除安裝** 會把 mod 從清單移除，它的效果也會離開你的效果庫，除非還有東西在使用。它已套用的外觀會保留，直到你重設。
- **匯出 mod** 會用目前生效的外觀做成檔案：某個 agent 的主題與圖片和它放置的效果、身分卡文字與小工具、你的側邊欄小工具，以及你的自訂 CSS 與它用到的檔案。匯出的檔案可以原樣匯入。**只有你可以帶走的效果才會被包含**：你自己的，以及有人共用的。別人放在那個 agent 身上的私人效果不會被帶走，頁面會告訴你略過了幾個。Agent 自己的匯出（`export_web_mod`）對 agent 也套用同樣的規則。
- **Agent 的 mod。** Agent 可以把自己的外觀匯出成 mod 檔案（`export_web_mod`，寫在它的工作目錄），也可以提議一個 mod 給你檢視（`propose_web_mod`）。提議會出現在 **Agent 提議的 mod**：按 **檢視** 進入同樣的兩步匯入，按 **略過** 則捨棄。Agent 提議的 mod 永遠不能帶自訂 CSS，agent 也永遠不能匯入。
- Mod 裡的**效果**需要效果庫（見下方「效果」）。效果庫無法使用時，帶有效果的 mod 會被拒絕（`effects_unavailable`）。
- Mod 是已登入的人才能做的事，或在你要求時由 General 代勞（見下方）。透過臨時公開連結永遠無法使用，一般 agent 只能提出 mod。

### 請 General 幫你改

General（以及 coordinator 或 full profile 的 instance）可以替你修改 **設定 → 網頁外觀**：在聊天中提出即可。
- **它用的工具：** `get_web_settings` 以白話告訴它每一項設定，`set_web_settings` 經過與網頁相同的檢查修改其中一項。
- **它能改的：** 是否顯示 agent 的主題、識別色與顯示位置、卡片大小、側欄小工具、某個 agent 的顏色、聊天中的效果與你的效果欄位、agent 提出的 mod（會先給你看內容，再只安裝你要的部分），以及還原預設。
- **自訂 CSS：** 維持原本的安全規則。General 可以把它放上試用、保留或還原試用、改用較早儲存的版本，或關閉它。你說喜歡時，它才會保留試用中的版本。
- **只有你能在網頁上做的：** 從你電腦選擇檔案（mod 檔、效果資料夾、CSS 資源、卡片圖片）、這個瀏覽器自己的開關、下載匯出的檔案，以及卡片上傳上限。

### 效果

Canvas Worker 效果是一段在隔離的 Worker 裡執行、用程式畫出來的小動畫，沒有自己的頁面或 DOM。**設定 → 網頁外觀 → 效果** 負責管理；agent 則用 `web-appearance` 工具放置自己的效果。
- **效果庫。** **上傳效果資料夾**：`effect.json` 與 `worker.js`，以及可選的點陣圖素材，處理後最多 1 MiB。每個效果標示 **你持有的副本** 或 **他人與你共享**。**將你的副本共享給這個 fleet 的 agent 與使用者** 讓他們也能使用；**刪除你的副本** 會刪除未使用的副本（其他人的副本會保留）。**Profile history** 顯示它在觀看者頁面上的執行情況——只是回報的觀察，不能證明它的成本。**重新載入效果庫** 會重新讀取。
- **給某個聊天。** 選擇 **聊天**，設定效果的 **參數**，再按 **儲存到這個聊天**（會以這些數值取代該聊天的參數）或 **從這個聊天移除**。
- **你的效果選擇。** **側邊欄**、**頁首**、**頁面**、**區塊** 各選一個效果，各自可 **暫停 / 恢復** 與 **清除**；另有 **游標**，會顯示目前狀態，可 **清除**。選擇會跟隨這個平台的登入身分（Discord 與 Telegram 帳號各自獨立）；以主機操作者身分登入的人共用 **主機共用效果選擇**。
- **播放與 HTML 預覽分開。** CW 使用 dashboard listener 上的 opaque 隔離頁面，不需 HTML 預覽同意、預覽 port 或 localhost。已登入的公開連結／訪客可以播放其可查看聊天中目前放置的效果，不會取得效果庫、個人槽、Try 或 profile 權限。Try 仍須已登入非公開 dashboard 的管理員明確點擊。游標使用靜態圖片。播放不需等待 FPS 校準；顯示、安全模式、隱藏分頁、瀏覽器支援與即時守衛仍適用。僅限本裝置的**效果：跟隨系統的「減少動態效果」設定**預設關閉，與環境效果共用；系統要求本身及節省數據不會阻擋播放。 公開連結／訪客可用聊天頁首的顯示／關閉開關與恢復操作，只影響本瀏覽器，不改主機設定。
- **暫停額度。** 讓頁面變慢的效果會被暫停以維持頁面順暢（「為維持頁面順暢，已暫停效果」）；**恢復** 仍保留三次暫停的上限。
- **你的開關**（**顯示 agent 的主題、效果與小工具**）與 `?safe=1` 會關閉 agent 的效果。
- **沒設定，就不載入。** 在開著的聊天有效果、你選了自己的效果，或 agent 提供「試試看」之前，頁面完全不會載入效果播放器，所以不花任何資源。上述任一情況第一次出現時才會載入，和效果本來開始播放的時間一樣快。環境效果與你的自訂 CSS 不需要它。

放置的效果無法播放時，聊天中持續顯示提示，效果對話框也會指出原因。外觀開關連到**網頁外觀**；
公開檢視者關閉顯示時，可直接按**在這裡開啟效果**，不改主機偏好。隔離框架無法使用時提供重新載入，
不再要求設定 HTML 預覽。聊天會顯示一次跟隨系統減少動態效果的提示；因使用者選擇的動態偏好而停止時，
包括公開連結／訪客都可按**仍然播放效果**，安全模式可按**離開安全模式**。隱藏分頁、瀏覽器支援與安全紀錄各有明確說明。
未知代碼只在本機顯示。Agent 只能看到五分鐘內回報的封閉阻擋原因，不含觀看者識別資料、人數或裝置資訊；
回報不會授予播放權限。

### 還原預設值

**設定 → 網頁外觀 → 還原預設值** 會把這台主機的外觀設定改回預設值。執行前會先詢問，並說明會重設：
- 是否顯示 agent 的主題與效果；
- 卡片大小，以及各張卡片自己的大小；
- 你的側欄小工具；
- 識別色顯示的位置，以及是否關閉顏色；
- 關閉你的自訂 CSS（版本會保留），以及這台裝置上的 CSS 開關。

有人替 agent 挑的顏色、已安裝的 mod、上傳的效果與身分卡上傳限制都不會變。

## 從別的裝置連線

### 手機使用臨時公開連結

管理員在所屬 General 的 `/web` 選 **🌐 Other device (temporary public)**（其他裝置，臨時公開）（Discord 原生 slash；Telegram 輸入指令）。按下前不下載、不開入口。bot 私送連結與登入碼；Discord 私訊失敗時改用須確認送達的 ephemeral 回覆。Telegram 請先私訊 bot 的 `/start`。General 絕不貼登入碼。

啟動期間，你按的那個選單會逐步顯示每個階段與經過秒數，最多每 2 秒更新一次（Telegram 為 3 秒）：

1. 檢查 cloudflared；
2. 下載（已下載 / 總共 MB）；
3. 驗證檔案（固定版本與 SHA256）；
4. 啟動 tunnel；
5. 等待公開網址可以連上；
6. 私送連結給你。

只有需要下載 AgEnD 自己的 cloudflared 時才會出現第 1–3 步；第一次之後只會看到第 4–6 步。失敗的那一步會標出原因，再執行一次 `/web` 即可重試。選單上只有這些文字和數字，不會出現連結或登入碼。

使用 AgEnD 固定版本、checksum 驗證的 cloudflared，不採用 PATH 上的任意程式。Linux 先從 pkg.cloudflare.com 下載，失敗或太慢時改用 GitHub，第 ② 步會標出改用的來源；macOS 只用 GitHub。一次只能開一條 tunnel，與公開 `/login` 終端共用名額。期限固定 **兩小時**，含啟動時間；再次取得連結不延長。Settings 可改為 1–480 分鐘或停用選項；設定[固定網域](named-tunnel.zh-TW.md#更長的期限與重啟後自動重開)時，最多 10080 分鐘或設 `0` 代表不到期，並可選擇重啟後自動重開。私送的關閉按鈕（要按兩下：關閉公開連結，再按確定關閉；按取消會恢復原狀）、新選單、`/web revoke`、到期及 fleet 關閉都會關入口。子行程無法確認停止時封鎖下一條 tunnel，但網頁存取已關閉。

獨立 gateway 只接受當前 tunnel Host 與核准面板路由；`/view` 一律要登入，不暴露 SSE、`/health`、`/agent` 或發碼 API；預覽框架也絕不從它提供（預覽有自己的通道，見 [HTML 預覽](#html-預覽)）。聊天立即輪詢。關閉會撤回該入口的碼與 session，本機 session 另行隔離。Host 只暫時允許，不寫入 `allowed_hosts`。

這是完整 web-admin 權限，含終端、檔案、設定與主機操作。Cloudflare 終止 TLS，能看到流量。不要轉傳連結或碼。公開 session 啟用前，所屬 General 必須在五秒內確認收到 🔐 公開登入通知，即使 `notify_login: false` 也一樣；平台故障可能使登入不可用。公開猜碼也可能耗盡共用登入 breaker。自行設定的 proxy 仍需自己的保護。

### 自行管理連線

server 只回應 `127.0.0.1`。要從別的裝置使用 dashboard，你需要開一條路，並告訴它別人會用哪個名稱連進來。

1. **選一種連線方式**，越前面越安全：
   - **SSH port forward**：`ssh -L 19280:127.0.0.1:19280 <host>`，然後開 `http://localhost:19280`。fleet 這邊什麼都不用改。
   - **Tailscale**（`tailscale serve`）或其他私有網路。
   - **reverse proxy 或 tunnel**（例如 Cloudflare）。建議用有名稱、有存取控制的 tunnel，而不是公開的 Quick Tunnel。
2. **允許這個名稱。** fleet 不認得的 `Host` 一律回 403，這就是擋住 DNS rebinding 的機制。把你的名稱加進去：
   ```yaml
   web:
     allowed_hosts: [dashboard.example.com]
   ```
3. **不讓陌生人看 `/view`**：設定 `web.view_access: session`，因為 `/view` 會顯示 agent 的終端畫面。
4. **使用 HTTPS。** proxy 送出 `X-Forwarded-Proto: https` 時，session cookie 會帶 `Secure`。
5. **即時更新。** 有些路徑傳不了即時串流（Server-Sent Events），例如 Cloudflare **Quick Tunnel**，或會把回應 buffer 起來的 proxy。dashboard 發現串流靜默 15 秒時，會改成每 5 秒抓一次同樣的更新；不會漏掉、也不會重複，串流恢復後會自動切回來。

不論誰連到這個網址，都還是要用你給的登入碼才能登入，而且每次登入都會通知 General。

## 設定

| 設定 | 預設 | 說明 |
|---|---|---|
| `health_port` | `19280` | dashboard 的 port（只聽 `127.0.0.1`） |

## 安全說明

- 任何憑證都不會出現在網址裡：fleet token、登入碼、session 都一樣。
- 已登入的瀏覽器要寫入時，必須同時有 session、每個 session 專屬的 CSRF header，**以及**相符的 `Origin`；光有 cookie 什麼都改不了。用 `X-Agend-Token` header 的腳本不受影響，因為瀏覽器不會自己帶上這個 header。
- 每個面板都帶 Content-Security-Policy：script、樣式、圖片與連線都只限 dashboard 自己的位址。
  - 只會執行頁面自己的 script：每次載入都帶一個新的 nonce，script 不允許 `'unsafe-inline'`，所以被注入到頁面的標記無法執行程式碼。
  - 樣式也一樣：只會套用頁面自己的樣式表（不允許 `'unsafe-inline'`），所以被注入的標記無法加上自己的 inline 樣式（但仍可能套用頁面既有的 class）。

## 遇到問題時

| 你看到 | 原因與處理方式 |
|---|---|
| 經由 proxy 或 tunnel 打開 dashboard 時出現 **403** | 這個 `Host` 沒有被允許：把它加進 `web.allowed_hosts`。 |
| 登入頁說登入碼錯誤 | 登入碼只能用一次、5 分鐘後到期，而且只有最新的那組有效：請重新取得。 |
| 「登入已結束」 | 閒置 48 小時或登入已滿 48 小時（預設值）；公開連結則是 4 小時、閒置 30 分鐘或連結已關閉；或有人執行了 `/web revoke`、**全部登出** 或 `agend web-token rotate`：重新登入即可。 |
| 更新會晚幾秒才出現，沒有即時串流 | 你這條連線傳不了即時串流（或這是公開連結），頁面改成每 5 秒輪詢，紀錄分頁最多可能晚 30 秒：不需要處理，也不會當成問題顯示。 |
| 儲存自訂 CSS 後，頁面怪怪的或有東西被藏起來 | 在網址最後加上 `?safe=1`，就會不套用你的 CSS 地載入。設定 →「網頁外觀」永遠不受它影響：在那裡修正或關閉即可。 |
| `/web` 回覆「disabled」 | 這個 bot 沒有設定任何 fleet admin：把你的使用者加進它的 `allowed_users`。 |
| 在登入頁，瀏覽器的開發者工具顯示 `/auth/session` 有紅色的 **401** | 這是預期行為：頁面會先檢查你是否已經登入，「沒有」就會回 401。不需要處理。 |

### Windows／WSL：Linux 有回應，Windows 卻連不到 dashboard

如果更新後從 Windows 打不開 dashboard，先關閉 dashboard 分頁，停止重連流量。用明確的 timeout 比較同一個設定中的 port（下例為 19280）：

```sh
# WSL 內
curl --noproxy '*' --max-time 5 -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:19280/health
```

```powershell
# Windows
curl.exe --noproxy "*" --max-time 5 -sS -o NUL -w "%{http_code}\n" http://127.0.0.1:19280/health
```

Linux 回任何 HTTP 狀態碼（**200**，或 fleet 狀態不佳時的 **503**）、Windows 回 **000**，表示可能是轉送或連線層的問題；只有空白頁還不能下這個結論。保留結果與 Windows／WSL 版本。反覆重啟 fleet 不一定能修復轉送層。

AgEnD 在停機時結束 SSE response，最多等一秒讓一般 HTTP 工作完成，再關閉其餘自己持有的 socket。新版頁面收到停機提示後等 10–15 秒才重連，之後沿用原本有上限的 backoff。更新前已載入的頁面，重新整理前仍用舊的重連規則。這能減少未結束的 stream 和重連流量，不能保證修復卡住的 Windows relay。Listener 仍在停機尾端才關閉，但 replacement 會先啟動 instances 才綁 HTTP，所以整次中斷可能超過一秒。突然退出時無法送出提示。

若要在不中斷 fleet 的情況下恢復連線，可使用**已經可用、可信任的 WSL SSH 路徑**，繞過 Windows localhost 轉送。例如在 Windows 執行，把 `WSL_SSH_HOST` 換成那個既有的 SSH 目的地：

```powershell
ssh -N -L 127.0.0.1:19290:127.0.0.1:19280 WSL_SSH_HOST
```

打開 `http://127.0.0.1:19290/signin`，用 `/web` 或 `agend web` 取得新的登入碼。（19290 只是一個空的 port：不要用預覽用的 19281；在這個替代位址上 HTML 預覽會關閉。）替代 port 只綁 Windows loopback，原本的登入、Host 與 same-origin 檢查仍有效。用完關閉 tunnel。已明確核准、仍有效的公開連結也是一個選項。不要為了這個 workaround 把本機 listener 開放到 LAN，或關閉認證。沒有替代路徑時，可繼續使用 chat，請操作者安排維護；這裡沒有保證不中斷工作就能重設 relay 的方法。

預防方面，WSL 內有 `wslinfo --networking-mode` 時，可用它確認目前模式；沒有輸出就視為 **unknown**。Microsoft 的文件說明 NAT 透過 wslrelay 轉送 localhost，而 mirrored 使用不同架構。在支援的 Windows 11 22H2+ 主機，操作者可自行選擇在 `%USERPROFILE%\.wslconfig` 既有的 `[wsl2]` 段落設定 `networkingMode=mirrored`。這會影響所有 WSL2 distributions 與 firewall 行為，要在**預先安排的 WSL 重啟**後才生效，重啟會中斷其中的工作。AgEnD 不改 Windows 設定，也不重啟 WSL。Mirrored 是選項，不是保證修復。

來源：[Microsoft networking](https://learn.microsoft.com/en-us/windows/wsl/networking#mirrored-mode-networking)、[WSL 設定](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)、[WSL 轉送架構](https://github.com/microsoft/WSL/blob/master/doc/docs/technical-documentation/localhost.md)。調查與限制：[#1738](https://github.com/songsid/AgEnD/issues/1738)。

### 確認敏感變更

變更存取／F／C 名單、secret、connection 目的地／順序、公開曝光、控制類 instance 設定，或放寬網頁設定（延長本機 session 或閒置時間、開啟瀏覽器終端機或增加分鐘數）會回傳 `202 pending_confirmation`。請求人可用 `GET /api/settings/pending[/:id]` 列出或輪詢，並用 `DELETE /api/settings/pending/:id` 撤回尚未被認領的請求；其他 session 會得到 404。輪詢屬被動讀取，不延長登入有效期；`remaining_ms` 用來倒數，顯示的時間戳不是授權期限。

Fleet admin 在 General 核對遮蔽 secret 的 diff 後確認。Chat 不可用時執行本機命令 `agend settings confirm <id>`；Reject、到期或 session 撤銷都不套用變更。Apply 重試須沿用相同的 `Idempotency-Key` 與 body，回到同一個請求。終態失敗後應重新檢查並用新 key 提出；secret 必須重新輸入。在網頁 app 中，等待確認的請求會在任何面板顯示成一張卡片，附倒數時間和 **撤回**（見 [`/settings`](#settings)）。

**哪個 bot 的 admin 能確認？** 既有連線的變更需要每個受影響連線的 admin
資格；agent 搬移時包含原、新兩個 owner。共用 token 需要所有使用該環境變數的
連線 admin 資格。Fleet 層級變更與新增連線，需要設定中 primary General 所屬 bot
的 admin；primary bot 沒有 General 時，採第一個設定的 General。混合變更需要
同時滿足兩類權限。提示移到另一個 General，不會把確認權限交給該 bot 的 admin；
套用前會重新檢查 admin 資格。跨平台或目標不明時，必須用 host CLI 確認。
首次 Setup 仍由 host 確認。

**這個瀏覽器已通過網頁驗證時，你按的套用本身就是確認（#2170）。** 按過 **授權這個瀏覽器**（見上方
「聊天」一節）後，原本要等聊天卡片的變更，在以下條件都成立時由你的套用直接確認：你的帳號和這次變更影響的
連線在同一個平台，而且是每一個受影響連線的 fleet admin（上面的規則）；變更範圍是已知的；也有一個 General 原本能收到
聊天卡片（已連線、在那個平台、不是這次變更影響的連線）。卡片會顯示「由你的帳號確認」，那個 General 會收到一則
純文字通知：誰從網頁確認、來源、請求人、摘要與結果。變更執行時所有檢查都會再做一次：授權被撤銷或到期、你已登出，
你已不是那些連線的 admin，或已沒有能收到聊天卡片的 General（斷線、agent 停止），就不會套用（變更以 stale 結束）。其他情況都和以前一樣等聊天或 host 確認：未通過網頁
驗證的瀏覽器、訪客、公開連結、host 自己的 `agend web` session、其他平台的帳號，或需要 host CLI 確認的變更。
請了解它依據的是什麼：授權瀏覽器是在私訊裡做的**一次**確認，對這個 session 一直有效，直到被撤銷、到期或登出——
不是每次套用都重新確認。任何人用這個已驗證且仍登入的瀏覽器（無人看管的瀏覽器，或複製走的 session cookie），
都能用同樣方式確認這類變更。離開瀏覽器時請登出，或撤銷授權（設定 → 網頁 → **撤銷網頁授權**，或私訊卡片上的 **不是我**）。

首次 Setup 同樣回傳 pending 請求。在 host 確認後，還要明確按 **Start AgEnD**。Pending 回應、舊的成功 commit 或已改動的設定，都不能將 setup listener 交給 fleet。
