# Personal effects in the app-owned runtime (#1629 B2)

The session-only app bridge now connects four personal regions to the same pool as Chat. It constructs no second loader, registry, safety provider or profiler. The later [host cursor integration](1629-effect-cursor-mount.md) reuses this app episode and metadata lane; Try still needs its own explicit authorization/preview contribution.

## Targets and lifetime

After the core claims the Window episode, the bridge owns one reviewed region helper. Only its fixed resolver receives a closed slot, authoritative manifest and fresh stock proof against the registry's exact root. Header/sidebar are actual stock DOM; page/box are empty hidden geometry references. Unsupported target setup contributes nothing and cannot break Chat. Auth end, pagehide, a changed document and bridge teardown independently release the helper, subscriptions and core; a dead episode requires reload.

A coalesced microtask after mutations inside `#app` reprojects late panel commits, including Fleet/Settings where there is no Chat lease. Body-level effect roots/frames and CSSOM geometry writes never schedule that hook themselves. Existing window/device events update viewport references; the registry separately observes/revalidates live target geometry and paint. Closed inventory/neutral ordering still refuses unsupported panels and overlays. Human choices keep the approved foreground exemption; agent foreground remains denied while owner CSS is on/loading/unknown.

## Authoritative changes and controls

Preference revision changes invalidate only the personal source, and theme revisions only Chat placements. Simultaneous changes do both. Explicit Settings Reload, a successful preference Save (including saved-but-refresh-failed), and catalog refresh invalidate runtime metadata independently. Settings GET completion never frees or supplies the runtime's physically held metadata lane. Runtime responses never optimistically rewrite saved choices.

Settings subscribes to the app owner for current per-slot status and local Pause/Resume. A failed runtime resource is shown as unavailable while the saved id stays clearable through the existing authorized preference write. Resume uses the existing safety path and keeps the three-pauses history. Per-platform buckets and the visibly shared web-only operator bucket are unchanged. Cursor has no Worker descriptor or Pause/Resume controls; the later host cursor integration adds status/Clear separately.

Unshare still takes effect at the next resource authorization; it does not promise to erase already-running code or force a new backend revision/poll. A later authoritative read or retarget can discover unavailable state. The stored reference persists until Clear. Personal dispatch never borrows an instance's retained-runtime permission.

## Evidence, risk and rollback

Unit controls model the bridge, stores and target factory; actual service/registry/frame/Worker evidence comes from `scripts/manual/effect-owner-mount-1629.mts` using the real Shell/Fleet/Chat/Settings producers and built local preview/service/library. Its synthetic session and private stores are not a live fleet or account. Linux WebKit is not real Safari.

Callbacks and DOM commits add lifecycle risk; all unknown setup/geometry remains no contribution. A physically stuck request intentionally occupies its shared reservation. Rollback withdraws the resolver, region-helper asset and UI runtime controls together; Chat keeps its existing app-owned pool. Stored selections, claims and profile history need no migration.
