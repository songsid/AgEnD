# The directory writer selects its mounted owner

This follows #3829. It composes the private source and singleton writer provider for an already valid canonical role document. It does not register role cutover, change the directory HTTP controller, or enable an auxiliary administrator's mounted Save journey. Full S-129 remains open.

The actual server factory's directory decision now produces callback-local proofs. The same factory-owned database, transport and persisted role clock are supplied to the management authority's explicit decision assertion. Ordinary management still uses its strict ordinary reader. The source publishes the exact decision getter only for a strict role document; legacy settings sources continue to omit it. During its own SQL generation rebind, the existing decision-owned policy basis remains the source of retained group references. No ambient generation exception or alternate decision is introduced.

`HubRuntime.directoryAdministration()` selects only the current running mount. The ordinary settings getter may fall back to cold settings for configured-root repair, but this role-writer selector never does. It refuses stopped, held and off recovery generations, a different physical completion participant, and changes to mount identity, admission tickets, methods or proof getter observed during synchronous callbacks. Both current checks require exactly `true`, and ownership is checked after them. Source errors return no admission.

The returned packet keeps the actual decision and directory identities, a copied frozen root identity, the exact source image and epoch, and the exact callback-local getter. It omits service credentials, candidate configuration and directory group lists. This packet selects a participant; it does not grant authority. The existing writer still requires the session's opaque named administrator witness, the exact sealed root and decision, current source image, request and session, and its final proof-owned time sample in the same SQL transaction.

FleetManager passes a dynamic provider into its existing singleton sealed-settings writer. It reads the current runtime each time and returns no packet while stopping or while Hub effects are disabled. It creates neither a second writer nor another runtime. Existing prepared witnesses remain bound to their original source and decision by the writer's current checks.

Verification includes real initialized sealed homes, the actual factory and SQLite transport, loopback HTTPS sign-in with fictional directory answers, and direct invocation of the existing writer using the real session's named proof. Both the configured root and an auxiliary Administrator preserve the acting identity; the configured root is not replaced, and old sessions retire at commit. A canonical-row change refuses before a decision. The legacy host-owner control still saves. Inert runtime boundaries separately exercise current owner, cold/recovery, method, epoch and secret-projection controls. FleetManager's test uses a recorder runtime with real singleton writer construction; it does not launch agents.

These tests do not cover candidate-directory authentication, preparation-only recent-authentication or session rotation, mounted HTTP Save, successor response release, a browser, containers, a real directory or accounts. Those adapters remain later work. This slice changes no user-facing flow, so the built-in Hub skill needs no update. Parent-first plain alpha sync, conflict review and exact-head CI/readiness are still required. Before controller activation, rollback is to leave the later controller integration uncomposed; any already committed directory operation still uses the existing forward recovery.
