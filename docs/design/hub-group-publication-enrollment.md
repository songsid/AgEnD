# Publication enrollment

This [#3298](https://github.com/songsid/AgEnD/issues/3298) step adds the catalog caller for [prepared group enrollment](hub-group-action-permits.md), superseding its earlier note that publication wiring is still pending. Pairing has its own enrollment slice. The complete confirmed control and all caller gates remain prerequisites for exposing activation; no editor capability or enable route is added here.

The receiver validates and copies the complete snapshot, immutable owner and link callback before any directory await. An exact catalog revision/digest retry is idempotent without a new lookup. Withdrawals, freezes and unchanged exact published bindings remain narrowing or metadata operations and do not require another group allowance. A new effectively published binding needs a fresh permit for the current fleet plus a prepared allowance for each new or revised exposure. Existing manual fleet provenance does not grant permission to publish a new agent. Missing, suspended, revoked or retargeted fleet bindings refuse. Never-enabled/legacy policy needs no membership read or new provenance.

Manual publication is exact-revision grandfathering. A revised publication requires new group provenance; a withdrawn manual revision cannot silently revive by reusing its old provenance. The member must publish a newly consented revision. A same-revision Hub freeze remains frozen; only a new revision with current permission can become visible again. Existing owner grants, grant-revision checks and one-time local publish consent remain independent requirements.

All directory work precedes SQL. The catalog transaction rechecks the complete prior cursor/material image and current link/fleet/policy permits, performs the existing snapshot writes, then records the expected result of those owned writes before invoking extension audit callbacks. It commits all prepared provenance and required registration/snapshot audit in that same transaction. Final checks compare actual catalog material, exact fleet credentials/generation/owner and lifecycle permits after the audits; a stale or reentrant change rolls the batch back. A failure on any publication cannot leave another one partially published or enrolled. A group refusal still applies the valid narrowing part in a separate required-audit transaction: absent agents are withdrawn, explicit withdrawals/freezes reduce the previous exact material, their grants are revoked and rooms closed. Refused publications and all their new provenance remain unchanged; the catalog cursor is not advanced, so a later complete snapshot can retry. The captured current link, original ordinary fleet, prior/result material and final grant/room closure are rechecked; stale/malformed consent or failed required audit cannot use this narrowing path. Source-frame request IDs correlate allowance, registration and snapshot evidence.

The receiver awaits publication completion before pruning quota or treating the frame as handled. Group refusal stays bounded as denied/unavailable; directory details do not reach the peer. Unknown facts never broaden publications or advance the cursor; an independent owner withdrawal still narrows as described above. This is not an eligibility cache or automatic resumption mechanism.

Tests use real SQLite, policy/provenance and hash-chain audit with inert directory facts. A separate owned TLS/WSS rig uses real pairing, member profile, member client, S1 receiver and S3 unit of work: an allowed frame publishes with provenance, then an unknown-membership revision refuses while the prior publication remains. The people and directory are fake; this is not a real AD, account, native-host, browser/editor or pilot claim. All listeners, clients and scratch state belong to the fixtures and are closed afterwards.

There is no new schema. Rollback before activation is a code revert. Once activation is delivered, its documented full-stack prerequisites and matching-state rollback rules still apply; this slice does not bypass them.
