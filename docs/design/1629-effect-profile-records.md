# Reported host-budget profiles (#1629 B2)

These are **unmounted** foundations: the per-owned-mount browser collector (`effect-profiles.js`) and the host's closed codec/store (`web-effect-profiles.ts`). No page imports the collector, no HTTP write route or agent profile writer is enabled, and `profile_web_effect` retains its explicit unavailable adapter until the authenticated integration lands. A profile is diagnostic data, never an admission baseline, safety receipt, consent proof or permission.

## What is measured

The registry's real `EffectBudget` produces host-observed two-second windows after warmup. A collector binds the exact host key, immutable effect id and device class. Wrong ownership, unknown fields, invalid clocks, a changed pre-effect floor or invalid snapshots revoke that collector. A null warmup window yields no report. Only a real `poll()` observation writes `metrics.at` from the host monotonic clock. `frame`, `gates`, `loaded` and `stop` retain that timestamp. The collector accepts strictly newer windows at least one second apart; repeated or delayed old snapshots never add samples or renew freshness. A paused duplicate may update the last verdict/reason only. Only the latest 120 windows are retained. A report older than five seconds since its observation (not its callback receipt) cannot be refreshed as a new observation. Disposal prevents stale reporting.

Profiles use nearest-rank p50/p10 of observed **window FPS**, p95 of known host long-task milliseconds per second, and p95 of known attributed long-task milliseconds per second. These are quantiles of the observed windows, not individual-task durations or private animation-frame timings. The sampled pre-effect comparison floor is retained. The last host-observed iframe load duration is nullable.

Missing task APIs or frame attribution remain null/unknown. The report includes both the all-host and attributed sample counts. Each task quantile uses its own known subset: an attributed p95 can exceed the all-host p95 when their coverage differs. `observed` means there is at least one attributed sample, not complete coverage. No RTT/lag/pong, Worker FPS/CPU/GPU/memory, text, message, instance name, person, URL or arbitrary string enters the record. There is still exactly one ready-only inbound frame channel; this collector is not a frame-message handler.

The verdict is the last reported host budget (or the human device's sticky-off state), not verified isolated effect cost or ongoing Worker health. Unrelated host load can conservatively pause a light effect. A browser owner can forge a report; server persistence cannot prove native observations. All stored records therefore carry the host-owned label `source: "reported_host"` and server receipt time, and are never used to admit, resume or clear safety state.

## Persistence and ingress contract

`WebEffectProfiles` constructs without I/O. `read(id)` returns reported records or explicit `unmeasured`, never an invented healthy result. `record(id, input)` validates the closed finite/enumerated numeric contract, stamps server time (clamped against this id/class's latest record on wall rollback), and retains the last 20 independently per id/class. The storage path is fixed `<dataDir>/web-effect-profiles.json`. It is not derived from an incoming path or actor.

The single-fleet-owner store rereads its bounded regular file through one fd, opens nonblocking where supported before requiring a regular file, refuses symlinks where `O_NOFOLLOW` is available, checks growth/short reads, requires valid UTF-8 and a fully known schema, and never repairs an unreadable index. Writes use the reviewed complete-byte atomic writer at 0600; only a successful rename publishes data. Reentrant writes to the same resolved lexical path refuse across participant objects. This is a synchronous in-process fence, not a multiprocess lock or OS-user isolation. A failed write leaves the old file readable and no new cached record is fabricated. Bounds: 512 ids, 20 records per class, 120 windows per report and 8 MiB physical/index JSON. A bound refuses a new write rather than silently discarding unrelated reports. No migration or background scan is added.

The later authenticated ingress must authorize the **exact** effect id through the library before reading or writing profiles, reject public-link/agent profile writes, bound the request and report frequency, and fence the browser's current mount around an asynchronous post. Agent tools stay read-only. A list should use only the latest summary per class; full history is on demand. The library ACL is not replaced by a valid id, profile JSON or device enum. No such ingress is supplied here.

## Verification and rollback

Tests exercise real profiler snapshots, independent quantile fixtures, ownership/clock/staleness revocation, unknown-field privacy, coverage counts, retention/reopen/id/class isolation, server timestamp ownership, atomic-write refusal, bounded/symlink/corrupt files and reentrant writes. The open-flag assertion inspects the actual regular-file open; it is not a native FIFO experiment. These are pure/owned-FS tests, not a browser Worker-cost or product-mount claim. Earlier registry/runtime native proofs remain separate evidence.

Risk: host reports may be forged or reflect unrelated jank; bounded retention can eventually refuse new ids. Neither condition changes admission. Rollback reverts these unmounted modules/tests/docs; no production route/startup/config/data migration is enabled. Future readers must not convert unreadable or unmeasured profiles into health.
