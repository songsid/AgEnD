# Resumable Hub sharing (#3743, M-3015)

擁有者可以「暫停分享」與「繼續分享」；允許提問的人與 AD 群組不變。暫停後不接受新提問；暫停前已核准且正在傳送給 Fleet 的授權，仍可能在原本最長 5 秒的期限內開始一次輸入。這不是立即中止正在處理的工作。既有對話顯示「分享已暫停」，仍可依原權限讀取。授權的到期時間照常計算，不會補回暫停的時間。另保留較強的永久「停止分享」：要再分享，需從 Fleet 重新分享並重新允許提問。

- Store an owner pause and monotonic sharing epoch on the Hub's exposure row, independently of the member's publication revision. Complete snapshots, reconnects and Hub restarts cannot clear a pause. Only the exact current owner can resume, after fresh session/person and operational fleet/exposure checks. A policy hold or permanent stop cannot be resumed through this action.
- Keep person/group grant rows, IDs, revisions, recorded absolute expiries, rooms and history unchanged. New grants remain subject to the existing 90-day limit; retained longer grants retain their expiry. Resume does not resurrect expired/revoked grants or obsolete publication revisions. Group membership and all operational AND gates remain live checks.
- Hide paused agents from the new-question catalog. Existing authorized rooms remain readable and show a paused banner with a disabled composer. New questions, member dispatch/admission/tools and answer release still require the effective exposure to be published. No automatic replay or retry of a refused question.
- Increment the sharing epoch on every pause/resume and permanent stop. Bind Hub-side asynchronous operation permits to it even on legacy-policy fleets, so a pause/resume cycle cannot revive an older Hub decision. Immediately retire Hub-consumed release leases. Pause/resume also commit a global authorization-version advance in the same DB transaction, then use the existing member reconnect refresh. Once a member observes that fence, old locally consumed capabilities stay invalid after Resume. Links briefly reconnect; no credential is revoked and no listener is restarted.
- **Accepted issued-capability boundary (leader decision, 2026-11-13):** a pre-Pause authorization result already in transit may cause at most one first input per issued operation inside the existing ≤5-second lease. This includes a result held through Pause→Resume before the member observes the fence. After expiry or an observed fence it is refused; no new authorization is issued while paused. This is an explicit bounded exception, not already-running work or an instant distributed revocation guarantee. Do not add a new acknowledged member-fence protocol. State and `exposure.paused` / `exposure.resumed` audit still commit together; audit failure rolls back the action and emits no reconnect refresh.
- Keep the existing destructive freeze/Stop sharing endpoint and its re-publication fence. Pause is a separate owner-only endpoint, with exact publication revision and sharing epoch. Member snapshot schema and member execution protocol stay unchanged; `paused` and the sharing epoch are Hub browser projections only. The Fleet's Share switch continues to mean local publication; manage the Hub pause on My shared agents.
- Offer pause/resume only when the server session and client both advertise `sharing-pause-v1`. An old tab retains Stop sharing; old browsers may lack the new paused presentation, but server authorization still refuses questions. No new shared-module static imports. Use existing cards, buttons and tags; load the small touch-target stylesheet with the renderer so retained shell CSS also keeps 44px phone targets.
- M-3014 rooms remain unimplemented. Future room exposures must use this same effective exposure state and epoch, without a second pause model or grant migration.

One alpha PR: additive migration and server tests (Ridge co-review), owner/asker UI and EN/zh-TW strings, skill, fail-first and mutation receipts, desktop/phone light/dark PNGs and retained-asset checks. Rollback requires the matching pre-upgrade Hub database backup; older binaries must refuse the added migration rather than silently ignore a pause.
