# Hub administrator directory settings API

M-2687 / S-112 / #3425. This slice composes the existing directory proof, one settings writer, SQL decision, response ownership and HubSessions transition on the Hub listener. The AD form, CA bootstrap UI and cold fleet/D3 recovery remain unfinished. First-time browser setup is already separate and landed; no UI modules or layouts change here.

The host offers `directory-settings-v1` only when it supplies the lazy controller provider. The session response and HTTP entry carry the mark; without the provider these endpoints answer 404. A mark describes availability, never authority. A future editor must require both its own module capability and this mark; retained older UI ignores the new field.

Every supported request acquires the existing configured-administrator authority before the controller factory runs. Mutations also require the existing same-origin and CSRF checks, bounded JSON bodies, and a current eligible session. Neither the fleet token, a member credential, a public/guest link nor a body field supplies that authority. Query keys and wrong methods are refused. Session and disconnect currency are rechecked after acquisition and body/factory awaits, through the proof controller's physical directory waits and before effects. A private factory failure returns a bounded unavailable error, never exception text.

| Endpoint | Method/body | Result |
|---|---|---|
| `/hub/v1/admin/hub/directory` | GET | Editable connection values, immutable realm/profile, `bindPasswordSet`, and `reauthentication: recent|required`. No password or secret reference. |
| `…/prepare` | POST `{directory, bindPassword?}` | Opaque single-use preparation, expiry and one trust challenge when required. |
| `…/test` | POST `{ref, confirmation?}` | Fresh candidate identity/group check; no setting changes. |
| `…/save` | POST `{ref, confirmation?, credentials?:{login,password}}` | The same proof plus the sealed writer/SQL decision, remount and original-response delivery. |
| `…/cancel` | POST `{ref}` | Cancels that actor/session's preparation. |

The strict editable directory object accepts only URL, base DN, service bind DN, CA PEM, login attribute, filter and timeout. The server supplies the existing realm/profile and refuses caller-selected secret references, actor, changes, recipients or other keys. It derives changed-field enums itself and fixes durable old recipients to the existing host sink and old configured administrator. The existing full notice/audit decision persists those payloads with the credential/session/config epoch transition, not as a later best-effort event.

The service password is write-only. The old secret is reused only under the existing proof rule: unchanged server URL, CA and bind DN. The preparation uses ordinary verified TLS without application credentials. A changed server or CA requires the exact trust challenge before candidate binds; the candidate driver pins the probed leaf and uses only service credentials. Save always re-tests the same immutable configured administrator and configured policy-group GUIDs against the candidate. Realm/profile, Hub identity, browser certificates, listener origins and administrator designation are outside this editor's patch.

An administrator needs authentication within five minutes against the OLD trusted directory. The service consults the current mounted HubSessions proof; a stale proof requires personal credentials only for the old directory's sign-in method. A generation/image change cannot inherit that proof. A same-host search/filter/credential edit needs no extra trust click. The existing proof/writer enforces final material, clock, eligibility and image checks; the route does not substitute a previously successful Test for them.

FleetManager constructs one host-lifetime controller lazily, using its already-created writer. The controller reads the latest mounted source/session adapter each time and uses that generation's same physical 4/person, 32/total directory pool. Reading the settings spends only the listener's normal administrator eligibility check, not another one inside the projection. The future page should load this resource without mounting a second hidden settings reader. The listener's eligibility-admission exhaustion answers 429 with Retry-After 10; unavailable candidate proofs remain 503 and preserve the old settings. The form must show the established busy wording for admission pressure and must not silently replay a Save.

Save prepares the exact HubSessions rotation and captures its fully consumed original response before the synchronous SQL decision. It then survives logical revocation of its old browser generation, finishes the normal remount and closes the durable mount intent before any cookie. The successful successor keeps the old absolute session expiry and has no inherited authentication proof. A refused replacement uses only the existing bounded forward compensation and returns restored/503 without a cookie. A proven pre-decision refusal can return a bounded error on the captured socket. An uncertain outcome is discarded, never labelled not committed or automatically resent.

For completion after the old listener is physically closed, Runtime lends either the exact existing participant or validated cold existing state under the full registry. It does not create or migrate a DB. The loan captures an admission ticket before importing, rejects a changed view or A→Off→A continuation, rejects Promise callbacks, and expires its frozen method facade when the synchronous callback returns. The writer receives the actual same owning participant only during that callback. Stop fences the controller synchronously and joins its physical work in FleetManager's existing asynchronous shutdown phase; the member side is not broadened or independently stopped by this adapter.

Evidence includes fail-first 404→200 route coverage, private CA-verified loopback HTTPS and real SQLite for ready/restored/unknown/stale outcomes, renewed old-directory authentication, no candidate personal-password call, fixed recipients/field enums, one projection eligibility read, late factory cancellation, callback expiry and unchanged/ABA cold-import controls. FleetManager uses a recorder only in its wiring tests; shutdown regressions use their existing inert harnesses. No real directory/account, native process, pilot or live fleet is used. This is backend evidence, not the final AD form/PNG/SKEW acceptance. Alpha.10 also requires the local host path to load and edit AD settings without AD sign-in when the directory is down, alongside the existing host-owned start/stop controls. The host adapter below does not depend on this administrator route or weaken its authentication gate; the form and off/held cold-source path are still pending.

This slice adds no migration. Reverting its code removes the endpoints/mark and leaves existing authoritative operations and recovery state intact. It never authorizes a DB restore or a floor/epoch rewind; the already-documented matching-build/pre-upgrade-backup downgrade rule remains in force.


## Local host recovery adapter

The fleet listener serves `GET /api/settings/hub/directory` and `POST` children `/prepare`, `/test`, `/save`, `/cancel`. Before reading a body or lazily acquiring the shared controller, every request requires the host's own local D3 cookie session (`hubSetupSession`): the exact host/Origin, mutation CSRF, session-store identity and web-authority epoch. Other local admin sessions, guests, header tokens, forwarded/public links and remote addresses do not provide that proof. Query strings and wrong methods are refused. A disconnect permanently cancels the request; authority is checked after body/factory waits and through the shared proof's candidate waits.

The adapter constructs only a host-owner actor with the proved session/request identity. It never accepts a caller's actor and never calls Hub sign-in or `requireAdmin`. Read returns `reauthentication: host`; host Save refuses personal credentials. Candidate checks still prove the same configured immutable administrator and policy groups, enforce the existing trust challenge and shared physical 4/person,32/total pool, and use the same sealed writer/SQL decision/audit/notice transaction. No separate writer, secret location, budget or broad authority is introduced.

The fleet listener survives the Hub remount, so it awaits the existing coordinator directly without transferring a response or rotating a Hub cookie. `ready` returns 200; a forward-restored result returns 503 with its result. Known errors are bounded; admission pressure returns 429 plus Retry-After 10. A failed or disconnected Save is never automatically retried or labelled uncommitted based only on a network error. If the D3 authority ends while Save is already completing, the route withholds its result and answers 403 `revoked`, even when the controller committed successfully. That refusal describes the caller’s authority, not the Save outcome; it never carries `committed:false`. The form must reload the authoritative state before offering another save.

The real-listener test closes the old fake LDAPS listener before reading, testing or saving. A new owned CA-verified LDAPS peer receives only service binds, not personal credentials. A negative candidate test leaves epoch/config unchanged; a successful Save uses real FleetManager, sealed files, SQLite, audit, notices and Runtime remount. No Hub browser session is created; identity/certificates and disabled group policy remain intact. Separate contract-faithful controller doubles exercise dispatch, D3 rejections, held factory cancellation and bounded errors. This is backend evidence, with no browser/PNG/SKEW claim.

Current limit: this adapter still requires a valid mounted source from the shared controller. A directory network outage does not invalidate that source, and the host path does not contact the old directory. An off/held Hub without a current mounted source still returns unavailable; existing-state cold source access and the actual Settings form remain work for M-2687. Host-owned Run this Hub remains independent of AD authentication. No new UI availability mark is offered in this backend slice.
