# Hub roles: inactive writer (M-3010 / S-127)

This slice implements the SQL write boundary for [the accepted design, Appendix A](https://github.com/songsid/AgEnD/blob/9e0006256/docs/design/hub-roles-permissions.md). It builds on #3767. The directory-backed, lossless cutover and live operation permits remain separate slices; there is no startup, HTTP, feature advertisement, UI or migration-registry caller of this writer.

## Delegation and document changes

The held bundle is independent of the self-use policy state. It comes from live assignments, fresh person eligibility and group membership, with each permission retaining its own scope, quota and expiry. The configured root has virtual administration for delegation to others, with no implicit self-use grant. An eligible administrator can delegate any supported role to others within the model's 0–8 quota bound; other assigners must dominate each permission individually. They cannot combine a large short-lived grant with a small permanent grant to make a large permanent assignment, infer subset relationships between groups or grant a personally denied permission. Destructive assignment edits also require dominance of the old bundle. Management assignments remain persons-only and Hub-wide.

Role definitions require `hub.admin`. Their changes are checked against every referenced assignment, including indirect self-increase through a group and a permission addition through the editor's own assignment. Direct self-assignment edits are excluded from the ordinary writer, including removal and narrowing. Unknown self-membership refuses an increase. The private planner stamps the actual actor and server time on new/edited assignments and refuses a rewrite of unchanged historical attribution. Definition kinds and the immutable built-in administrator stay protected.

Both approval permissions are reserved for phase 3 and refused in every proposed role. The fixed catalogue still has twelve entries; the phase 1/2 defaults now contain ten for Administrator, five for Manager and three for Member. This is the deliberate correction to the inactive defaults introduced by #3767, following the clarified design at 8fecd55fc. No stored live role document has been activated yet.

## Preview and atomic commit

The writer takes a real `HubRequestContext`, captures its methods, and proves its actual directory identity, session and fresh eligibility. It does not use the root-only presentation flag or a browser-provided actor. It reads the one policy row and refuses old/missing/corrupt or foreign-bound state; it does not migrate it.

A single-use, session/person-bound preview retains the exact proposed request, current serialized policy, authorization epoch, complete inventory fingerprint, private effect-plan identity, displayed impact and semantic directory observations. The returned impact is detached. Apply consumes the preview, repeats preparation and authentication, and refuses changed evidence even if its presentation is unchanged. Assignment attribution is stamped again at apply time, rather than freezing the preview's timestamp into the committed history.

The actor's held bundle is proved before full inventory or other-person reads. Preparation uses the existing policy object's 4/person, 32-total directory pool, holding admission until the physical read settles. New group references are re-resolved by immutable GUID; new/changed personal assignments require current target eligibility. A read result outside its own observed-time interval is unknown. Preparation has a 20-second monotonic acceptance budget and previews have a 120-second wall-clock expiry; rollback of the clock refuses rather than extending a preview. These are acceptance fences, not a claim to abort a directory driver's physical operation. There is no Promise.race that releases its slot early.

One immediate SQLite transaction installs the exact policy CAS, server-prepared retained-resource consequences, required audit, notice recipients and authorization epoch. After audit and epoch writes it rechecks the exact policy image, original ordinary inventory, current session, role authority and time. A failed synchronous or thenable audit refuses; a failed effect or final proof rolls the SQL transaction back. Existing independently raised transport floors are not rolled back: uncertainty still holds subsequent work. Refresh effects run after commit only. If a post-commit refresh fails, apply reports unavailable without claiming that committed policy was rolled back or recording it as a refused write. A policy no-op with a retained-resource consequence still advances the epoch.

`RoleWriteEffects` is a required **server-side integration boundary**, not a request field. It seals an exact resource inventory and impact before the commit, commits its exact narrowing/capture consequences synchronously and proves them after. This slice's tests use an owned SQL resource model for that boundary. The real manual/code/invitation provenance, pending-join and suspension adapter is not supplied or mounted here; cutover must supply and test it before this writer becomes reachable.

## Root activation and notices

The root's one named exception has separate preview/apply methods and a separately typed private candidate. The server constructs only a Hub-wide personal assignment of the three self-use bits with quota 8, without touching state, latch, denies or anyone else. It uses a dedicated self-use-only role, not an Administrator assignment that would leave an old root with management rights after a root change. The operation requires the configured root's real eligible session, records `role.root-self-use-activated`, its once-only marker and an administrator notice in the same transaction. Ordinary writes cannot create or edit a reserved root role or assignment; removing them remains permitted through the ordinary authorization checks. Revoking the assignment/definition does not erase the marker or permit a second activation. Root defaults still obey ordinary self-use denies and suspension.

Management changes notify all effective admins at the change, with recipient identities recorded in that commit. The supported administrator set is the configured root plus live personal Hub-wide Administrator assignments: the strict document graph refuses every management permission on a group subject, including `hub.admin`. All person subjects from both policy images enter recipient preparation even when absent from the resource inventory; this is not a known-inventory-only administrator list. Notice reads therefore need fresh person eligibility and current personal administrative authority, without a group-membership lookup. A group-admin document is refused at both the write and read boundaries; supporting that shape later would require a design/model change and fresh group proofs. Reads and acknowledgements prove current eligible administrative authority and the recorded recipient, so a removed or expired admin cannot read its retained notice. Acknowledgements are idempotent and audited. Notice bodies contain role metadata and the server's bounded impact; they confer no conversation-content access and do not create entries in `hub_auditors`. Root activation markers survive audit retention; notice rows may follow their retained event.

## Activation boundary and rollback

The exported auxiliary-table migration is unregistered. Tests install it explicitly in an in-memory fixture and place a role policy into that fixture only after constructing the existing directory-pool owner. No production caller does either operation. Current group-only readers continue to be the only live path, and older tabs receive no new feature or asset.

Atomic migration, the once-only migration announcement, expiry settlement/scheduling, retained resource and pending-join consequences, downgrade floors and live route/lease/SSE conversion remain S-128/S-129 acceptance. Reverting this unreferenced slice requires no production database reversal. Once activated, a binary downgrade requires the separately reviewed schema/backup protocol, not deletion of role rows or a pre-migration snapshot restore.
