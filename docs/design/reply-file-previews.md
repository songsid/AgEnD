Reply file previews (M-3283) add inert file references to the existing reply tool. The structured `previews: [{path, line?, endLine?}]` argument works through MCP and `agend-agent reply --previews JSON`; it avoids interpreting ordinary prose or Markdown links as file authority. Up to ten references are accepted. The optional range is inclusive and one based. Discord and Telegram copies append plain `path:line-endLine` references; the web caption stays unchanged.

An agent reply keeps the validated references in the normal web history and archive. A person's message cannot create them. Guests receive no preview metadata or controls. Clicking Preview fetches only that file through `GET /ui/reply-preview?instance=…&path=…&op=meta`. A signed-in administrator session is required on every request, on either the local listener or the public link (decision 7933bf90). CLI bearer tokens, guests and read-only sessions are refused. The app shell adds only its validated own origin plus `/ui/reply-preview` to the allowed frame sources for an admin, retaining the existing HTML-preview source. This does not widen the existing Files/Changes gate or add directory listings.

The server resolves the path inside that agent's configured working folder. Absolute paths, parent components, backslashes, drive/alternate-stream syntax and control characters are refused. Existing workspace secret-name and state-folder exclusions apply. Parent and final symlinks are refused; the opened descriptor, canonical location and named inode must agree. Session, listener and working-folder identity are checked after asynchronous reads. Responses are private/no-store and errors contain no absolute paths. Text is bounded to the existing 1 MiB workspace limit. Images and PDFs are bounded to 95 MiB; raw reads support a single byte range. A PDF must have the PDF signature. Raw text/HTML cannot be served as active content by this endpoint.

Code and text reuse the existing numbered workspace viewer, scrolling to and highlighting the requested lines. Markdown without a line uses the existing Markdown panel; Markdown with a line uses its source view. Images use the existing image viewer. PDFs use the browser's native PDF renderer inside the same preview shell; browser PDF support is required. Nothing executes a shell command or writes to the file. A preview reads the **current** file, not a frozen copy of the version described in the reply; a deleted file shows a localized missing-file message. Switching previews retires earlier reads.

Step 1 supports local agent backends via CLI or MCP. A paired Windows computer's files are not transferred. Both the remote-pane tool guard and the reader give the explicit limitation: “previews of files on a paired Windows computer aren't available yet”. A later remote-transfer feature needs its own card.

Rollback removes the optional tool field, dedicated read route and UI adapter. Saved references remain inert data; old clients ignore the field. No migration or new permission profile is introduced.
