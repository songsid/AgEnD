# Hub installation inventory and owner handoff

Initialization writes a private `hub/install-inventory.json` before its final enable step. The record contains only setup time, Hub id, browser/member origins, member pin, coexistence choice, the account service label, and the locations of shared configuration, Hub data and logs. Directory credentials, directory/admin identities, PEMs and imported source paths are omitted. The initializer's existing private atomic writer is used; a failed write keeps the Hub off. Resuming an already-sealed, unfinished setup writes the record without replacing its identity or seal.

The signed `hub/init-manifest.json` remains the runtime prerequisite. The inventory is a separate informational snapshot; runtime admission, consent, service control and cleanup never consult it. It cannot authorize file removal. Changing Settings does not rewrite the historical setup snapshot.

The wizard prints the handoff after its existing optional service step. `agend hub handoff` shows it again without a TTY, secret reads, network operations or lifecycle actions. A missing record from an older setup, malformed metadata, symlink or nonprivate record produces a local diagnostic and no service inspection. Optional current service inspection supplies the service definition path; an unavailable manager does not hide the remaining handoff. Current addresses and state belong to Settings, not the snapshot.

EN and zh-TW guidance shows the selected data home, pairing steps and pin, and shell-quoted commands for stop, restart, interactive service removal and redisplay. It states that lifecycle commands control the existing service and every agent it runs, including an existing fleet. `agend uninstall` removes the service definition; the AgEnD package, configuration, Hub keys/secrets/database/audit and logs remain. Retention runs while the Hub runs. Separate manual data removal requires the owner's own choice and backup; no removal command or automatic cleanup is added here. Imported source files remain outside this inventory.

Validation uses private temporary homes, a fake directory/identity, inert service inspection and a compiled CLI with runtime construction/service mutation disabled. It covers failed inventory persistence, same-identity resume, existing-fleet preservation, localized guidance, safe copying with unusual home names, and missing/invalid records. This slice changes no native service-manager behavior and does not touch the running pilot.
