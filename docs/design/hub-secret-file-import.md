# Private-file bind secret import

During `agend hub init`, including a same-plan resume, the local operator chooses hidden password entry (the default) or private-file import. This choice is explicit: a password starting with `file:` remains a literal password when entered through hidden entry. Import takes an absolute normalized file path through the terminal, not a secret-valued command argument, environment variable or chat message.

The source must be a regular file belonging to the current POSIX user, mode 0600 or 0400, with no symlinks in its path. Native Windows has no new ACL claim; the existing supported WSL/POSIX initializer boundary remains. The reader checks the path and descriptor identity, ownership, mode, size and modification metadata around the actual bounded read, then rechecks ancestor identities. Replacement, retargeting or an owner edit during reading refuses the import. Descriptors close on all paths.

Only non-empty valid UTF-8 up to 1024 bytes, without NUL, is accepted. All bytes are preserved: spaces, a BOM and trailing newlines are part of the password. The wizard explains this before selection. Nothing trims or normalizes the secret; a failed decode cannot substitute replacement characters. The source is not deleted or modified by the importer. Failure gives fixed local guidance without echoing content or raw filesystem errors, and permits retry or cancellation before directory sign-in.

The selected bytes follow the existing in-memory sign-in and sealed initialization flow and are copied to the existing private `hub/secrets/directory-bind` file on commit. Runtime directory composition reads this opaque secret with BOM preservation too; default JSON/config text reads keep their existing encoding semantics. The plan/configuration retains only its existing `bindPasswordRef`, never the import path or password. No new secret store, schema, runtime credential source or authority is introduced. The operator remains responsible for removing their source when they no longer need it; cancellation leaves it available for retry.

Acceptance uses private scratch files, actual descriptor reads and controlled owner-file edits, plus the real initializer with inert directory-person, identity and service adapters. EN/zh-TW initialization, hidden-entry fallback, failed-file cancellation, exact stored bytes and same-plan resume are checked. No real credential, account, directory, host or pilot is accessed. Committed secrets keep the existing private-file format. When rolling back, retain the opaque-secret decoding fix if a BOM-prefixed password has been imported: older runtime readers strip that byte marker.
