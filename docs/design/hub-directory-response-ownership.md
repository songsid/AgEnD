# Owning the AD Save response through remount

M-2687 / S-112 / #3425. This private resource adapter extends the mounted session adapter from #3465. It adds no AD route, capability mark, actor lookup or browser token/ref lookup endpoint.

A directory decision ends the old generation before its replacement mounts. The ordinary listener teardown would destroy the originating Save response, while waiting for that response would prevent same-port remount. HubRuntime therefore owns one bounded response across its server generations. The server factory tracks actual TLS requests and can transfer that exact response, its socket and the closing HTTPS server to the runtime owner. The listener stops accepting first; every other raw or TLS connection is destroyed. The selected response is retained only after the listening socket has closed. No private TLS internals are used: the TLS socket must have one unambiguous raw connection with the same local/remote tuple.

Capture requires a fully consumed request, one active response on that socket, no previously sent headers, a current caller proof and an available slot. A pipelined companion aborts it. The global-per-runtime slot remains occupied until physical socket closure and, after transfer, the old server's close callback both acknowledge. A bounded cleanup failure retains ownership and rejects Stop; a later close retries. It does not claim physical completion merely because admission stopped.

The lease expires after 30 seconds, rejects a backward clock, and cannot survive permanent Runtime.fence(). Stop destroys its response synchronously, then awaits positive drainage in the asynchronous shutdown phase. An ordinary remount does not permanently fence the runtime owner. A failed replacement does not release a token: the future route must discard the response or let it expire.

Reply is one-shot. Its synchronous builder obtains the successor from the newly mounted generation's actual HubSessions; a final current/lifetime check precedes all headers and body bytes, with no asynchronous callback in between. A builder cannot return a Promise. The response uses no-store, bounded JSON, a bounded single cookie and Connection: close. A disconnect, late invalidation, failed flush, or expiry aborts delivery. An ambiguous delivery is never retried with the same rotation handle; the user may sign in normally again.

This adapter proves resource ownership, not permission to edit AD. The eventual public route must separately enforce the old trusted-directory reauthentication, exact admin/PersonKey, Origin/CSRF, candidate trust confirmation, opaque draft and authoritative writer decision. It must capture immediately before that synchronous decision, remount through the existing lifecycle, and complete the exact operation only through the new mounted session adapter. There is no second settings writer.

Evidence: real CA-verified HTTPS tests cover same-port rebinding, the originating response's successor cookie after the real proof/shared-writer decision and remount, old-cookie refusal, one-shot release, synchronous Stop and held physical server acknowledgement. The request-capture route exists only in the test wrapper; it is not a product route. Directory eligibility and candidate TLS probe are inert fixtures. No browser, real directory/account, native manager, pilot or live fleet is driven. Public Save orchestration, durable notice delivery and failed-mount forward compensation remain unfinished M-2687 integration. No schema component is added by this slice.
