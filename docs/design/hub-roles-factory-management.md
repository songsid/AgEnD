# Composing the reviewed role management consumers

The service-level management and first-issuer consumers were prepared in #3802, but the actual Hub factory still omitted their dependency. This slice gives those existing consumers one mount-owned management authority, with the reviewed management policy reader, persisted authorization clock, actual transport version and shared physical directory admission owner. The group operational reader consumes that same real clock.

The authority is passed to HTTP, company-code and invitation administration, manual pairing and retained first-issuance preparation. Management assignments remain person-subject, Hub-scoped and freshly eligible. A `join.manage` assignment does not confer an unmapped admin route. Legacy images stay configured-root-only. The narrow intact legacy never-enabled generation-repair path remains; no mismatched role image gains that exception.

No startup role migration or cutover is registered or invoked. Role writer/endpoints, session/admin display mapping, resource-effect adapters, expiry scheduling and member/SSE retirement remain later S-129 slices. Existing unmapped administration remains configured-root-only until its separately reviewed mapping. This is consumer composition before activation, not complete phase-1 delivery.

Tests initialize and seal owned Hub homes, use the actual factory and loopback HTTPS, and replace only directory answers with fictional people. The test explicitly invokes the real cutover on the actual owning database after mount, then provisions a role assignment privately. It does not claim supported live migration or role remount. A synthetic retained expiry term is inserted to test the clock reader; no expiry-worker execution is claimed.

The routes show root access before conversion, refuse a non-root legacy actor, allow named join management after the private conversion, refuse an unrelated admin overview, and retire the named permission after removal. Manual first-issuance preparation shares that authority and loses it when roles are turned off. Further controls cover rollback, the retained expiry floor, held directory work and the narrow generation-repair boundary. Existing factory contexts are completed with inert current-session/eligibility methods without removing their original assertions.

No UI, asset, HTTP payload, protocol or configuration key changes. Cached-client behavior remains the same; no new PNG/SKEW claim. No real directory, account, backend CLI, Fleet, browser, native OS or pilot operation.

Draft parent order is #3795 → #3802 → #3805 → #3806, then this slice; plain alpha sync and current-head review/CI are required. Before eventual activation rollback is a code revert. Never restore old role databases, policy snapshots or independent floors after activation.
