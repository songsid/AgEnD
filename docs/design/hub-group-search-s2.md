# Hub group prefix search (S2)

Implements the feedback-only search in [the Phase A/B build spec](https://github.com/songsid/AgEnD/blob/d015e6ce/docs/design/hub-ux-simplify.md#12-hub-the-administrators-讓同仁加入-card), under #3658. U2 owns its user interface. Selecting a suggestion still requires the existing GUID resolve, impact preview and apply path; a search never creates a person, grant or enrolled resource.

`POST /hub/v1/admin/group-policy/search { q }` uses the configured directory administrator's exact current session and CSRF boundary. Control characters, extra keys and prefixes outside 2–64 trimmed characters refuse. It performs one service-bound, verified-LDAPS subtree search within the configured base. Its AD security-group filter escapes each RFC 4515 literal and appends the prefix wildcard outside that literal. Attributes are objectGUID, cn and distinguishedName; dereferencing is disabled; limits are 20 entries and 5 seconds. Continuation references are ignored and never followed. Since ldapts does not expose the accepted size-limit status, exactly 20 suggestions conservatively sets `truncated: true`.

The response is `{ ok: true, groups: [{ objectId, cn, dn }], truncated }` or `{ ok: false, reason: "unsupported" | "unknown", failure? }`. Unknown failures use only the existing closed directory diagnostic names. Unsupported profiles keep the DN input available. HTTP 429 `{ ok: false, reason: "limited" }` plus `Retry-After: 60` answers the 31st request per exact administrator session in one minute. Rate buckets are bounded at 1024. A new session has its own budget; raw LDAP text, credentials and arbitrary driver fields never appear in responses.

Search spends the existing policy store's shared 4-per-person / 32-total physical read pool. It introduces no parallel pool. The five-second deadline destroys only the operation's owned TLS socket. Its promise retains the pool slot through LDAP settlement, unbind and the physical socket close, including timeout and abort. The server rechecks the captured administrator, exact session, policy image, directory generation, method and current mount after I/O before disclosing a snapshotted result. A session change or policy/directory replacement retires that result.

S2 changes no database component or authority semantics. Rolling back its binary removes the endpoint; clients must treat a missing endpoint or `unsupported` as a request to use the existing DN/resolve flow. S1's separate component upgrade and rollback rules do not apply to this PR. Fake-LDAPS/HTTP and inert interleaving fixtures exercise the bounds; there is no live AD or native-platform claim.
