# Group permission impact preparation

This unmounted library prepares part of [#3298](https://github.com/songsid/AgEnD/issues/3298)'s confirmed policy change. It exposes no route, capability mark or enable control. The server control and actual pairing/publication enrollment gates are still required before activation.

The impact builder receives the server's current exact inventory, the proposed policy and fresh immutable-person group facts. It reports affected ask-grant holders, including the configured administrator's Chat eligibility; owners losing new or revised publication; exact manual revisions retained; resources that would be suspended; and a separate HELD list with each person's uncertain capabilities. This is a projection and plan, never an allowance or mutation.

Unknown membership neither grants new access nor suspends existing resources. Explicit policy narrowing, such as a person deny or switching the experiment off, is independent of an unknown directory read. Authoritative complete negatives suspend active group-derived resources. Existing exact manual revisions remain membership-exempt, except for explicit person denies. First enable plans capture of the server's exact pre-enable fleet/publication inventory; it never grandfathers askers. Rejoining, switching on, or raising a limit does not resume suspended resources. A smaller positive fleet limit constrains new enrollment without removing existing fleets.

The facts reader snapshots all subject keys before awaiting. It sequentially reads the known Hub people supplied by the server; it does not enumerate the directory. It checks the configured realm, exact immutable identity, observation window and bounded GUID list, and copies each result before another await. An empty or partial AD direct-membership read stays unknown, including the documented last-direct-group exception. It starts no further directory read once the preparation budget expires; the remaining people stay explicitly HELD. It does not race and abandon a physical read: the driver's existing request timeout bounds that read.

Preview and apply must each acquire fresh facts. Semantic comparison removes observation timestamps but retains identity, sorted membership and ineligibility reasons. The future control must independently reauthenticate the configured administrator, seal the exact policy, inventory and impact, and commit only its own current confirmed plan in one database transaction. These helpers do none of that authentication or committing and must not be used as an authorization cache.

Tests use fake people and inert driver callbacks, including held reads and mutated caller/driver objects. They make no real directory, browser, HTTP, pilot or native-host claim. This step has no schema change; rollback is a code revert.
