# Rooms Track R2: agent routing

This slice extends the R1 room model, using seam 2 and the Track C adapter contract (#3860). It leaves direct-chat questions, grants, leases, receipts and answers in their existing services. Ordinary pilot review applies.

A manager can add their own currently published agent. That stores the exposure ID and its owner on a distinct per-room membership row. Room membership is the owner's consent for room questions; it creates no one-to-one grant. Roster IDs for agents are exposure IDs. Removing an agent, changing its owner or publication revision, removing/re-adding the asking person, or archiving the room retires retained work. Pausing sharing preserves membership and queued work. Other owners' agents require C's invitation integration, a later slice; the narrow synchronous addAgentMember callback is available for its guarded acceptance transaction.

A person's message is saved once by its idempotency key. Its distinct @agent targets, or all current agent members for @all, each get one durable delivery ID and one reply placeholder. A person mention is a reminder only. The existing member/manager @all setting still applies. New work and the person message commit together. Text and frozen payloads use the existing encrypted content port; SQL stores references/digests. Dispatch intent is persisted before the socket write so a fast answer has an issued record.

Each room.ask has one frozen payload: messageId is the delivery ID (not the person's parent-message ID), roomId, roomName, exposureId, display-name asker, text, and the latest 30 eligible context rows, oldest first. A replied-to row older than those 30 is included once with repliedTo:true, within both the asker's and the agent's join-history cutoffs. Context rows are UTF-8 truncated to 2 KiB and names to their wire bound; the complete JSON must fit the existing frame budget. The Hub retains the same bytes and delivery ID across reconnects. It freshly checks exact membership/owner/publication, eligibility and operational group permits before dispatch; no browser session is needed for a retained ask.

Offline, stopped or paused targets wait, and a target unanswered for 24 hours becomes not-answered. Link/state/post/publication events wake dispatch. Offline targets arm only their earliest expiry; live transient failures retry at30 seconds. The global timer reads indexed due expirations, not every retained row. Validity work on room reads or room/member changes is scoped to that room, and publication changes scope it to the affected Fleet/exposure. Idle links are not swept or queried every second. One flush per Fleet is in flight. A failed/uncertain socket write retries the same payload. Known consent loss is terminal and cannot be revived by a new membership row. Directory unavailability holds rather than inventing consent or an answer.

The Fleet retains its exact room.answer until room.answer-ack. The Hub commits the answer once, rejects a conflicting ID/body, and ACKs exact retries. A known retired delivery can be ACKed without publishing its answer. A pause or transient operational read withholds the ACK without closing the member link. On completion, the same placeholder ID receives its text and a new chronological sequence so an answer arriving after a read marker is unread. Parent progress travels with message.updated. History, list previews/unread and SSE filter an answer by its original question’s join floor, so a late answer cannot become an orphan for a later joiner. System and pending placeholder rows do not count as unread; agent answers do, including for the agent's owner.

room-ask-v1 requires welcome-caps-v1 and explicit offers on both ends. Default member capabilities omit it. The factory offers it only when its actual HTTP dispatcher reports support. Incoming room.ask uses the member's bounded work tail while answer ACKs remain on the control queue. The unmounted Track C adapter supplies the explicit member opt-in in its separate integration.

agent.state retains idle/working/paused and optional portable reason codes. The HTTP roster and presence.changed expose presenceReason; note is a legacy fallback. A connected stopped/crashed process is normalized by C to paused+stopped (grey Stopped in UI); an absent link is offline. New links and publication changes update room presence. The factory's memberClosed callback publishes link loss without periodic reads of all idle links. One-to-one canAsk is true only when the separate current grant/operational path proves it.

## Scope and rollback

The migration adds s3-room-agents, new columns on R1 group tables, and a delivery table/index. Existing direct and group fields stay unchanged. Older binaries refuse this component; rollback requires a compatible corrected build and retains the DB and content keys. It must not delete queued input or frozen answer history.

This is the Hub dispatcher and synthetic member integration. Production Fleet adapter composition, invitation/team/assistant/creator/admin integration and the complete UI walkthrough remain with the next cross-track slices. No live directory, account, Fleet, model CLI or host operation is part of this slice. No new browser modules or screenshot claim.
