# Retaining successor authority through directory Save

The private directory Save coordinator previously completed browser rotation through the legacy configured-root helper inside its response producer. A role-marked directory operation instead needs the new directory generation's fresh `hub.admin` permission, retained until the response's final disclosure check. Its old preparation is not effect authority in the new generation.

After the durable directory decision, remount and successful mount-intent completion, the coordinator acquires the private successor-release handle from the exact resulting mounted sessions view. It captures the mount, sessions getter, stable view and acquisition method by identity and checks them again after the await and around every final assertion. An administration-marked or preparation-marked operation cannot fall back to legacy completion when this helper is absent or refuses. Legacy unmarked root, host/no-cookie, compensated and disconnected paths retain their behavior.

The handle stays private. Its methods must be stable, it must be frozen, and its assertion must return void. The coordinator calls release only inside the original response owner's synchronous producer, then re-proves through the owner's final current predicate. The response owner publishes no packet when that final check fails. Cleanup discards the handle and rotation and always attempts response cleanup. Closing the coordinator retires the lifetime and drains an awaited acquisition.

A lost successor permission, changed session/mount/provider, expiry or response loss withholds the cookie. It does not compensate or retry an already committed ready directory decision. Independent floors, the durable mount outcome and forward recovery remain unchanged. No browser token is serialized to a file, journal, notice or audit by this composition.

The optional method on HubDirectoryBrowserSessions is forwarded by the actual factory's existing frozen view. It adds no HTTP capability, feature flag, caller-supplied proof or fallback authority. The public HTTP preparation producer and full auxiliary Save/cookie/install/crash acceptance remain later work. Canonical activation must mark root operations too; this slice does not activate roles or certify the existing unmarked adapter for an active role policy.

Tests distinguish their boundaries: coordinator controls use an inert proof, mount and role handle, with tagged opaque inputs solely because proof validation is mocked. They prove ordering, exact method/view identity, cancellation and no packet after final loss; they do not authenticate a forged proof. The mounted projection test initializes and seals an owned Hub and dispatches to a spy-refused actual HubSessions method, proving forwarding rather than successful authorization or Save. The parent successor tests use actual in-memory SQL/Core/Sessions/role-clock and fictional directory answers. No real directory/account/Fleet/backend CLI/browser/container/pilot or native-OS run is claimed.

Before activation rollback is a scoped code revert of the three product files. Keep the existing session and mount recovery state; never restore historical policy, database or independent-floor images after activation. Parent-first plain alpha sync, conflict-resolution review, current-head CI and coordinator-only gating remain required. Full S129 is still incomplete.
