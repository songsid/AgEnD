# Current administrative sessions (S-129 preparation)

The configured root remains the immutable recovery identity and the default administrative gate when no management authority is composed. It is not a substitute for an auxiliary administrator's current role assignment. For an auxiliary identity this slice makes the actual session context ask the composed authority for `hub.admin`. The configured root keeps its existing fresh-directory repair path; named role-aware operations must still take their own management permit, including for the root. A split join/fleet/role-assignment/audit manager does not thereby become an administrator. Roles-off, assignment expiry, directory eligibility, session identity and the existing persisted policy/clock/epoch fences remain the authority's responsibility.

`HubSessions.presentation()` derives an auxiliary identity's existing `admin` display flag from a current proof, without returning the session bearer token. The root's existing presentation does not depend on a healthy policy binding; its immutable identity is a repair hint, never a substitute for a named operation permit. HTTP sign-in uses the actual newly created token; a session read uses the exact validated cookie token. Both paths re-check an auxiliary positive proof after their presentation await and immediately before sending it. Unknown directory state remains unavailable, rather than a cached positive or a fabricated denial. Sign-out while a read is held retains the signed-out refusal. The low-level synchronous session row and configured-root claim witness remain separate from this presentation.

The core wrapper captures the selected management object and its method before awaiting. Its returned proof permanently retires after observed replacement, even if the same object or method later returns. Presentation has the same permanent retirement rule. Neither the `admin` flag nor a returned actor is an operation permit: administrative writers, route adapters, member leases and streams must still retain their own proof through their final effect or disclosure.

## Cost, compatibility and limits

A composed auxiliary session presentation performs one fresh administrative eligibility read through that authority's existing shared admission owner. The root's existing session presentation does not add a directory read or depend on the policy binding. There is no positive directory cache, parallel pool or five-permission fan-out. Unknown directory state may hold an auxiliary administrative presentation; it never manufactures a positive flag. A server-owned `roleSessionMode()` classification reads only the exact owned canonical image kind. False retains legacy session display and the configured-root repair path even when a legacy directory binding is mismatched. This hint cannot grant a role permission: a roles result still needs the full current authority proof. The classifier refuses corrupt or unreadable images. Without composed authority, the legacy session display and root-only gate remain unchanged.

The HTTP response field names, cookie, origin and CSRF contracts are unchanged. Old clients may display an old administrative flag; it supplies no authority to a request. No UI module, user text, screenshot or cached-asset claim is added. This slice does not activate roles or convert the remaining root-bound administrative adapters. In particular, it does not claim complete auxiliary administration, metadata-only audit routes, startup cutover or full S-129 acceptance.

## Evidence and rollback

Tests use actual role/session SQL, the actual management evaluator and owned loopback HTTP, with fictional directory answers and inert transport. No sealed factory activation, browser, real AD, account, vendor CLI, native host, pilot or live fleet is involved. The broader current factory and group-composition suites are separate compatibility controls. See `docs/evidence/hub-roles-session-s129/`.

Before activation this preparation can be reverted. After activation, use a forward fix and preserve role state and independently persisted floors; never restore an older database or policy snapshot.

Compatibility discovery: the first broad run exposed the enabled-legacy repair/sign-in regression from using the strict role reader for every session. The fix keeps the root repair path and classifies the persisted image before evaluating auxiliary role presentation. All original group-composition assertions, including ordinary sign-in during enabled repair, remain intact.

The classifier retains the existing mount barrier's permanent owner-failure refusal; restoring row bytes does not revive an observed stale mount. Its direct owner-row comparison is extra defence beside that barrier, not an independently reachable new authorization gate.

A final-await control signs out the real token after the core permit resolves but before the session context returns. The whole managed branch re-checks the actual session on refusal, preserving `revoked` without removing its final classifier or permit checks. This is classification only; a current but unauthorized session still receives the original permission refusal.
