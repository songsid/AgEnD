# Explicit administrator-approved fleet pairing

This corrects the manual-path narrowing identified in #3383 and follows the final [#3298 ruling](https://github.com/songsid/AgEnD/issues/3298#issuecomment-6715088331). Group permission governs self-service pairing. A configured Hub administrator can explicitly approve an eligible directory owner's exact pending pairing when no group grants self-service, including unknown membership. It grants no Chat, publication or self-service capability. An explicit per-person `pair_fleet` deny still blocks approval/claim and can suspend an existing manual fleet.

Approval freshly authenticates the configured administrator and checks the immutable owner's current directory eligibility. It captures the exact fleet/owner/fingerprint and records the approving PersonKey. A boolean from an older pending attempt is not an administrator identity; it needs fresh explicit approval. The approval write and its final session/policy fence share the owning transaction. Claim repeats eligibility and prepares a separate manual grant from the persisted approver. It never widens pre-enable `captureManual` or turns a group decision into human approval.

The actual credential/fleet, exact `source: manual` provenance and required `group-resource.admin-granted` audit commit together. The audit names the approving administrator and states that self-service permission was not required, without pretending unknown membership was a negative. Failed or reentrant required audit rolls everything back; an already advanced transport floor remains uncertain. The preparation is one-shot and tied to the owning active DB, current policy, lifetime and authorization version.

Manual issuance can exceed the per-person automatic limit. Retained manual fleets still count against a later automatic claim; global capacity includes all fleets. Automatic claims keep the fresh group allowance and quota check. Membership loss or group-policy switch-off alone does not suspend manual provenance; deliberate person denial, authoritative owner ineligibility and ordinary revoke remain effective. Unknown eligibility holds the action without durable suspension.

An intact never-enabled directory-generation repair preserves the ordinary pairing path without opening a mismatched strict policy store. The exact approver remains in the ordinary pairing record and audit; first enable captures its exact resource under the normal confirmed inventory. Enabled or corrupt repair is unavailable, never reset to legacy.

Transport metadata version 2 adds the optional persisted approver identity; existing state bytes remain unchanged on upgrade. Older binaries refuse the newer component. Before deployment or rollback, back up state and use the matching binary/backup; there is no live deployment in this change. Acceptance uses fake directory people, real loopback HTTPS sessions/admin-owner confirmations and real SQLite/audit/floor transactions.
