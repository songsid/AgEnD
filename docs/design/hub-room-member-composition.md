# Track C room member composition

This slice composes the #3860 adapter in the Fleet member factory against Track R's #3863 transport/dispatcher. It follows the existing private state selector and ordinary representative delivery. It creates no agent, model request, direct grant or alternate signed envelope. The contracts are `room.ask`, `room.answer`, `room.answer-ack` and `agent.state` from R2. The HTTP/UI room service remains owned by R/U; invitations, teams, assistant and roles are separate.

The factory always knows the additive `room-ask-v1` member migration. Before any direct or room recovery, it authenticates all retained room rows using the selected set's content key and immutable Hub/issuer/Fleet/owner binding. An unbound legacy set is checked before its pairing adoption can advance the journal floor. A matching already-bound set is checked before recovery; a proven foreign legacy set stays intact and the normal selector chooses the new binding's complete set. Location, origin, credential and authorization-version changes do not change that immutable namespace.

Only a host providing the complete room state callback causes the client to offer `room-ask-v1`; it remains absent from default optional capabilities. R2 negotiates both marks. The factory holds one wrapper per exact link with a captured authorization version. It is current only for that online link, current pairing and version. It starts the adapter and presence publisher after reconciliation. Link loss, a hold or fence clears both; a reconnect can flush frozen answers, but retained local queued work still needs a fresh exact `room.ask` from the Hub. R2's separate work queue means agent input never blocks ACK/control frames.

The current local mapping must be published under this owner/Fleet, use representative readiness, and match the durable consent's agent and lifecycle token. The ordinary delivery callbacks perform the final check and durable first-input intent. A delayed IPC failure is routed by exact correlation ID and agent to a held row, without overwriting a frozen/acknowledged answer. Reports first try the room adapter, then the existing direct representative. Existing direct question/grant/release behavior is unchanged.

Frozen answers retry on connect and a five-second timer until the exact answer ID is acknowledged. The same timer samples cached Fleet process/execution/interaction state. Publication changes also request a refresh. The existing publisher coalesces in-flight state reads and sends only changes. A positive approval state requires a current, non-suspected permission/dangerous-command wait; no vendor/pane probing occurs. Stopped/crashed processes send the portable stopped reason, wakeable idle sleep is Idle, and the viewer translates the reason. R/U must include the agreed `presenceReason` rendering and `stStopped` wording before the complete feature is presented. No Fleet-localized note or crash details are exported.

Teardown stops the timer, fences/clears room links, closes the adapters and finally the selected database. Late callbacks are guarded. The migration is additive; an older binary does not understand the component and must not be used to erase or recreate history. Rollback uses a compatible corrected build while retaining the database, floors, content keys and frozen answers. Withholding the negotiated feature prevents new room delivery without changing direct chat.
