# Private directory Save orchestration

M-2687 / S-112 / #3425, on the mounted response/session adapters in #3465–#3466. This module is not yet mounted on either HTTP listener. It grants no actor authority and introduces no browser capability, token/ref lookup or second settings writer. Durable notice delivery and the AD settings UI remain unfinished.

The caller supplies the existing proof controller and writer, exact current mounted control, host-lifetime check, serialized remount of the latest accepted config, and access to the existing decision participant. An unavailable mount may borrow the validated cold recovery participant synchronously through the same writer; it cannot create a replacement database or schema. The future configured-admin/D3 route must still acquire Origin/CSRF/session authority, trusted-directory reauthentication, candidate immutable identity and the one trust confirmation. Candidate/recipient metadata comes from the server's prepared plan, not a Save body.

The coordinator snapshots actor, credentials and delivery references before awaits and admits one Save at a time. The proof controller has an optional synchronous pre-commit hook: after current authentication/candidate checks and writer preparation, it captures the fully consumed original response, then rechecks the current proof before the synchronous writer decision. A Promise cannot stand for capture. Capture is never delayed until after awaiting apply, when the host's config-save microtask could already retire the listener.

After a known successful writer result, old session/generation currency is expected to end. The coordinator finishes physical remount independently of browser disconnect, using only the permanent host lifetime and a [bounded durable recovery intent](hub-directory-mount-intent.md). It verifies the original operation against the captured expected head and exact actor, then requires the mounted successor's exact operation and directory epoch. An audited root transaction closes that intent before success or cookie release. Only that successor's HubSessions may release the one-time rotation on the original response. Host recovery creates no browser session. A missing rotation on the administrator path is refused.

If the replacement does not mount, the only automatic recovery is a new forward compensation of that exact operation. A later head or material change refuses; there is no rollback of a database, policy, deny, resource, floor or epoch. The existing writer retains newer security state and queues another full notice. The coordinator passes the original bounded deadline into compensation so the writer's final clock sample, after proof/material checks, still enforces it. A final expiry after floor advancement preserves the existing uncertain-floor journal/hold. Compensation cannot recursively compensate itself.

A successfully remounted compensation returns `restored` with HTTP 503 and no replacement cookie; the old connection content is active, but its sessions remain ended and the person must sign in again. A failed restoration stays unavailable. A committed operation whose writer throws before returning a known receipt is not guessed at or automatically compensated by this request: the existing journal/recovery barrier owns physical completion, and the response is discarded. The allowance survives database reopen; the separate [startup reconciliation](hub-directory-startup-reconciliation.md) path handles a new runtime without competing with this request.

A refusal after response capture can still have a visible exit before any authoritative decision. Before sending `{ok:false, code, committed:false}`, the coordinator borrows the same Hub's decision participant and requires its complete stamp to equal the captured pre-decision stamp. The original mounted control, caller and host lifetime must also remain current through the response's final synchronous proof. Only known error classes and a closed set of codes/statuses cross the response; arbitrary exception text is never reflected, and no cookie is issued. The original rejection is still returned to the calling adapter. A public adapter must not write a second response after ownership was transferred.

An advanced head, an unreadable/uncertain floor, a foreign participant, Stop or a lost response refuses that packet. In particular, SQL rollback does not establish that the decision was harmless: a raised durable transport floor remains uncertain even if the SQL head and operation rows rolled back. Such cases discard the response and retain the existing journal/hold rather than claim that settings were not committed. The borrowed-stamp and old-mount stamp comparisons intentionally overlap; neither comparison alone is the whole no-decision proof.

Stop permanently fences late proof/remount/decision continuations. It starts response discard synchronously, then waits for the physical work and positive cleanup. A rejected cleanup retains the response for a later close retry. Ambiguous browser delivery never reuses the rotation handle or draft.

Evidence uses inert controller controls plus owned CA-verified HTTPS with the real proof controller, shared file writer, SQLite decision, runtime and cold recovery. It covers a normal successor cookie on the original response and a deliberately refused replacement mount followed by forward restoration: epochs/operations/full notice rows advance to two, old sessions remain ended, no cookie is returned, and the Hub is ready again. Pre-decision refusal returns 409 with the old session still valid; an injected post-decision failure and an audit failure after floor advancement both close without a refusal claim or cookie. Existing writer controls retain newer denies and refuse a later rename. No public route, browser, real directory/account, native manager, pilot or live fleet is driven.
