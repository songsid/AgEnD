# Hub 聊天室：畫面規格（第二段：房間與房間助理）

給實作的人看。產品決定在 `hub-product-plan.md`（2026-11-13，R1–R10 照建議）；分工與介面在 `hub-rooms-split.md`。
示意圖：`docs/evidence/hub-product-plan/q1-room.png`（房間）、`q2-room-settings.png`（新房間、權限、邀請）、`q3-teams.png`（團隊，第三段）。

擁有者的要求：**聊天模組照 AgEnD 最新的聊天室做，每個細節都一樣。** 所以這份規格只寫 Hub 和 Fleet 聊天**不同**的地方；沒寫到的，一律和 Fleet 聊天相同，用同一個共用模組（`src/ui/shared/chat-*.js`），不另寫一份。

## 1. 用詞

| 中文 | English | 說明 |
|---|---|---|
| 對話 | Chat | 一對一：我和一個 Agent |
| 房間 | Room | 多個人加多個 Agent |
| 成員 | Members | 房間裡的人 |
| 房間管理 | Room manager | 可以管理成員與設定的人 |
| 房間助理 | Room assistant | Hub 提供、只屬於這個房間的 AI |
| Hub 助理 | Hub assistant | 一對一清單裡的同一個東西 |
| @所有 Agent | @All agents | 房間裡每個 Agent 各回一則 |
| 邀請 | Invitation | 請別人的 Agent 進房間 |
| 稍後回覆 | Reply later | 目前不在線上，上線後補答 |
| 團隊 | Team | Hub 的虛擬團隊（第三段） |

不用的詞：群組（留給 AD 群組）、頻道、聊天室（畫面上一律叫「房間」）、機器人、bot。

## 2. 整體版面

和 Fleet 聊天相同的三欄：左側清單、中間對話、右側面板（可收合，手機是底部抽屜）。Hub 沒有的 Fleet 專屬項目不出現：View、Log、Details、檔案與變更、工具步驟、斜線指令。

**左側清單**，由上到下：

1. Hub 名稱；搜尋框「搜尋」。
2. 分組「房間」：每列是方形頭像（房間名稱第一個字）、名稱、第二行「3 人 · 12 個 Agent」、未讀數。
3. 分組「Agent」：一對一。每列是圓形頭像加狀態圓點、Agent 名稱、第二行擁有者姓名。「Hub 助理」排在這一組最後，第二行「Hub 提供」。
4. 底部兩個按鈕：「＋ 新對話」「＋ 新房間」。沒有開房間權限的人看不到「＋ 新房間」。
5. 排序：有未讀的在前，其餘依最後一則訊息的時間。釘選、收藏的行為與 Fleet 側欄相同。

空的時候：「還沒有對話」「用「新對話」開始；清單裡是允許你提問的 Agent。」；有開房間權限的人多一句「也可以開一個房間，把人和 Agent 放在一起。」

## 3. 房間的對話區

**標題列**：方形頭像、房間名稱、「3 人 · 12 個 Agent · 房間助理」；右邊是成員面板的開關與選單（房間設定、離開房間）。

**訊息**，和 Fleet 聊天相同的泡泡、時間、Markdown、程式碼區塊與複製、回覆與引用、複製文字、複製連結。不同的地方：

- 每一則都顯示作者：
  - 人：姓名。自己的訊息靠右，不顯示姓名。
  - Agent：「project-helper · 林小華的 Agent」。
  - 房間助理：「房間助理 · Hub 提供」。
- 訊息裡的 @ 用強調色。
- 沒有 @ 任何 Agent 的訊息只是人和人的對話，沒有送達狀態。

**@ 了 Agent 的訊息**下方有一行進度，會即時更新：

- 一個 Agent：沿用 Fleet 聊天的送達標記（等待 → 已送達 → 已回答）。
- 多個 Agent：「已回答 7 · 處理中 2 · 稍後回覆 3」。全部回答後變成「12 個都回答了」。
- 回答以「回覆」的形式接在這一則底下（和 Fleet 聊天的回覆相同，點了會跳到原訊息）。超過 3 則時先顯示前 3 則，加一個「展開其餘 7 則」；展開後每則照到達順序排列。
- 稍後回覆的 Agent 列在最後：「report-bot（吳小安）· 上線後回答」。它回答時，訊息補在這一串裡，並在清單上算一則未讀。
- 24 小時沒有回答：「沒有回答」。

**房間助理的回答**用淡綠底色的泡泡，其他都和 Agent 的回答一樣。

**處理中**：和 Fleet 聊天相同的工作列（WorkBar），文字是「project-helper 正在處理」；多個同時處理時「9 個 Agent 正在處理」。不顯示工具步驟。

## 4. 輸入框

和 Fleet 聊天相同：多行、Enter 送出、Shift+Enter 換行、附加檔案、貼上圖片、草稿保留、回覆中的提示列。不同的地方：

- 佔位文字：「在「研一主管週會」說話；@ 一個 Agent 請它回答」。
- 打 `@` 出現選單，依序：
  1. 「@所有 Agent」，右邊小字「12 個都會回答」。房間關閉這個功能時不出現（房間管理仍然有）。
  2. 「@房間助理」，右邊「Hub 提供」。房間沒有助理時不出現。
  3. 房間裡的每個 Agent：名稱，右邊是擁有者姓名與狀態圓點。可以打字篩選（名稱或擁有者）。
  4. 房間裡的人（@ 人只是提醒對方，Agent 不會因此回答）。
- 選了「@所有 Agent」，輸入框上方出現一行：「12 個 Agent 中 9 個在線上，3 個上線後回答」。
- 輸入框下方的固定小字：「沒有 @ 任何 Agent 的訊息只有房間裡的人看得到，Agent 不會回答。」
- 斜線指令不適用：開頭打 `/` 當成一般文字。

送不出去時的訊息（沿用 Fleet 聊天「沒有送出：…」的位置與重試）：

| 情況 | 文字 |
|---|---|
| 這個房間不允許成員 @所有 Agent | 「這個房間只有房間管理可以 @所有 Agent。」 |
| 已經不是成員 | 「你已經不在這個房間裡。」 |
| 房間已封存 | 「這個房間已封存，不能再發言。」 |
| 房間助理不可用 | 「房間助理暫時無法回答。」其餘照常送出 |
| 連不上 Hub | 和 Fleet 聊天相同：「沒有送到…，請檢查網路連線」與「重試傳送」 |

## 5. 右側面板：成員

標題與順序：

1. 「成員 · 3（線上 2）」：頭像、姓名、身分（「你」「管理」），第二行是圓點加狀態。
2. 「Agent · 12（線上 9）」：頭像、名稱，第二行是圓點加狀態；滑過顯示擁有者。排序：處理中、待命、暫停、離線、上線時回答。超過 8 個時收合成「… 其餘 7 個」。
3. 房間助理（有的話）。
4. 「誰看得到」：「房間裡的每個人都看得到所有訊息與回答。Agent 被 @ 時會讀到最近的對話。」
5. 連結「房間設定」（房間管理才有）。

狀態的圓點與用詞（和 Fleet 側欄相同的顏色）：

| 對象 | 圓點與文字 |
|---|---|
| 人 | 綠「線上」／灰「離線」 |
| Agent | 綠「待命」／跳動的綠「處理中」（和 Fleet 側欄相同）／黃「暫停」加原因（「額度用完」「等待登入」「等待核准」）／灰「已停止」（Agent 本身停了或當掉，Fleet 還連著）／灰「離線」（Fleet 連不上）／灰「需要更新 AgEnD」 |
| 上線時回答的成員（第四段） | 綠「線上」／灰「上線時回答」 |
| 房間助理 | 綠「待命」／跳動的綠「處理中」／黃「暫時無法回答」 |

睡著但會被訊息喚醒的 Agent 算「待命」。「已停止」和「離線」一樣算不在線上：問題排隊，回來後補答。原因只給固定的幾種說法，不顯示當掉的細節。

點一個 Agent：小卡片顯示名稱、擁有者、狀態，兩個動作「在這裡 @ 它」「和它一對一對話」（後者只在我被允許提問時出現）。房間管理另有「從房間移除」。

## 6. 新房間

入口：左側「＋ 新房間」。對話框標題「新房間」。

| 欄位 | 內容 |
|---|---|
| 名稱 | 必填，最多 60 個字。佔位「例如：研一主管週會」 |
| 成員 | 搜尋框「加入人、團隊或 AD 群組：輸入名稱搜尋」。選到的顯示成標籤；自己固定在內，標示「管理」。團隊與 AD 群組的標籤顯示人數 |
| Agent | 搜尋框「加入自己的 Agent，或邀請別人的」。自己的 Agent 直接加入；別人的顯示「邀請 · 等擁有者同意」。可以選「邀請這個團隊所有人的 Agent」 |
| 房間助理 | 開關「加入房間助理（Hub 提供）」。Hub 沒有啟用時不顯示 |

按鈕：「建立」「取消」。建立後直接進入房間；房間裡第一則是系統訊息：「王經理 建立了這個房間。」，有邀請時再一則「已邀請 7 個 Agent，擁有者同意後會加入。」

名稱沒填：按鈕不反灰，按了把游標放到名稱欄並顯示「請輸入房間名稱。」（和 Hub 其他表單的做法相同）。

## 7. 房間設定

入口：標題列選單或右側面板。分三段：

**基本**
- 名稱（可改）。
- 「成員可以 @所有 Agent」開關，預設開。
- 「新成員看得到」：「加入之後的訊息」（預設）／「全部的歷史訊息」。

**成員與 Agent**
- 兩張清單，每列右邊的選單：「設為房間管理」／「改為成員」「從房間移除」。
- 「加入成員」「加入或邀請 Agent」，和新房間的搜尋框相同。
- 等待中的邀請列在 Agent 清單下方：「project-helper（林小華）· 已邀請，等擁有者同意」，可以「取消邀請」。
- 房間助理的開關。

**其他**
- 「封存房間」：確認框「要封存「研一主管週會」嗎？房間會變成唯讀，內容仍然看得到。」按鈕「封存」「取消」。
- 「離開房間」（每個人都有，在標題列選單）：最後一位房間管理不能離開，提示「請先把另一個人設為房間管理。」

系統訊息（灰色置中，和 Fleet 聊天的系統列相同）：「陳主任 加入了房間」「project-helper（林小華的 Agent）加入了房間」「王經理 把房間改名為「…」」「房間助理已加入」。

## 8. 邀請：擁有者這一邊

- **在哪裡看到**：Hub 左側清單上方出現一列「邀請 · 2」；「我分享的 Agent」頁面上方也有同一張清單。
- **每一筆**：「王經理 邀請你的 Agent「project-helper」加入房間「研一主管週會」」，小字「房間裡的 3 個人可以在那裡 @ 它；它的回答房間裡的人都看得到。」，按鈕「同意」「不要」。
- 同意後：這一筆消失，房間裡出現加入的系統訊息；「我分享的 Agent」那個 Agent 的頁面多一段「在這些房間裡」：房間名稱、人數、「退出這個房間」。
- 擁有者暫停分享這個 Agent 時，它在所有房間顯示「暫停」，恢復分享後自動回來，不用重新邀請。
- 邀請 7 天沒有回應就失效，房間管理看到「邀請已過期」，按「重新邀請」可以再邀一次。

## 9. 一對一對話

維持現在的行為，只換成和房間相同的版面與元件：

- 清單裡的一列，圓點是 Agent 的狀態。
- 每一則都會得到回答，不需要 @。
- 右側面板改為：這個 Agent（名稱、擁有者、狀態）、「我可以問到 {日期}」、「誰看得到」（「這個對話只有你看得到。Agent 的擁有者看得到你問了什麼。」）、訂閱額度的概略狀態（有開放時）。
- 「新對話」的選擇畫面不變，加上狀態圓點。

## 10. 房間助理

**在房間裡**（使用者看到的）
- 是成員清單裡的一個，名稱固定「房間助理」，第二行「待命 · Hub 提供」。
- 被 @ 才回答。常見的三種說法在輸入框裡不另做按鈕；但在「@所有 Agent」那一則的進度行右邊，有回答之後出現一個小連結「請房間助理整理」，按了等於送出「@房間助理 整理上面的回答」。
- 它每次回答都只讀這個房間最近 30 則訊息，不記得更早的內容。回答的泡泡底下小字：「根據這個房間最近 30 則訊息」。
- 要它處理更早的內容，用「回覆」點那一則訊息再 @ 它：被回覆的那一則會一起帶給它。
- 額度用完或超過同時執行的上限：狀態變黃「暫時無法回答」，@ 它的訊息下方顯示「房間助理暫時無法回答，稍後再試。」超過上限但可以排隊時顯示「房間助理正在別的房間忙，稍後回答。」

**一對一的「Hub 助理」**
- 清單「Agent」分組的最後一列。每個人自己的對話，只有自己看得到。
- 第一次打開的空白畫面：「這是 Hub 提供的 AI 助理。它讀不到你的電腦，也讀不到其他房間。」

**管理 → 房間助理**（Hub 管理員）

| 區塊 | 內容 |
|---|---|
| 開關 | 「啟用房間助理」。關閉時所有房間的助理顯示「暫時無法回答」 |
| AI 帳號 | 後端（下拉）與帳號狀態：「已登入」／「需要登入」加一句怎麼登入（在 Hub 這台電腦的 AgEnD 設定裡）。小字：「房間助理使用這個帳號的額度。」 |
| 同時執行 | 「同時最多幾個」數字欄（預設 3）；「閒置幾分鐘後停止」（預設 15） |
| 現在 | 清單：哪些房間的助理正在執行或待命、最後使用時間，每列可以「停止」 |
| 用量 | 近 7 天每天的回答次數；帳號額度的概略狀態（充足／快用完／用完） |

還沒設定時的空白狀態：「房間助理還沒有啟用。」「先在這台電腦的 AgEnD 登入一個 AI 帳號，再回來開啟。」

## 11. 管理 → 房間（Hub 管理員）

- 「誰可以開房間」：預設只有管理員。搜尋框「加入人或團隊」，選到的顯示成標籤。小字：「每個人都可以開一對一對話。」
- 「所有房間」：名稱、人數、Agent 數、房間管理是誰、最後活動時間、狀態（使用中／已封存）。管理員看不到內容，小字：「這裡看不到任何房間的內容。」每列選單：「加入自己成為房間管理」（之後就看得到內容，房間裡會出現系統訊息）、「封存」。

## 12. 未讀與通知

- 清單每列的未讀數；瀏覽器分頁標題前加「(3)」；和 Fleet 聊天相同的桌面通知（要先允許）。
- 會算未讀的：房間裡別人的訊息、@ 我的訊息（列上多一個 @ 標記）、我 @ 的 Agent 的回答、新的邀請。
- 打開房間並捲到底，就算讀完。

## 13. 驗收時我會走的路

1. 管理員指定王經理可以開房間；王經理開「研一主管週會」，加兩個人、自己的 Agent、邀請一個團隊的 Agent、打開房間助理。
2. 三位擁有者中兩位同意、一位不理；房間顯示兩個 Agent 加入、一個等待中。
3. 王經理 @所有 Agent：一個在線上的馬上答，一個離線的列在稍後回覆；讓它上線後補答。
4. 王經理按「請房間助理整理」；再用回覆追問其中一個 Agent。
5. 陳主任（成員）發一則沒有 @ 的訊息，再 @ 一個 Agent；確認王經理那邊的未讀與通知。
6. 關掉「成員可以 @所有 Agent」，陳主任再試一次。
7. 一對一對話、Hub 助理、封存房間、離開房間。
8. 以上在桌面與手機寬度、中文與英文、淺色與深色各看一次；Fleet 自己的聊天不能有任何可見的改變。
