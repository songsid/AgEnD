# Claude Code model observations

Detection only. AgEnD never changes a model, policy, permission or lifecycle state because of these observations.

The configured model is the saved selection. The launch model can differ when the existing next-spawn failover policy selected it. The session model comes from this launch's statusline hook. The last served model comes only from main-thread assistant `message.model`; it is an observed response, not a final-answer attestation. These values stay separate.

Typed `model_refusal_fallback` and `model_fallback` records confirm safeguards and availability switches. Keep `originalModel`, even when `requestedModel` already names the fallback. A concrete unexpected served model without a typed notice is labelled only as an observed difference, with unknown cause/scope. A local fallback is a turn; omitted historical refusal scope is a session. Same-model retries and `model_refusal_no_fallback` are not switches.

Only concrete Claude Opus/Sonnet/Haiku version IDs are compared, ignoring case, recognized date suffixes and `[1m]`. Family aliases, `default`, `best` and `opusplan` remain unresolved; a statusline alone cannot resolve their historical turns. Main-thread Haiku is valid. Synthetic, API-error, refused, sidechain, subagent and marked auxiliary records are excluded. No verified universal marker identifies an otherwise-unmarked main-file assistant row as auxiliary; Haiku or proximity to compaction never supplies that missing evidence. Arbitrary text, prompts, API refusal explanations and SDK snake_case events are never detection inputs.

Each launch explicitly prepends `AGEND_CLAUDE_LAUNCH_ID=<random UUID>` to the existing command environment. This non-secret observational nonce selects no model, policy, credential or permission and grants no authority. It is inherited by the CLI and its statusline child, whose existing hook stamps it into statusline JSON; arbitrary children still gain no metadata admission without the main-file/session filters. The inherited value, rather than a rewritten script's embedded current value, distinguishes an old hook from the next launch. All other launch bytes, including credential and cache-TTL behavior, stay unchanged. The hook stamps that inherited marker, so a late old hook cannot impersonate a new launch by executing the rewritten script. A record needs the current marker, matching session and main JSONL path, current daemon/monitor/launch generation, a new append, and a timestamp within this launch. Resume/bootstrap history is a baseline. A startup metadata-only tail (at most 8 MiB of physical reads including boundary discovery, and 2,000 records, with the separate existing 16 MiB whole-line bound) can recover records written by this exact launch before monitor construction; it never replays existing text, tools or usage alarms. The tail verifies a complete line at or before its captured cursor; it never scans a later unfinished suffix. If its boundary/read budget runs out, it omits incomplete records. The earlier inherited monitor baseline lookup is unchanged. UUID/message-model dedupe handles repeated blocks; a bounded v2 metadata checkpoint keeps an existing incident quiet across resume and persists no-intent, unresolved-intent and concrete-unconfirmed-intent separately. Legacy v1 or invalid/missing intent is restored as unresolved, because replay dedupe may already contain the omitted command. A fresh return to the configured/original model retires it. Repeated notices update the same incident. A new incident after recovery gets a new Needs-you identity.

AgEnD's own `/model` intent and outcome update the expected model only on the existing successful outcome. Raw command markers are unconfirmed intent; matching concrete statusline and response metadata corroborate an intentional change. An unresolved picker or alias intent remains unconfirmed: metadata-only mismatch inference stays off until a concrete owned/confirmed selection, a new session or a typed fallback notice. Served-model values continue to update and typed fallback notices still register; a served value alone never resolves the alias. Typed fallback evidence still applies. Existing automatic next-spawn failover is unchanged.

The instance card/details and Log localize cause, pair and scope. Needs you lists one item per incident; subsequent observations are quiet and recovery removes it. `describe_instance` adds only an active four-field switch summary by default; `detail:true` adds the bounded configured/launch/session/served observation. No transcript, prompt or arbitrary explanation is exposed.

Evidence basis: Ridge's portable redacted producer handoff, Claude Code 2.1.323, binary SHA-256 `604d29a6869409106b6a1110bdadcc8b72e8654a5a865d23258f938a696e348e`, embedded build `66b1ade1dce6269a9b608cea1920135b24a97a66`, built 2026-11-12. Historical observed versions were 2.1.226–2.1.316. Availability shape was verified in the producer, not observed in the historical main-thread sample. Fixtures use synthetic identifiers and model/time metadata only. No vendor API or live pane is required. Opaque upstream substitutions with unchanged metadata remain undetectable. A CLI launch predating the marker becomes observable at its normal next restart; detection never initiates that restart.

Rollback removes the observational readers, fields and optional checkpoint. It does not alter configured models, policies, transcripts or runtime permissions.
