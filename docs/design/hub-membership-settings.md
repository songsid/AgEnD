# Owner Settings for Hub membership

On the fleet's own dashboard, open **Settings → Access & security → Hub membership**. The switch is available while membership is off. It changes only the boolean `hub_member.enabled`; enabling still requires the existing local-owner Settings confirmation. Pairing a Hub and sharing a representative agent remain separate owner choices. Neither a Hub account nor an agent can supply this local approval. Public-link pages show no control and both the confirmation gateway and route refuse their requests.

Off remains the default. Turning the switch off uses the existing immediate narrowing continuation and runtime switch observer: new work and later answer disclosure stop, while input already delivered to an agent's shared conversation remains there. Pairing/exposure records, working folders, tools and credentials are not edited by this switch. Re-enabling does not publish an agent or manufacture new consent.

The endpoint reads the raw switch because resolved fleet configuration does not contain Hub sections. Confirmation classifies a captured bounded `fleet.yaml` snapshot, so an old cached on value cannot bypass approval after a manual file edit turned it off. Existing Settings fingerprints reject a changed file or revoked owner before execution. A save applies just the enabled leaf through the lossless atomic configuration writer and the existing Hub observer. Invalid/unknown state is unavailable, never implicit consent.

The small lazy Settings module uses existing shared exports and owns its EN/zh-TW strings. It loads no Hub client or pairing module while off. On an already marked member page, saved enablement exposes the existing pairing card. When the saved flag differs from the page's original Hub mark, the owner reloads to refresh those controls; a stale off page never selects a stub pairing client. An old panel simply has no new switch. Older-server or ambiguous responses disable changes until a fresh read.

Acceptance uses scratch configuration, the actual Settings gateway/confirmation/replay/save path with inert runtime/notification adapters, plus renderer and real-browser cache cases. No live fleet, real account, directory, host service or pilot is used. The format remains one existing boolean; rollback removes the UI/route and leaves the saved value usable by existing configuration and runtime handling.
