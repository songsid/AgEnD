# Directory security notices on the Hub listener

M-2687 / S-112 / [#3425](https://github.com/songsid/AgEnD/issues/3425), following the durable [recipient history service](hub-directory-security-notices.md). The sealed server factory now creates that service over its existing owning database, audit and transport store, binds it to the mounted generation and closes it during teardown. It adds no migration or settings writer.

The Hub listener exposes `GET /hub/v1/security-notices/directory` and `POST /hub/v1/security-notices/directory/:id/ack`. GET accepts only singular `before`, `limit` and `unread` query parameters; `unread=1` selects unread rows. The service retains its default 50 / maximum 100 page limit and exact owned UUID cursor. ACK does not depend on which page was loaded. Both use the actual Hub session context and fresh immutable eligibility; ACK additionally requires the existing same-origin and CSRF checks. Operational group permissions and administrator status grant no extra notice access.

After either asynchronous service call returns, the route rechecks the mounted generation and the actual session before sending a response. A sign-out during a held response yields signed-out; a real directory epoch/head change yields unavailable. An ACK that committed before a later sign-out remains a committed ACK: refusing the late response does not pretend to undo that earlier transaction.

`directory-security-notices-v1` is offered only when the service is supplied, independently of group permissions. Older injected entries omit the mark and answer 404. Existing tabs ignore the new mark; no UI module or EventSource changes here. This is authenticated pull access, not yet the notice presentation or host Needs-you integration. The fixed host target remains queued when a person acknowledges their own target. AD Save and the write-only form are still uncomposed.

Evidence uses the initialized sealed Hub, real runtime, shared settings writer, SQLite and verified loopback HTTPS. Dummy directory methods are in-process, not a real LDAP service. The tests sign in through the public session route, perform real directory decisions/remounts, check old-cookie refusal, original-recipient isolation, groups-absent access, CSRF/origin/method/query refusals, older pages, exact ACK, durable reopen and late-session/epoch response fences. No browser, real directory/account, vendor, native manager, pilot or live fleet is driven. Source removal restores the prior missing-feature behavior; it does not require a database rollback.
