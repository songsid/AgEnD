# Hub 產品計畫：讓主管問得到團隊的 Agent

狀態：提案，等擁有者決定（2026-11-13）。只有設計與規劃，沒有程式。
對照的原始碼：`release/2.3.5-alpha` @ `db484be1`（2.4.0-alpha.3 之後）。文件中的位址一律用 `hub.example.com`。

## 1. 目標，用一句話

**主管打開 Hub，選「整個團隊」，問一個問題，幾分鐘後看到每個人的 Agent 的回答，以及一份整理。**

現在的替代做法是 Telegram 的 ClassicBot 群組：把一個團隊的 Agent 拉進同一個群，主管一次 @ 全部，再由主管自己的 bot 讀完整理。它的問題是每個人都要自己建 bot、建群，群一多就分不清哪個 bot 是誰的。

Hub 要取代它，所以判斷每一項工作的標準只有一個：**它有沒有讓這句話更快成真。**

三個推行目標（擁有者的原話）：

1. 很多人用最簡單的方式綁上 Hub。
2. 研一日報的橫幅放一個連結與教學，讓部署人員照著裝。
3. 教學要簡單：截圖加說明，繁體中文。

正式上線時 Hub 會有正式的憑證與網域；自簽憑證與 IP 只在試行期間使用。

## 2. 現在離目標多遠

| 目標的一段 | 現在 | 差距 |
|---|---|---|
| 同仁加入 Hub | 公司帳號連接、加入碼、AD 群組都已完成。**但有三種連接方式並列**，試行的自簽憑證讓主要的那一種走不通（#3839），退到配對碼又要三次確認（#3840） | 入口要剩一個；沒有「從連結開始」的頁面 |
| 擁有者分享給團隊 | 可以分享 Agent；可以允許一個 AD 群組或用姓名搜尋（#3781）；可以暫停再恢復（#3803） | 分兩個地方做（Fleet 分享、再到 Hub 允許）；加入之後沒有人提示下一步 |
| 主管問一個 Agent | 已完成（新對話 → 選 Agent → 提問） | 回答是否送達只有文字狀態；沒有通知 |
| **主管一次問整個團隊** | **沒有** | 這是目標的核心，整段不存在 |
| **整理成一份** | **沒有**。Hub 本身不執行任何 AI | 要決定由誰整理 |
| 主管看團隊誰加入了 | 角色與權限的伺服器模型已合併、未啟用；沒有畫面 | 第二階段 |

結論：加入與分享的零件都有了，缺的是把它們接成一條路，以及目標本身（一次問全部、整理）。

## 3. 目標流程

### (a) 新同仁：從日報的連結到連上 Hub，四步

1. 點日報橫幅的連結，打開 Hub 的「加入」頁（`https://hub.example.com/join`，不用登入就看得到）。
2. 照頁面上的一行指令安裝 AgEnD。指令已經帶著 Hub 的位址。
3. 安裝完成後自動開啟自己的儀表板，Hub 位址已填好；按「以公司帳號登入」。
4. 在開啟的 Hub 分頁輸入公司帳號與密碼。分頁自動關閉，回到自己的頁面，看到「已連接」。

已經裝好 AgEnD 的人從第 3 步開始：在「加入」頁按「連接我的 AgEnD」，會開啟自己儀表板的「設定 → Hub」，位址已填好。

不需要加入碼、配對碼、指紋。管理員事先把研一的 AD 群組加進「讓同仁加入」即可（已有功能）。

示意：`docs/evidence/hub-product-plan/p1-join-page.png`

### (b) 擁有者：連上之後，一步分享給團隊

連接完成的同一頁直接出現下一步，不必另外找：

> **分享一個 Agent 給團隊**
> 選一個 Agent　·　誰可以問：☑ 研一主管（管理員建議）　·　〔分享〕

按一次「分享」，完成本機確認（和現在相同），就同時做完「分享」與「允許提問」。現在這是兩個地方的兩件事。

- 「誰可以問」預設帶入 Hub 管理員設定的建議對象（一個 AD 群組）；擁有者可以改、可以不勾。**永遠是擁有者自己按下去的，不會自動分享。**
- 之後要暫停，在同一列關掉開關；再打開時允許名單還在（#3803 已完成）。

示意：`docs/evidence/hub-product-plan/p2-share-step.png`

### (c) 主管：問一個，或一次問整個團隊

Hub 的「新對話」改成可以多選：

1. 按「新對話」。清單列出所有允許我提問的 Agent，依擁有者的部門分組；每組有「全選」。
2. 選「研一 · 全選（12）」，輸入問題，按「送出」。
3. 進入一個「團隊提問」的畫面：上方是問題，下方每個 Agent 一列，各自顯示等待中、已回答、離線。回答進來就展開。
4. 按「請我的 Agent 整理」。主管自己 Fleet 的 Agent 讀完這些回答，回一份整理，顯示在最上方，也會出現在主管自己的聊天裡（接了 Telegram 的話，Telegram 也收得到）。

常用的對象可以存成清單（例如「研一 一部」），下次一按就選好。

問一個 Agent 的流程不變。

示意：`docs/evidence/hub-product-plan/p3-team-ask.png`

### 這取代了 Telegram 群組的什麼

| Telegram 群組的做法 | Hub 的做法 |
|---|---|
| 每個人建自己的 bot、被拉進群 | 每個人把自己的 Agent 分享給團隊；身分是公司帳號，畫面上永遠寫著擁有者是誰 |
| 主管一次 @ 全部 | 「新對話」多選，一次送出 |
| 所有人看得到所有回答 | 回答只有主管看得到；每個 Agent 在自己擁有者的 Fleet 裡、用自己的資料回答 |
| 主管的 bot 讀完整理 | 「請我的 Agent 整理」，由主管自己的 Agent 做 |

## 4. 請擁有者決定

| # | 問題 | 建議 | 理由與代價 |
|---|---|---|---|
| P1 | 用「一次問多個 Agent」取代群組，還是做「共用的團隊房間」（#3765）？ | 做一次問多個；#3765 先不做 | 目標是「主管問得到」。房間仍然需要某個人的 ClassicBot 房間與頻道，沒有解決「每個人都要建 bot 與群」。房間裡所有人互相看得到，適合討論，不適合主管收集各自的回答。之後有討論的需求再做 |
| P2 | 誰來整理？ | 主管自己的 Agent | Hub 不執行任何 AI，也不登入任何 AI 帳號，這一點不該改。代價：主管自己要有一台連上 Hub 的 Fleet；別人 Agent 的回答會進到主管的 Agent 裡，內容不可信，整理時要當成資料、不能當成指令 |
| P3 | 「團隊」怎麼定義？ | 第一版不定義：主管多選，並可以存成清單。依 AD 群組自動分組放到角色功能啟用之後 | 多選不依賴尚未啟用的角色功能，最快可用。代價：主管第一次要自己選一次 |
| P4 | 加入後要不要自動分享一個 Agent？ | 不自動。顯示下一步，預先勾好管理員建議的對象，由本人按 | 分享代表別人可以讓你的 Agent 用你的額度、在你的資料夾裡回答，必須是本人的決定 |
| P5 | 試行期間的自簽憑證怎麼辦？ | **把正式憑證與網域提前到試行就用**；不做「靠連結信任」 | 三種連接方式今晚都不好用的根本原因是憑證。提前之後主要的那一種直接可用，其他兩種就可以收起來。「靠連結信任」是只為試行做的安全例外，上線後用不到。若憑證無法提前，退而求其次是 #3839 的訊息修正加上一個安裝憑證的指令 |
| P6 | 配對碼與「連接我的 Fleet」一次性代碼要不要收起來？ | 公司帳號連接開啟時，兩者都不顯示；保留在管理員的「進階」，給沒有 AD 的 Hub | 這就是「三種方式」變成一種。代價：沒有 |
| P7 | 一次問很多人會用掉很多人的額度，要不要限制？ | 要：每人每天的團隊提問次數上限、一次最多的 Agent 數；擁有者看得到誰問了（已有） | 數字在規格階段訂，先建議每天 20 次、一次最多 50 個 |
| P8 | 同仁該分享哪一個 Agent？ | 教學建議分享「自己專案用的那個 Agent」；General 不預選 | General 是整個 Fleet 的協調者，權限最大，不適合預設拿來回答別人 |

### 要收起來或拿掉的

- Fleet「設定 → Hub」的「其他方式」（配對碼）：公司帳號連接可用時不顯示。
- Hub 首頁「連接你的 Fleet」底下的一次性代碼：同上。
- 管理員卡片的「含金鑰指紋的連結（進階）」：有正式憑證後不顯示。
- 管理員的「進階：使用配對碼連接」：留著，只給沒有 AD 的 Hub。
- Fleet 頁面最上方的「設定 Hub」卡片：只在還沒連接任何 Hub、而且是這台電腦的主機登入時顯示。一般同仁不需要看到「架一個 Hub」。

## 6. 分階段

### 試行（現在，自簽憑證或提前拿到的正式憑證）

目的：讓幾個人順利連上，驗證「加入 → 分享 → 問一個」。

- 第 3 項：入口只剩一個。
- 第 8 項：合併 #3842。
- P5 的決定：憑證提前，或訊息修正加安裝憑證的指令。
- 我用實際版本重走一次加入與分享，更新流程板。

### 上線（正式憑證與網域）

目的：研一全體照日報的教學裝好、連上、分享；主管可以一次問整個團隊。

- 第 4 項：從連結加入。
- 第 5 項：連上之後一步分享。
- 第 1 項：一次問多個 Agent。
- 第 7 項：存成清單。
- 第 9 項：搬到正式網域。
- 第 11 項：教學與橫幅。

### 上線之後

- 第 2、6 項：請我的 Agent 整理、通知。
- 第 10 項：角色與主管的團隊檢視。
- 定時提問（例如每天早上問整個團隊昨天的進度），以及從主管自己的聊天（Telegram）直接發起。這兩項都建立在「請我的 Agent 整理」之上。

「整理」放在上線之後，是因為它要新的協定與一項安全設計（P2 的代價）；先讓主管看得到所有回答，本身就已經取代群組的大部分用途。若擁有者認為沒有整理就不算達成目標，它可以提前到上線，代價是上線日期往後。

## 7. 教學計畫（日報橫幅用）

流程確定後由我撰寫。形式：一頁，繁體中文，每一步一張截圖加一兩句話；放在 Hub 的「加入」頁，日報橫幅只放一句話與連結。

橫幅文字（草稿）：「把你的 AgEnD 連上研一 Hub，三分鐘完成 →」

大綱與截圖清單：

| 段落 | 內容 | 截圖 |
|---|---|---|
| 這是什麼 | 兩句話：Hub 讓主管與同事可以問你的 Agent；你決定分享哪一個、誰可以問 | 無 |
| 1 安裝 | 複製一行指令、貼到終端機 | ① 終端機貼上指令；② 安裝完成的畫面 |
| 2 連接 | 自動開啟的頁面上按「以公司帳號登入」，輸入公司帳號密碼 | ③ 設定 → Hub，位址已填好；④ Hub 的登入頁；⑤「已連接」 |
| 3 分享 | 選一個 Agent，按「分享」，完成確認 | ⑥「分享給團隊」這一步；⑦ 確認卡；⑧「分享中」 |
| 已經裝過 AgEnD | 從「連接我的 AgEnD」開始 | ⑨ 加入頁上的按鈕 |
| 主管怎麼問 | 新對話 → 全選 → 送出 | ⑩ 多選；⑪ 團隊提問的畫面 |
| 遇到問題 | 三個最常見的訊息與做法；找誰 | ⑫ 一個訊息的例子 |

截圖從實際版本擷取，帳號與名稱用示範資料。教學同時更新內建的 `hub` 技能，讓同仁也可以直接問自己的 Agent。

## 8. 安全上的代價（照實說）

| 改變 | 代價 | 減輕的做法 |
|---|---|---|
| 一次問多個 Agent | 一個人的一個問題會讓很多人的 Agent 同時工作，用掉他們的額度；問題的內容會進到每個人的 Agent 對話裡 | 每個 Agent 仍然個別檢查授權；次數與數量上限；擁有者看得到誰問了、可以隨時暫停 |
| 請我的 Agent 整理 | 別人 Agent 的回答進到主管的 Agent。回答裡若有惡意的指示，主管的 Agent 可能照做 | 回答以資料的形式送入並標明來源；整理用的對話不給工具；結果由主管自己看 |
| 加入頁不用登入就看得到 | 內網裡任何人都看得到 Hub 的名稱與安裝方式 | 頁面不含任何人員、Agent 或加入碼 |
| 「連接我的 AgEnD」開啟本機儀表板並帶入位址 | 任何網頁都可以做出同樣的連結，把別的位址帶進去 | 帶入的只是輸入框裡的文字，仍然要本人按「以公司帳號登入」；頁面照常顯示查到的 Hub 名稱與身分是否改變 |
| 建議的提問對象預先勾好 | 同仁可能沒細看就按了分享 | 那一步用一句話寫明誰可以問；之後隨時可以關 |
| 把配對碼收起來 | 沒有 | — |
