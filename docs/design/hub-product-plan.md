# Hub 產品計畫（第二版）：Hub 是聊天室

狀態：提案，等擁有者決定（2026-11-13 第二版，依擁有者對第一版的回覆重寫）。只有設計與規劃，沒有程式。
對照的原始碼：`release/2.3.5-alpha` @ `db484be1`。文件中的位址一律用 `hub.example.com`。

## 0. 和第一版的差別

第一版把 Hub 做成「主管一次問整個團隊」這一個功能，擁有者的回覆是：太單一。方向改為：

- **Hub 就是聊天室。** 和一個 Agent 一對一聊，或在群組房間裡聊、用 @all 叫所有 Agent。沿用 AgEnD Fleet 聊天的設計語言。
- **整理可以交給自己的 Agent，也可以交給 Hub 提供的 AI**：Hub 自己有一個 Fleet，裡面有管理 Hub 的 General，以及每個房間一個的房間助理，由 Hub 的擁有者管理。
- **團隊是 AD 之下的虛擬團隊**，因為 AD 群組只到部門。
- **先做介面、流程與功能的完整度**；通訊協定與安全設計不在這一輪，上線前另外列。
- 試行的憑證還沒準備好，先放寬連接條件讓人測得了；正式憑證在上線前才綁。
- 桌面版的 Codex 與 Claude 使用者也要能加入。
- 日報的安裝教學先擱置。

已確認、不再討論：加入後不自動分享，由本人確認；配對碼與一次性代碼收起來；教學建議分享專案用的 Agent、不預選 General；不做「團隊提問次數上限」這個功能，改由房間裡的 @all 取代。

## 1. 房間模型

示意圖在 `docs/evidence/hub-product-plan/`：`q1-room.png`、`q2-room-settings.png`、`q3-teams.png`。

### 1.1 兩種對話，一個清單

| | 一對一 | 群組房間 |
|---|---|---|
| 成員 | 我 + 一個 Agent | 多個人 + 多個 Agent（可以加 Hub 助理） |
| 誰看得到 | 只有我 | 房間裡的每個人都看得到所有訊息與回答 |
| Agent 什麼時候回答 | 每一則都回答 | 被 @ 到才回答 |
| 現況 | 已有（新對話 → 選 Agent） | 沒有 |

兩種都列在左邊的同一個清單，像 AgEnD 自己的聊天：左邊清單、中間訊息、右邊成員與說明。

### 1.2 在房間裡說話

- **@某個 Agent**：只有它回答。
- **@所有 Agent**（@all）：房間裡每個 Agent 各回一則。回答多的時候先顯示前幾則與「已回答 9 · 等待中 2 · 離線 1」，其餘收合。
- **@Hub 助理**：Hub 提供的 AI 回答，例如「幫我整理成一份」。
- **沒有 @**：只有房間裡的人看得到，Agent 不回答。人和人可以直接在房間裡討論。
- Agent 被 @ 時讀得到房間最近的對話，所以可以追問「剛剛那一點再說清楚」，也因此可以請任何一個 Agent（自己的或 Hub 助理）整理其他 Agent 的回答。
- 離線的 Agent 顯示「離線」；它的擁有者上線後補答。

### 1.3 誰在房間裡

- **人**：個別加入，或加入一個**團隊**、一個 AD 群組。
- **Agent**：
  - 自己的 Agent：自己加進去。
  - 別人的 Agent：房間管理者發出邀請，**擁有者同意後才進房間**（延續「分享由本人確認」）。可以一次邀請「某個團隊所有人的 Agent」，各自同意。
  - Hub 助理：房間管理者自己加。
- 把 Agent 加進房間，就等於允許房間裡的人在那裡問它；不需要另外逐一「允許提問」。一對一的「允許提問」維持現狀。

### 1.4 房間權限

- **誰可以開房間**：由 Hub 管理員決定。預設只有管理員；可以指定某些人或團隊也能開（例如主管）。任何人都可以開一對一對話。
- **房間裡兩種身分**：
  - 房間管理：加入與移除成員和 Agent、改名、封存、設定下面兩項。
  - 成員：看訊息、發言、@單一 Agent。
- **每個房間可調的兩項**：成員能不能用 @所有 Agent（預設可以）；新成員看得到「加入之後」還是「全部」的歷史（預設加入之後）。
- Hub 管理員在「管理 → 房間」看得到所有房間的名稱與成員，看不到內容。

### 1.5 虛擬團隊

- 團隊是 Hub 自己記的一份名單：名稱、所屬部門（一個 AD 群組）、成員（從 AD 的人裡挑）、負責人。
- Hub 管理員建立團隊並指定負責人；負責人可以自己增減成員。
- 可以選「人」的地方都可以選團隊：房間成員、邀請 Agent 的對象、一對一的「誰可以問」、加入 Hub 的建議對象。
- 團隊頁同時回答主管原本想知道的事：誰已加入 Hub、分享了哪些 Agent。

細節（2026-11-14 定案）：

- 成員是一個一個選出來的人，不會自動等於那個 AD 群組的所有人。「所屬部門」只用來歸類與預設搜尋範圍；可以加入其他部門的人（跨部門的專案團隊），名單上標示他的部門。
- 每個團隊一定有一位負責人，而且負責人一定是成員，所以團隊至少有一個人。建立團隊時就要指定負責人；要換人，就指定另一位（他會同時成為成員）；最後一位成員不能移除，要清空就刪除團隊。負責人的帳號被停用時，團隊照常運作，管理員的團隊頁提醒「負責人的帳號已停用，請指定新的負責人。」
- **把團隊加進房間、或邀請團隊的 Agent，是「當下這份名單」**：之後團隊增減成員，不會自動把人加進或移出房間，已同意的 Agent 也不受影響。房間設定可以再按一次「加入團隊」，把後來才加入團隊的人補進來。
- **「誰可以問」與「誰可以開房間」選了團隊，則是隨時依目前的名單**：離開團隊的人就不再適用，和 AD 群組相同。
- 刪除團隊：之後不再有以這個團隊為依據的「可以問」與「可以開房間」；已經在房間裡的人與 Agent 不受影響。刪除前的確認框會列出哪些設定會因此失效。

### 1.6 Hub 自己的 Fleet：Hub General 與房間助理

擁有者追加的想法（2026-11-13）：Hub 也有一個 General 來管理 Hub，底下替每個房間配一個 ClassicBot 式的 Agent 給主管用。評估結果：**可行，而且比第一稿的「一個 Hub 助理」好**，因為它幾乎都是把 AgEnD 已有的東西組起來。

Hub 那台電腦上跑一個 AgEnD Fleet（Hub 的 Fleet），由 Hub 的擁有者管理。裡面有兩種 Agent：

**Hub General（管理助理）**
- 只有 Hub 管理員可以和它說話：在 Hub 網頁的一對一對話裡，或 Hub 擁有者自己的聊天平台。
- 它用一組 Hub 管理工具做事，每一項都對應管理頁上已有或這次要做的動作：

| 管理員對 General 說 | 對應的管理頁 |
|---|---|
| 「幫研一主管開一個房間，把研一 一部的 Agent 都邀進來」 | 管理 → 房間 |
| 「建一個團隊叫登入頁專案，成員是這五個人」 | 管理 → 團隊 |
| 「讓研一這個群組可以加入」「做一組今天有效的加入碼」 | 讓同仁加入、加入碼 |
| 「誰還沒加入？」「這週連上了幾台？」 | 團隊頁、已連接的 Fleet |
| 「把吳小安那台舊的撤銷」 | 已連接的 Fleet → 撤銷 |
| 「這個房間的助理關掉」 | 管理 → 房間助理 |

- 規則：General 做得到的事不超過管理頁；它只替正在和它說話、而且身分已確認的管理員做事；撤銷、刪除、移除成員這類收不回來的動作，先出確認卡，管理員按了才做（沿用 AgEnD 現有的確認卡）。
- 它不讀房間內容，和管理員一樣。

**房間助理（每個房間一個）**
- 房間管理者在房間設定打開「房間助理」，Hub 的 Fleet 就替這個房間開一個 Agent，做法和 ClassicBot 的房間 Agent 相同：一個房間一個、只看得到這個房間。
- 在房間裡它是一個成員，被 @ 才回答：整理 @all 的回答、回答追問。它每次回答時讀的是這個房間最近 30 則訊息；更早的內容它不會記得（試行的做法，2026-11-14）。
- **看得到**：這個房間的對話。**看不到**：其他房間、一對一對話、Hub 的管理資料、任何人的 Fleet。
- **做得到**：在這個房間回話。預設沒有其他工具，也沒有檔案。
- 一段時間沒有人用就停下來，下次被 @ 再啟動，所以房間多不代表同時跑很多個。
- 一對一也可以找它：清單裡的「Hub 助理」是每個人自己的一個小房間。

**帳號與額度**
- 兩種 Agent 都用 Hub 擁有者在 Hub 的 Fleet 裡登入的 AI 帳號，額度算在 Hub 這邊，和同仁各自 Fleet 的額度無關。
- 「管理 → 房間助理」：總開關、用哪個後端與帳號、哪些房間開著、近期用量、同時最多跑幾個。額度快用完時，房間裡顯示「房間助理暫時無法回答」。
- 主管不想用 Hub 的額度時，把自己的 Agent 加進房間 @ 它整理，效果相同。

**現況與要注意的地方**
- Hub 目前不執行任何 Agent。Hub 的設定程式現在還**建議不要**讓 Hub 和 Fleet 用同一個系統帳號，理由是 Fleet 的 Agent 有完整工具時讀得到 Hub 的金鑰與紀錄。所以 Hub 的 Fleet 裡這兩種 Agent 必須是受限的（General 只有管理工具、房間助理沒有工具）。這一點功能上不擋路，列在上線前清單。
- 試行的那台 Hub 電腦目前只裝了 Hub，沒有 Fleet（已確認）；試行期間會在同一個系統帳號下加上 Hub 的 Fleet。

### 1.7 誰在線上

房間右側的成員清單，每個名字前面一個圓點加一個詞，和 AgEnD 側欄顯示 Agent 狀態的方式相同。

| 成員 | 顯示 | 依據 |
|---|---|---|
| 人 | 🟢 線上 / ⚪ 離線 | Hub 網頁開著，或桌面連接器在最近幾分鐘內用過 |
| Fleet 的 Agent | 🟢 待命 / 🔵 處理中 / 🟡 暫停 / ⚪ 離線 | 沿用 Fleet 自己的狀態。暫停包含登入過期、額度用完、等待核准；離線是那台 Fleet 和 Hub 的連線斷了 |
| 「上線時回答」的桌面使用者 | 🟢 線上 / ⚪ 上線時回答 | 只有 App 連著的時候是線上 |
| 房間助理 | 🟢 待命 | 一直都在（閒置時實際上停著，被 @ 才啟動，使用者不需要知道）；Hub 的額度用完時顯示 🟡 暫時無法回答 |

- 清單依狀態排序：處理中、待命、暫停、離線。標題顯示「Agent · 12（線上 9）」。
- 左邊的對話清單，一對一的 Agent 也帶同一個圓點。
- 狀態只有這幾個詞，不顯示 Agent 正在做什麼、用了多少額度；那些留在擁有者自己的 Fleet。

**@所有 Agent 遇到不在線上的成員**

- 待命與處理中的：馬上送達。
- 暫停與離線的：問題排隊，回到線上就補答，補進原本的那一串；超過保留時間（一般 24 小時；「上線時回答」的成員建議 7 天）就標示「沒有回答」。
- 送出前，輸入框上方提示一行：「12 個 Agent 中 9 個在線上，3 個上線後回答」。
- 結果分成三組：已回答、處理中、稍後回覆。整理只等前兩組，不會被離線的人卡住。

### 1.8 和既有設計的關係

- 「我分享的 Agent」「允許提問」「暫停／恢復」維持不變，是一對一的基礎。
- #3765（把同仁 Fleet 上的 ClassicBot 房間分享到 Hub，Hub 的人以訪客身分進去）和這裡方向相反：這裡的房間在 Hub 上，助理由 Hub 的 Fleet 提供。兩者可以共用同一套做法（一個房間一個 Agent、訪客只能聊天不能下指令、發言者顯示「名字（Hub）」），所以 #3765 的設計不白費；它原本要解決的「把團隊的 Agent 聚在一起」已由 Hub 房間涵蓋。建議 #3765 暫不單獨實作，把「Hub 房間接到 Discord／Telegram 頻道」留作之後的選項。
- #3226 的版面（清單、對話、右側面板、共用聊天模組）就是這次要用的設計語言，當時留到第二階段的「團隊房間」現在提前。

## 2. 試行期間放寬連接條件

示意：`q4-pilot-trust.png`。

**做法：在「Hub 位址」那一格直接信任。** Fleet 連到自簽憑證的 Hub 時，現在是一句「憑證不受這台電腦信任」然後沒有下一步。改成顯示憑證指紋與一個按鈕「信任這個 Hub 並繼續」。按一次，這台 Fleet 記住這張憑證，之後照平常的流程：找到 Hub → 以公司帳號登入。加入碼照常可以接在位址後面。

- 多一次點擊，不用配對碼、不用比對兩邊的畫面、不用裝憑證。
- 憑證之後若改變（自簽憑證 30 天會重新產生），會再問一次。
- **關閉方式**：Fleet 的一個設定「允許信任自簽憑證的 Hub（測試用）」，alpha 版預設開、正式版預設關。Hub 換上正式憑證之後，這一段自然不再出現，已信任的 Fleet 改走一般的憑證檢查。
- 一起做：配對碼與一次性代碼收起來（已確認），#3840 的錯誤訊息。

沒有選的做法：讓管理員的長連結帶憑證（要貼長連結，比按一個按鈕麻煩）；每台電腦安裝憑證（要管理員權限、要重啟）。

代價（上線前清單會再列）：第一次連接時無法分辨真的 Hub 與同一個網路上的冒充者；這是「測試用」開關存在、而且正式版預設關閉的原因。

## 3. 桌面版 Codex 與 Claude 的使用者（不安裝 AgEnD）

擁有者已排除「安裝一個精簡的單一 Agent 版 AgEnD」。這一節只談不安裝 AgEnD 的路。

### 3.1 做法：Hub 提供一個 MCP 連接點

Hub 在自己的網址上多開一個 MCP 服務（`https://hub.example.com/mcp`），用公司帳號登入。桌面 App 把它加成一個連接器之後，使用者可以直接對自己的 AI 說話來用 Hub：

| 對自己的 AI 說 | 連接器做的事 |
|---|---|
| 「我有哪些房間？研一主管週會最近在談什麼？」 | 列出房間、讀訊息 |
| 「在登入頁改版那個房間說：測試環境修好了」「@所有 Agent 問進度」 | 在房間發言、@ Agent |
| 「問林小華的 project-helper：上次的重跑記錄在哪」 | 一對一提問、讀回答 |
| 「Hub 上有沒有人在等我回答？」→「幫我回這一題」 | 讀等待中的問題、送出回答 |

不用裝任何東西的還有一條路：**用瀏覽器開 Hub 網頁**，全部功能都有。連接器是給想留在桌面 App 裡的人。

### 3.2 兩款 App 現在各支援到哪裡

依 2026-11 查到的公開文件；沒有實測，動手前要對著當時的版本再確認一次。

| | Codex 桌面版 | Claude 桌面版 |
|---|---|---|
| 加一個遠端 MCP 網址 | 可以。寫在設定檔的一筆，或在 App 的 MCP 設定裡加；用 OAuth 登入 | 可以加「自訂連接器」，**但連線是從 Anthropic 的雲端發出，不是從使用者的電腦** |
| 連得到內網的 Hub 嗎 | 連線從使用者的電腦發出，所以連得到 | **連不到**：雲端進不了公司內網，也不接受自簽憑證或內部主機名稱 |
| 現在可行的做法 | 直接加 Hub 的 MCP 網址，登入公司帳號 | 需要變通：(1) 裝一個桌面擴充（一個檔案、按一下安裝，不是 AgEnD），由它在本機轉接到 Hub；或 (2) 讓 Hub 的 MCP 能從外部連到；或 (3) Anthropic 的 MCP tunnels（文件有提到，我沒有查到細節） |
| 自簽憑證（試行期間） | 未確認，可能也要正式憑證 | 不行 |

結論：**Codex 桌面版照「加一個網址」就可以；Claude 桌面版在 Hub 只在內網時，至少要按一下裝一個擴充。** 兩者在 Hub 換上正式憑證之後才好用，所以這一段排在聊天室之後。

來源：[Claude 自訂連接器](https://claude.com/docs/connectors/custom)、[Anthropic 說明：用遠端 MCP 建立自訂連接器](https://support.anthropic.com/en/articles/11503834-building-custom-connectors-via-remote-mcp-servers)、[Codex 的 MCP 文件](https://developers.openai.com/codex/mcp)、[內網 MCP 與桌面擴充的例子](https://apidocs.polytomic.com/guides/mcp-server-on-premises)。

### 3.3 他們能「被問」到什麼程度

桌面 App 不會自己去看 Hub，外面也沒有辦法把問題送進 App。所以桌面使用者**不是隨時待命的**：只有 App 開著、而且他叫自己的 AI 去看的時候，才會回答。這和 Fleet 上的 Agent（電腦開著就會答）不同，房間要把這個差別講清楚：

- **身分**：桌面使用者在房間裡是一個「人」，可以另外登記一個「上線時回答」的代表（顯示為「王小明 · 上線時回答」），讓別人可以 @ 他、問題會留給他。
- **@所有 Agent**：照常送給隨時待命的 Agent；「上線時回答」的成員列在結果下方的「稍後回覆」，不算在等待中，不會讓整理一直等。
- **稍後回覆的佇列**：問題為他保留，他下次在 App 裡說「看看 Hub」就會看到、回答；回答補進房間原本的那一串。保留多久是一個決定（建議 7 天；現在一般提問是 24 小時）。
- **房間助理的說明**：整理時自動加一句「王小明上線後回答」；他回答之後可以請房間助理更新整理。
- 一對一也一樣：問他的人會看到「對方上線時回答」，不是一直顯示等待中。

做不到的：主動通知桌面使用者有人問他（可以改用公司的通訊軟體或信件提醒，之後再說）；讓 App 裡正在進行的那個對話直接被問。
