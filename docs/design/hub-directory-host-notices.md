# Host-owner access to directory security notices

M-2687 / S-112 / [#3425](https://github.com/songsid/AgEnD/issues/3425). The Hub's signed-in recipients already have authenticated history and acknowledgement routes. This slice connects the **host target** to the fleet listener at `GET /api/settings/hub/security-notices/directory` and `POST …/:id/ack`, independently of whether the Hub listener can mount. The future host Needs-you card will consume these routes; this slice adds no UI or automatic acknowledgement.

The route reuses the existing `hubSetupSession` authority adapter: the host's D3 cookie on this computer, with the exact session-record, token, session-store and authority-epoch identity. It refuses guests, ordinary named/remote administrators, header tokens, forwarded requests and public links. `authorizeSession` enforces the existing same-origin and CSRF checks on POST. The proof is obtained before the lazy controller factory; currentness and disconnect are rechecked before any controller effect and before the response. There is no additional confirmation dialog.

The stateless controller does not create an initializer or runtime. It validates the current configured Hub identity, snapshots the request and binding, and borrows existing state through the **same** cold-state validation used by directory recovery. That shared path requires the complete private state set, matching identity, exact compiled schema registry, all authority tables, valid transport floor and coherent head/session epoch. It opens SQLite with `create:false` and never calls migrations. A missing or newer component answers unavailable without initializing, upgrading or overwriting state.

The cold callback receives only a frozen host read/ACK facade, not the database, keys or a decision writer. It must remain synchronous; the facade closes before the database closes and the file-read key buffer is zeroed on every path. Input identity, layout and migration records are copied before caller proof callbacks. Reads and ACKs use the same existing notice/audit transaction as the mounted service. The fixed host sink cannot be selected through a query or body. A person's ACK leaves the host target queued, and a host ACK leaves every person target unchanged. History retains the same owned UUID cursor, 50 default / 100 maximum page and optional unread filter.

The request proof and configured hubId/memberOrigin remain current through the required audit. An audit failure or a host-authority/binding change rolls back the ACK and its audit together. Errors carry closed codes, never private paths or raw SQLite messages. No directory client, network connection, Hub listener, new schema or second settings writer is created. The old `withHubDirectoryRecovery` callback still receives the same decision participant; only its internal state-opening implementation is shared with this narrow reader.

Evidence uses an initialized sealed scratch Hub, the real settings writer, a deliberately refused replacement mount, existing WAL/FULL SQLite and actual fleet HTTP/D3 sign-in. Directory methods are inert and no real LDAP/account is contacted. Tests cover independent host ACK, unauthorized entry before the factory, authority/store changes during held imports, disconnect, required audit rollback, binding changes during audit, missing/newer state, scoped callback lifetime and synchronous-only work. No browser, native manager, pilot or live fleet is operated. Host Needs-you/Hub notice presentation, final AD Save/D3 adapters, startup recovery intent and the AD form remain unfinished M-2687 work. Reverting these routes leaves retained notices intact; no database rollback is needed.
