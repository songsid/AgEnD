# Directory preparation authority (#3425)

This internal controller supplies authority to the shared `settings-commit.ts` directory operation. It does not introduce a second writer, mount a route, register a production migration, or enable AD editing. The subsequent composition must provide a verified sealed source, its complete config/material/policy/lifecycle/epoch image and live fence, the actual shared 4/person and 32/total pool, and a genuinely configured-admin or hostSessionHere/D3 context. A boolean from a browser is never that context.

Preparation snapshots the actor, callbacks, exact source, candidate and opaque service secret before any await. It performs credential-free **normally verified** TLS inspection. A changed URL or CA produces one unpredictable, session/draft-bound challenge showing the server, leaf and CA fingerprints (or system roots). Confirmation precedes sending either password. The candidate's actual LDAP connections require normal CA/hostname verification plus the confirmed leaf pin. Same-target ordinary edits need no extra trust dialog. An old service secret is retained only when URL, CA text and bind identity are unchanged; a different target/trust/bind needs an explicitly supplied secret. BOM and whitespace remain opaque.

Apply consumes the draft even on refusal. A configured admin supplies recent server-attested AD authentication (at most five minutes) plus fresh old-directory eligibility, or reauthenticates by sending their personal password **only to the mounted old directory**. A bounded failure/in-flight window prevents a new password-guessing path. Host recovery does not manufacture a directory identity or session and does not require the unavailable old directory. An expired old sealed CA may be identified for replacement; this never relaxes candidate verification.

Candidate tests use only service credentials. They freshly read the same immutable administrator, resolve each configured security group by its GUID rather than its old DN, and recheck the administrator after group work. Missing, ambiguous, recreated, disabled, unsupported, partial or unavailable results refuse the operation. Tests are advisory; apply repeats them. Every await, callback and final synchronous writer proof checks the captured actor/session, source lifetime, full image, epoch, cancellation and both clock bounds. A changed generation never inherits a prior authentication proof. Closure and cancelled work retain their shared admission until the physical promises, including owned driver close, settle.

Only then does the controller call the **existing** writer's prepare/commit pair with the exact candidate and a synchronous final proof. Post-decision physical completion and forward compensation remain the writer's responsibility, not the disconnected browser's. The controller returns only an opaque preparation, trust summary or receipt/epoch; it does not return service or personal passwords, material references, or old/new file images.

Still required before exposure: concrete current-source and HubSessions attestation adapters, required audit for preparation/refusals, actual owning-DB decision/mount barrier/session rotation, durable notice delivery/retention, D3 and Hub HTTP/CSRF adapters, real Settings-shell UI, SKEW and cumulative acceptance. The new tests use inert controllers or owned loopback fake LDAPS; they claim no real directory, account, service, pilot or production mount operation.
