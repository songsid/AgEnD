# App-owned effect pool primitive (#1629 B2)

The session-only `app-effects.js` bridge now starts this owner once from the full app’s Chat-store boot, including when Fleet is the initial panel. The actual Chat component contributes its committed lease instead of constructing a private registry/loader. An optional personal contribution model is described in [1629-owner-effect-source.md](1629-owner-effect-source.md); the product bridge now connects its fixed stock targets, authoritative preference invalidation and Settings controls. Cursor and Try remain separate work. Importing either host module starts nothing.

## Ownership

`createAppEffectRuntime({window,current,observe,onChange,onDispose?,resolveOwnerTarget?,onOwnerUnavailable?,factories?})` freezes the existing server-rendered person/operator epoch, subscribes to auth-end and pagehide before async admission, and owns exactly one registry, loader, writer, safety provider and profile receipt map. Without an optional personal resolver, no Chat contribution means no metadata/resource read. A WeakSet allows only one owner attempt per Window episode, including after disposal; BFCache must not recreate that episode. Identity refusal creates no participant.

`attachChat({name,element,current,observe,onChange})` returns a route handle. Detach/replace first retires the old contribution; it does not dispose/recreate the app pool. Page-level `changedChat()` and `reply(event)` forward only to the current contributor, for the one app subscription. A handle's `dispose`, `changed`, `pause`, `resume`, `reply`, `remove` and `snapshot` are fenced to that exact contribution. Existing manual pause/provenance/params behavior stays scoped to its Chat lease. Page/session end disposes the whole pool once, continuing other cleanup if one participant throws.

The bridge subscribes to the existing navigation store and synchronously detaches on each route sequence change, before an asynchronously loaded panel can attach its committed DOM. A contribution also checks the exact captured route/name/sequence, document identity and view lease. The bridge supplies page gates, CSS lifecycle, theme and the existing fresh-only reply subscription; only a themes revision invalidates authoritative Chat metadata. A retried Chat module may replace that one reply-store subscription without creating another pool. Structural proof never supplies identity/consent. Anonymous/View-only imports remain isolated, and a full public-link/header/poll page obtains no owner identity.

## Requests and scopes

A single physical metadata operation survives route cancellation until `placementsSettled` finishes. A new route waits rather than mistaking logical cancellation for free capacity. `resourceSettled` similarly keeps the registry's existing physical reservations meaningful. No new scope, endpoint, polling, retry, capacity or timeout is introduced. A hung operation that ignores abort remains reserved; UI teardown must not await it or build a replacement pool.

Each descriptor has a route-serial key and a private immutable binding containing its exact source and generation. Resource and profile dispatch require that current key/id/binding; they never choose a scope by id alone. Old successful or failed reads for the same content id cannot publish into or fail a newer route. Revision and abort fences reject stale metadata. A current source failure latches that contribution; another route can reuse the same pool, while an internally revoked loader cannot issue further reads. Only one Chat source exists; optional personal aggregation shares this owner and its global auth revocation across all contributors.

Profile collectors require the exact current registry receipt and binding. Writes retain the frozen epoch and captured instance; responses never grant authority. State/reply originate only from the current contribution; only closed state and boolean reply/theme signals are published. The caller still must use the existing fresh-only reply store. Mention remains reserved/not emitted. No new names, identity or manifest text are added to event fields; the existing current-Chat instance tag remains owned by the registry codec.

## Reentry and evidence

Every route/metadata/descriptor change invalidates its prior pass. Reentrant attachment during retirement or observation abandons the old continuation and schedules one new sync; an old handle cannot retire the replacement. Current predicates are checked again after callbacks, so disposing inside a predicate cannot return an old valid source. Source signatures preserve unrelated manual pauses and resolve Resume by namespaced registry key.

Offline tests mock registry/frame/cap internals and state that limit explicitly. They pin one constructor across handoffs, identity refusal, physical held reads, same-id key/scope isolation, stale metadata/resource/remove/profile completions, auth/pagehide/BFCache/route teardown, source failure, pause/params, closed events, observer/retirement reentry and partial setup/cleanup. A real loader plus fake registry additionally proves held late-body cancellation serializes metadata across Chat handoff. The checked-in actual Shell/Chat recipe additionally checks initial Fleet, Chat A→B→Fleet→A, the same owner and layer, existing device caps, exact same-id resource scopes, and the prior paint/signal/consent/CSS/auth controls. Synthetic private sessions and Linux WebKit are not real accounts or Safari.

`onDispose` notifies the app bridge once after participant cleanup; the bridge independently releases all global observers and ends current UI subscriptions. The Window tombstone remains after disposal; BFCache or a module retry cannot start a second episode. Optional setup failures leave Chat usable with playback unavailable.

Rollback restores the prior Chat adapter/boot and static asset map together, then removes the bridge. No stored state, migration, permission, endpoint, cap or CSP change is included.
