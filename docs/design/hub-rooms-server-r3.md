# Rooms Track R3 integration checkpoint

This work follows the R1/R2 room model and keeps custom roles out of the rooms pilot.

Creator policy is its own additive s3-room-creators component. The configured administrator can always create a room; explicit selected people can create new rooms while eligible. Removing a creator assignment removes future creation, without deleting rooms or demoting their existing managers. GET/PUT /admin/rooms/creators returns the seam5 arrays of immutable person/team IDs. The optional TrackC HubTeamReader supplies live roster checks for Team creator rights. Missing or deleted Teams confer nothing. Room creation expands selected Teams once, checks each selected person's eligibility, then rechecks the exact Team revisions and expansion inside the write transaction; later roster changes do not rewrite room members.

GET /admin/rooms projects only room ID/name, person and agent counts, manager names, last activity and archived status. It never calls the content store or returns text. Administration does not imply room membership. POST /admin/rooms/:id/join explicitly joins/promotes the acting administrator, writes a named system line and audit, and then uses normal member history cutoffs. PATCH /admin/rooms/:id {archived} archives without changing memberships or saved history, retires pending room work and forgets the local assistant.

The assistant admin routes consume the agreed four-method provider: settings/configure/usage/stopRoom. Until A's typed DTO module is in this branch, HTTP deps declare only those structural methods with opaque results; configuration validation, account choice, daily usage and physical worker ownership remain A's. The room-assistant-v1 feature and routes exist only with both roomAssistant and assistantAdmin ports, including a configured-disabled provider. The HTTP adapter applies current Hub administrator authority and CSRF, retains its permit after every await, and awaits stopRoom's physical drain before replying. No provider is constructed here or reused across mounts.

Room assistant asks use a local retained call table, separate from Fleet exposures/grants. Each person lazily gets a private direct row when the provider is enabled; that row answers plain messages and cannot gain extra members or be joined through room administration. Group calls require an assistant member and @assistant. The same bounded oldest-first context helper supplies Fleet and local asks. An unavailable provider leaves the person's message saved with assistant-unavailable; pending replies have the normal progress and answerTo fields. A single room call runs at a time; TrackA owns global cap, quota, account and process lifecycle.

Input intent is committed before calling the external worker. On restart, uncertain working calls become not-answered and are never automatically repeated. Removal/archive invalidates the exact assistant membership, forgets its worker, and withholds late output even after a new member is added. Completed text is committed once with audit. Current person eligibility and operational self-use are rechecked before input and output; no browser session has to remain open while a saved ask runs. Closing the HTTP mount fences local continuations, while TrackA retains physical drain ownership.

TrackC's exact invitation/team type contracts are included unchanged from 0ea339d0d and eec1da11d. R implements invitationHost() with current non-private, unarchived manager/room checks, effective published exposure/owner reads and same-transaction addAgentMember. The owner-only exposure rooms inventory returns the physical membership ID and survives owner pause. The optional roomInvitations(core, host) factory is invoked once per HTTP mount. Only a supplied service enables invitation routes, pending counts and manager invited rows; consent, expiry, invitation storage and Team SQL remain C-owned. Owner invitation.changed events carry only an empty refresh marker and require current owner eligibility; they do not imply room membership. Room/member/system events publish after commit.

Directory group expansion/search, the concrete C/A factory integration and real shared-UI walkthrough remain the next S142 steps. This draft uses an inert provider and invitation/Team adapters for integration tests; it does not execute a real CLI or claim C's consent implementation. This is not a full TrackR or joined-UI acceptance claim. No security/mutation gate is added to ordinary pilot parity review.
