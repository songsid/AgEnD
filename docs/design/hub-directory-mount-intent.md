# Durable directory mount intent

M-2687 / S-112 / #3425. This extends the shared sealed-settings writer and private Save coordinator. Startup reconciliation and the public AD settings routes/form still need composition; this slice exposes no new route or authority.

The request-local recovery deadline used by the private coordinator was lost on restart. Its synchronous pre-commit hook now supplies a bounded deadline to the existing writer. The writer clamps it to the prepared proof's expiry and binds `{v:1, expiresAt}` into the signed receipt and authoritative operation. The same SQLite decision that records the operation, full old-recipient notices, directory binding and epochs creates a pending mount-intent row. Staged files alone create no allowance. Older/internal operations without the field acquire none.

Both initial and final writer clock samples must be within `[operation.at, expiresAt)`, at most five minutes. Compensation verifies the retained receipt hash and recovery metadata, then checks its canonical hash against the confirmationId returned by issuer-signature verification of the installed manifest. SQL and a staged receipt agreeing with each other is insufficient; their coherent modification cannot extend the issuer-signed allowance. A cold recovery participant checks the complete migration registry and the intent table before invoking its callback. It neither creates nor migrates state.

Only the current head's intent is selectable. After the exact generation mounts, `completeMount` uses a root transaction, exact-head and current-mounted proofs, a required audit, and a final row/image comparison to change pending to ready. This closes recovery before any successor cookie or success response is released. Completion changes the transport revision for its audit, but advances no directory or authorization epoch. Closing an allowance may be idempotently acknowledged after its deadline under the exact still-current mounted proof; expiration never broadens recovery authority.

If the mount fails within the allowance, forward compensation consumes pending to compensated inside its new authoritative decision, after all callbacks and before the epoch/head transition. It restores only the recorded prior connection content. It cannot restore old sessions, policy, denies, revokes, resource provenance, floors or epochs. A later head, completed intent, changed receipt or expired/backward clock refuses. Compensation cannot authorize a recursive intent. A failure after floor advancement retains the existing uncertain-floor/journal hold rather than pretending to undo that floor.

The new `s5-directory-mount-intent` schema component is part of the production Hub database plan. **An older binary refuses this migrated database.** Downgrade requires an authorized pre-upgrade state backup, taken while stopped, or a matching binary. Do not delete registry rows or rewind security state. No real installation or pilot was upgraded for this slice.
