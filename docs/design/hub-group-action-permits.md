# Group action permits

This internal step follows [#3298](https://github.com/songsid/AgEnD/issues/3298), the [resource lifecycle](hub-group-policy-lifecycle.md) and [authorization refresh](hub-authorization-refresh.md). It connects fresh group decisions and durable suspension to the current global transport version. The server now composes these permits and registers their two schema components, initially never-enabled. Protected chat effects use them as described below. The confirmed impact preview, enrollment/publication gates and welcome/pairing UI remain required before any enable control is exposed; the experiment stays off.

`createHubGroupAuthorization` returns `asker`, `check`, `enroll`, `resume` and `close`. An allowed operation receives a permit, not a cached boolean. The caller must use a new check at each protected action, read, dispatch and release boundary, and call `assertCurrent()` immediately before the actual effect. Each permit binds the validated resource kind/ID/exact revision/immutable owner, lifecycle row revision/source/state, complete policy snapshot, store/composition identity, global authorization version, and server/caller fences. Input objects and callbacks are captured before awaits. The synchronous assertion does not repeat LDAP; it fences changes during that one operation. It is not an eligibility allow-cache for another request.

`enroll` records provenance only after a fresh group allowance. It creates no exposure, fleet credential, room, grant or delivery. Its caller still owes ordinary ownership, account eligibility, local consent, fingerprint proof, quota and grant checks, plus the final actual-resource commit. In enabled mode, `check` refuses absent provenance. An asker is always `{kind:"asker", id:person.objectId, revision:1, owner:person}`: new sessions or fabricated revisions cannot evade a suspended person's explicit-resume requirement. Publication and fleet bindings use their actual persisted IDs/revisions; display names are not identities.

For new fleet/publication effects, `prepareEnrollment` separates directory work from the actual-resource transaction. It captures validated resource/caller/policy/composition/authorization-version facts, obtains one fresh audited group allowance, and returns a one-operation preparation with `assertCurrent`, the effective `maxFleets`, and `commit(database)`. Preparation creates no provenance or actual resource. The caller still performs ordinary consent, fingerprint, owner and quota checks, then calls `commit` inside the **same database transaction** as the new fleet/publication. The effective fleet limit must be compared with the current ordinary fleet count there; a preparation is not a reservation or a quota waiver. Asker enrollment remains the canonical first-use path, not this API.

Commit requires the owning DB's active transaction and publishes the required registration audit and exact provenance there. Its attempt is consumed even if the outer operation subsequently rolls back; a new attempt needs a new directory preparation. The actual resource, registration event and provenance roll back together. The earlier allowance audit can remain as diagnostic evidence; it is not evidence that a fleet or publication was created. A successful permit rechecks the exact committed lifecycle row as well as the captured policy/version/current fences. Unknown, stale or denied preparations cannot publish provenance. The legacy preparation does not consult LDAP or create group state and still requires the owning transaction. Pairing and catalog publication commit provenance with their actual resources. The complete control is composed, but group permissions remain off until the configured Hub administrator saves them.

`resourceState` is an internal display-only exact lifecycle read for the welcome projection. It returns `{source,state,revision}` or null, makes no directory call or audit/write, and never supplies a permit. A non-current server, foreign owner realm or non-ready binding refuses; repair must not be displayed as an active default. The welcome still authenticates its own person and restricts the projection to that person's fleets. This method does not replace the fresh action checks.

Allowance audit derives the resource ID/revision from the validated binding, overriding caller-supplied context. Group decision evidence includes the immutable person, matching group GUIDs, capability, policy revision, directory generation and observation time, with the precise resource revision in its hash-bound event body. Standard operation audit, consent and audience checks remain the endpoint's responsibility. Manual grandfathering remains exact and membership-exempt, while an explicit person deny still suspends it.

## Suspension and refresh

Unknown directory facts hold only the current action. They do not change resource state or advance the global version. Diagnostic audit may be recorded. A fresh complete positive recovers without resume if nothing was suspended. The documented last-direct-group/omitted-memberOf exception remains unknown rather than a proved negative.

A complete negative updates the lifecycle record and calls a synchronous required version writer inside the same SQLite transaction. The runtime composer must supply the transport store on that exact DB. The writer must advance the version and must not close sockets or perform asynchronous work. No transaction is kept open across directory or administrator awaits. After a successful commit the adapter invokes synchronous non-retiring refresh. Old server link contexts already fail their version gate before sockets close; unaffected paired fleets reconnect with their credentials intact. A failed transaction never invokes refresh.

The lifetime fence in the options is the server/composition lifetime; the per-request/session/link fence belongs in the check context. Suspending a member's old-version context intentionally invalidates that caller. This does not undo the narrowing suspension. Resumption broadens access, so its captured authorization epoch is compared inside the lifecycle transaction before advancing that epoch. An unrelated advance during membership lookup or a reentrant lifecycle audit rolls back the pending resumption and its audit; it cannot become the resume's own advance. The independent administrator/session fence is checked after the version writer too. Reentrant policy changes roll the transaction back.

A required writer returning a thenable, failing to advance the version, throwing, or losing current authority withholds the result. If a later transaction failure follows an independent monotonic-floor advance, the established transport store deliberately freezes as uncertain; the adapter never resets that floor or restores permissive state. A refresh error after commit cannot undo the committed suspension/version, and no permit is returned. The normal listener/component owner remains responsible for directory and socket cleanup. `close()` permanently fences outstanding permits and directory continuations; it does not own a separate directory connection pool.

## Legacy and administrator boundary

An intact never-enabled policy preserves legacy behavior without group lookup or new group state. A same-Hub/same-realm never-enabled record needing directory-generation repair uses the reviewed binding probe without constructing the strict mismatched store. The probe fingerprints the validated selected Hub/realm/generation and complete stored policy; the permit captures and rechecks that fingerprint as well as the authorization epoch. A later generation change invalidates it even when both observations still report repair-required/legacy. Missing or malformed fingerprints refuse. Foreign, corrupt or previously enabled/suspended repair states refuse; there is no silent reset. Changing that binding or enabling the policy invalidates existing legacy permits. Sign-in and administrator repair are separate routes, not group-authorized actions.

Resume calls the supplied existing `requireAdmin()` authentication path and requires the configured immutable directory administrator. A typed actor or local-host label is not accepted as that identity. The future endpoint must also apply same-origin/CSRF and exact-resource confirmation. A newly positive membership alone never resumes a suspended row.

Tests use real SQLite/hash-chain audit and an inert directory, plus real private TLS/WSS for two members. The network case suspends a group resource, observes committed state/version and stale server contexts before refresh, reconnects both members, and dispatches to an unaffected exact manual publication. The existing transport rig's audit writer is a synchronous scratch writer; the new group evidence uses the real hash-chain store. Separate group-directory suites cover real fake-LDAPS listeners. None is a production endpoint, real-directory/account, pilot, native-host or deployment claim. Runtime migration registration now requires a DB backup before deployment. An older binary may refuse the newer components; rollback must restore the matching backup and binary, preserving the existing monotonic-floor rules. No deployment is part of this slice.

## Composed message boundaries

The factory hashes the normalized, non-secret directory identity/search/trust configuration into a stable generation. Timeout tuning and bind-password rotation do not change it. The strict store is lazy, so an intact never-enabled generation mismatch keeps legacy operation while a previously enabled mismatch refuses protected actions and leaves sign-in/admin repair available. Closing the factory permanently closes its authorizer. A lifecycle suspension advances the existing transport version in the same DB transaction and refreshes current sockets only after commit.

`HubCore` obtains a fresh canonical asker permit plus separate fleet and exact exposure permits for a protected chat operation. It captures the current fleet credential/generation and exposure policy/revision, then rechecks all of them after the directory awaits and immediately at the effect. First-use asker enrollment creates only canonical group provenance after a fresh allowance. Concurrent first actions reconcile through a further fresh check; a new session never creates an alternative identity. Unknown and authoritative denial remain distinct, and neither creates a provenance row when the first action is refused.

Room opening, typed questions, button/vote writes, automatic poll-result queueing, room lists/views/history, browser file reads/uploads, member file chunks, dispatch and every authorization lease/answer commit use these guards. The existing owner grant, exact message facts, session/link fences and content/audit transactions still apply. A synchronous session check fences sign-out during a group lookup. Protected writes assert the permit both before work and after the synchronous audit, inside the same transaction, so a reentrant invalidation rolls them back. Read projections assert again before returning content. Dispatch asserts immediately before calling the current transport.

Group uncertainty holds queued questions without changing their stage or sent epoch. Automatic poll results remain held and may retry with a new check; closure of the poll itself is independent. Receipts, reconcile acknowledgments and an already accepted answer's idempotent ACK preserve durable evidence; they disclose no new answer content and do not manufacture permission. Sign-in, the owner's own administration metadata, grant revocation and exposure freeze/withdrawal retain their ordinary authority. A group allowance does not grant another person's room or agent.

This slice supplies no policy editor or activation endpoint. It does not yet enroll new exposure resources or accept publication under enabled policy. Those boundaries and the confirmed exact manual inventory must land before activation. Tests exercise the real HTTP handlers, SQLite lifecycle/audit and composed factory with fake people and directory facts; they are not a live-directory, pilot or native-host acceptance claim.


## Pairing enrollment

The server factory supplies pairing with the authorizer and an outer transaction on its own DB. After fresh ordinary eligibility and both existing owner/admin fingerprint confirmations, an enabled-policy claim prepares the exact new fleet ID/generation/immutable owner outside SQL. The transaction rechecks the current one-time offer, proofs, durable claim budget and number of all active credential-bearing fleets belonging to that owner, including manual fleets. Revoked fleets do not consume the owner's active limit. Concurrent preparations do not reserve or bypass that limit.

The ordinary store mutation, required pairing audit, new credential/fleet, required group registration audit and provenance share the same outer DB transaction. Final checks run after the store has written its new state, avoiding its intentional floor-before-write interval. They recheck the actual credential hash, owner, generation, offer fingerprint/confirmations and current permit before returning a credential. A late audit/lifetime failure rolls back both fleet and provenance, and an already advanced monotonic floor remains uncertain; it is never reset to make a retry appear successful. No separate committed core transaction, raw DB export or transport-store API change is used.

Unknown, denied and quota-refused attempts still consume the existing durable claim budget; exhaustion stops further directory work. Pending offers do not perform group lookup before ordinary confirmations. Intact never-enabled claims retain legacy behavior without membership lookup or provenance. The original eligible owner is also fenced against retargeting during the ordinary eligibility await, including with the feature off. This is an intentional proof-binding refusal, not a new owner-selection route.

Tests use real pairing, SQLite, floor, group and hash-chain audit with inert directory/session callbacks. A real factory over a sealed scratch home pre-provisions the enabled policy privately, proves unknown refusal and positive pairing with provenance, and serves its fake S3 ping over verified loopback HTTPS. That case proves composition, not a public activation endpoint or real LDAP sign-in. No native host, pilot or account is contacted.
