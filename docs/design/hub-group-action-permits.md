# Group action permits

This internal step follows [#3298](https://github.com/songsid/AgEnD/issues/3298), the [resource lifecycle](hub-group-policy-lifecycle.md) and [authorization refresh](hub-authorization-refresh.md). It connects fresh group decisions and durable suspension to the current global transport version. It does not register migrations, install HTTP/action hooks or expose an enable switch. Endpoint gates, confirmed impact preview, runtime composition and the welcome/pairing UI remain required before activation; the experiment stays off.

`createHubGroupAuthorization` returns `check`, `enroll`, `resume` and `close`. An allowed operation receives a permit, not a cached boolean. The caller must use a new check at each protected action, read, dispatch and release boundary, and call `assertCurrent()` immediately before the actual effect. Each permit binds the validated resource kind/ID/exact revision/immutable owner, lifecycle row revision/source/state, complete policy snapshot, store/composition identity, global authorization version, and server/caller fences. Input objects and callbacks are captured before awaits. The synchronous assertion does not repeat LDAP; it fences changes during that one operation. It is not an eligibility allow-cache for another request.

`enroll` records provenance only after a fresh group allowance. It creates no exposure, fleet credential, room, grant or delivery. Its caller still owes ordinary ownership, account eligibility, local consent, fingerprint proof, quota and grant checks, plus the final actual-resource commit. In enabled mode, `check` refuses absent provenance. An asker is always `{kind:"asker", id:person.objectId, revision:1, owner:person}`: new sessions or fabricated revisions cannot evade a suspended person's explicit-resume requirement. Publication and fleet bindings use their actual persisted IDs/revisions; display names are not identities.

Allowance audit derives the resource ID/revision from the validated binding, overriding caller-supplied context. Group decision evidence includes the immutable person, matching group GUIDs, capability, policy revision, directory generation and observation time, with the precise resource revision in its hash-bound event body. Standard operation audit, consent and audience checks remain the endpoint's responsibility. Manual grandfathering remains exact and membership-exempt, while an explicit person deny still suspends it.

## Suspension and refresh

Unknown directory facts hold only the current action. They do not change resource state or advance the global version. Diagnostic audit may be recorded. A fresh complete positive recovers without resume if nothing was suspended. The documented last-direct-group/omitted-memberOf exception remains unknown rather than a proved negative.

A complete negative updates the lifecycle record and calls a synchronous required version writer inside the same SQLite transaction. The runtime composer must supply the transport store on that exact DB. The writer must advance the version and must not close sockets or perform asynchronous work. No transaction is kept open across directory or administrator awaits. After a successful commit the adapter invokes synchronous non-retiring refresh. Old server link contexts already fail their version gate before sockets close; unaffected paired fleets reconnect with their credentials intact. A failed transaction never invokes refresh.

The lifetime fence in the options is the server/composition lifetime; the per-request/session/link fence belongs in the check context. Suspending a member's old-version context intentionally invalidates that caller. This does not undo the narrowing suspension. Resumption broadens access, so its independent administrator/session fence is checked after the version writer too. Reentrant policy changes roll the transaction back.

A required writer returning a thenable, failing to advance the version, throwing, or losing current authority withholds the result. If a later transaction failure follows an independent monotonic-floor advance, the established transport store deliberately freezes as uncertain; the adapter never resets that floor or restores permissive state. A refresh error after commit cannot undo the committed suspension/version, and no permit is returned. The normal listener/component owner remains responsible for directory and socket cleanup. `close()` permanently fences outstanding permits and directory continuations; it does not own a separate directory connection pool.

## Legacy and administrator boundary

An intact never-enabled policy preserves legacy behavior without group lookup or new group state. A same-Hub/same-realm never-enabled record needing directory-generation repair uses the reviewed binding probe without constructing the strict mismatched store. Foreign, corrupt or previously enabled/suspended repair states refuse; there is no silent reset. Changing that binding or enabling the policy invalidates existing legacy permits. Sign-in and administrator repair are separate routes, not group-authorized actions.

Resume calls the supplied existing `requireAdmin()` authentication path and requires the configured immutable directory administrator. A typed actor or local-host label is not accepted as that identity. The future endpoint must also apply same-origin/CSRF and exact-resource confirmation. A newly positive membership alone never resumes a suspended row.

Tests use real SQLite/hash-chain audit and an inert directory, plus real private TLS/WSS for two members. The network case suspends a group resource, observes committed state/version and stale server contexts before refresh, reconnects both members, and dispatches to an unaffected exact manual publication. The existing transport rig's audit writer is a synchronous scratch writer; the new group evidence uses the real hash-chain store. Separate group-directory suites cover real fake-LDAPS listeners. None is a production endpoint, real-directory/account, pilot, native-host or deployment claim. Before runtime migration registration, rollback is a code revert; later deployment must account for the newer schema components and take a DB backup.
