# Hub simplification: Phase A server enablers (S1)

Implements S1 in [the Phase A/B build spec](https://github.com/songsid/AgEnD/blob/d015e6ce/docs/design/hub-ux-simplify.md), under #3658. Fleet forms, reconnect orchestration and Hub page wording belong to U1/U2. No Fleet input file changes here.

The metadata `features` array advertises `join-supersedes-v1` and `member-leave-v1` while company connections are enabled. The optional display name is **top-level `name`**, outside the signed, closed `hub` identity. Discovery and redeem accept `X-AgEnD-Join-Display: 1`: only those requests receive the optional metadata name and redeem `ownerLabel`/`hubName`. Old Fleets use strict schemas, so requests without that header keep the old response shape. An old Hub ignores the header and a new Fleet must accept missing display fields. Display fields confer no authority and never alter identity digests or sealed receipt bindings.

Admin overview adds `label`, provenance `source` (`group`/`manual`) and issuance `createdAt` (milliseconds). Unproved historical values are null; retention is not replaced with invented dates or provenance. No credential is projected.

`member.leave` has an empty strict payload. The exact authenticated current, reconciled link supplies its Fleet and owner. Both ends must negotiate `member-leave-v1` and `welcome-caps-v1`. The Hub commits the normal credential removal, generation/global-version increment and `member.left` audit before retiring sockets. It sends no durable ACK: its own successful revoke invalidates the link. Failure/offline removal can be repaired by supersession. Legacy peers never receive an unsupported frame. `HubRuntime.memberLeave(expected)` proxies `HubMemberClient.leave(expected)`, with the exact `{ hubId, binding }` captured by the local disconnect operation. The client verifies the private profile digest, live profile and negotiated link; the mount fences a changed member/generation after the write. It returns false on unsupported, offline, stale or failed writes and never supplies an acknowledgement. U1 owns the bounded wait, local tombstone and final local binding recheck.

Push accepts an optional `supersedes: { fleetId, credential }` only on the existing pinned, key-proved member endpoint. The credential is 64 lowercase hex characters. Only a matching active credential admits a Fleet ID to the private record; no credential copy or digest is persisted there. Wrong proofs are ignored. At approval and again at issue, a still-active old Fleet must belong to the same immutable AD person. That exact row is discounted from the personal quota. A different owner refuses. Global retained and 256-Fleet ceilings are unchanged.

Only issuance revokes the old row, within the existing root immediate transaction that creates the new credential, provenance, sealed receipt, required audit and notice outbox. The old Fleet receives no new-connection notice. No history is deleted, no pairing approval is forged, and no share/ask grant is added. Lost delivery recovers the same receipt and cannot supersede twice.

Permits bind the previous global authorization version. The issue transaction completes its ordinary permit checks, then performs the narrowing transport mutation. Its optional synchronous final proof runs after the required audit. The store raises the independent floor first; inside the uncommitted transaction it temporarily matches that revision while keeping the prior authorization image, checks the captured permit/session, checks that neither callback nor audit replaced the image, then publishes the narrowing image. The callback cannot yield. Errors roll back SQL but never rewind the floor. No other connection observes the intermediate image. Socket refresh occurs after root commit.

An active pairing offer or another approved reservation yields HTTP 409 `{ code: "offer-pending" }`. The browser request remains pending and can be approved after the other attempt is stopped; it is never reported as unknown issuance. Other conflicts retain their existing code. The key-proved Fleet status relays `offer-pending`, `limit-reached`, `denied` or `backpressure` on the still-pending exact request. It adds no issuance or terminal state. Successful approval clears that hint. This covers the alpha.14 rehearsal’s full-slot → offline disconnect → same-owner re-join failure; the actual Fleet rendering/orchestration remains U1’s.

Company-join component version 2 protects the added private record format. Upgrade preserves v1 rows and their raw-body CAS, normalizing a missing `supersedesFleetId` to null. Older binaries refuse v2; downgrade needs matching pre-upgrade state. Restoring an older database alone cannot rewind the independent authorization floor. UI old-tab behavior and the final integrated reconnect path are covered by U1/U2, separately from these backend/strict-reader controls.
