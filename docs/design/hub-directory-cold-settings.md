# Local AD settings while the Hub is stopped or held

M-2687 / #3425. An authorized D3 request can load and change a previously initialized Hub's AD connection without an AD sign-in or a running Hub listener. This extends the existing settings controller and sealed writer; there is no alternative writer, public recovery route, migration or directory authority.

The fleet adapter still proves the exact local host session, Host, Origin, CSRF, web-authority epoch and request lifetime before requesting the shared controller. Hub browser routes retain their configured-administrator proof. The ordinary off startup remains lazy: only an explicit authorized settings request can create the existing runtime/writer and acquire a headless source. Acquiring it never calls runtime.apply or starts a server/member listener.

The runtime first waits for an existing transition and positively drains a held server and its leftover cleanup. `HubMount.closeServer()` fences and drains only that side, without admitting or changing a membership in another Hub. An unchanged active server supplies its existing source instead. Every authorized controller access reacquires the current source, even when the host-lifetime controller is cached. A same-owner Refresh cannot leave later reads bound to a missing source; old drafts remain bound to the retired source and cannot be saved.

A headless source opens only the complete existing private state set, with `create:false`. It validates the complete build's migration registry, authority tables, Hub identity, transport floor, directory head and epoch. It never migrates, creates missing state, resets an epoch or repairs a damaged seal. The initialization signature and fixed private service-secret reference must verify against the current material. Older, newer, partial, uncertain or tampered state refuses. A Hub whose database has never been started on this build may need an explicit normal Run before cold editing can be available.

A cold lease owns the SQL participant used by its source proof; an expired live-generation reference cannot substitute another connection for the callback-scoped proof basis.

The lease constructs the old directory client without contacting it, and captures source material through the same mount barrier as a running generation. Read does not sign in or query directory eligibility. Its policy store supplies the existing 4/person and 32/total physical-promise budget. A cold lease and live server generation cannot overlap: replacement and Stop fence first, retain physical reads, await directory-client close, then close the database and zero its content key before replacement. Read ownership is registered before dispatch, including callbacks that synchronously close the lease. Failed cleanup retains ownership and refuses replacement. If construction fails and the created driver's close rejects, a private cleanup participant retains the driver, database and key. The runtime must positively drain it before another cold source, Run or Stop completes; it is not a usable settings source.

The admission ticket observes the complete Hub configuration even while `enabled:false`, when the ordinary listener reload view omits the directory. A held selection cannot revive after A → B → A, Off/On, identity change, same-configuration Refresh or Stop. Physical construction is registered before reentrant callbacks and drains before replacement; waiting for an earlier transition is kept outside that construction participant to avoid a cycle. Source admission rechecks after imports and construction; source capture checks the signed material again. Probes and Save drafts remain tied to their exact source rather than to the current address alone.

The shared directory writer can verify an explicitly disabled Hub for directory operations. It preserves that exact switch in the before/after image, staged files and compensation. Rename retains its existing running-Hub requirement. Changing the AD settings while stopped does not implicitly start the Hub, change membership or grant a browser session. Candidate TLS, immutable administrator/group continuity, service-secret reuse restrictions, audit, full fixed-recipient notices, authoritative SQL decision and forward-only compensation remain required.

A headless lease identifies its recovery mode. `off` can confirm a stopped Save's exact new head; `held` cannot certify successful listener startup. An enabled Hub that still cannot mount follows the existing compensation/unavailable path, even if another authorized settings read acquires a headless source during completion. It never reports ready merely because the database and seal agree. The local listener survives the Hub's remount and returns the existing bounded result; a revoked caller still receives no result.

Focused acceptance includes the existing actual D3 HTTP and fake-LDAPS journey in running and stopped modes. The old owned LDAPS peer is physically closed before read, preparation, test and Save. Only the replacement receives dummy service credentials; no AD sign-in is used, the Hub identity/certificate stay intact, no browser session is minted, group policy stays never-enabled, and the stopped case remains off. A later explicit Run starts normally at the new epoch. The same two journeys also inspect the replacement certificate through the composed CA API without a bind. Other tests use real scratch SQLite/seals/HTTPS with inert directory drivers for budget, ticket, cleanup and failed-mount controls. There is no real directory/account, native, pilot or live-fleet operation.

This is backend recovery composition. The AD form, its single trust dialog, desktop/phone EN/zh-TW PNGs and retained-module SKEW remain unfinished. No UI or completed M-2687 acceptance is claimed. Revert removes stopped/held editing without changing stored formats; existing matching-build/pre-upgrade-backup downgrade limits remain. Never rewind security epochs or floors to undo a directory operation.
