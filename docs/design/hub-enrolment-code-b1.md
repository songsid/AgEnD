# Reusable Hub enrolment codes — B1 server

加入碼只代表管理員允許連接 Fleet。每台 Fleet 仍須由持有人登入公司帳號，並保留 Fleet 本機同意、Hub 身分固定與金鑰證明。加入碼不授予詢問或分享 Agent 的權限。外洩時，同一公司內符合範圍且取得加入碼的人，可能在到期或停用前使用剩餘名額；管理員可隨時停用，已連接的 Fleet 則須個別撤銷。

Implements server sections 2.1–2.5 of [the approved simplification spec](https://github.com/songsid/AgEnD/issues/3658), decision 428768a0. Alpha only. U2 is a **merge** dependency: this work stays draft/held until U2 lands, then plain-merges alpha. B2 owns the slot UI and browser retry presentation. This PR does not edit the Fleet input or claim that those UI legs already pass.

Eight Crockford characters (40 bits; no I/L/O/U aliases), shown XXXX-XXXX. Defaults: local end of today, thirty uses, any eligible directory person, one Fleet per person. Choices are one hour/today/seven days, 1–200 uses, 1–8 Fleets per person, directory or an exactly resolved security group. Limits: eight live codes and ten creations/hour. Wrong code number eleven closes all code pushes for the remaining minute; group and individual invitations use their existing paths.

The new private file `hub/secrets/enrolment-code.key` is flushed with its private ancestors before database publication. HKDF separates HMAC lookup and AES-GCM keys and binds them to the Hub identity. The ciphertext authenticates the complete immutable code row. No material cache bypasses a failed durability retry. A durable database fingerprint binds the key even after all ended rows are pruned. A missing or replaced key refuses; it is not silently replaced. Ended sealed copies are erased lazily; ended listings last seven days from actual ending. Only configured-admin session/CSRF routes disclose live code text. It is never placed in request records, notices, audit or URLs.

Push proves the Fleet key and spends no use/reservation. AD browser approval reserves the exact code/request, enforces owner eligibility/excludes, exact fresh scope membership, remaining uses, same-owner offers and all-source Fleet quota. The code path has its own 120/min code/global budgets and 256 retained-request pool; group/quick admission retains its 48 pool and shared directory physical 4/person,32-total pool. Issued uses are excluded from unissued reservations to avoid counting twice. An unissued reservation ends at its 60-second redemption deadline even if the Fleet never polls. The captured immutable code image is rechecked after the directory wait and after required approval audit.

Issuance runs code-use CAS, request receipt, credential, code provenance, required audit and notice outbox inside the existing owning immediate SQLite transaction. Duplicate `request_id` use receipts must match code/Fleet/owner exactly. The use counter advances once. Final synchronous checks after required audit pin the consumed code image, revocation/expiry, use receipt, current owner/session/policy/resource and transport generation. A late refusal rolls SQLite back; the existing transport's conservative independent floor policy is retained. Redelivery of an already-issued result verifies its retained provenance/receipt without requiring a still-live code, so ending a used code does not disconnect its Fleets.

Code provenance is membership-exempt after issuance, like explicit admin approval, while fresh eligibility and explicit person `pair_fleet` excludes still apply. Group-policy off does not suspend it; a saved explicit deny blocks new code admission and suspends a retained code Fleet even before first policy enable. The confirmed impact plan follows that same code-specific rule; unrelated manual/legacy behavior remains unchanged. Removing the exclusion does not reactivate the Fleet: its current administrator must explicitly Resume the exact suspended revision, including before first policy enable, through fresh eligibility and all existing session, policy, row and authorization-epoch fences. Stored-source parsing includes revoked code history, so policy preview and apply remain available. A code Fleet cannot use the never-enabled legacy publication shortcut. It may publish only with an independent group publication allowance. Ordinary independent owner grants remain required to ask.

Notices use `pairing-notices-v3`, require `source:code` plus `codeId`, and keep code rows queued for v2-only links/browser readers. No downcast to manual/group. Member Settings explicitly selects group-only by default, manual at v2, and code only at v3; the current v2 UI never receives a code row. Authenticated browser approval can distinguish `reason:code-scope` from `reason:code-ended`; machine errors retain their closed generic DTO. Creation returns `freeFleetRows` for B2’s capacity warning. Member storage retains before ACK and binds code identity on replay.

Rollback requires matching pre-upgrade state. Components advance: new `enrolment-code` v1; company join v3; group resource format v2; member inbox v2; audit v2 with authenticated optional code attribution. Null attribution preserves every historical hash-chain byte. Migration of existing resources preserves rows/events. Older component plans refuse upgraded state. Restore the pre-upgrade backup to run an older binary.

Validation and runtime evidence are recorded in the eventual exact-head acceptance comment. Partial/fail-first logs are retained locally; no live directory, pilot, model/vendor account or native Windows run is implied.
