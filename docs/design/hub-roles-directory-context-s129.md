# Directory preparation belongs to its Core

This follows #3828 and adds a private `HubCore.directoryPreparation` adapter. It has no production caller, mounted-source producer, writer provider or HTTP/controller activation. Full S-129 acceptance remains open.

The raw management preparation retains its policy, directory, session and time basis. It does not know which HTTP Core selected it. Forwarding that handle unchanged would let it and its newly acquired effect proof survive replacement of the Core's management provider. The new adapter retains the actual Core configuration, directory, transport store, unit of work, method identities, mode/clock providers and caller request methods. Its synchronous ownership check uses the Core's existing atomic epoch/lifetime checks before and after reentrant proof callbacks. An observed owner failure permanently retires both preparation and its returned effect proof, even if the old object is restored later.

The optional preparation method is separate from ordinary management. Existing injected providers that expose only `require` still support their existing routes and refuse preparation. There is no root or eligibility-only fallback.

The adapter starts with an actual named administrator preparation. It preserves the upstream fixed five-minute preparation budget and obtains a new physical administrator proof on exchange. It does not extend the ordinary acquisition budget or five-second effect deadline. The fresh proof remains bound to the same Core, including its explicit callback-local directory-decision assertion. Both assertion methods return their original trusted wall-clock scalar. Neither method manufactures an opaque decision frame or relaxes its upstream checks.

Preparation consumption is separate from owner retirement. A successful exchange consumes preparation; subsequently asserting or retiring that consumed handle does not revoke its already acquired effect proof. Explicit cancellation while acquisition is held still prevents publication after settlement. A concurrent second exchange answers backpressure without cancelling the first. Sign-out during the held read uses the real token context's revoked answer. Physical directory work remains owned until it settles.

The tests use actual memory SQLite, HubSessions, canonical roles, the shared directory pool, persisted clock and transport floor with fictional eligibility responses. The explicit SQL test uses the real decision kernel and cutover clock, with inert file-image hashes. Its late-owner negative verifies rollback directly in SQL and separately verifies the independent floor's fail-closed hold; it does not reset that floor to make a read succeed. These are not mounted Save, file installation, successor response, browser, container, live AD, account or Fleet acceptance.

Method checks against the frozen raw handles and the duplicate actor/capability checks retain defensive validation of the typed provider contract. Their individual necessity is not claimed. The mutation receipt names only reversals that compile and turn semantic assertions red. The typed pass-through replay reproduces the original two failures with two passing controls; the original fail-first scaffold was a runtime test checkpoint, not a claim that its incomplete adapter type compiled.

Next work composes the mounted source and singleton writer, preparation-only recent-authentication/rotation adapters, and the fresh new-generation response release. It must acquire current effect authority before disclosure and preserve physical read ownership. Parent-first plain alpha synchronization, conflict review, exact-head CI and readiness remain required; only the coordinator merges. This slice changes no user-facing flow, so no built-in user skill changes. Before activation, rollback is to leave this private adapter uncomposed; committed directory changes still use forward recovery.
