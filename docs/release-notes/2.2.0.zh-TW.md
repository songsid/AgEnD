# AgEnD 2.2 更新重點

[English](2.2.0.md) · [升級指南](../upgrade-2.2.zh-TW.md) · [變更紀錄](../CHANGELOG.zh-TW.md)

**從 2.1.12 升級：** 預發期間請在支援的主機執行 `agend update --beta`；2.2.0 發布為 npm `latest` 後，在 General 傳 `/update` 就會選到它。2.1.0–2.1.11 請照升級指南的手動步驟操作。

## 在網頁聊天

Dashboard 每個 instance 都有自己的聊天：訊息、Markdown、檔案、投遞狀態和 Stop。選用的 HTML 預覽使用獨立的預覽來源，需要先同意開啟。詳見[網頁 dashboard 指南](../web-dashboard.zh-TW.md)。

登入時，在 General 傳 `/web`，再選：

- **💻 AgEnD 電腦登入（取碼）**：在執行 AgEnD 的電腦使用；
- **🌐 其他裝置登入（臨時公開）**：在其他裝置使用，須由 fleet 允許公開連結。

連結和一次性登入碼會私下送出；Discord 私訊失敗時可用僅自己可見的回應。代碼只能用一次，五分鐘內有效。本機 session 預設 48 小時；公開連結 session 最長四小時、閒置 30 分鐘失效，連結關閉時也會結束。`/web revoke` 可讓瀏覽器登出。

## 集中處理需要你的事

**Needs you** 彙整待處理提示和確認。Settings 的敏感變更會成為提案，由有權限的 General 管理員在聊天確認；主機備援方式是 `agend settings confirm <id>`。待確認提案不會跨 fleet 重啟保留。

ClassicBot 空白允許清單不再讓所有人直接開新房間。ClassicBot 管理員可略過准入名單；其他新啟動需要明確授權或 General 核准。Telegram 群組仍必須由 ClassicBot 管理員啟動。已註冊的房間不受影響。

## 投遞證據與明確轉交

跨 instance 訊息使用持久化 outbox。`uncertain` 代表可能已送達，不要貿然重送。`Delivery not found` 也可能是無權讀取或證據已過期，不能當作從未送達的證明。

轉交需要另一個 agent 查證的訊息時，每一跳都要把 ID 放進 `forwards`；只在文字中提到 ID 不會授權。使用者收據會分別保留原始身分和內容，不會把 agent 的轉述當成原始授權。網頁顯示名稱或認得的使用者 ID 都不授予平台權限。詳見[投遞驗證](../delivery-verification.zh-TW.md)。

回覆請求會依 correlation 追蹤；請用相同 `correlation_id` 回覆才能結案。重啟提醒會合併成一則；舊義務預設 24 小時後過期，不再每次重啟都翻出來。

## 選用的 Log 步驟與更多回覆方式

管理員可開啟 `web.log_tab`（預設關閉）。Claude Code 與 Codex 會顯示目前、已有 owner 證據的對話步驟及 fleet 事件。Kiro 與其他後端只顯示 fleet 事件，並說明為何無法提供原生步驟。

Agent 可附上回覆按鈕、限時投票及支援的貼圖。回覆和檔案會出現在網頁聊天及所連接的聊天平台。

## 更少廣播，更清楚的失敗說明

主機記憶體壓力仍會減慢或暫緩啟動，並反映在健康狀態和 dashboard。所有記憶體壓力聊天廣播（包括恢復通知）均已取消；啟動、重啟或喚醒操作被暫緩時，會向發出操作的人說明原因。

靜默排程不要求向頻道回覆。排程投遞失敗或 uncertain 時，仍可能通知 General；「靜默」不代表隱藏錯誤。

更新失敗會在可取得時附上階段、原因及更新日誌路徑。回報問題時請保留日誌。舊更新程式及不支援主機的處理方式，見[升級與復原步驟](../upgrade-2.2.zh-TW.md)。

## 主機需求

支援 macOS，以及有 glibc 和 systemd 的 Linux（包含已啟用 systemd 的 WSL）。不支援 Alpine／musl Linux、沒有 systemd 的 Linux 或原生 Windows。在 Linux glibc 2.28+、macOS 11+ 的 x64／arm64 上，一般安裝會附上 AgEnD 釘定的 Node runtime；其他情況請看升級指南的 Node 需求。
