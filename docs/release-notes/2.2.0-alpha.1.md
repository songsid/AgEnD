## Install and update (pending #1259)

> These commands work once the alpha release channel (#1259) has merged. Until then there is no `@alpha` npm tag.

- Install: `npm i -g @songsid/agend@alpha`
- Update: `agend update`. An alpha install stays on alpha; it is never moved to stable or beta. `/update` in the chat does the same.
- Back to stable: `agend update --stable`

## Testers, read this first

- **Everyone signs in again once after upgrading.** The old cookie is no longer accepted. Send `/dashboard` in Telegram or Discord, or run `agend web` on the host, for the sign-in link and a one-time code.
- **If you expose the dashboard through a tunnel, set `web.view_access: session`.** Reading `/view` needs no sign-in by default, and `/view` shows each instance's live terminal. On loopback only, the default is fine.
- **The CSP still allows `'unsafe-inline'`.** Every panel carries a Content-Security-Policy that keeps connections to this origin. `'unsafe-inline'` goes once the dashboard's `onclick=` handlers are rewritten.
- **Uploaded files go to the instance's workspace inbox** (`<AGEND_HOME>/workspaces/<instance>/inbox`), where files from Telegram already go. A file attached but not sent within 30 minutes is deleted.
- **A sign-in you did not make?** New sign-ins are announced in the General topic. To sign every browser out:
  - Telegram: `/dashboard revoke`;
  - Discord: `/dashboard` with `action: revoke`;
  - on the host: `agend web-token rotate`.

## What's new

### 1. One-time sign-in codes; no credential in any link
- `/dashboard` (Telegram/Discord) or `agend web` gives the sign-in page and an 8-character code. The code works once and expires after 5 minutes.
- Signing in starts a server-side session. It ends after 12 hours, or after 2 hours idle, and survives a fleet restart.
- Every write passes CSRF and Origin checks.
- New sign-ins are announced in the General topic (`web.notify_login: false` silences this).
- An old `?token=` link or bookmark opens the sign-in page, with the token removed from the address.
- The CLI and scripts keep using the `X-Agend-Token` header.

### 2. One navigation bar and one Session menu
- `/ui`, `/view` and `/settings` share *Dashboard · View · Settings*.
- The Session menu shows:
  - this browser, and when its session ends;
  - every other signed-in device, each with its own Sign out;
  - Sign out everywhere.
- `/` opens the dashboard.

### 3. Web chat
- **Markdown**: headings, bold, italics, strike-through, `code`, code blocks, lists, quotes, rules and links. Nothing in a message can produce HTML of its own.
- **Composer**: several lines (Enter sends, Shift+Enter adds a line). If sending fails, the text is given back.
- **History**: a reload no longer empties the chat. Long agent replies go up to 16,000 characters (was 2,000).
- **Files and images**: 📎, paste or drop. Limits: up to 5 per message, 10 MB each, 25 MB together; PNG, JPEG, GIF, WebP, PDF and text. The agent receives them exactly as from Telegram, and files the agent attaches to a reply show in the chat.
- **Delivery ticks**: ◷ queued, ✓ handed to the agent, ✓✓ the agent has it, ! not delivered, ⊘ cancelled by Stop.
- **"*name* is working…" and Stop**: Stop does what Telegram's cancel button and `/cancel` do. It sends Esc and drops the messages still waiting. It does not stop the instance's process.
- **One conversation with Telegram/Discord**: a web message is echoed into the topic (`🌐 web-user: …`). The agent's reply goes to Telegram/Discord as usual and also shows on the web.

### 4. `/view`
- Reading needs no sign-in by default (`web.view_access: open`). Set it to `session` to require one.
- Writes (profile, avatar, sidebar order) always need a session.
- No token in the address bar or `localStorage`. A token an older version stored in the browser is removed.

### 5. Connection
- If the live stream (SSE) is silent for 15 seconds or keeps failing, the page polls every 5 seconds. The switch loses nothing and shows nothing twice, so Cloudflare Quick Tunnels and buffering proxies work.
- Automatic polling is not activity, so it never extends the idle limit. Ticks missed while the stream was down are caught up on reconnect.

## Suggested test path
1. Get the link and code (`/dashboard` or `agend web`), sign in, and land on `/ui`.
2. Pick an instance and send a text message. Watch the ticks go ✓ → ✓✓, and see it in Telegram/Discord too.
3. Attach an image with 📎 and send it. Check the agent got it.
4. Give the agent a longer task. When "is working…" shows, press Stop.
5. In the Session menu, look at your devices. Sign one out, then sign out everywhere.
6. Open `/view` in a signed-out window: you can read, but not edit.
7. Open an old `?token=` bookmark: you get the sign-in page, and the token is gone from the address.
8. (Through a tunnel) open the dashboard, and check it falls back to polling when SSE does not get through.

## Settings
| Setting | Default | Meaning |
|---|---|---|
| `web.view_access` | `open` | `session` requires sign-in to read `/view` too |
| `web.notify_login` | `true` | `false` stops announcing new sign-ins in General |

## Not in this alpha
- Answering the agent's prompts with buttons on the dashboard (R6, #1261)
- External gateway mode (waits on decision D2)
- Agent-defined reply buttons (C-2), the task board
- Markdown tables and nested lists in the chat
- Removing `'unsafe-inline'` from the CSP
