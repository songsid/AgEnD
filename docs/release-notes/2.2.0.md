# What's new in AgEnD 2.2

[繁體中文](2.2.0.zh-TW.md) · [Upgrade guide](../upgrade-2.2.md) · [Changelog](../CHANGELOG.md)

**Upgrading from 2.1.12:** during the prerelease, use `agend update --beta` on a supported host. Once 2.2.0 is published as npm `latest`, plain `/update` in General selects it. From 2.1.0–2.1.11, use the upgrade guide's manual steps.

## Chat from the web

The dashboard has a chat for each instance: messages, Markdown, files, delivery status and Stop. Optional HTML previews use a separate preview origin and require opt-in. See the [web dashboard guide](../web-dashboard.md).

To sign in, send `/web` in General and choose:

- **💻 AgEnD computer: get a code** for the computer running AgEnD;
- **🌐 Other device (temporary public)** for another device, when the fleet permits public links.

The link and one-time code are sent privately; Discord can use an ephemeral response if DM fails. A code works once for five minutes. Local sessions default to 48 hours; public-link sessions last at most four hours, expire after 30 minutes idle, and end when the link closes. Use `/web revoke` to sign browsers out.

## One place for requests that need you

**Needs you** collects actionable prompts and confirmations. Sensitive Settings changes are proposals: an authorized General admin confirms them in chat, with `agend settings confirm <id>` as the host fallback. A pending proposal does not survive a fleet restart.

ClassicBot's empty allow lists no longer make new rooms open to everyone. ClassicBot admins bypass the admission lists; other new starts need an explicit grant or General approval. Telegram group starts still require a ClassicBot admin. Existing registered rooms keep working.

## Delivery evidence and explicit forwarding

Cross-instance sends use a durable outbox. `uncertain` means a message might have arrived: do not resend blindly. `Delivery not found` can mean hidden or expired evidence, not proof that a message was never delivered.

When relaying a message that another agent must verify, put its ID in `forwards` on every hop. Mentioning the ID in the text grants nothing. Human receipts retain the original actor and content separately from an agent's relay. A web display name or recognized user ID grants no platform authority. See [delivery verification](../delivery-verification.md).

Reply requests are tracked by correlation: reply with the same `correlation_id` to close one. Restart reminders are batched, and stale obligations expire after 24 hours by default instead of being raised on every restart.

## Optional Log steps and richer replies

An admin can enable `web.log_tab` (off by default). Claude Code and Codex show steps from the current owned conversation plus fleet events. Kiro and the other backends show fleet events, with the reason native steps are unavailable.

Agents can attach reply buttons, timed polls and supported stickers. Replies and files appear in web chat as well as the connected chat platform.

## Quieter operation and clearer failures

Host memory pressure still slows or holds admission and appears in health/status and the dashboard. All memory-pressure chat broadcasts, including recovery notices, are gone; a held start, restart or wake action tells its requester why.

Silent schedules do not require a channel reply. A failed or uncertain scheduled delivery can still notify General; silence is not a guarantee that errors are hidden.

Update failures include the stage, a cause and the update-log path when available. Keep that log when reporting a problem. See the [upgrade and recovery steps](../upgrade-2.2.md) for old updaters and unsupported hosts.

## Host requirements

Supported hosts are macOS, and glibc Linux with systemd, including WSL configured with systemd. Alpine/musl Linux, Linux without systemd and native Windows are unsupported. On Linux glibc 2.28+ and macOS 11+ (x64/arm64), the normal installation includes AgEnD's pinned Node runtime; otherwise consult the upgrade guide's Node requirements.
