Shared backend/model defaults

The old loader merged the Fleet backend and model independently. An agent selecting another backend still inherited the Fleet model. The resolver and dev Settings counter repeated this fallback; model/backend differences then used the generic cold stop/start reconcile.

The fix scopes a model to its exact declaring backend, preserves explicit agent models, and applies the same rule to ClassicBot's room → Classic defaults → Fleet defaults chain. Changing the shared backend clears its prior model selection. Counts use matching-backend consumers; previews also include model inheritance gained/lost when a default backend changes.

Before Save, choose **Next restart · no restart now** (the safe default) or **Restart running agents now** (confirmed before the first write). This shared path offers next-start adoption rather than calling individual model switching, which writes own overrides and may restart on an unconfirmed CLI result. Deferred identities survive unrelated reloads without hiding other cold changes. The confirmation gives the exact running-agent count and display names, with an explicit Restart now button. Consent is bound to that named list and the current saved value/runtime owner; newly affected or unknown owners wait for the next start. Stopped and paused agents stay stopped. Runtime-facing model/backend readouts and command dispatch keep the old identity until the next start. Other edits retain their own visible apply costs.

R2 closes the write-to-Apply race: Save returns an opaque, single-use receipt for that write’s exact pending entries and runtime owners. Apply uses that receipt instead of minting consent from the latest entries. A later save or replacement owner defers adoption; missing, stale or expired receipts cannot authorize restart. The browser freezes both backend/model values and the named list shown in confirmation. Receipts are bounded to 256 retained snapshots and expire after ten minutes. The ClassicBot model selector now describes inheritance only from defaults matching its selected backend.
