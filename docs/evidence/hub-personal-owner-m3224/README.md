## Risks and rollback

The migration is intentionally forward-only and has not been registered. Existing Fleet publications retain their
ids and all inbound references. A production caller cannot create a personal publication through a member snapshot.
The follow-up must compose fresh authorization, durable question ownership and answer disclosure before registering
the migration or advertising a feature. Omitting this layer leaves the existing Hub flow unchanged; an unused local
personal profile can be disconnected through the ordinary Runtime command.
