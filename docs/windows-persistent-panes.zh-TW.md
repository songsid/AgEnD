# 常駐 Windows 代理（alpha）

這個介面須在 **2.3.5 alpha 線**明確選用；原有每回合啟動一次的 **exec** 仍是預設。協調端繼續在 WSL/Linux 執行；這台電腦或已配對 Windows 電腦上的 Codex、Claude Code，則在常駐的原生 ConPTY 終端執行。每個代理都有自己的終端與確切保存的對話，Windows 不需執行 tmux。

## 選擇執行方式

先在**設定 → Runtime**開啟對應開關：這台電腦使用「使用這台電腦的 Windows CLI」，配對電腦使用「允許其他 Windows 電腦配對」。明確偵測該機器上的 CLI。在**新增代理 → 原生 Windows**為 Codex 或 Claude Code 選擇「常駐終端（alpha）」，並核對管理員確認卡上的工作目錄、檔案權限與目的地。建立時一併保留設定檔、實例與話題；無法確認清理完成時，這些資源會一起保留待處理。

初次驗證的版本是 **Codex 0.165.0** 與 **Claude Code 2.1.316**。其他版本不會啟用這個介面；偵測清單之後才更新的 CLI 也一樣。每次開啟終端前，受控輔助程序會關閉自動更新，執行有時間上限的純版本檢查。這與管理員發起的完整偵測不同，不會在啟動時檢查登入、搜尋模型或同步帳號。刻意更新 CLI 後請重新偵測；新版本仍須先通過介面驗證。

設定表示方式如下：

```yaml
runtimes:
  windows_cli: true
  remote_runtime: false
  max_agents_per_machine: 4
instances:
  example:
    runtime: windows
    native_agent_id: "<既有原生設定檔的 UUID>"
    native_adapter: pane
    native_sandbox: read-only
```

請透過需要確認的新增代理流程建立設定檔，不要自行填造 UUID。省略 `native_adapter` 或設為 `exec`，會使用原有每回合執行方式。匯入或 YAML 設定不會自動建立外部話題。常駐代理建立流程會將目的地綁在管理員確認中，確認後不會悄悄改用另一個 General 連線。

「每台電腦同時執行的 Windows 代理」可設為 1–16，預設 **4**。這台電腦與每台配對電腦分別計算，包含執行中的 exec 工作與常駐終端。調低上限只阻止新啟動，不會停止既有代理；程序結果不明也會占用名額。常駐代理沒有全 Fleet 共用一個名額的限制；exec 仍維持原有回合排程與五分鐘上限。

## 訊息與權限

常駐代理使用一般實例的 daemon、話題／聊天、投遞日誌、回覆檢查、進度與「需要你」流程。畫面擷取來自無視窗終端，工具與回合證據來自該代理確切持有的原生對話。AgEnD 不會挑選資料夾中最新的對話，接續時固定使用保存的對話 ID，不使用 `--last`，失敗後也不悄悄開新對話。若 Windows Claude 尚未儲存固定的對話，執行端須肯定證明對話檔不存在，才會自動開一次新對話並通知；原本的識別碼保留在收據中。

一般權限對話保留 CLI 自己的政策，仍需既有管理員／人工操作權限。通過驗證的 Windows Claude 畫面在重繪時，選項旁可能殘留較早的命令字元；AgEnD 按擷取結果顯示。若導覽途中卡片改變，回答會停止，需要重新選擇，不會自動接著送按鍵。按鈕綁定目前實例、終端、啟動與互動，不能核准替換後的終端。Codex 使用原生沙箱與按需核准。Claude 唯讀模式開放 Read/Glob/Grep 與限定的 AgEnD 查詢工具；**這是工具政策，不是作業系統沙箱**。Claude 的工作目錄權限使用 `acceptEdits` 與本次啟動專用的 `blockWritesOutsideWorkingDirectories` 檔案工具檢查，不加 `--add-dir`，也不略過權限確認。兩種執行方式都加上 `--setting-sources ""`，不載入使用者、專案與本機設定（包括額外目錄與允許規則），但不改寫這些檔案；組織管理政策仍然適用。Shell 與 MCP 工具有各自的政策，這不是作業系統沙箱。Windows Job Object 與私人檔案權限用來確認程序歸屬、保護狀態，不是檔案或網路沙箱。

每次啟動有自己的角色指示與限定的 AgEnD MCP 連線，不改寫共用專案指示、不將 Windows 憑證複製到 WSL、不修改帳號設定，也不用協調端的登入帳號。Codex 加上 `--no-daemon`，只有明確設定的 AgEnD 輔助工具預先核准，其他工具仍依 CLI 政策處理。

Alpha 限制：原生附件／檔案傳輸工具與推理強度控制尚未提供，會明確拒絕；這個介面不提供 CLI 用量報表。從聊天請代理建立新代理，是另一項整合，不等同於需要管理員確認的新增代理頁面。投遞 Enter 與一般終端採用相同規則：只有後端自身認得的執行期對話框會阻擋，不因畫面無法辨認為輸入框而阻擋。投遞、僅限輸入框的操作，以及明確的人類選項回答，各有獨立的內部證明，仍須綁定當下畫面與輸出序號。畫面重繪可能明確拒絕尚未輸入的操作。Claude 自動信任步驟也要求顯示路徑與設定的工作目錄完全相符。

## 斷線、停止與復原

Claude 對話檔不存在或無法讀取時，不會反覆重試續接。肯定證明不存在時，只自動開一次新對話；替換後的對話仍未儲存時，不會再自動另開。無法確認時會出現在「等你處理」，管理員可在聊天或詳細資料按「開始新對話」。確認操作綁定當時的啟動與對話，既有對話檔不會刪除，舊輸入也不會重播。舊分頁的復原操作會拒絕並提示重新整理。主機或傳輸暫時不可用時，保留一般啟動重試，不視為對話不存在。管理員確認開新對話前會再檢查一次；若對話已可讀取，會保留原識別碼，改請管理員按「啟動」。尚未開啟的替換終端採用目前的模型、權限、角色與工具清單，保留已選定的啟動識別碼。

- 協調端重啟、WebSocket 重連或前景 Runtime 用戶端結束，都只分離連線、保留常駐終端。重接須核對同一受驗證主機、終端、啟動與設定檔身分。斷線期間撤回待處理 MCP 權限；重連不會重送 Enter、貼上或結果不明的工具變更。
- **停止**會關閉確切受控的工作程序，等待肯定的結束收據。崩潰復原會先核對先前投遞，再釋放舊權限，於有限次數內接續同一對話。反覆崩潰會保留待處理；手動重啟不抹除對話。
- 主機程序死亡或無法確認結束時，會保留持久名額。中斷的 relay 會在下一次獨立要求前捨棄；失敗輸入不重播。確切的結束收據，或啟動前記錄且已證明改變的 Windows 開機身分，才會釋放該次啟動並接續已固定的對話。只有 PID／連線消失不算結束；沒有開機證明的舊終端仍保留。
- 管理員可在聊天與詳細資料中使用「復原已停止終端」。先確認該代理的 Windows 程序已全部停止，再確認畫面指定的啟動；這只記錄管理員的停止證明，不發送程序訊號、不重播工具／輸入，也不刪除舊帳本。之後另外按「啟動」接續原對話。缺少已固定對話、終端仍屬目前主機或啟動身分已改變，都拒絕復原，絕不改開新對話。同一電腦上的其他代理仍可在名額內啟動。
- 舊 alpha 終端主機若不支援啟動結果或 Claude 對話證明協定，會在開啟終端前保留一次。停止該電腦的 Windows 代理並重新啟動 Windows，再按「啟動」。開關保持開啟時，協調端／relay 重啟仍保留終端，不等同關閉主機。
- 關閉 Runtime 開關會立即禁止新輸入／MCP，並清理確切持有的終端。離線或結束不明仍會保留；重新開啟不能越過未完成的清理。
- 每個終端都有確定的結束或未啟動收據後，明確關閉開關會結束空的終端主機；重新開啟時按需啟動新主機。開關仍開啟時，relay／協調端重啟只分離連線，不關主機。CLI 在斷線期間結束會先核對收據再釋放名額；被拒的啟動即使後來有空位也不會重播。是否重新接上由主機回報，涵蓋啟動回覆遺失；對話尚未確認的重新連線不會收到啟動按鍵。
- **撤銷機器**會清理該配對身分確切持有的終端工作，並撤銷憑證。一般斷線與連線替換只分離連線。執行端離線或無法證明清理完成時，中央仍保留名額，不假稱已停止。

終端命令使用封閉操作集合、身分核對與持久的操作／順序紀錄；Runtime 連線不提供任意執行檔、參數、環境或 shell 命令 RPC。傳輸與輸出佇列有上限並會施加背壓，原始診斷日誌輪替，對話缺口會明示，不偽裝成完整歷史。

## 退回 exec

1. 停止常駐代理，等待確定的受控結束。結果不明時，先檢查並處理保留的啟動，不要替它另開一種介面。
2. 保留原生設定檔、確切對話 ID、日誌與實例／話題，只在 `fleet.yaml` 將該實例的 `native_adapter` 從 `pane` 改成 `exec`，再重新載入設定。
3. 透過原有 exec 路徑送一個簡短接續回合，使用同一設定檔保存的對話 ID。CLI 本身仍須支援該對話及一般 exec 命令。改回 pane 也需先停止。

這個退回流程不會同時接管兩種介面，不自動開新對話、不刪除設定檔，也不改寫帳號資料庫。

## 封裝與驗證範圍

Runtime 附有固定版本 node-pty ConPTY 的 Windows x64／ARM64 預編譯檔與無視窗終端。組包時檢查雜湊、原生 PE 架構與模組完整性；原生 Windows x64 有實跑，ARM64 封裝檢查不代表已在 ARM64 真機驗證。不會在使用者電腦上編譯原生模組。

私人暫存位置會先核對不可變套件，防毒／檔案鎖干擾有有限次重試。啟動過慢有期限並保留結果，不另開無法追蹤的 CLI。暫存測試包含一般防毒行為，未修改 Defender 或清快取；測量不是其他電腦的速度保證。

參閱[本機 Windows 設定](windows-cli-preview.md)與[配對 Runtime](remote-runtime.md)（英文）。手動驗證程式及隱私限制記錄於 `scripts/manual/windows-pane-adapter/README.md`。

忙碌畫面重繪可能讓執行端明確拒絕尚未送出的 Enter。只有這種肯定未輸入的回覆，才允許重新觀察並再送 Enter：第一次拒絕後兩秒內最多五次，啟動身分須相同，每次檢查後端認得的執行期對話框，並附上新的輸出序號證明。僅限輸入框的呼叫，以及綁定選項身分的人類逐步回答，仍保留原本的獨立檢查。不重貼訊息，不重試未知或遺失的回覆；達到限制後，傳送會保留為未確認並出現在「等你處理」。

建立未附觀察證明的輸入操作前，擷取失敗可在兩秒內最多重新讀取五次。這只重讀畫面；貼上 RPC 僅送一次，貼上回覆遺失時保留待確認收據，不重送輸入。
