# 處理中斷的 Kiro 對話帶入

TUI fleet agent 同時有原本帶入的對話，以及含有工作的較新對話時，才使用此功能。自動恢復會維持等待，不會自行選擇要放棄哪份工作。

`reconcile_kiro_instance` 提供給 full／coordinator 工具權限。呼叫只會在 **General 請 fleet admin 確認**，不會立即封存或變更資料。目前只支援保留已證明屬於該 agent 的原始帶入對話，不能任意指定另一份新對話。CLI 必須已停止；暫停的 agent 也必須通過程序已停止的檢查。

```json
{
  "name": "your-kiro-instance",
  "keep_session_id": "original-carried-uuid",
  "archive_session_id": "newer-uuid"
}
```

確認提示會列出 agent 與兩個 ID。取消、過期、非管理員點擊、證據已改變或無法寫入稽核紀錄，都不會進行處理；沒有強制執行或略過確認的參數。

確認後，AgEnD 會保留該 agent 的操作權，阻擋衝突的啟動與訊息投遞，再檢查設定、擁有權、完整帶入歷史與程序停止證據，完整保留**兩份** V2 檔案。只把明確指定的較新對話視為已確認封存的衝突；第三份含有工作的對話仍會阻擋。接著修復原對話登記，用既有驗證交易備份並移出原對話凍結的經典副本，再驗證首次啟動與一次一般重啟中的對話 ID、模型、紀錄來源與鑑識讀取器。失敗會停止等待，不會改開新對話或切回經典模式；若無法確認清理程序已停止，會明確說明。

## 封存與稽核

原生 V2 的 `.json`、`.jsonl` 與存在時的 `.history` 都不會被改寫、搬移或刪除。完整副本保存在：

```text
<AGEND_HOME>/kiro-reconciliations/<agent 名稱 SHA256 的前 32 碼>/<receipt>/
```

檔案權限為 `0600`，目錄為 `0700`。`manifest.json` 記錄檔案雜湊、原大小與時間、明確選擇、確認者及先前的 AgEnD 登記。兩份對話都可在主機上以原格式讀取，二進位 `.history` 也會原樣保留。封存不會自動刪除，復原後也一樣。請勿修改封存或已退出使用的原生對話，否則後續啟動會因證據改變而停止等待。

該 agent 封存目錄的 `active.json` 記錄收據與處理階段。General 與 agent topic 會通知結果及收據；即使 Kiro 原始歷史讀取仍未開放，Log 分頁也會顯示 `kiro_reconcile` 事件。稽核事件及工具回傳不含對話本文。

檔案、目錄與清單都會先 fsync 並讀回驗證，才寫入允許修復登記的持久意圖。已確認的流程若中斷，只能完成同一個選擇；格式錯誤、資料改變或不確定的證據都會維持等待。工作在既有、有時間及資源上限的 Kiro worker 內執行，不阻塞 fleet 主事件迴圈。

## 復原到停止等待狀態

先用一般單一 agent 控制停止它，不要為此使用會停止整個 fleet 的 `agend stop`。以**相同的兩個 ID** 加上結果收據提出復原：

```json
{
  "name": "your-kiro-instance",
  "keep_session_id": "original-carried-uuid",
  "archive_session_id": "newer-uuid",
  "rollback_receipt": "64-lowercase-hex-receipt"
}
```

仍需要新的管理員確認。已被後續選擇取代的登記、範圍不符或擁有權已改變，都會拒絕。復原會從匹配且驗證過的封存還原凍結的經典資料列，不覆蓋衝突資料，再還原先前的 AgEnD 登記並維持停止。兩份原生 V2 對話（含接回後新增的工作）及所有封存都保留；不回退工作目錄的修改，也不貼上或重播任何提示。

持久的復原中／已復原標記會阻擋自動啟動自行選擇對話。檢查後，可重新明確提出保留原對話的處理。復原不代表允許切回經典模式或任選另一份對話。

請先部署審查過的程式碼，再要求真實操作。發布版本或先前的使用者選擇，不能取代 General 的當次確認；由 fleet leader 監督的修復，還需等待 leader 核准實際呼叫。
