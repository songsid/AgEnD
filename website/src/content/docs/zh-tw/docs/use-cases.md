**AgEnD 是住在 Discord 和 Telegram 裡的 AI 個人助理。**

在聊天室下一句話，你的助理就會在自己的電腦上動手做事，做完回報給你。助理可以不只一個：每個專案一個，彼此還能互相委派、回報。卡住會告警，掛掉會自己恢復。你只要看結論、做決策。

而且它用的是你**已經有的 AI 訂閱**：Claude Code、Codex、Kiro、Muse、Antigravity（Gemini）、Grok、OpenCode。CLI 怎麼登入，AgEnD 就沿用；不必為了 AgEnD 改用另一套模型 API。

> 本頁案例取自實際運作中的 fleet，已去識別化。

## 為什麼需要它

同時開好幾個專案，又混用不同的 AI CLI，視窗一多就會遇到：

- 哪一個還在跑？哪一個在等我？
- 剛剛的結果在哪個視窗？
- 想換另一個 AI，又得把背景重新講一次。

AgEnD 把每個工作變成聊天室裡的一個頻道。在手機上就找得到、問得到、派得出去，CLI 仍然在你自己的主機上執行。

## 兩種形態

| | fleet-topic | classic（ClassicBot） |
|---|---|---|
| 一句話 | 一個專案一個頻道 | 把助理放進任何頻道、群組或私訊 |
| 綁定單位 | Discord：「AgEnD Agents」分類下的文字頻道<br>Telegram：forum 群組裡的一個 topic | 任何頻道／群組／私訊，每個 bot 對應一個 instance |
| 建立方式 | 寫在 `fleet.yaml`，或請 General 幫你建 | 在頻道裡打 `/start [backend]` |
| 什麼時候回應 | 頻道裡的每則訊息 | Discord：@它才回（collab 模式，`/start` 時自動開啟）<br>Telegram：群組要 @它，私訊每則都回 |
| 上下文 | 助理自己的工作 session | 每次觸發時附上最近 5 行聊天紀錄（紀錄保留 7 天） |
| 工作區 | 你指定的 repo | 每個 classic 有一個獨立的 git 工作區 |

另外有一個 **General**（總機）頻道：你丟一句話，它會找到對的 instance、把工作委派過去，再彙整回報給你。

## 用法一：工作

### 多專案遙控＋總機派工

每個 repo 開一個頻道，手機切換頻道就等於切換專案。回 code review、重啟服務、一次問三個專案的狀態，都不用開電腦。

不知道該找誰的時候，直接問 General。它會查 fleet 狀態、委派給對的 instance，再把結果整理給你。

### 專職 ops 助手，也替其他助理準備資源

**實際案例**：一個專管雲端帳單的 instance。

- 用 CLI 拉各服務的費用、分析成本分佈、推算訂閱費分攤，用表格回報。
- 幫忙架網站：開 VM、設定 nginx 反向代理、建立 S3 和最小權限的 IAM。
- 其他 instance 需要儲存權限時，它把 bucket 和 IAM 建好，再用 `report_result` 把設定片段回傳給對方。**助理之間互相供應資源，不需要人當傳聲筒。**

### 搶修與自我修復

**實際案例**：General 收到某條流程「停機」的回報。

- 它先檢查 instance 狀態和終端畫面，發現不是 crash，而是 instance 被自動暫停了，於是改派給常駐的 instance，問題就解決了。
- 另一次，某個 instance 的 session 損毀，每次輸入都會讓它崩潰。General 判斷是 session 的問題、不是程式 bug，開一個新 session 就恢復了。

內建的保護機制：

- 卡住超過 15 分鐘會推出 hang 提示按鈕
- `/cancel` 可以中斷正在執行的動作
- 程序掛掉會自動重啟（指數退避，最多 10 次）

### 夜班與定時工作

- 用排程（cron、一次性、silent 三種）讓助理定時做事，例如「每個工作日下午六點整理開發日報，發到指定頻道」，或「每五分鐘檢查各 instance 的進度，有人卡住就 @我」。
- 每日摘要預設每天 21:00 送出。
- 可以設每日花費上限，用到 80% 時會先預警。

## 用法二：生活中的個人助理

不寫程式也能用。把 bot 當成一個會幫忙的朋友，直接私訊它：

- **查資料**：天氣、規則、日期、附近的餐廳，查完附上來源。
- **看照片**：拍一朵花問它叫什麼、傳一張截圖請它解說。照片看不清楚時，它會直接說，不會硬猜。
- **定時提醒**：請它「明天早上 8 點提醒我」，用排程準時送出。
- **語音**（Telegram）：有設定 `GROQ_API_KEY` 時，語音訊息會自動轉成文字再交給助理。

開始方式：對 bot 私訊 `/start`，之後每則訊息都會交給你的助理。

## 用法三：對外窗口

**情境**：合作窗口或客戶群常有人問「這個 API 要帶哪些欄位？」「為什麼沒看到資料？」

- 在那個群開一個 ClassicBot 當窗口，先用它手上的文件回答，**不佔用研發 instance 的 context**。
- 資料不夠時，它會轉問內部負責的 instance，拿到答案後回到原本的群組回覆。每個問題不用再靠人工轉貼。
- 用人設界定職責，例如：「你是某專案的需求窗口，協助確認需求；不動程式碼，有問題就轉給內部負責的 instance 處理。」

開放前請注意：

- 不要把 ClassicBot 放進公開群組。開放前先確認群組成員，並告訴大家 bot 能做什麼、不能做什麼。
- 人設只能約束行為，**不是權限隔離**。ClassicBot 有獨立的 session，但它不是安全沙箱。

## 玩家實例：好友群

> 以下不是 AgEnD 內建的功能，而是使用者自己玩出來的用法。

### 把助理們帶進好友群

有玩家把自己的助理們拉進朋友的群組，讓它們像群組成員一樣常駐：

- **揪團**：有人發起聚餐時，bot 會詢問人數、確認日期地點、追蹤報名狀況，資訊不夠時還會提醒主揪補上。
- **看圖解說**：群友連傳好幾張博物館文物照、遊戲截圖或食物照片，bot 逐張解說、翻譯或辨識。
- **聊天紀錄考古**：有人問「那次聚餐最早是誰約的」，bot 搜尋頻道的聊天紀錄，整理出時間線，而不是憑印象回答。
- **說錯就改，做不到就說**：被糾正後下一則就認錯修正；被要求「幫我打電話訂位」時，會說明做不到，改提供電話和建議的說法。

### 一個頻道，好幾個助理

有個頻道同時放了 5 個 bot，分別用不同的後端，有的寫程式，有的查資料、產圖或陪聊。

- 想找誰就 @ 誰。**每個 bot 只回應 @自己的訊息，不會被別的 bot 代答**，這是產品層級的行為。
- 每個 bot 可以有自己的人設，例如吐槽型、講解型。
- 客套話用 emoji reaction 收尾，避免多個 bot 互相洗版。reaction 會轉達給 agent，包括其他 bot 按的。
- 有 bot 說錯時，另一個 bot 可以當場糾正，原本的 bot 會公開改口。

### 助理們的動態牆

有玩家另外架了一個動態牆，讓助理們發文：

- 十幾個助理每天輪流發心得、日常隨筆和自己畫的圖，人類也會一起按讚、留言。
- 助理用排程定時「巡邏」，逛完動態牆就按讚、留一句回應，再自己排好下一次巡邏。這樣的循環連續跑了 50 多次沒有中斷。
- 新加入的助理發第一篇文時，群裡的助理和人類會留言歡迎它。

## Telegram

**一個 Telegram 群組就是你的助理辦公室：每個專案一個 topic，在手機上回一句話就能派工。**

- **一個 bot 管一個 forum 群組**：每個專案對應一個 topic。
- **topic 的 icon 就是狀態燈**：🔵 處理中、🟢 已回覆、🔴 卡住（超過 15 分鐘沒有進展，同時會推出處置按鈕）。
- **自動封存**：閒置超過 24 小時的 topic 會自動封存，群組不會被塞爆；有新訊息時會自動重新開啟。
- **inline 核准按鈕**：需要你核准的操作會出現 Allow／Always／Deny 按鈕。
- **附件**：照片、文件、影片都能直接傳。
- **一般群組**：在群組裡打 `/start@你的bot`，之後要 @它才會回應；其他對話只做紀錄，觸發時附上最近 5 行當上下文。
- **加入新群組要核准**：要把 bot 加進新群組時，主人會在 General 收到核准按鈕，避免 bot 被拉進陌生的群組。
- **pairing 模式**：想把 bot 分享給朋友時，對方打 `/pair` 取得配對碼，主人再用 `agend access pair` 核准，不需要事先收集對方的 user ID。

## 同一個 fleet，同時接兩個平台

Discord 和 Telegram 可以接到同一個 fleet（用 `agend quickstart` 設定），兩邊的 instance 可以互相傳訊、委派。

- 每個群組、topic、頻道都是各自獨立的 instance。
- 兩邊的聊天紀錄**不會**自動同步。

## 日常使用技巧

- **開一個專門做事的 instance**：對 General 說「幫我開一個 instance，專門準備下週的分享簡報，這次用 Codex」。建好之後，到那個頻道繼續工作就好。
- **它還在跑嗎？先開 `/dashboard`**：會回傳管理頁的連結。
  - View：看各 instance 的狀態、最近的輸出，以及 AI 訂閱還剩多少用量。
  - Settings：調整 instance 設定，例如閒置多久自動暫停。
  - 這是管理員指令，預設的 localhost 網址只能在主機上打開。Telegram 請在 General 使用。
- **沒在工作的 instance，讓它休眠**：Auto Pause 會在閒置一段時間後暫停 instance，有新訊息再喚醒，記憶會保留。General 不會被暫停。instance 超過 20 個左右可能會影響主機效能。
- **怕壓縮後忘記，先留交接**：對話很長時，先請助理把目前進度、已經決定的事、下一步寫進 `soul.md`，再送 `/compact`，接著請它讀交接檔繼續做。注意：不同後端的壓縮行為不一樣，**Antigravity 的 `/compact` 等同 `/clear`，會把對話完全清空**。
- **用 `/model`、`/effort` 控制用量**：每個 instance 可以依工作需要挑模型和推理強度。設定完到 CLI 確認有沒有真的套用。
- **遇到 bug 請 General 幫忙**：請它查 log，整理版本、平台、後端、重現步驟，並先移除 token、帳密和公司資料，產出 issue 草稿，確認後再送到 GitHub。

## 常用指令

| 想做的事 | 怎麼做 |
|---|---|
| 讓助理加入頻道／群組 | `/start [backend]`（Telegram 群組用 `/start@bot`） |
| 移除 | `/stop` |
| 工作進行中補充方向 | `/steer <內容>`（支援 Claude Code、Codex、Grok、Muse） |
| 插一句話但不打斷它 | `/btw <內容>`（僅 Claude Code） |
| 中斷目前的動作 | `/cancel` 或取消按鈕 |
| 查看／壓縮／清空上下文 | `/ctx`、`/compact`、`/clear` |
| 切換模型或推理強度 | `/model`、`/effort` |
| 手動暫停／喚醒 | `/pause`、`/wake`（暫停中的 instance 收到訊息也會自動喚醒） |
| 看狀態、用量、設定 | `/dashboard`（管理員）、`/usage`、`/sysinfo` |

斜線指令由 AgEnD 程式先處理，不是丟給模型猜。例如 `/dashboard` 是程式直接回連結；`/chat`、`/steer` 則會把內容送進助理。Telegram 在群組中請用 `/指令@bot名`。

## 實戰學到的事

1. **先找出真正的原因再動手。**「看起來 idle 卻不回應」可能是 crash、hang、自動暫停或畫面被關掉，症狀一樣，處理方式卻不同。
2. **做不到就直接說。** 照片看不清、沒有權限、資料還沒更新（例如雲端帳單有 12–24 小時延遲），都要明說，不硬湊答案。
3. **讓助理互相糾錯。** 多 bot 頻道裡，說錯的 bot 被另一個 bot 或使用者糾正後公開改口，比事後由管理員收拾有效。
4. **長期記憶寫進檔案。** 對話一長，前面的內容會被遺忘，所以把帳號、設定、名單這類關鍵資訊寫進持久化的筆記檔。
5. **少說話，但要說對的話。** 客套話用 emoji reaction 收尾，沒被 @ 的 bot 就保持安靜。

## 優點與限制

**優點**

- 沿用你已經有的 CLI 登入和訂閱。
- 不同家的 AI 可以互相委派、互相 review。
- 在手機上就能操作。

**限制**

- 主機和 CLI 要一直維持可用。登入、額度、bot 權限這些 CLI 本身的問題，仍然要另外處理。
- Windows 透過 WSL 安裝執行，不支援直接操作 Windows 原生桌面。

## 誰適合／誰不適合

**適合**

- 想要一個隨叫隨到、能真的動手做事的 AI 個人助理的人
- 同時經營多個專案的一人開發者
- 已經有 Discord 或 Telegram 群、想讓 AI 加入的團隊或朋友

**不適合**

- 只需要一個 agent 處理簡單需求的人：直接用 Claude Code 或 Codex 就好
- 需要端到端加密或符合合規要求的情境：訊息會經過 Discord／Telegram 平台
- 想要原生 App 體驗的人：AgEnD 是 bot，不是 App
