# Interrupted task-work recovery (#2473, stage 3)

Build this checkout in a capped unit, check `free -m`, and keep within the fleet's
two-heavy-job budget. Then run:

```sh
bash scripts/manual/working-recovery/run.sh
```

The runner packs the candidate with `npm pack --ignore-scripts`, records its
tarball hash and checkout revision, and installs that package in one disposable
systemd249 container. It copies existing local dependencies and the mock fixture;
there is no registry, account or provider access. The container has private
PID/cgroup/network namespaces, no host mounts, 1.5 GiB RAM, zero swap and two CPUs.
Only its nonce-labelled container is removed. Never run `driver.py` on the host.

The persistent scratch-user service is generated by real `agend install`, with a
768 MiB inner limit. The harness checks loaded Type, NotifyAccess, OOMPolicy and
memory values. Mock Telegram uses loopback only. Every fault is preceded by a
fresh sibling reply through thread 87; reset drains stale mock long pollers.

The task is created, claimed and updated through the real instance MCP tool,
not inserted into SQLite. Reads use read-only SQLite connections; final copies
use SQLite backup so WAL state is retained. It exercises these legs:

1. **Manual restart under pressure.** Keep elevated memory-reader input for more
   than two real minutes after final READY. No continuation may enter stdin.
   Release pressure; require thirty real seconds of normal pressure before one
   advisory continuation. The fleet PID and NRestarts stay unchanged while held.
2. **Actual main-process OOM.** Verify the private MainPID's UID/cmdline/cgroup,
   raise only its victim score, then allocate inside the capped unit through a
   mock child. Require increased cgroup `oom_kill`, an automatic service restart
   and a new MainPID. After final READY and the real stability interval, exactly
   one continuation reaches the unfinished task owner.
3. **Repeated failed boots.** Exit twice before READY, preserving the data home.
   No continuation occurs during the failed boots; after convergence the same
   work is continued once. No accelerated production timer is used.
4. **Ambiguous input.** Observe the real continuation on mock CLI stdin, then kill
   the private main before its acknowledgment. Let another real stability window
   pass. Its durable possible-input fence must prevent a second paste.

`bootstrap.mjs` supplies a directly owned session ID only for the mock backend,
an empty fixture composer/raw-input mode, and a positive mock stdin receipt as
submission proof. It controls the memory reader and injects boot/fence faults.
Production recovery decisions, monotonic stability timers, pacing, journal,
episode/outbox transactions, native tmux paste/Enter, service notifications and
restart supervision run unchanged. This is orchestration evidence, not an audit
of a provider's session parser or background inventory. Unknown session ownership
and known running background work are separate real manager/daemon unit controls.

Stage 3 owns task-only work. #1209 interrupted turns and #926 reminders remain
unchanged and are excluded from this coordinator; their consolidation and full
turn-recovery harness belong to stage 4. An ordinary SIGKILL is never labelled
an OOM. Inspect each leg's journal, timeline, physical-input receipts and database
backup in `.artifacts/working-recovery-*`. A final acceptance receipt must name
the exact committed candidate; exploratory receipts also retain an uncommitted
patch and must not be described as exact-head acceptance.
