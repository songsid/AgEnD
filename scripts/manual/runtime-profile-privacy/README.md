# #2965 N7 Windows ACL check

Run `check.ps1 -PrivacyScript <this checkout's templates/runtime-assets/runtime-pane-private.ps1> -ScratchParent <an owned NTFS scratch directory>` with Windows PowerShell 5.1. It creates and removes one GUID directory, uses synthetic text only, starts no Runtime/provider and changes no existing parent ACL. It proves new-directory privacy under an explicitly shared parent, private reuse, shared-directory refusal, unrelated-file preservation, and rejection of an explicit broad child ACL. It also refuses an ancestor granting another user DeleteSubdirectoriesAndFiles before creating a profile. It also covers generic-all and generic-write ancestor grants. Expected output: eight passing cases (nine in hosted CI with the shared scratch negative).

Linux unit models prove the constructor gate/ordering, safe refusal and file identity fences. They do not prove NTFS enforcement or the .NET Framework directory-creation ACL overload; do not label them a native Windows run. [Microsoft's creation API](https://learn.microsoft.com/en-us/dotnet/api/system.io.directoryinfo.create?view=netframework-4.8.1), [ACL propagation](https://learn.microsoft.com/en-us/windows/win32/secauthz/automatic-propagation-of-inheritable-aces), and [bypass traversal](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/bypass-traverse-checking) explain the design.

CI runs this same script with Windows PowerShell 5.1 on a fresh GitHub-hosted `windows-latest` machine, using the runner user’s local `TEMP` beneath `USERPROFILE`, requiring NTFS, and logging its ancestor ACLs. The genuinely shared hosted `RUNNER_TEMP` remains a separate ninth negative case; neither parent ACL is changed. The release-only job checks out the exact PR head/push SHA, has a five-minute deadline and no retry. The build aggregate rejects missing, failed or skipped NTFS results on the required release events. No user Windows host or WSL interop is used.
