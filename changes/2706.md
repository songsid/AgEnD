section: Fixed
---
- **Offices saved with an Edit layout survive a rollback to 2.3.1 (#2706).** 2.3.1 accepts only an office's name, members, style and old layout in its entry in `web-offices.json`. It didn't show an office that had a layout from Edit layout, and its next save deleted that office for good. An office's layout is now kept beside the office list in the same file, as night places and seat reservations already were. On 2.3.1 every office shows, only without its layout. A file written by an earlier 2.3.2 beta is read as it is and moved to the new shape on the next save. A layout that no longer checks leaves its office in, without the layout; before, it dropped the office. The data-downgrade check now reads and saves offices with the published 2.3.1 store. A 2.3.2 beta from before this fix shows offices without their layouts after a rollback. An office id can no longer be `__proto__`, `constructor` or `prototype`, so no office loses its layout to a name every object already has.
