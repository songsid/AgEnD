- **A main task shows what its sub tasks' agents are really doing, and how the baton passes from one sub task to the next (#4335).** "In progress" is a status, not a sign that an agent is working, so a sub task's row on a main task's page now says it itself, with no extra line: while its agent is running the sub task the row is tinted and its title shimmers (nothing moves with "reduce motion"), and every other state is a short label beside the title — "Waits for S-1", then "Handed to dev" → "Read", or why the hand-over did not arrive ("dev offline", "dev paused", "Not sent", "Not told": the agent's task board is off, the notice was lost) — or "Blocked", "Waiting for you", "Looks stuck", "Idle", "Busy · 2 cards". Pointing at a row shows the whole sentence, and what the agent is doing right now ("dev · Edit src/game.js") when steps are offered (an admin, the agent's `tool_progress` on, Show activity on); the state alone otherwise. The main task's "Agent activity" block lists the same instead of "The work is in its sub tasks", its status gets "Running" while a sub task's agent is, and its activity gains the sub tasks' moves and a row for each hand-over ("S-1 done → handed to dev to start S-2", then where it stands). Nothing starts the next sub task by itself: its assignee is sent one `[Task board]` notice when everything it waited for is done (or when a card is assigned to it) and claims the card itself — the notice and `task get` now say to claim it before starting, and the page says so. An agent that goes ahead and works on its assigned card without claiming it is no longer invisible: while it is working, has no other card and the hand-over notice has reached it (not one that was not sent, or is still on its way), the card's row (shimmering, labelled "Not claimed yet", flagged if it stays so for a while), the main task's block, the hand-over row, the status and the board's tile show it running; nothing moves the card for it. The state is read from what the dashboard already knows and the steps from the chat's own activity feed, with the same permissions as before; a read-only session sees the state and the sub tasks' moves, not the delivery of a notice. Nothing is rewritten and no data is lost on a downgrade: the new table `task_handoffs` is additive and old code never reads it.
