- **A failed chat `/update` now shows a short cause and logs the full output (#1818).** Before, a failing updater only reported `updater exited 1` with no information. Now: (1) the updater's stdout and stderr are written directly to `$AGEND_HOME/update.log` via a file descriptor (not a pipe) — this means the updater can keep writing even after the fleet process that spawned it has stopped, avoiding SIGPIPE killing grandchild processes such as `agend restart` or service installation commands; (2) `update.log` is capped at ~400 KB across runs (mode 0600 — raw output, owner-readable only); (3) the failure message includes a short cause extracted from this run's output only — the last `npm ERR!`/`npm error code` line (skipping npm 10's generic "A complete log of this run can be found in" footer), the last `✗` line, or the last non-blank line — truncated to ~300 characters and masked for secrets; (4) the message ends with "Full log: `<path>`". The success, pending (exit 75) and interrupted paths are unchanged.
