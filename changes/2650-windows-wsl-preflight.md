section: Fixed

- **The Windows installer checks the computer before it sets up WSL, and checks that what it enabled really is on (#2650).** It reads the Windows build, the architecture, both Windows features WSL needs (Windows Subsystem for Linux and Virtual Machine Platform) and whether virtualization is on. A Windows older than 10 version 2004 (build 19041) or a 32-bit Windows now stops early with what to do, instead of failing later with a generic "Ubuntu installation failed". Virtualization that is clearly off in BIOS/UEFI gets a specific hint. The installer enables only the feature that is missing. Before, Virtual Machine Platform was skipped whenever the WSL feature was already on. It also checks each DISM result and reads both features again, rather than announcing "enabled" whatever happened. On an ARM64 PC the WSL download fallback now takes the ARM64 package instead of the x64 one, and it has a time limit. A new install whose `wsl --install` did not produce Ubuntu (older WSL without `--location`) falls back to importing the official Ubuntu image, as the separate-distro path already did.
