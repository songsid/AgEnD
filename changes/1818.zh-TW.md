- **聊天 `/update` 失敗時現在會顯示簡短原因並記錄完整輸出（#1818）。** 以前 updater 失敗只會回報「updater exited 1」，沒有其他資訊。現在：(1) updater 的 stdout 與 stderr 透過檔案描述符（非 pipe）直接寫入 `$AGEND_HOME/update.log`——這樣即使啟動 updater 的 fleet 行程已停止，updater 仍可繼續寫入，避免 SIGPIPE 打斷 `agend restart` 或服務安裝等孫行程；(2) `update.log` 上限約 400 KB（模式 0600，僅擁有者可讀，內容為原始輸出）；(3) 失敗訊息包含只從本次執行輸出提取的簡短原因——最後一行 `npm ERR!`/`npm error code`（略過 npm 10 的通用「A complete log of this run can be found in」結尾）、最後一行 `✗`，或最後一個非空白行——截短至約 300 字元，並遮蔽機密後才顯示；(4) 訊息結尾附上「Full log: `<路徑>`」。成功、等待中（exit 75）與中斷的路徑不受影響。
