- **主任務會顯示子任務的 agent 是不是真的在做，以及子任務之間怎麼交棒（#4335）。** 「進行中」只是狀態，不代表 agent 正在做，所以主任務頁的每個子任務列現在自己就會說明，不再多佔一行：agent 正在執行這個子任務時，那一列會有淡淡的底色，標題有一道光掃過（系統設定「減少動態」時不會動）；其他狀態是標題旁一個簡短的標籤——「等 S-1」，接著是「已交給 dev」→「已讀」，交接沒送到時會說明原因（「dev 離線」、「dev 已暫停」、「沒送達」、「沒通知到」：agent 的任務板關閉或通知遺失）——或是「卡住了」、「等你回應」、「似乎卡住」、「閒置」、「忙碌中（2 張）」。滑鼠移到那一列上會看到完整的句子；有提供步驟時（管理員、該 agent 的 `tool_progress` 開啟、「顯示活動」開啟）還會看到它現在在做什麼（「dev · 編輯 src/game.js」），否則只顯示狀態。主任務的「Agent 活動」不再只寫「工作在子任務裡」，而是列出同樣的內容；有子任務的 agent 在執行時，狀態旁會多一個「執行中」；動態裡多了子任務的狀態變更，以及每次交接一列（「S-1 完成 → 已交給 dev 開始 S-2」，底下是目前進度）。下一個子任務不會自己開始：前面做完（或卡片指派給它）後，負責的 instance 會收到一則 `[Task board]` 通知，由它自己認領——通知與 `task get` 現在都會明講要先認領再開始，頁面也把這件事顯示出來。agent 如果沒認領就直接做指派給它的卡，也不會再隱形：只要它正在執行、手上沒有別張卡，這張卡的那一列（標題閃動，標上「尚未認領」，拖了一陣子還沒認領會加上警示）、主任務的區塊、交接列、狀態旁和看板卡片都會顯示它在執行；系統不會替它改卡片的狀態。狀態取自 dashboard 本來就有的資訊，步驟取自對話的活動資料，權限和以前一樣；唯讀連結看得到狀態和子任務的變更，看不到通知的送達狀況。降版不會遺失資料：新資料表 `task_handoffs` 只增不改，舊版不會讀它。
