section: Added

- Settings → Runtime → Connect a computer opens on two install methods. **Windows (PowerShell)** shows a copyable install command and connect command with the confirmed AgEnD address filled in; **Other install methods (ZIP)** keeps the existing download and `connect-agend.bat` flow unchanged. The install command downloads `install.ps1`, checks it against the SHA-256 the page shows, and runs it only if they match, so a modified script never runs whatever the TLS trust decision was. The script checks Node.js 22.14+, downloads this AgEnD's Runtime, verifies its pinned SHA-256 before unpacking, installs under `%LOCALAPPDATA%\agend-runtime\<version>` next to any earlier version (an existing version is never deleted), and adds `agend-runtime` to your user PATH. It needs no administrator rights and does not connect or pair; the one-time code is still typed in the terminal and the computer still needs your approval.
- The AgEnD server now serves `/runtime/install.ps1` and `/runtime/v1/bundle/windows.zip` as read-only, static, rate-limited downloads that need no sign-in. They exist only while Allow other Windows PCs to pair is on (otherwise they answer 404), never through a public gateway link, and only over HTTPS or loopback. They carry no token, secret, pairing code or server address, and grant no access.
- A Runtime whose version does not match this AgEnD (no common protocol, or no `exec` capability) is now refused instead of connecting and failing later: its card in Settings → Runtime stays offline and says to run the install command again, and its own window says the same and keeps the pairing.
