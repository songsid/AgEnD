section: Added

- **Access & security → Sign-in & authorization is reworked for a fleet with no chat connection (#3061).** The page lists Owner verification first, then the sign-in session settings, then Web authorization, with the reference page's wording. The "Connections from outside" card is now "Owner verification": a status badge, badges naming the supported authenticator apps (Google Authenticator, Microsoft Authenticator, other TOTP authenticators), and the rule that set-up, re-binding and removal happen on the AgEnD computer only, with no email or backup-code recovery. Setting up or re-binding the authenticator opens a dialog (steps 1 and 2: QR code and key, then the code) instead of unfolding inside the card; Esc and Cancel close it and change nothing, and a wrong code is answered inside it. The Web authorization card says the owner is verified with the authenticator instead of in Discord or Telegram. No setting or stored value changes.
- **A new device signs in with an 8-character code (#3061).** The sign-in page on the dashboard's own address offers "Sign in with another device": it shows a code and a five-minute countdown. A device already signed in as the owner (this computer's admin, or signed in from outside with the authenticator) approves it under Settings → Access & security → Sign-in & authorization → Devices & sign-in → Add device, after seeing where the request is from, its address and the code to compare with the new device's screen. Approving copies no sign-in to the new device: it makes a session of its own, without owner authorization. Codes are single-use, expire after five minutes and are rate-limited (limits count the connection's own address, an IPv6 address by its /64); wrong codes at the approving side pause approving. Not offered through the public link, on a fleet with a chat connection, or while web authorization is off (no one could approve).
- **A list of signed-in devices, and an optional login QR code (#3061).** Devices & sign-in lists the signed-in devices: this one marked, how each was approved (sign-in code, device code, this computer, authenticator app), whether its owner is verified, and when it was last active. The verified owner can sign another device out there. **[Behaviour change]** On a web-only fleet, ending another device's session — by that button or the `DELETE /auth/sessions` routes the Session menu uses — now takes the owner; a session a code or a device approval made can still sign itself out. With web authorization off nobody is the owner, so the card says so and points to `agend web-token rotate` on the AgEnD computer, which ends every session. A fleet with a chat connection is unchanged. The new `web.login_qr` switch (off by default) makes the new device's page also draw a QR code of the approve link: only the page's own address and the code on screen, never a credential. Open it on a device that is already signed in as the owner, not on a signed-out one (its sign-in link does not carry the code).
- **The agent file reader refuses `web-remote-access.json` and `web-authorizations.json` (#3061).** An agent could name these two files, which hold the authenticator secret and wrong-code state and the session authorizations, from an admitted staging directory. They are on the private-name list now.
