- **Chat `/update` works when AgEnD was installed with nvm (#3440).** When the fleet service's PATH listed a system npm (such as `/usr/bin/npm`) before the nvm Node that installed AgEnD, `/update` refused with "… is not an installed AgEnD package", and the update it would have run could pick the wrong npm too. `/update` now asks the npm beside the running AgEnD first (run by that prefix's own Node), then the npm beside the Node running AgEnD, then PATH's. An npm counts only when its global root holds the running AgEnD, and the rest is verified exactly as before. When no npm on the host manages the running install, `/update` says so, naming the global root it expected and what each npm answered. The updater it starts puts that install's `bin` directory first on PATH, so `agend update` checks and installs with the same npm.
