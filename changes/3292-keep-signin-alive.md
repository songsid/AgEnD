- **Settings → Accounts: Keep sign-in alive.** A Claude Code or Codex login that no agent runs on used to go stale unnoticed, because the CLIs renew a sign-in only when they run. Each Claude Code and Codex account (the default sign-in and every named account) now has a **Keep sign-in alive** box, off unless ticked. AgEnD then checks that sign-in about once a day and renews it when it is due, with the CLI's own tools and no model request: `claude auth status` for Claude Code, and the app-server's account read with a refresh for Codex. It reads the result back from the account's own file. A sign-in a running agent or ClassicBot room uses is left alone. For Claude Code, a second box allows one tiny request on the smallest model when the status check did not renew it. The row shows when the sign-in ends (a Claude Code sign-in's end date never moves when it is renewed), Codex's plan and the last result. **Needs you** asks you to sign in again when renewing fails or did not work, after two failed days when the service could not be reached, and from ten days before a Claude Code sign-in ends. The log records names, results and dates only, never a token.
