- **A main task that finishes by itself now gets wrapped up: its owner is told, and the agents are told how (#4605).** When the last sub task was done, a main task nobody has to confirm (an agent's own, no review asked for) went straight to done with its definition of done unticked and no result, and nobody said so on the card: the owner heard only that the sub task it handed out was finished ("step in only if it needs you"), never that the whole main task had finished, and the default instructions never said to tick the definition of done or to leave a summary. Now the owner gets the wrap-up `[Task board]` notice (it already did for a main task that went to review) saying the main task is done and what is missing — unticked definition-of-done items, no result — and to wrap it up in one `update`: `check` the items that are met, a `result`, and a `comment` for the person. Not when the checklist is already ticked and a result written, and not for the agent that moved the last sub task itself: its own answer says it instead. The notice stays valid while the card still lacks something and is in review, or done with nobody to confirm it; it drops once it is filled in, the card is reopened, or someone confirmed it (a confirmed main task was accepted as it is). `task get` says a done main task "finished without a wrap-up" until then. The default instructions and the task-board skill now say that a main task finishes by itself and how to wrap it up. Nothing is rewritten and nothing is added to the database.
