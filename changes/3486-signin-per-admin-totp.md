- **Sign a new browser in with YOUR OWN authenticator app (#3486).** A browser that is not signed in yet can sign in as one admin with the 6-digit code of that admin's own authenticator (the app set up in Settings → Access & security → Owner verification), on chat fleets and web-only fleets alike. The browser types the admin's name (their chat handle, user id, or `connection:id`) and the code; the session is that admin's own, and their confirmations follow their own rules afterwards (including their own switch). It works on a direct connection (LAN, tailnet, your own proxy) and, on a chat fleet, over a public link; "Only this computer can authorize" closes it. Nothing lists admins and nothing tells a stranger from an admin: a wrong code, an unknown name, an admin with no app and a demoted admin all get the same answer, counted the same way. Each time step is used once (shared with that admin's confirmations). One person's typos pause only their own browser (5 wrong codes); shared ceilings (per admin, per name typed, fleet-wide) stop guessing, and a browser the admin has already signed in from (a signed "known device" mark that grants nothing by itself) is not held by them (its own wrong codes are counted by the mark and by a per-admin known-path limit of 30, so a stolen mark cannot be used to guess for ever; a thief who keeps failing can in the end pause that admin's known devices too, after a Notice). Shared counts forget only after a day without a wrong code, and the admins get one Notice half-way. Every sign-in is a Notice to all admins. The 8-character sign-in code is unchanged, and an admin with no app keeps using it. The sign-in page for this is temporary: `/signin/authenticator`.
