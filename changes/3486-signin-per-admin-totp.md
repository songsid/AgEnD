- **Sign a new browser in with YOUR OWN authenticator app (#3486).** A browser that is not signed in yet can sign in as one admin by typing **only the 6-digit code** of that admin's own authenticator (the app set up in Settings → Access & security → Owner verification), on chat fleets and web-only fleets alike. There is no name to type and nothing lists admins: the server compares the code with the app of every admin who has one and is still an admin (each of them, every time, with the same time-step window), and exactly one match signs that admin in. No match, or two apps matching at once (about 3 in a million for each other admin), signs no one in and gets the same answer as any wrong code ("the code is not right; if it has just changed, wait for the next one"), spending nothing — so nobody can tell a collision from a typo. The session is that admin's own, and their confirmations follow their own rules afterwards (including their own switch). It works on a direct connection (LAN, tailnet, your own proxy) and, on a chat fleet, over a public link; "Only this computer can authorize" closes it. Each time step is used once (shared with that admin's confirmations). One person's typos pause only their own browser (5 wrong codes); a shared ceiling of **20** wrong codes for the whole sign-in then pauses new devices (15 minutes, doubling to a day) — tightened from 50 because with N admins having an app, each guess is N times as likely to match; `docs/SECURITY.md` has the odds (about 2.2 % × N a year for a guesser who never stops, who also sends the admins a Notice every day). A browser the admin has already signed in from (a signed "known device" mark that grants nothing by itself) is not held by that shared pause (its own wrong codes are counted by the mark and by a per-admin known-path limit of 30). Shared counts forget only after a day without a wrong code, and the admins get one Notice half-way (the 10th wrong code) and one when a wait starts. Every sign-in is a Notice to all admins. A request that still sends a name (`account`) keeps working, the old `signinName` in `GET /ui/outside` is gone, and the 8-character sign-in code is unchanged (an admin with no app keeps using it). The sign-in page for this is temporary: `/signin/authenticator`.
