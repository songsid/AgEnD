section: Added
---
- **One pasted command installs a Windows Runtime and connects it: any computer, no pairing code, no approval step.** **Settings → Runtime → Connect a computer** now makes a short-lived, single-use install command. Pasted into PowerShell on any Windows computer that can reach this AgEnD, or handed to an AI agent or CI job running there, it installs the Runtime and connects that computer in the same window, interactive or not (`powershell -NonInteractive` works), then keeps it running in the background (see below). The command carries a one-time token: 256 random bits, valid for 15 minutes and one use, stored by AgEnD only as its SHA-256, ended at once by **Revoke and close** or by making a new command, and every issue, use, revoke and refusal is recorded. It is issued by the same people, through the same dashboard-session check, as a pairing code, so it grants nothing to anyone who could not already pair a computer. The command also carries AgEnD's server fingerprint: the Runtime first checks an Ed25519 proof from the server it reached and only then sends the token, which goes on the Runtime's standard input (never an argument, an environment variable or a file) and is sealed with AES-256-GCM under keys agreed with X25519, so a server that merely relays the identity check cannot read the token or the credential that comes back. When a computer joins this way AgEnD **tells the owner** through its usual notice pipeline (computer, host, token id and how to revoke it), and the Runtime page announces it (**A new computer joined with an install command**, with **Revoke**). A computer already connected to this AgEnD just reconnects without using the token; one connected to another AgEnD gets its own profile. Expired, used, revoked, malformed and wrong-server tokens each stop with a clear message and a non-zero exit code.
- **A pairing code stays available under Manual options.** A command without a token, run in an interactive console, connects the way the ZIP's `connect-agend.bat` does: a new profile asks for the one-time pairing code shown on the page, shows the fingerprint and waits for your approval in AgEnD; a profile already paired to this AgEnD reconnects without a code. Anywhere else (an AI agent, CI, a pipeline, or a pseudo-terminal where a usual CI variable such as `CI` or `GITHUB_ACTIONS` is set) or with `$agendNoConnect = 1` it only installs, prints the exact `agend-runtime connect --server "…"` command and exits with 0. The pairing code is still typed only into an interactive terminal.
- **The installer leaves a reconnect entry.** `agend-server.json` (only the public address) and `connect-agend.bat` go under `%LOCALAPPDATA%\agend-runtime\connect\<server>` for a double-click next time, and `agend-runtime` accepts `--connection-dir DIRECTORY` to use such a folder; `agend-runtime connect` also gains `--enroll-stdin` and `--server-fingerprint`. `install.ps1` is the same fixed bytes pinned by the hash on the page. Anyone who gets the install command while it is valid and unused could connect their own computer as your Runtime, so treat it like a password; `docs/SECURITY.md` states the risk plainly and `docs/remote-runtime.md` has the details. When no chat destination exists for the owner's "a computer joined" notice, it is kept until a delivery is acknowledged (a refused send is retried; past 100 undelivered notices the oldest fold into one summary). This replaces the earlier statement that the install command "does not connect".
- **A computer that asks to pair opens an approval dialog, waiting computers come first, and computers with one name can be told apart.** In **Settings → Runtime** a computer waiting for approval no longer hides its **Approve** far down a long list: the page opens a dialog by itself with the computer's name, host name, platform, when it asked and the **pairing fingerprint in large type** to compare with the one in that computer's terminal. **Approve** still sends the fingerprint, stays off for the first second and does not take the focus; **Reject** drops the request with no second question and refuses (409, nothing revoked) a computer that was approved meanwhile in another tab; **Later**, Esc, the backdrop and × only close it, and a computer put off that way does not open it again by itself. Several waiting computers are shown one at a time, waiting computers come first in the list under a bar ("N computers are waiting for approval", **Review and approve**), a request that has expired opens nothing and is cleared with **Reject**, and computers that share a name get **#1**, **#2**, when they paired and a hint to rename them. A computer that joined with an install command never waits, so it is announced by its own notice instead.
