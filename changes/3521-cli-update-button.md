- **Update an installed AI CLI from Settings, to the version AgEnD has audited (#3521).** On Settings → Agents → **AI accounts and API keys**, an installed CLI now shows its version beside the newest version AgEnD has audited. When it is older, the row has **Update to \<version\>**: it runs the CLI's own official installer pinned to that exact version (Claude Code, Codex, OpenCode, Grok, Kiro) in the same install window `/login` and the Install button use — one at a time, cancellable, with the version before and after, or the installer's exit code and last lines. It never goes to "latest". A CLI that updates itself in the background (Antigravity, Muse) shows both versions and no button; one that is newer than anything audited says "not verified by AgEnD yet". On Settings → Runtime, a Windows computer's Claude Code or Codex that is older gets **Update to \<version\>**, which is the same pinned install with every check of the Windows install (exact version, hashes, registry signatures, publisher signature); the pins moved to the newest audited releases (Claude Code 2.1.318, Codex 0.166.0). The page sends only the CLI's id, and who may update is the same as who may install.  The audited versions are the maintainer-confirmed ledger (Claude Code 2.1.319, Codex 0.167.0, Kiro 3.1.0, Grok 1.0.77, Antigravity 1.5.3, OpenCode 1.19.5, Muse 1.4.14-R7309.1; the Windows pins and their hashes follow), Muse keeps its build in what the page shows, and an update only starts from a fresh, successful reading of the installed version. Installing or updating a CLI on a paired Windows computer is now a held change of Settings, like the same on the AgEnD computer: an administrator who asked for their own authenticator code is asked for it first, and the computer owner's own switch is still asked on that computer.
