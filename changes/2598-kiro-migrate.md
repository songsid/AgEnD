- **kiro: move an instance from the classic engine to the TUI and keep its conversation (#2598).** kiro-cli 3.0 drops the classic engine that most kiro instances run on (`kiro_ui: legacy`). Changing `kiro_ui` by hand started the instance on an empty TUI conversation, without saying so. The new `migrate_kiro_instance` tool moves one instance. It resumes the instance's classic conversation once under the TUI, where kiro copies the whole history over, and records that conversation as the instance's own. A running instance restarts. Nothing happens until a fleet admin confirms the "Move it" prompt in General. The outcome is posted there and in the instance's topic.
- **kiro: a moved instance is never launched on classic again (#2598).** Going back would resume the frozen classic copy and lose everything done under the TUI. AgEnD refuses that launch and says why. `kiro_engine_status` shows each instance's `engine_floor`. This also applies to an instance that ran under the TUI before this release and was later set back to `kiro_ui: legacy`: it does not start until `kiro_ui` is `tui` again.
- **kiro: a TUI launch no longer uses kiro's plain `--resume` (#2598).** When AgEnD cannot choose a TUI instance's own conversation (an older kiro-cli), it starts a fresh conversation and says so. kiro's plain `--resume` could resume another instance's conversation or fork a classic one. Classic launches are unchanged.
