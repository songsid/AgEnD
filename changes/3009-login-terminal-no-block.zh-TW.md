- **開啟登入的公開連結不再可能讓整個 fleet 卡住；若 fleet 真的卡住，日誌會寫出卡在哪裡。**
  - **這些檢查不再在 fleet 主執行緒上執行。** 登入公開連結對本機檔案做的檢查（在 `PATH` 上找你自己的 `cloudflared`、確認它能執行、寫入 tunnel 租約）以前都在主執行緒上。若 `PATH` 上某個資料夾位在已停止回應的網路或自動掛載磁碟上，主執行緒就會卡住，systemd 的看門狗會在一分鐘後停掉所有 agent（native Linux 回報兩次，#3009；WSL 也有，#1880）。現在這些檢查在背景執行並有時間上限：磁碟一直不回應時，只有這次登入的公開連結會結束並說明原因；若來不及找到你自己的 `cloudflared`，就改用 AgEnD 自己的那份，其他 agent 照常運作。
  - **daemon.log 會記下卡住的情況。** 只要 fleet 主執行緒停住 15 秒，就會由另一條執行緒寫下一行，說明它正在等什麼（狀態、等待通道與系統呼叫），而且趕在 systemd 看門狗動作之前。以前卡住時日誌裡什麼都不會留下。(#3009)
