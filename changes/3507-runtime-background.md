---
section: Changed
---
- **The Windows Runtime keeps running in the background after it connects, and reconnects when you sign in.** `connect`, `connect-agend.bat` and the one-time install command now move the Runtime to the background once it is connected and end, so closing the window no longer disconnects it, and an AI agent or CI that pasted the command gets its exit status right away. The pairing code, fingerprint and approval (or the token) still happen in the window first. `--foreground` (or `$agendForeground = 1` before the install command) keeps the old behaviour. `agend-runtime status` now lists every profile (state, process, AgEnD address, autostart, log folder; `--json` for programs); new `stop`, `restart`, `logs` and `start` commands manage the background Runtime, and one Runtime runs per profile: starting a second one says "already running" and exits with status 0. A background Runtime writes `%LOCALAPPDATA%\agend-runtime\logs\<profile>\runtime.log` (2 MiB per file, six files at most) and survives the in-place update. The first background connect also adds one Task Scheduler task for your own account that runs `start` when you sign in (no administrator rights, not a Windows service); `agend-runtime autostart enable|disable|status` changes it per profile and `disconnect` removes it. The install command restarts a background Runtime after it switched to a different build, and so does a repair run. `status` without `--profile` no longer prints one profile's JSON: use `status --json`. `connect-agend.bat` now ends with a different closing line; close any window that is still running the old one before the next install rewrites it.
