section: Changed
---
- **Reasoning-effort choices follow the model, read from the CLI's own catalog (#3656).** Claude's levels come from the account's `GET /v1/models` (`capabilities.effort`): Opus/Sonnet 4.6 have no `xhigh`, Opus 4.5 stops at `high`, and Haiku 4.5 has no effort setting at all. Grok's come from its `models_cache.json` (`reasoning_efforts`), so `xhigh` is offered on the models that have it and a model with no effort setting gets no `--reasoning-effort`. When the catalog cannot be read (no cache, an alias such as `opus`, a stale cache) the lists are the same as before. Grok's fallback model list, used when its CLI cannot be asked, is its own model cache, then the models it lists today. Muse's Settings summary no longer shows "—" for effort.
- **The chat header's effort chip is always shown (#3656).** An agent whose backend takes an effort setting shows the chip even when none is set — `auto`, the CLI's own default — so `/effort` is one click away. Before, the chip appeared only after an effort had been set.
- **On a phone, the model list shows each model's effort (#3656).** `/model` lists one model per row with its effort (or Auto) and a `›`; the `›` opens that model's own effort list (the one in use ticked, `‹` to go back), and choosing a level sets the model first if it is not the one in use, then the effort. A model with no effort setting has no `›`. The Claude Code / model buttons above the message box are the small button size (30 px, were 44 px), and their touch area stays 44 px. The desktop header is unchanged. Choosing "Auto" again is not offered there, as in the chip's `/effort` list.
