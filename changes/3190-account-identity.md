- **Settings show which account a Claude sign-in is (masked e-mail and plan).** On a Windows computer's card in Settings → Runtime and in the agent's **Claude account** choice, each credential profile and the default sign-in appear as `work · ab***@example.com · Team`; Settings → Agents → **CLI sign-ins** shows the same for the AgEnD host's own Claude Code sign-ins (the default and every `credential_profile`). Only the first two characters of the address are kept (one if it is that short), then `***`, then the whole domain, so a work and a personal account can be told apart; the full address never leaves the computer that holds the sign-in and is never logged. A Windows Runtime reports it only on **Detect again** (and after `agend-runtime login`), AgEnD rejects anything but that exact masked form, and a Runtime that does not know about it simply shows nothing. An API-key sign-in is shown as having no account e-mail, and a plan that is not one of `free`, `pro`, `max`, `team`, `enterprise` is shown as an unknown plan. One shared parser now reads `claude auth status` for the sign-in check, the host list and the Windows Runtime.
