- **用 nvm 安裝的 AgEnD，聊天的 `/update` 可以正常使用（#3440）。** Fleet 服務的 PATH 把系統的 npm（例如 `/usr/bin/npm`）排在安裝 AgEnD 的 nvm Node 前面時，`/update` 會拒絕並顯示「… is not an installed AgEnD package」，而且接下來要跑的更新也可能用到錯的 npm。現在 `/update` 會先問正在執行的 AgEnD 旁邊的 npm（用同一個 prefix 自己的 Node 執行），其次是執行 AgEnD 的 Node 旁邊的 npm，最後才是 PATH 上的 npm。只有全域根目錄裡就是這個正在執行的 AgEnD 的 npm 才算數，其餘內容照舊逐項驗證。主機上沒有任何 npm 管理目前執行的安裝時，`/update` 會直接說明，列出預期的全域根目錄，以及每個 npm 回報的位置。它啟動的更新程式會把該安裝的 `bin` 資料夾放在 PATH 最前面，讓 `agend update` 的檢查和安裝都用同一個 npm。
