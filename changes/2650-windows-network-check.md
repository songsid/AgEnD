- **The Windows installer checks the sites it really needs, from Windows and from WSL, and says why one cannot be reached (#2650).** Before, a single request to Google decided whether to install at all. A network that blocks Google stopped the install even when everything needed was reachable. A network where only the Windows browser gets out, through a company proxy, passed the check and then failed later in WSL. Now Windows checks AgEnD's install site (required) and GitHub (warn only). Once Ubuntu is ready, WSL checks AgEnD's installer, npm, Node.js and nvm (required), and the Ubuntu archive and the AI vendors' sites (warn only). Each site gets at most two 10-second tries, and any HTTP answer counts as reachable. A failure is named (DNS, timeout, refused, an untrusted HTTPS certificate, a proxy) with what to do. For a certificate problem, the advice is to get the company root certificate for Ubuntu and set `NODE_EXTRA_CA_CERTS`. For a proxy, it is to set the Windows proxy for WSL; only the host and port are shown, never credentials. When a required site fails, the installer asks before going on; the default is to stop. The one-line command's own download now has a time limit and names proxy, certificate and timeout failures.
