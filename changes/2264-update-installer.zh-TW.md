section: Fixed
---
- **更新不會再讓主機變成沒有 `agend`，而且再執行一次安裝程式一定能修好（#2264）。**
  - 更新現在由新版本自己的安裝程式執行：`agend update` 透過 `npm exec` 執行它，安裝的一行指令也一樣。安裝、更新、修復是同一個程式。
  - 安裝程式會先修好中斷的安裝留下的東西：
    - 它在做任何事之前先取得安裝鎖，並持有到完成為止。另一個安裝程式正在執行時，什麼都不碰，包括那次更新的聊天訊息。沒有人持有、或讀不懂的鎖會被移到一旁；
    - npm 移到旁邊的那份 AgEnD 在它是唯一完整的一份時會被放回去。只有在主機上沒有其他 npm 正在安裝套件時才會這麼做；
    - 不會刪除任何東西：其他被移到一旁的都保留在 `<npm prefix>/.agend-quarantine/`。
  - 接著安裝新版，並確認 `agend --version` 能執行。npm 失敗但前一版仍能執行時，不再做其他事，並如實說明。沒有任何能執行的 `agend` 時，才重新裝回前一版。
  - 服務沿用原本的管理方式（系統層的服務仍是系統層）：先更新設定但不啟動，接著艦隊重新啟動；服務原本停著就啟動它。
  - `agend update` 只執行目標版本自己的安裝程式，而且只在該版本有安裝程式時；較舊的目標版本用原本的方式更新。
  - 在 Node 版本低於 22 的 Mac（或任何主機）上，更新不會再在安裝程式開始前就停下：npm 只為了執行安裝程式而下載的那份，不會因為內建的 Node 而被拒絕。
  - 安裝腳本移除舊 plugin 套件的步驟已刪除。
  - 使用 sudo 時，搬到 nvm 之後只有 2.1 版的系統層副本會被退役。
  - 手動 `npm install -g` 不會再因為鎖而被拒絕。
  - `agend install`、`start`、`restart` 現在會開啟 systemd linger，所有服務指令都會自己找到執行期目錄，所以 `agend start`／`restart` 從任何 shell 都能用（包括 WSL 上的 root）。啟動更新的那次登入結束時，更新也不會再被中斷。
  - 聊天裡的更新訊息一定會有最終結果。艦隊重新啟動後的版本和更新的目標不同時，會直接說出來，並給出完成更新的一行指令。
