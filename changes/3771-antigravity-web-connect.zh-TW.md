- **設定 → 帳號：從儀表板連接 Antigravity，支援多個帳號，主機和配對的 Windows 電腦都可以（AGEND-224，來自 AGEND-113/119/124；上游 #3330 方案 A）。** Antigravity 的預設連接現在和 Claude Code 一樣有「連接」／「重新連接」：儀表板在專用的連接視窗（絕不在 Agent 的 pane）執行 `agy acp --login`（需要 agy 1.5.0 或更新；稽核過的版本是 1.5.5），顯示 Google 的連結，並接收你貼回的授權碼。只有指令以 exit 0 結束、而且 `agy models` 能用，才算連接成功；失敗或取消的指令，不會因為舊的連接還在就算成功。連接視窗沿用每個 backend 各一個的規則（#3725），連接 Antigravity 不會擋住其他 CLI。多帳號：「＋新增帳號」會給 Antigravity 帳號自己的資料夾（`agy --app_data_dir <資料夾>`，並用 `SSH_CONNECTION` 固定，讓 agy 把這個帳號的連接存在該資料夾的檔案裡，而不是每個資料夾共用的系統鑰匙圈）；連接之前，AgEnD 會先問 agy 一個空的暫存資料夾，除非它回答「尚未連接」，否則拒絕（`not_isolated`，什麼都不會啟動）。Agent 可以選擇用某個帳號執行（Agent 啟動時才為該帳號產生首次啟動的檔案，只在檔案不存在時寫入，而且只信任該 instance 自己的工作目錄；不會從預設帳號複製任何東西）；「撤銷連接」會刪除該帳號的 token 檔，再用 `agy models` 確認有沒有生效；「移除」會刪除整個資料夾；「保持連接」會在帳號的 token 快過期時執行 `agy models`（大約每小時一次，Agent 正在使用時不會執行）。該列會顯示是哪個帳號（從 agy 自己的 token 檔在本機讀出的完整 email），以及 Antigravity 回報的每一個額度池（Gemini、Claude 與其他模型、Gemini 4 Argon）和每一個時段，一個池一個區塊；連接完成後會立刻重新讀一次用量。配對的 Windows 電腦有同樣的帳號、「連接」與「撤銷連接」，帳號資料夾放在 Runtime 自己的 `credential-profiles` 下，並使用同樣的隔離檢查；電腦自己的預設連接（每個 Windows 使用者一個，存在 Credential Manager）只有在網頁先確認、而且擁有者已打開 `accounts` 時才會被取代。只做 Google 帳號（訂閱）連接。較舊的 agy 維持「從聊天連接」並提示更新；第一次安裝頁面和聊天裡的 `/login agy` 不變。**請把伺服器和 Runtime 一起升級：**Runtime 現在會回報 `signin-antigravity` 與 `accounts-antigravity`，伺服器不會對沒有回報的 Runtime 提供這些功能。
