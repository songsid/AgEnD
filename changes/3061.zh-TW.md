- **沒有連接聊天平台的 fleet，「存取與安全 → 登入與授權」整個重做（#3061）。** 頁面依序列出擁有者驗證、登入工作階段設定、網頁授權，文案對齊參考頁。「從外面連線」卡改名為「擁有者驗證」：有狀態標籤、標示支援的驗證器 App 的徽章（Google Authenticator、Microsoft Authenticator、其他 TOTP 驗證器），並寫明設定、重新綁定與停用只能在 AgEnD 電腦上進行，沒有電子郵件或備援碼復原。設定或重新綁定驗證器改為開啟彈窗（步驟 1、2：QR Code 與金鑰，再輸入代碼），不再在卡片內展開；Esc 和取消會關閉彈窗且不改任何東西，輸錯代碼會在彈窗內回應。網頁授權卡改說明以驗證器（而非 Discord／Telegram）確認擁有者。沒有設定或儲存的值改變。
- **新裝置可用 8 碼代碼登入（#3061）。** dashboard 自己位址上的登入頁新增「使用其他裝置登入」，會顯示代碼與五分鐘倒數。已登入且已驗證擁有者的裝置（AgEnD 電腦的管理員，或用驗證器從外面登入的人），到「設定 → 存取與安全 → 登入與授權 → 裝置與登入 → 新增裝置」，確認請求的來源、位址，以及要與新裝置畫面核對的代碼後核准。核准不會把登入狀態複製給新裝置：它會建立自己的工作階段，且不含擁有者授權。代碼只能用一次、五分鐘後失效並有頻率限制（限流看連線本身的位址，IPv6 以 /64 計算）；核准端輸錯代碼會暫停核准。公開連結上、有連接聊天平台的 fleet、以及網頁授權關閉時（沒有人能核准）都不提供。
- **已登入裝置的列表，以及選用的登入 QR Code（#3061）。** 「裝置與登入」會列出已登入的裝置：標出目前這台、每台的核准方式（登入碼、裝置代碼、這台電腦、驗證器 App）、擁有者是否已驗證，以及最後活動時間。已驗證的擁有者可以在那裡登出其他裝置。**[行為變更]** 在 web-only fleet 上，結束別的裝置的工作階段——不論用那個按鈕，還是工作階段選單用的 `DELETE /auth/sessions` 路由——現在都需要擁有者；用登入碼或裝置核准建立的工作階段仍可登出自己。網頁授權關閉時沒有人是擁有者，卡片會說明這點，並指向在 AgEnD 電腦上執行 `agend web-token rotate`（會結束所有工作階段）。有連接聊天平台的 fleet 不變。新增 `web.login_qr` 開關（預設關閉），開啟後新裝置的頁面會多畫一個核准連結的 QR Code：裡面只有頁面自己的網址和畫面上的代碼，沒有任何憑證。請在已登入並驗證擁有者的裝置上開啟，不要在未登入的裝置上開（它的登入連結不會帶代碼）。
- **agent 的檔案讀取會拒絕 `web-remote-access.json` 和 `web-authorizations.json`（#3061）。** 這兩個檔案存放驗證器金鑰與輸錯代碼的狀態，以及工作階段授權；agent 以往可以從已准入的暫存目錄指名讀取它們。現在它們已在私密檔名清單中。
