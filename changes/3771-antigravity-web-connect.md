- **Settings → Accounts: connect Antigravity from the dashboard, with several accounts, on this host and on a paired Windows computer (AGEND-224, from AGEND-113/119/124; upstream #3330, option A).** Antigravity's default connection now has **Connect** / **Reconnect** like Claude Code's: the dashboard runs `agy acp --login` (agy 1.5.0 or newer; the audited release is 1.5.5) in its own login window, never in an agent's pane, shows Google's link, and takes the code you paste back. It counts as connected only when the command ended with exit 0 and `agy models` works; a failed or cancelled command is never "connected" because an older login is still there. The login window is the per-backend one (#3725), so connecting Antigravity never blocks another CLI. Extra accounts: **+ Add account** gives an Antigravity account its own folder (`agy --app_data_dir <folder>`, pinned with `SSH_CONNECTION` so agy keeps that account's connection in that folder's file and not in the system keyring every folder shares); before it connects, AgEnD asks agy about an empty scratch folder and refuses (`not_isolated`, nothing started) unless that says "not connected". An agent can run on an account (when it starts, the account's first-run files are generated, only when missing, with just that instance's working directory trusted; nothing is copied from the default account), **Disconnect** removes the account's token file and then asks `agy models` whether it took effect, **Remove** deletes the folder, and **Keep connection alive** runs `agy models` for an account whose token is about to lapse (about once an hour, never while an agent uses it). The row shows which account it is (the whole address from agy's own token file, read locally) and every quota pool Antigravity reports (Gemini, Claude & others, Gemini 4 Argon) with every window, a block per pool; a finished connection reads the usage again at once. A paired Windows computer gets the same accounts, **Connect** and **Disconnect**, with the account folders under the Runtime's own `credential-profiles` and the same isolation proof; its own default login (one per Windows user, kept in the Credential Manager) is replaced only after the page asks, and only where the owner turned `accounts` on. Google-account (subscription) connection only. An older agy keeps "Connect from chat" with a note to update; the first-install page and `/login agy` in chat are unchanged. **Upgrade the server and its Runtimes together:** a Runtime now reports `signin-antigravity` and `accounts-antigravity`, and a server will not offer these to one that does not.
